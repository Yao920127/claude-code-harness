# Agent Note: 基於檔案系統與程序管理執行世界的可移植消費方

Status: implemented

[English](2026-07-28-portable-execution-world-consumers.md) | 中文

## 問題

檔案系統與程序管理 seam 使檔案存取和普通程序存取具備可替換性，但 PTY 和 LSP 仍直接呼叫主機 Node API。因此，即使領域行為沒有變化，遠端執行提供者看起來仍需要獨立的 PTY 與 LSP 包。這些包只會成為淺層介面卡：每個包都僅為替換檔案與程序操作而複製一個現有消費方。

只有檔案操作、命令、終端和語言伺服器共享同一個沙箱身份時，遠端編碼世界才有用。若把完整 harness 移入該沙箱，還會把提供者實驗與外掛載入、憑證、模型傳輸、工作階段永續性、監督和部署糾纏在一起。

普通管道無法滿足其中一項要求。持久終端需要分配 PTY、檢查前臺程序組併傳送訊號，以及清理完整的終端工作階段。如果假設可以在 `dsh-terminal-bash` 中基於普通 `spawn()` 控制代碼重建這些操作，最終不是洩漏提供者內部細節，就是削弱其生命週期約定。

## 決策

`ctx.fs` 與 `ctx.subprocess` 共同定義一個執行世界。共同掛載的提供者必須描述相同的路徑名稱空間、可執行檔案、程序和終端工作階段；上層能力消費這兩個介面，而不引用具體提供者。

前臺 Bash 和 PowerShell 呼叫由同一執行器 deadline 覆蓋非同步 confinement 準備與程序執行。準備超時返回沒有程序退出或訊號事實的結果，晚到的 argv 不能啟動程序；後臺準備仍只跟隨呼叫方取消。子類透過受保護的執行結果區分是否已呼叫 subprocess provider，只有釋出後才附加 enforcement 事實。

檔案系統介面負責其他能力需要的路徑事實，同時不公開其不透明目標身份：規範化程序路徑、規範化 `file:` URI 和包含關係。現有完整文字與流式文字操作仍歸檔案系統負責；協定消費方在消費流時執行各自的保留上限。

程序管理介面負責可執行檔案查詢與程序原語：以原始或收集模式 spawn 普通程序，以及 `spawnTerminal()`。普通控制代碼把 target identity 保持為私有事實：`.done` 報告 direct target，`terminate()` 與 `waitForExit()` 則控制並觀察同一個由提供者管理的範圍。[原生 containment 決策](2026-08-28-subprocess-native-containment.zh.md)負責本地 Linux scope、Windows Job 及其已宣告的 fallback。終端操作是一項深層原語，其控制代碼負責文字 I/O、前臺程序組、訊號傳送，以及一項須等待的 TERM→KILL 操作；該操作會結算所有在途控制代碼呼叫，並使提供者擁有的範圍中每個成員完全停穩；觀察型 fallback 只能把該範圍限制為它仍可觀察到的 identity。其訊號只取消分配；控制代碼一經發布，便負責自身生命週期。提示符檢測、空閒推斷、scrollback、沙箱策略和所有者生命週期仍由 PTY 消費方負責。

通用消費方使用該執行世界：

- `dsh-bash-local` 繼續把 Bash 語義對映到普通的 `ctx.subprocess.spawn()`。
- `dsh-lsp-stdio` 透過 `ctx.fs` 讀取原始檔並驗證包含關係，透過 `ctx.subprocess` 解析和啟動語言伺服器，並讓由提供者負責的檔案 URI 貫穿初始化與結果渲染。一個提供者生命週期訊號會在資源釋放期間中止檔案系統與協定操作，包括取得佇列所有權之前的工作區查詢；其 JSON-RPC、池化、同步和規範化保持不變。
- `dsh-terminal-bash` 把持久 shell 語義對映到 `ctx.subprocess.spawnTerminal()`。本地 `node-pty` 與程序檢查實作移入 `dsh-subprocess-local`；其他程序管理提供者則提供相同原語。`danger-full-access` 不需要 `ctx.sandbox`；受限模式要求同一執行世界中存在沙箱提供者，未掛載時會在 spawn 前失敗。提供者開始寫入時，系統會丟棄非同步寫入前檢查期間收集的提示符與靜默證據。取消會在在途寫入結算期間保留髮送預留，隨後向前臺程序組傳送訊號，因此延遲位元組和該訊號都無法落到後續傳送；在途就緒檢查無法釋放該預留，寫入被拒絕時也不會傳送訊號。絕對截止時間會在整個取消期間保持啟用。訊號傳送失敗會成為終結性傳輸失敗。陳舊檢查完成後，會針對目前傳送恢復輪詢。啟動取消會立即開始終端復原，而不等待停滯的就緒檢查或訊號傳送呼叫。關閉操作會拒絕新的公開訊號，並把由提供者管理的工作階段完全停穩委託給控制代碼上須等待的終止操作。

## 遠端提供者的職責

[E2B 提供者移除決策](../simplification/2026-09-11-remove-e2b-providers.zh.md)取代本決策中的 E2B 實作。檔案系統／子程序約定與非同步終端約定繼續適用於遠端實作。[POSIX SSH 提供者](2026-09-11-posix-ssh-runtime.zh.md)透過一個已安裝輔助程式與獨立流通道實作這些約定。

遠端提供者負責可變檔案、命令與終端程序、語言伺服器程序，以及提供者私有執行時檔案。主機負責 Cordis 與外掛物件、智慧代理迴圈、智慧代理／工作階段／目標狀態、工作階段日誌與持久化、模型傳輸、權限、技能、子智慧代理編排、終端就緒判斷和 LSP 協定狀態。移動執行位置不意味著工作區同步或持久遠端控制代碼。

## 驗證

本地檔案系統、子程序、終端與 LSP 測試覆蓋路徑身份、可執行檔案查詢、受管清理、輸出上限、取消與資源釋放。終端消費方測試保留延遲的提供者寫入、前臺檢查和訊號傳送，以便在無需遠端服務時驗證非同步所有權。

## 考慮過的替代方案

**為每個遠端提供者分別保留 PTY 與 LSP 包。** 不予採納，因為這會在現有 seam 之上重複實作提供者機制。刪除檢驗揭示了這一問題：刪除這些介面卡不應使領域行為散落到遠端提供者中；通用消費方本已負責這些行為。

**為每項能力或工具建立獨立沙箱。** 不予採納，因為檔案與程序操作將無法共享身份或狀態，從而破壞編碼案例，並增加生命週期所有者的數量。

**把終端建模為普通的管道子程序。** 不予採納，因為管道無法分配控制終端、確定目前前臺程序組或證明完整終端工作階段已清理。一項終端原語比公開特定於執行基底的逃生口更小，也更能如實表達約定。

**把 PTY 就緒判斷與工作階段策略移入程序管理服務。** 不予採納，因為這些屬於持久終端消費方的語義，而非 OS 程序機制。程序管理提供者負責只有其執行基底才能完成的操作；`dsh-terminal-bash` 負責 Harness 終端的語義。

**分別公開終端終止與完全停穩操作，並提供共享生命週期控制器。** 不予採納，因為每個終端消費方都需要相同的單一清理結果。拆分操作會把提供者簿記、有界觀察者和重試語義暴露出來，卻沒有生產消費方；由提供者提供一個須等待的操作，介面更深。

**在檔案系統 seam 中新增穩定的有界讀取原語。** 不予採納，因為只有 LSP 需要完整文件位元組上限，而它可以在消費現有文字流時執行該上限。第二項原語會迫使每個提供者實作穩定控制代碼和不跟隨符號連結的機制，遠端提供者甚至需要輔助協定，卻沒有已觀察到的並行替換缺陷。

**在遠端環境中執行整個 harness。** 不予採納，因為這是另一種部署模型。讓執行能力可移植，並不意味著移動模型呼叫、工作階段狀態、外掛狀態或 agent loop。

**把所有提供者操作都放進一個共享所有者包。** 不予採納，因為沙箱身份與生命週期是所有者唯一的關注點。檔案系統與程序管理保留各自獨立的約定、測試和消費方，同時避免把所有者變成無邊界的能力集合。

**只透過 shell 命令實作遠端檔案系統操作。** 不予採納，因為這會丟棄現有檔案工具已消費的結構化檔案系統身份、錯誤、流式輸出、版本保護和原子變更語義。

**新增通用分散式執行時抽象，或重新連線活躍控制代碼。** 不予採納，因為現有能力 seam 已承載經證實的約定，而僅憑遠端身份無法重建回呼、待處理 promise、權限、協定狀態或輸出遊標。新增一層只會推測 已驗證消費方約定之外的持久化與同步問題。

## 後果

遠端執行家族提供共享連線管理器及配套檔案系統、子程序提供者；受限呼叫還需要沙箱提供者。Bash、PTY 與 LSP 組合在這些介面卡之上，因此對這些能力的修復仍與提供者無關。

基礎介面更寬，一對檔案系統／程序管理提供者必須在同一個執行世界上保持一致。新增操作僅限目前通用消費方所需的事實與生命週期機制；模型 schema、協定分幀、就緒策略和呈現不會滲入提供者。

本地實作承接 `node-pty` 和平臺程序檢查，因為它負責本地終端機制。在受支援的 Linux 主機上，user-systemd scope 會保留呼叫 `setsid` 或發生 reparent 的後代，程序檢查則繼續負責前臺歸屬與同步 fallback 證據。其他主機使用觀察型拆卸：dispose（資源釋放）會在終止頂層 shell 前後清理後代程序，等待前臺檢查期間保留下來且受精確 PID 身份圍欄保護的後代程序，並繼續追蹤在頂層程序退出後仍存活的 Linux 工作階段成員。macOS 無法在 POSIX 工作階段 leader 退出後列舉該工作階段，因此在兩次檢查快照之間重新設定父程序的子程序仍是明確的本地提供者限制，而不是把程序機制移回 PTY 消費方的理由。

遠端實作必須保留現有消費方約定，或明確拒絕不支援的操作。傳輸特定的緩衝、身份與斷線限制歸提供者負責；這些限制不是複製 Bash、PTY 或 LSP 實作的理由。
