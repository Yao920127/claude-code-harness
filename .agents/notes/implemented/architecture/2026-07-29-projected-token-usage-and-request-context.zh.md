# Agent Note: token 用量投影與上下文佔用率

Status: implemented

[English](2026-07-29-projected-token-usage-and-request-context.md) | 中文

## 問題

Web 統計行原先從目前已載入的工作階段節點推導 token 總量。該視窗是分頁的，因此滾動會改變總量；壓縮（compaction）又會替換可見內容，而不保留其背後的計費用量。持久的提供者計費用量需要一個能同時經受這兩者的資料來源。

上下文佔用率需要一個分子和一個分母，而這兩者都不曾由任何既有介面送達瀏覽器：最新一個請求的提示詞規模，以及該請求所用路由的容量。

## 決策

這兩個值都是普通的持久工作階段投影狀態。當 `ctx.sessionProjections` 存在時，`@deepseek-ai/dsh-token-meter` 會註冊兩個單元。

`tokenUsage` 將完整持久日誌歸併為未快取輸入、輸出、快取讀取和快取寫入四類計數項。它會展開每個 `assistant/message` 或 `assistant/attempt` stream 並採用最後一個 usage sample；message 頂層 usage 優先於其嵌入式 sample，因此不會重複計數。`assistant/attempt` 由此保留失敗請求的 usage。匹配的 `llm/retry-started` 邊界會開啟新 attempt，因此複用同一 `(turn, step)` 的重試會單獨貢獻用量。推理（reasoning）仍是輸出的細分項。compaction 和 surface replacement 不會抹除先前計費。

token-meter 還擁有在持久事件上執行的共享純 attempt／Turn fold。它採用相同的重試邊界，並增加精確單輪次 disclosure 所需的更嚴格完整性與精確總量檢查。展示消費方可以選擇完整 Turn 視窗並呼叫該 fold，但不擁有或複製記帳語義。

`contextPressure` 攜帶可選的 `pressureTokens`（提供者報告的最新提示詞規模，為未快取輸入加快取讀取與寫入之和，不含輸出），以及來自最新一條 `request/context` 記錄的可選 `contextWindow`。在各自來源出現前，兩個欄位都不會被合成。

`request/context` 是新增的僅入日誌工作階段事件，記錄請求所解析到的路由的、繫結註冊項的中繼資料。AgentLoop 在步驟內緊隨 `request/header` 追加它，資料取自 `prepareCall()` 現在與已解析設定一併返回的上下文中繼資料：正是那次已經驗證過推理的、繫結註冊項的查詢，因此不會發生第二次解析。當提供者、模型和容量都與上一條記錄相同時會跳過。介面卡不公佈容量的路由會以缺失 `contextWindow` 的形式記錄，從而清除較早路由的分母。

容量刻意不進入 `EpochHeader`。該型別是重建約定，即請求由什麼建置而成，而 `headerEquals` 會逐欄位比較它，以判定某個快照是否真的是一次 `change`。容量是描述路由的介面卡中繼資料，把它放進去會讓容量變化偽裝成請求封裝的變化，還會把它拖進 AgentLoop 的重建不變式。

兩個單元都沿用標準投影生命週期：歷史尾頁基線、`session/projection` 即時幀、seq 高者勝的用戶端儲存、JSON 檢查點、快取恢復和單元解除安裝。系統沒有任何 token 專用的歷史欄位、mux 幀、投影器、修訂計數器或用戶端柵欄。

Web [`StatsPills`](../../../../packages/client/ui-chat/src/client/chat/StatsPills.tsx) 透過標準 `useProjection` 席位讀取兩者。視窗內節點仍作為無投影退回提供輪次和步驟計數，以及 LLM（大語言模型）與工具的牆鍾時間：它們回答的是「螢幕上有什麼」，按視窗作用域正是正確的。壓縮使可見 assistant 步驟歸零後，持久用量 pill 仍會保留。快取寫入會計入計費輸入和快取命中率分母。未部署 token-meter 時會去掉用量 pill；上下文佔用率由輸入框旁的 ContextMeter 圓環承載。精確 token 數字顯示在用量 pill 點選展開的彈層裡，而非懸停提示。

## 上下文佔用率是近似值，而這正是決策本身

`pressureTokens` 與 `contextWindow` 是兩個各自後者勝的獨立欄位，不是一次原子觀測。切換模型時，新容量會與上一路由的壓力配對，直到下一個請求報告用量為止；分子描述的是最後一個請求，而不是此刻的表層。

這是刻意接受的結果。佔用率百分比是面向使用者的參考數字：harness 中沒有任何環節依據它做決策，壓縮改為直接讀取 `measure()`。TUI 狀態行一直以這種方式計算佔用率，即用 `measure()` 總量除以為所選模型單獨解析出的容量；因此在這裡做成原子版本才是異類，而不是常態。

這種非原子性是有意為之，不是缺陷。確實需要同一邊界精確數字的消費方，應在自己的請求邊界呼叫 `ctx.tokenMeter.measure()`，那裡兩個值同時可得，而不是讀取該投影。

## 備選方案

**以臨時 mux 幀交付請求邊界上的原子快照（已實作，隨後否決）。** 較早的一個修訂版會發出 `session/model-request`：一個不可回放的幀，攜帶在同一個 `agent/model-request` 邊界測得的 `contextTokens` 與 `contextWindow`。真正讓它失效的，是它成了 mux 流上唯一的不可回放類別。Host 流與 mux 流是兩條獨立的 SSE（Server-Sent Events）流，彼此之間沒有順序保證：在移除之前發出的請求可能在 `host/session-removed` 之後才到達，讓一個已死工作階段的遙測資料復活；而複用同一 id 的新生命週期的合法請求，又可能被一條遲到的移除攔下。`session/subscribed` 不能證明生命週期：它只說明某個佇列開始訂閱某個 id，而不說明新的記憶體工作階段替換了較早的工作階段；`lastSeq` 則是兩個生命週期可以共用的持久水位線。正確的修法需要在幀上、訂閱上和移除上都帶一個單調遞增的生命週期代次，再加上一次用戶端水位線比較。

這份代價換來的是更差的顯示：佔用率在每次重連後變為空白，而且工作階段增長期間從不移動。它還把傳輸介面卡變成一個測量點，每個請求都要呼叫 O(surface) 的 `measure()`，並透過一個 UI 必須特殊處理的、連線開啟時的合成 `cancelled` 錯誤來表達重連狀態。

**在 React 中歸併已載入的節點視窗。** 無法跨分頁或壓縮保留資料，還會迫使展示包重建日誌語義。

**僅隨最終 assistant 訊息釋出用量。** 如果請求報告一個用量分片後失敗，就會丟失自己的計費用量。

**在 token-meter 內部解析容量。** 該包自述與模型路由無關，且在其他方面是一個從不向日誌追加內容的純讀取方。AgentLoop 在寫入請求頭的位置已經持有已解析的中繼資料。

**為 `session.models` RPC 增加容量欄位。** 其處理器已經解析出容量又將其丟棄，因此這個欄位幾乎是免費的；但統計展示（現為 `StatsPills`，ui-chat）與模型目錄位於兩個互不依賴的外掛。要送達它，就得增加第二個 dock 條目把一個表面拆到兩個外掛裡，或者做一次跨外掛的 store 寫入。

**在模型選擇器旁增加上下文圓環。** 該位置會讓人以為這是所選模型的狀態。統計行可以承載該數字，無需引入重複的 UI 或資料路徑。

## 後果

token 總量在分頁、壓縮、回放、重新啟動和重連期間保持穩定，因為它們是透過通用路徑恢復的普通持久投影狀態。跨流重排序競態從建構上就不存在，而不是被柵欄擋住。

佔用率在上文記錄的意義上是近似值。由於兩個欄位都是持久的，它在恢復或重連後立即可用；代價是它描述的是最後一條已記錄的請求，而不是精確的目前邊界。

每個工作階段日誌會為每次路由或已公佈容量變化增加一條小型 `request/context` 記錄。token-meter 是持久用量語義的正典所有方，包括累計投影中的重試 attempt 分離，以及可複用的精確 attempt／Turn fold；Web Chat 只選擇已完整載入的 Turn 並渲染 fold 結果。TUI 未掛載通用投影 seam，因此保留自己的即時逐步驟 map，而組裝 RemoteMock 情境提供相同投影值。Connection 與 API Gateway 不攜帶任何 token 專用程式碼，不擁有逐工作階段指標快取，也不執行測量。瀏覽器只保留兩個通用投影值，不保留連線本地的遙測資料；流式文字增量不會迫使統計行重新計算或反覆替換佈局 observer 訂閱。
