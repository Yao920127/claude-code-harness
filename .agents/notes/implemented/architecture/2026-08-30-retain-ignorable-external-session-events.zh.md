# Agent Note: 為外部外掛保留可忽略工作階段事件

Status: implemented

[English](2026-08-30-retain-ignorable-external-session-events.md) | 中文

## 問題

工作階段事件信封包含 `ignorable?: true`，讀取器因此可以接受不認識的資訊性事件，而不必把每次詞彙增加都視為新的工作階段格式。PR #3087 在沒有發現第一方生產方後刪除了該欄位，並把每個未知事件都改為讀取必需項。

該生產方清單沒有覆蓋目前依賴此欄位的一個第三方外掛。沒有 `ignorable` 時，第一方讀取器會拒絕包含該外掛資訊性事件的已存工作階段，因為該事件不在儲存庫生成的 `KNOWN_SESSION_EVENT_TYPES` 中。外掛沒有可替代的註冊或版本機制，因此在替代機制存在前刪除該欄位會破壞目前外部消費方。

## 決定

標準 `SessionEvent` 信封保留 `ignorable?: true`，每種表示都保留它：seed 驗證、JSONL、API 傳輸、生成目錄與測試 fixture。持久化 seam 的已存事件驗證（`validateStoredEvents`）繼續拒絕未知事件，除非已存信封顯式帶有 `ignorable: true`；欄位不存在時仍表示讀取必需。

只有替代機制在事件生產、持久化、重新載入與傳輸中都支援目前第三方外掛，併為已包含該標記的工作階段提供顯式切換方案後，才能刪除此欄位。[Session log 版本決策](2026-08-10-session-log-version-mechanism.zh.md)繼續定義預設讀取必需的安全規則與格式版本策略。

Alpha 實作中的歷史格式遷移有意更嚴格。v0-to-v1 遷移邊會拒絕每個未知 v0 型別，包括 ignorable 型別，因為不透明 payload 可能包含格式遷移邊無法驗證的引用。[Alpha 歷史事件決策](2026-08-31-alpha-historical-unknown-event-refusal.zh.md)定義該有限例外；同版本 append 與 reload 繼續遵循本記錄。

## 曾考慮的替代方案

**要求讀取所有未知事件。** 不予採用，因為目前第三方外掛會發出儲存庫生成詞彙之外的資訊性事件。即使省略該事件是安全的，第一方重新載入仍會拒絕該工作階段。

**先刪除欄位，以後再設計替代機制。** 不予採用，因為該順序會立刻產生相容缺口，而且外掛及其已存工作階段都沒有遷移或切換路徑。

**把所有儲存庫外事件都視為可忽略。** 不予採用，因為讀取器無法推斷未知持久事件是否屬於資訊性事件。外部事件可能改變後續重建或外掛自有狀態。

**把已掛載外掛的事件名稱註冊為已知。** 不作為刪除機制採用，因為只註冊事件名稱無法判定缺失該事件是否安全，而且接受結果會依賴讀取器的目前組合，而不是已存記錄。

## 影響

第三方資訊性事件的已存記錄帶有顯式標記時可以繼續重新載入，未知必需事件則仍會明確失敗。在替代機制滿足切換條件前，該欄位繼續屬於公開事件信封、JSONL 表示、傳輸型別、生成引用及其測試。
