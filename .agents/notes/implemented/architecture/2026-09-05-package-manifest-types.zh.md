# Agent Note: Package manifest 宣告歸屬

Status: implemented

[English](2026-09-05-package-manifest-types.md) | 中文

## 問題

外部包需要 Harness manifest 型別，而無需依賴啟動器或用戶端實作。將宣告放在各讀取方旁邊，會使完整設定 API 難以查詢，也容易讓重疊欄位發生偏離。

## 決策

[`@deepseek-ai/dsh-package-manifest`](../../../../packages/util/package-manifest/README.zh.md) 在一個純型別檔案中擁有 `DshManifest` 及其成員宣告。本包屬於現有工具庫分組，不匯出執行時值。[公共包中繼資料決策](2026-09-10-public-package-manifest.zh.md) 擁有公共欄位範圍及其與內部工具中繼資料的劃分。

各讀取方直接匯入共享宣告。啟動器保留 profile 載入、原始 JSON 檢查、預設值和解析後的執行時資料。用戶端模組保留歸一化的啟動圖。映像打包器將宣告路徑解析為目錄。Session 目錄生成器派生帶有已解析匯入路徑的只讀驗證結果；原始輸入和發現規則仍由本地負責。

App-boot 宣告生產依賴，因為其釋出的宣告檔案引用共享型別。用戶端模組使用開發依賴，因為其釋出 API 不暴露這些型別。內部映像打包器和 Session 目錄宣告保留在各自讀取方。每個包消費方都有 TypeScript 專案引用。外部作者從工具包匯入；app-boot 不提供相容性再匯出。

## 考慮過的替代方案

**將宣告保留在各讀取方。** 外部作者會依賴執行時實作，而僅覆蓋 profile 的部分定義會遺漏已有的用戶端和建置欄位。

**建立獨立的 types 分組。** 現有工具庫分組可以容納純型別庫，無需增加包分類。執行時服務和事件宣告仍由各自負責方擁有。

**統一 JSON 解析器。** 共享宣告不要求改變驗證、錯誤、預設值或解析結果；這些仍由各讀取方負責。

## 後果

作者獲得統一的公共匯入路徑，代價是一個釋出包和明確的依賴邊。已有的 app-boot manifest 型別匯入需要改用新包。[Profile 組合設計](2026-08-05-profile-plugin-bundles.zh.md) 繼續負責執行時語義；型別提取不改變設定接受範圍或模型可見行為。

編譯器與打包後的 NodeNext 消費方檢查覆蓋公共匯入。已有 profile、用戶端、映像設定和 Session 目錄測試覆蓋讀取行為；文件檢查覆蓋工具庫分類與生成的包目錄。新增可選宣告欄位時，仍需主動更新消費方。

目前安裝器和載入器不強制檢查 manifest 格式或主機相容性宣告。純型別包既不提供 SemVer 解析器，也不提供安裝策略；其 README 記錄此限制，避免將作者宣告誤認為相容性檢查。
