# Agent Note: 可等待的單個 agent 初始化

Status: implemented

[English](2026-09-09-awaited-agent-creation.md) | 中文

## 問題

共享 preset 為每個 Agent（智慧代理）分別安裝工具與提示詞段。安裝可能要等待外掛啟用，外部 SessionStart 掛鉤也可能非同步產生上下文。建立方必須知道這些貢獻已完成，才能允許 Agent 發起首次模型請求。

## 決策

`agent/created` 是工廠 setup 完成且進入註冊表後的序列初始化事件。每個監聽器完成後才啟動下一個；丟擲或拒絕會使建立失敗，並跳過後續監聽器。載荷保留 `SessionStartSource`，並接受工廠的取消訊號。呼叫方等待 `register()` 與 `announce()` 完成。生命週期來源由工廠釋出時透過 `announce()` 指定；`register()` 宣告全新啟動。

AgentLoop 在 setup 與建立分發期間保留現有的維護活動。初始化期間輸入可以進入收件箱，但只有成功完成後驅動器才會啟動。失敗會取消該活動而不喚醒已排隊輸入；有序 teardown 擁有收件箱清理。區分這兩項操作，能夠在另一條 teardown 已移除收件箱投影時保留初始化錯誤。

建立分發在監聽器等待期間保留作用域與 Session。Dispose（資源釋放）會取消初始化，並在釋放這些資源前等待分發結束。監聽器不得等待自身 Agent 的空閒狀態或自身所有者的 dispose，因為兩者都要等待該監聽器完成。另一個 Agent 上的後臺工作遵循該 Agent 自己的初始化生命週期。

本決策擁有非同步建立時序。[作用域執行時決策](2026-07-12-agent-scope-runtime-design.zh.md)繼續擁有註冊表身份與 teardown 歸屬，[攔截決策](../feature/2026-06-30-interception-extension-points.zh.md)繼續擁有策略與工具事件語義。

## 考慮過的替代方案

**單獨的 setup 事件。** 現有建立監聽器已經安裝針對單個 agent 的貢獻。第二個初始化事件會拆分這一職責，卻沒有獨立的消費方需求。

**分離執行的初始化。** 在外掛啟用或掛鉤上下文結算前返回，會讓首次請求缺少所需工具或上下文，也會使初始化失敗脫離建立方。

## 後果

建立延遲包括非同步外掛與 SessionStart 工作。初始化器失敗成為呼叫方可見的建立失敗，取消依賴監聽器協作結算。已經送達的通知無法撤回；復原會為其配對銷燬通知。

作用域安裝器測試驗證復原，生命週期測試驗證有序完成與取消，SDK serial-created 情境驗證非同步提示詞上下文進入首次請求。掛鉤測試覆蓋需等待的上下文注入與子程序 dispose。
