# Agent Note: 棄用對工作階段任意位置事件的同步讀取

Status: implemented

[English](2026-09-09-deprecate-synchronous-session-event-reads.md) | 中文

## 問題

同步存取任意事件位置，使消費方依賴完整工作階段事件序列在記憶體中隨時可用。儲存的演進方向是不再將完整序列儲存在記憶體中。歷史事件一旦需要儲存 I/O，執行時若不繼續保留歷史或阻塞等待儲存，就無法維持相同的同步讀取保證。

即使只讀取一箇舊事件，新增呼叫也會加深這種依賴。恢復後反覆掃描歷史，還會使普通領域邏輯依賴歷史儲存，而不是它真正需要的狀態。

## 決策

棄用所有同步讀取工作階段事件歷史任意位置或區間的操作，包括 `Session.eventAt()`、`Session.snapshotEvents()` 和 `Session.ownEvents()`。現有邏輯可以暫不遷移，但禁止新增呼叫。同樣禁止新增暴露相同同步歷史存取能力的別名或包裝層。

這三個方法透過 `@deprecated` JSDoc 宣告該規則。這是 API 使用決策；目前 Session 實作仍在記憶體中保留完整事件序列。

儲存庫測試檔案（包括 `scripts/**/*.spec.{ts,tsx}`）可以呼叫這三個讀取方法，以檢查已發出的事件並驗證 Session 歷史行為。測試檔案 lint override 允許 `snapshotEvents`、`eventAt` 和 `ownEvents`，其他棄用名稱仍報錯。在目前 linter 下，此豁免也覆蓋使用這三個名稱的其他宣告。它不適用於生產原始碼或非測試儲存庫腳本。

### 恢復後需要的狀態

結合設計持久事件欄位與工作階段投影，使每個領域都能重建其消費方所需的狀態。在恢復期間還原這些狀態，隨後透過新提交的事件增量維護。恢復後，普通邏輯讀取投影或處理目前收到的事件，而不是回頭查詢歷史事件。同步讀取已經維護好的投影狀態，不需要任意存取事件日誌。

按需展示的歷史內容採用顯式非同步分頁和漸進式載入，每次讀取限制在請求的視窗內。在同步輔助方法背後載入完整序列，仍保留了本決策要消除的依賴。

### 確實需要完整歷史的操作

fork 等少數操作可能確實需要完整歷史序列或繼承字首。它們對這些記錄的需求仍然成立，需要透過顯式儲存讀取來滿足。這不要求完整序列常駐記憶體，也不構成新增已棄用同步讀取呼叫的例外。每個此類消費方都必須說明，為什麼其結果需要完整序列，而不能只使用投影狀態或區域性歷史視窗。

## 曾考慮的替代方案

**只棄用完整快照，保留同步單事件讀取。** 單個被請求的事件也可能不在記憶體中。限制返回結果大小並不能消除儲存依賴，`ownEvents()` 等輔助方法對字尾序列也保留著相同假設。

**為保留讀取 API 而讓完整序列常駐記憶體。** 這會讓消費方的便利性決定工作階段的記憶體保留方式，阻礙預期的儲存設計。投影保留所需狀態，顯式歷史讀取則保留對記錄本身的存取能力。

**要求立即遷移所有現有呼叫方。** 本決策允許現有邏輯推遲遷移。禁止新增依賴可以限制剩餘工作規模，無需將每個現有消費方都納入同一次修改。

**在整個測試檔案中停用棄用 lint，或按名稱豁免生產程式碼中的讀取方法。** 測試只需要這三個讀取方法名；其他棄用 API 必須繼續報錯。生產程式碼仍禁止新增同步讀取。

**新增單獨的測試專用讀取 API。** 三個現有讀取方法已經提供這些測試所需的觀察結果。包裝它們會增加一個 API 及生產程式碼匯入檢查，卻不會改變這些觀察結果。

## 後果

新增領域行為必須使其事件資料與投影狀態足以支援恢復後的執行。使用者請求的歷史仍可漸進式載入，確實需要完整歷史的操作仍需設計儲存讀取路徑。本決策不表示恢復或 fork 已經能夠避免載入完整日誌。

測試檔案之外的呼叫帶有逐行的 `typescript/no-deprecated` 豁免，說明暫緩遷移或已棄用讀取方法之間的委託。刪除已棄用呼叫時應一併刪除其豁免；將豁免複製到新增生產呼叫違反本策略。實際執行 lint 的檢查允許測試讀取和已有豁免呼叫，拒絕未豁免的生產讀取，並拒絕測試中其他已棄用 API。文件檢查驗證與原始碼一致的 API 宣告及雙語記錄。
