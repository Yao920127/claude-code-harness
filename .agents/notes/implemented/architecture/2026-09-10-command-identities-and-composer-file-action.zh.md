# Agent Note: 命令標識與輸入框擁有的檔案動作

Status: implemented

[English](2026-09-10-command-identities-and-composer-file-action.md) | 中文

## 問題

用命令的英文說明匹配用戶端詞典，會讓標點修改影響在地化和填入的命令 token。同名覆蓋也可能複製這段說明，卻沒有實作內建命令的行為。「檔案」選單項需要輸入框即時的附件策略，包括掛載、鎖定和提交狀態，命令外掛中的另一套檢查無法確定這些狀態。

## 決策

命令註冊表在有效定義和描述符上保留可選的品牌型別 `CommandDefinitionId` 欄位 `definitionId`。內建命令的提供者用包名作為穩定標識。作用域覆蓋選擇完整描述符，不繼承被遮蔽定義的標識。該標識是發現中繼資料，不代表授權，也不進入命令生命週期事件。

用戶端命令目錄透過內部的 `resolution.ts` 解析輸入。精確註冊名優先，中英文別名只選擇工作階段有效目錄中對應的內建定義。選單認領使用目前語言的寫法，手輸認領保留原寫法，提交使用解析到的註冊名。`presentation.ts` 只負責分節、標題、說明和圖示。解析輔助函式與小節常數不從外掛入口匯出。

Conversation 透過注入的命令服務註冊「檔案」動作，並負責其在地化標題。已掛載輸入框繫結檔案選擇器回呼和一個即時可用性查詢。選單過濾與實際呼叫使用同一個查詢，統一處理鎖定、解除安裝、subagent 和提交狀態。繫結與呼叫留在包內回呼中，不需要跨外掛的檔案選擇事件。組裝層使用窄的結構化動作註冊介面，因為命令 UI 已消費 Conversation 的輸入型別，反向增加編譯專案依賴會形成迴圈。註冊測試使用命令外掛的貢獻項型別進行驗證。

本記錄只接管[輸入框選單決策](../feature/2026-09-08-composer-menu-sections-and-localized-rows.zh.md)中的標識匹配、輸入解析歸屬和檔案動作歸屬。原記錄繼續負責選單、滾動、認領保留和組合輸入時序的決策。

## 考慮過的替代方案

**按名稱和英文說明匹配。** 文案可以修改，也可以被無關定義複製。穩定標識將展示選擇與文案分開，無需把在地化文字移到主機。

**只按名稱匹配。** agent（智慧代理）作用域覆蓋可能刻意在同名下提供另一種命令。除非它顯式攜帶對應標識，否則不應繼承內建展示或別名。

**把檔案動作留在命令外掛。** 輸入框負責附件接收和 DOM 生命週期。維護另一套可用性條件會把同一策略分給兩個模組。

**匯出輔助函式以供複用。** 沒有生產呼叫方需要把小節常數或解析輔助函式作為外掛 API。測試直接匯入內部模組。

## 後果

內建命令提供者與用戶端對映必須使用一致的穩定標識，第三方定義可以省略標識。顯示文案可以獨立調整。註冊表測試覆蓋描述符保留和作用域覆蓋，用戶端測試覆蓋兩種語言下修改說明、別名解析和精確名稱優先。輸入框測試覆蓋即時可用性、回呼替換、解除安裝和動作註冊的 dispose（資源釋放）。現有工作階段驅動的選單和命令情境繼續負責組裝後的瀏覽器輸出。
