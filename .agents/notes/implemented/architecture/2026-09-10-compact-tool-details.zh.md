# Agent Note: Compact Tool Details from Recorded Results

Status: implemented

[English](2026-09-10-compact-tool-details.md) | 中文

## 問題

目標、任務清單和排程任務的結果包含少量面向使用者的事實，以 JSON 閱讀時較費力。專用展開內容需要融入現有對話行，不能為歷史呼叫新增一套呈現註冊表或即時狀態。

## 決策

`ui-tool` 包透過現有按鍵分發的插槽註冊目標和排程任務檢視，並與任務清單檢視共用一個包內欄位/列表元件。成功且可識別的結果顯示記錄值；未完成呼叫、錯誤、格式異常和不支援的結果格式保留通用輸入/輸出。排程任務領域錯誤（包括持久化不確定和刪除目標不存在）保留原始結果。

工具行保留展開和 Inspect 互動。任務清單標記是靜態的，並帶有可存取的狀態標籤。排程任務使用檢視者時區的絕對日期，狀態取自記錄的結果。目標詳情區分等待繼續的活動目標和已啟動的目標。這些顯示值不訂閱目前目標、任務清單或排程任務投影。

任務清單的變化將每個根呼叫或巢狀呼叫與之前的持久化 `todo/write` 比較，因此後續寫入不會改變較早的卡片。對話組裝器在載入更早的歷史時修復前序記錄。前序記錄尚不明確時，卡片展示提交的列表，不推斷新增或刪除。

這項有限的視覺調整是[用戶端派生工具呈現](2026-08-23-client-derived-tool-presentation.zh.md)中視覺等價要求的例外。該決策中的原始事件所有權、通用退回和唯一按鍵註冊表仍然有效。

## 考慮過的替代方案

**共享呈現框架：**現有按鍵插槽已負責工具分發。僅複用詳情內容，可以在其他包出現需求前將抽象限制在包內。

**在每張卡片中嵌入儀表盤：**互動控制元件、進度圖形和即時狀態會增加視覺負擔，也可能歪曲歷史呼叫返回的事實。緊湊的只讀欄位和列表保留了對話的層級。

## 影響

已註冊的工具獲得可讀詳情，無需改變 Host 工具、Session 事件或公開的 Client 匯出。工具專用介面卡解讀記錄中的 JSON 和文字；未識別的格式保留通用輸出。手寫的 tool-details Session 回放覆蓋這些工具組裝後的渲染。
