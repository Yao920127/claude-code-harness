# Agent Note: 原生 Windows 安裝頁面

Status: implemented

[English](2026-09-10-windows-native-installer-pages.md) | 中文

## Problem

Windows 安裝介面需要符合品牌設計的亮暗頁面，同時避免引入額外的應用執行時，也不能替換 Desktop 的解壓、註冊、升級和解除安裝釋出機制。

## Decision

安裝程式透過 electron-builder 的 NSIS include 接入自定義歡迎頁、進度頁和完成頁。原生腳本繼續負責安裝和解除安裝程式生成。完整自定義腳本會繞過 electron-builder 單獨生成並簽名解除安裝程式的流程，因此不適合這次介面改動。[Desktop 釋出決策](2026-08-25-electron-desktop-packaging-and-updates.zh.md)繼續負責釋出身份、更新分發和簽名要求。

NSIS 原生控制元件保留目錄編輯、資料夾選擇、複選狀態和鍵盤互動。x86 Win32/GDI+ 輔助庫保留 DWM 陰影，並在原生安裝工作執行緒執行期間，由介面執行緒繪製安裝進度。即使 NSIS 在 MUI 回呼之後重新顯示頁面，原生頁面仍保持隱藏。Windows 11 提供外框圓角半徑；Windows 10 保留其支援的視窗外觀。

安裝面向目前使用者。歡迎頁離開驗證在滑鼠和鍵盤導航時均讀取目前編輯框；防抖顯示的行內提示不決定實際安裝路徑。程序檢查匹配受影響的可執行檔案路徑，使其他安裝保持獨立。完成頁離開回呼在滑鼠和鍵盤導航時均遵循啟動核取方塊。electron-builder 在自定義初始化之前解析已登記目錄，因此不帶 `/D=` 的靜默更新會保留該目錄。目錄暫存和替換保留髮布安裝器的復原行為；首次啟動的設定檔準備仍不屬於安裝程式。

## Alternatives considered

**Electron 安裝介面**會在應用安裝前引入執行時，並要求額外的安裝通訊機制。原生控制元件能在現有安裝程式內提供所需互動。

**使用輕量原型替換完整 NSIS 腳本**還會替換升級、註冊表、解除安裝和簽名行為。原型的事務機制需要單獨進行釋出驗證，不納入介面接入。

**使用視窗區域裁剪圓角**會停用 DWM 視窗陰影。系統視窗框架保留陰影，同時接受平臺提供的圓角半徑。

## Consequences

Windows 打包額外要求 x86 Visual C++ 編譯器和 Windows SDK。輔助庫在嵌入前使用與其他 Windows 產物相同的簽名器簽名。準備掛鉤在所有平臺返回 true，使 electron-builder 收集生產依賴。目錄安裝器負責暫存、替換、註冊和恢復。其解壓掛鉤透過獨立進度管道和單獨的診斷檔案呼叫鎖定版本的 7-Zip 可執行檔案。子程序僅繼承標準流控制代碼，並在建立時加入關閉即終止的 Job，因此終止安裝程式也會停止解壓。只有結束代碼為零才允許替換目錄。輔助庫跨管道讀取邊界解析百分比，不自行實作壓縮包解壓或遞迴複製。準備、替換、註冊和清理仍使用有界估算。階段權重表示已完成工作量，而非剩餘時間。顯示進度不退回，文案跟隨顯示階段。NSIS 成功訊號允許執行 600 毫秒補滿動畫並短暫顯示 100%，切換目標時長為 750 毫秒；計時器不能宣告成功。視窗框架在品牌控制元件準備完成前保持隱藏，且只初始化一次，頁面切換保留其位置。點選完成後先隱藏視窗，再以目前使用者直接建立已安裝應用的程序；顯式提權的安裝程式保留透過使用者桌面啟動的方式。啟動失敗會恢復完成頁。應用啟動耗時與安裝視窗關閉分別處理。

原生安裝回歸建置僅英文和僅中文的變體，並從可見的歡迎頁按鈕識別語言；Windows 安裝語言不決定測試文案。順序執行的測試使用獨立產品身份和私有安裝目錄，驗證路徑拒絕、資料夾選擇、啟動選項、升級、執行中程序保留、原生進度條隱藏、首次顯示時就緒和解除安裝。末尾帶分隔符的已登記路徑仍可用於升級，磁碟根目錄仍然無效。確定性的原生進度測試覆蓋快速和慢速解壓、停滯、進度來源重置、分片進度文字、短暫清理，以及兩次介面重新整理之間成功的情況。目錄測試透過輔助庫執行解壓，覆蓋長路徑、新裝、替換、檔案佔用恢復、暫存目錄缺失、損壞壓縮包和取消。截圖和預期行為歸屬 Desktop 測試，不放入錄製 Session 快照。簽名釋出仍需使用已設定的憑證、Token 和真實 Windows 更新產物進行驗證。
