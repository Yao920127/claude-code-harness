# Agent Note: 外掛擁有訊息投影

Status: implemented

[English](2026-09-11-plugin-owned-message-projections.md) | 中文

## 問題

獨立的[圖片省略事件](2026-09-10-image-offload-events.zh.md)修改派生訊息內容，不替換節點。如果圖片遍歷和目標驗證在 Session 內實作，每種功能專用的訊息轉換都需要修改核心程式碼。普通的 session-projection 註冊表派生領域狀態，不參與模型歷史的標準派生過程。

## 決策

事件所屬的外掛提供純 `SessionMessageProjection`，包含一個事件型別和同步解釋此前歷史的處理器。它驗證完整的持久載荷，返回現有訊息的不可變更新，並保留訊息身份。Session 負責原子接受、即時與獨立回放共用的摺疊，以及內容版本驅動的快取失效。它不包含選圖或圖片投影實作。

所屬 `SessionEventMap` 成員上的 `@messageProjection` 標記生成必需處理器清單。缺少處理器時，追加、帶歷史的建立、恢復和純摺疊都會被拒絕。這份清單不會讓未知的第三方事件名變得可讀，也不改變 `ignorable` 的相容規則。投影事件不能同時宣告 surface 操作。

compaction-image-offload 外掛透過 fiber 擁有的 `ctx.sessions.registerMessageProjection()` effect 註冊處理器。每種事件只有一個註冊者。移除處理器後，尚未應用的已提交決策和使用過它的快取讀取都會失效。替換處理器需要重新恢復工作階段。被拒絕且未提交的候選事件不會保留對處理器的依賴。

獨立讀取器顯式傳入處理器。目前 Session 格式目錄裝配相同的瀏覽器安全外掛匯出，供持久資料總和檢查碼離線查詢使用。這項靜態裝配不掛載恢復監聽器。即時工作階段使用已註冊的組合，壓縮 invariant 借用該組合的處理器。不使用程序全域註冊表，也不在匯入模組時註冊。

圖片事件載荷和讀取時必須識別的語義仍由圖片省略記錄負責。索引、選圖策略、重試行為和 SDK 錄製保持不變。本決策部分取代該記錄中由核心負責解釋事件的職責劃分。

## 考慮過的替代方案

**保留 Session 內的圖片解釋邏輯。** 獨立呼叫者可以隱式獲得內建處理器，但外掛擁有的轉換會變成核心中特定事件的程式碼。顯式裝配能夠保留確定性回放，無需讓核心擁有演算法。

**使用普通的 session-projection 註冊表。** 它的摺疊在提交後公開領域狀態。沒有額外整合點，它無法否決無效追加，也無法提供標準 `deriveMessages()` 內容。

**只轉換髮出的請求。** 壓縮、分叉、離線回放和請求 invariant 也會派生訊息。傳送時轉換無法覆蓋這些消費方。

## 影響

增加修改內容的事件，需要事件宣告、純處理器、即時註冊和獨立裝配項。普通的僅記錄日誌事件不需要這些機制。純摺疊的消費方使用通用的 `projectedMessages` 結果。事件信封和已經儲存的圖片決策保持不變，因此不增加結構性的 Session 格式版本。

測試覆蓋缺少處理器、通用原子投影、已載入視窗、恢復與分叉、重複註冊、fiber 釋放、快取與待應用讀取，以及被拒絕的候選事件。圖片專用測試保留在外掛包。目錄檢查每種生成的必需型別都有獨立處理器，並拒絕無效圖片引用。現有 TypeScript 和 Python 圖片 SDK 錄製透過釋出的 profile 覆蓋相同的持久事件。
