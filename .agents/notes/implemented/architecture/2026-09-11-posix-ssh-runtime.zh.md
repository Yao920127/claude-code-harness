# Agent Note: POSIX SSH 執行提供者

Status: implemented

[English](2026-09-11-posix-ssh-runtime.md) | 中文

## 問題

遠端編碼需要檔案工具、Bash、終端、語言伺服器與 Node 程式看到同一個檔案系統與程序環境。[可移植消費方決策](2026-07-28-portable-execution-world-consumers.zh.md)提供這些介面。[E2B 退役決策](../simplification/2026-09-11-remove-e2b-providers.zh.md)保留其非同步語義，同時移除一個需要單獨傳輸專案才能透過標準流庫承載雙向 PTC 控制流的整合。

SSH 提供經過認證的位元組通道及逐通道流量控制，但普通 exec 請求不對映任意子程序描述符。若把 SSH 當作程序管理器的替代品，控制流橋接、啟動釋出、EOF、取消及斷連清理就會缺少實作。

## 決策

部署方持有的 OpenSSH 主機別名將本地 Harness 連線到已安裝的 POSIX 輔助程式。檔案系統、子程序及沙箱提供者共享該輔助程式；Harness 保留 Cordis 物件、模型傳輸、權限、回呼與 Session 持久化。終端方法保持非同步。提供者路徑描述執行環境，無需額外的本地／遠端標記。

限制解析支援非同步與取消：正在執行的輔助程式透過已載入的沙箱提供者解析每次策略，然後子程序提供者取得可直接執行的 argv。`ShellExecutor.start()` 在準備完成後返回 `Promise<ShellProcess>`。通用任務准入保持同步；由工具負責的 `JobHooks` 在預檢後啟動非同步 shell 準備，取消待完成的準備並等待任何延遲出現的程序控制代碼結束。

私有管理 RPC 與各條程式流使用獨立 SSH 通道。遠端預留操作在程式啟動前建立請求的流端點。stdout 與 stderr 無法承載管理回覆，暫停一條輸出通道也不會佔用 fd 7 的流控視窗。這用更大的遠端輔助程式換取顯式二進位制傳輸與有界流保留。

每條流透過私有管理 RPC 獲得新的 256 位 TLS 預共享金鑰。TLS 1.2 配合 `PSK-AES256-GCM-SHA384` 在流釋出前認證兩端並保護後續位元組。金鑰絕不作為流字首傳輸。僅靠套接字權限不足：檔案效果限制可能允許同使用者連線，或允許在可寫臨時目錄中替換路徑名。程式不會獲得管理 Unix 監聽端點或流金鑰。包裝完成後，取消責任轉移到 TLS 包裝流；清理先關閉該流，再關閉底層套接字，確保原生 TLS 讀取不會超過傳輸層的生命週期。

收集的 stdout 與 stderr 透過僅更新輸出觀測的處理器傳遞有界尾部快照。快照等待傳輸時，輸出捕捉繼續進行。最終快照保留原始位元組偏移，已完成的 spill 檔案在連線釋放後使用本地提供者的保留輸出儲存。

就緒流程驗證已安裝輔助程式的摘要，並在設定 PTC 時驗證已安裝 Node 載入程式的摘要。這些檢查固定預期部署產物，不用於認證惡意遠端作業系統。輔助程式停用透過 `SIGUSR1` 啟動 Node 偵錯程式：檔案效果限制仍可能允許同使用者訊號，這些訊號不得暴露輔助程式不受限的檔案系統和程序服務。檔案效果限制委託給遠端本地沙箱提供者，保留其完整／部分執行披露及平臺限制。

路徑規範化屬於檔案實際存在的位置。共享策略解析器保留執行環境中的絕對路徑寫法；執行限制的提供者在自己的檔案系統上解析符號連結與 `..`。headless 透過 `ctx.fs` 記錄和驗證 cwd。SSH 不提供主機路徑投影，因此 Node 執行需要顯式安裝的遠端載入程式。

連線丟失會使待處理操作失效，不進行重連或重放。輔助程序 EOF、訊號及心跳租期會啟動遠端原生清理。用戶端不能把租期到期當作觀察到的成功終止：被中斷的修改或啟動可能結果未知。管理請求截止時限、消費方執行截止時限及清理分別由各自歸屬方負責。

## 考慮過的替代方案

**在 SSH exec stdout/stdin 上為所有流分幀。** 這避免了 Unix 套接字轉發，但要求應用協定自行實作逐流額度、佇列上限及獨立 EOF 語義。獨立 SSH 通道使用傳輸層既有流控，並將程式輸出與管理幀分開。

**僅用 SFTP 替代遠端檔案操作。** SFTP 提供檔案傳輸，但不直接保留既有的帶保護原子寫入、編輯、策略及錯誤語義。複用遠端本地檔案系統提供者，使這些機制繼續歸屬現有實作。

**透過 TCP 或 HTTP 端點提供程式流。** 這允許獨立傳輸，但會在現有 SSH 連線之外引入遠端埠暴露、端點認證及伺服器部署。轉發 Unix 套接字使用已認證的 SSH 工作階段，並透過 TLS-PSK 額外認證流的兩端，以防禦同使用者連線或路徑名替換。

**把完整 Harness 移到遠端主機。** 這是另一種部署模型，會將模型憑證、Session 儲存及外掛狀態隨執行一起遷移，而不是提供現有能力的遠端實作。

## 影響

遠端提供者雖然複用本地檔案與程序機制，仍增加傳輸、預留及斷連責任。原始流、收集尾部及遠端 spill 檔案保留各自生命週期。消費方必須釋放流與控制代碼；傳輸丟失後無法重建輔助程序的清理結果。

初始組合範圍為 POSIX headless 與自定義設定組合。假定可存取主機檔案系統的 Web 工作區消費方需要獨立整合。網路限制、程序可見性隔離、惡意主機證明、持久遠端控制代碼及自動產物設定不屬於本提供者家族。

可移植消費方決策繼續有效；本文提供其 SSH 實作。E2B 退役決策仍負責已移除整合及維護取捨。兩篇記錄均未被完全取代。

## 驗證

必要的協定及生命週期證據覆蓋畸形訊息、上限、預留取消、經過認證的流釋出及斷連錯誤。原生 SSH 驗收必須覆蓋遠端檔案保護與符號連結身份、Bash 限制、fd 7 二進位制流、輸出暫停時的控制進展、終端操作、LSP 及 Node 執行。即時檢查要求顯式設定的可丟棄遠端工作區；無金鑰測試不建立遠端環境。

安全證據要求同時嘗試同使用者連線與替換套接字監聽端點，並確認其無法佔用預留流、獲知流金鑰、修改另一執行或收到其明文輸出。程序生命週期證據區分直接退出與託管程序範圍靜止，並測試啟動釋出前及程式啟動後的取消。原始碼與建置後設定組合檢查驗證已安裝輔助程式／引導安排，不向程式環境傳遞主機憑證。

## 延後工作

持久遠端重連需要獨立的操作身份與恢復設計，不能在斷連後複用活躍回呼控制代碼。更廣泛的 Web 支援需要由提供者負責的工作區資源。更強的資源計量或修訂後的 PTC yield/wait 與超時策略屬於 [Node 執行時參考](../../../../packages/ptc-runtime/ptc-runtime-node/README.zh.md)，不屬於 SSH 管理請求截止時限。
