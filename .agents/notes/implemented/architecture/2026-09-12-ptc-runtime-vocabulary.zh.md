# Agent Note: PTC 執行時詞彙

Status: implemented

[English](2026-09-12-ptc-runtime-vocabulary.md) | 中文

## Problem

PTC 模式及其執行提供者需要在包清單、服務查詢、公共型別、設定和文件中使用同一個可搜尋的名稱。混合的執行時字首使維護者難以從 profile 追蹤到提供者實作及打包後的載入程式。

## Decision

執行能力使用 `ptc-runtime` 包族、`PtcRuntime` 型別和 `ctx.ptcRuntime`。Node 與私有實驗性 Python 提供者共享這套詞彙。Profile 條目識別符號、內部引導選擇器、編譯器引用、包匯出和生成目錄使用相同名稱；不提供相容包或第二份服務註冊。

執行時包與 SDK 語言型別的 PTC 名稱取代[早期命名決定](../../archived/architecture/2026-08-25-rename-code-mode-to-ptc.md)記錄的例外，使提供者與呼叫方使用同一套可搜尋的詞彙。

面向模型的 `run_code` 操作、其 `code` 原始碼參數和穩定失敗標識保留描述性名稱。一般原始碼術語、錯誤碼、外部專案名稱與 URL、歷史遷移識別符號以及封存 Agent Note 保留原有含義和記錄拼寫。這一命名決定不改變程式執行、沙箱權限、期限、繫結或 Session 格式。

## Alternatives considered

**保留單獨的通用執行時字首。** 提供者仍獨立於工具和 Session 的所有權，但其包名與服務名標識 PTC 執行能力。單獨的字首會增加第二個名稱，卻沒有分離出獨立演進的功能。

**替換每一處“code”。** 程式原始碼、操作名稱、外部引用和歷史記錄描述不同物件。替換這些內容會改變執行時命名決定之外的公共操作或已記錄事實。

**釋出舊名稱別名。** API 尚未穩定，儲存庫中的每個消費方共同遷移。別名會保留重複的包和服務身份，使後續查詢含糊不清。

## Consequences

部署設定和原始碼消費方共同使用 PTC 包名與設定識別符號。已有的 `run_code` 記錄與錯誤路由仍可讀取。機械審計比較重新命名前後的原始碼 token，保留外部 URL 和凍結記錄，並檢查每一處殘留舊執行時名稱；建置後的 profile、包和 snapshot 檢查覆蓋靜態匯入無法驗證的消費方。
