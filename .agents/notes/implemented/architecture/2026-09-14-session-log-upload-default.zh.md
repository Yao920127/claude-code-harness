# Agent Note: DeepSeek 工作階段日誌預設上傳

Status: implemented

[English](2026-09-14-session-log-upload-default.md) | 中文
## 問題

普通 DeepSeek 請求不包含完整的規範工作階段軌跡。要求每個安裝環境啟用日誌貢獻，會使預設產品設定無法提供該軌跡。錄製工作階段情境也需要穩定、明確的上傳策略，因為接受事件屬於其期望日誌。

## 決策

`session-log-deepseek.Config.enabled` 在所有程序中均預設為 `true`。顯式設定 `enabled: false` 可關閉貢獻。外掛不讀取測試執行器或快照環境變數。

本決策僅取代[請求擴充功能決策](2026-08-21-deepseek-llm-api-request-extensions.zh.md)中的主動啟用預設策略；該記錄仍負責欄位序列化、目的地址、接受與重試語義。headless 和 ACP 語料的基礎 patch 以及 Web scaffold 顯式關閉上傳。後續情境 patch 可以啟用上傳。SDK text-turn 錄製省略該設定，驗證產品預設值及持久接受事件。

## 考慮過的替代方案

**根據測試環境標記決定生產預設值。** 呼叫者繼承這些變數時，下游 SDK 行為也會改變，普通測試還會採用不同的產品預設值。

**重新整理所有錄製工作階段以包含上傳接受事件。** 顯式測試設定保留現有情境，同時使用預設設定的 SDK 錄製和 Loader 迴歸驗證預設開啟路徑。

**保留主動啟用策略。** 沒有安裝環境專用設定時，該策略無法從普通產品請求提供完整軌跡。

## 後果

符合條件的請求會向解析後的 DeepSeek 端點或已設定閘道傳送未接受的規範日誌字尾，按[有上限上傳決策](2026-09-24-bounded-session-log-upload.zh.md)每次最多 `maxBytes`，包括訊息文字、工具參數與結果、工作區路徑和回饋。不增加提示詞 token 或模型可見內容。請求正文最多增加該上限，提供者拒絕仍會使請求失敗。OTel 保持獨立，關閉 OTel 不會關閉此貢獻。

設定測試覆蓋有無測試環境標記時的預設開啟與顯式覆蓋。兩種 DeepSeek 協定的 Loader 案例觀察預設請求欄位和已記錄的接受水位，顯式關閉案例觀察兩者均不存在。現有 headless、ACP、Web 和 SDK 錄製驗證各自宣告的上傳策略，無需重寫已提交的工作階段代際。
