# Agent Note: 原生 Desktop 致命錯誤恢復

Status: implemented

[English](2026-09-15-desktop-native-fatal-recovery.md) | 中文

## Problem

恢復文件依賴渲染器和 preload，而這些元件的故障本身就可能阻止應用啟動。同一次啟動失敗的多個報告還可能掩蓋原始診斷並打斷恢復操作。

## Decision

Electron 在每個應用程序中提供一次原生致命錯誤對話方塊。明確的主視窗建立、文件載入、preload、渲染器、Web 初始化和後端失敗進入此路徑。普通請求保留區域性錯誤處理，共享 Web 外掛管理器負責包操作失敗。預期取消和關閉不進入恢復。不透過耗時推斷慢啟動為致命故障。

首次報告在等待對話方塊前取得展示權。後續報告保留在日誌中。應用日誌目錄下的崩潰報告檔案保留完整的已報告診斷，對話方塊單獨一行標明該檔案（[致命診斷與崩潰報告](2026-09-22-fatal-diagnostics-and-crash-reports.zh.md)）。原生對話方塊無法滾動，因此僅顯示首次診斷末尾八行，並將包含截斷提示、報告路徑和重灌建議的完整詳情限制為 1,200 個 UTF-16 程式碼單元。對話方塊提供退出、重新啟動或停用第三方 bundle 後重新啟動整個應用。恢復操作等待 Host 關閉後，在已有 profile 鎖內呼叫共享 app-boot `sanitizeProfile` 函式。該函式恢復呼叫方指定的 bundle，並將 profile patch 重新命名為唯一備份，無需解析 patch、初始化執行時或刪除安裝檔案。呼叫方負責 profile 關閉並排除並行寫入；目前生產呼叫方是 Desktop。home 級 patch 保持不變。顯式恢復操作失敗會單獨展示，不計為另一次自動致命報告。

Web 文件保留在原位。主機回呼負責啟動失敗展示，共享啟動頁保留載入動畫；普通瀏覽器啟動仍顯示自身的失敗報告。只有主應用框架可以上報 Web 啟動失敗。後端狀態保留在主程序中，原生恢復直接負責停用全部第三方 bundle。Desktop 不提供 profile 重置或應急恢復文件。後端致命故障必須透過原生恢復操作處理，不在目前程序中重試。

本決策取代[立即顯示視窗決策](2026-09-09-desktop-immediate-window-and-direct-start.zh.md)中的恢復頁面和重置行為；其立即顯示與直接啟動 Host 的理由仍有效。[Web 薄殼決策](2026-09-10-desktop-web-wrapper.zh.md)負責共享外掛管理和原生 profile 準備。

## Alternatives considered

Web 模態框依賴用戶端初始化，而第二份恢復文件會增加渲染器資源和 preload 恢復路徑。原生對話方塊在這些元件失敗時仍然可用。自動重置設定或每次報告都重新啟動可能刪除使用者設定或形成重新啟動迴圈；顯式操作保留使用者控制權。

**停用 bundle，但保留生效的 profile patch。** 損壞的 patch 或插入故障外掛的 patch 仍可阻止啟動。重新命名保留使用者原始內容供手動修復，同時將該層移出啟動過程；唯一備份名保留此前恢復操作的備份。

## Consequences

恢復功能無法報告 Electron 主程序被終止或崩潰，靜默啟動掛起也沒有自動超時提示。損壞的 home 級 patch 在 profile 恢復後仍會阻止啟動，需要手動修復。備份在 profile 目錄中累積，不會自動清理；使用者在不再需要時刪除。無效的 profile JSON 可能阻止停用外掛；操作報告失敗後仍可退出和重新啟動。定向生命週期測試覆蓋致命訊號、取消、首次報告去重和關閉順序；語言預期記錄對話方塊診斷和操作，啟動測試保留普通瀏覽器失敗展示。
