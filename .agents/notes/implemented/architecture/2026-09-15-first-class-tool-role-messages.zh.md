# Agent Note：一等 tool-role 訊息

Status: implemented

[English](2026-09-15-first-class-tool-role-messages.md) | 中文

## 問題

已釋出的 Session 格式把工具結果儲存在 user-role 的 `tool-result` 內容塊中，而模型對話與提供者協定把工具結果視為獨立角色。兩種描述同時存在會使驗證、回放和介面卡投影互相不一致。

## 決策

Session format V4 將一次工具結果儲存為一等 `role: 'tool'` 訊息。它的 `toolCallId`、工具來源呼叫標識、結果內容和可選錯誤標記一起驗證。V3 到 V4 的邊緣遷移只提升一個已釋出的包裝，並在釋出前拒絕巢狀包裝，保留源代際。目前 V4 解碼僅接受原生形式；包裝行只由相鄰遷移邊緣接受。

移除歷史 wrapper 時，訊息與結果的擴充功能欄位分別保留為 `plugin:message:` 和 `plugin:result:` 名稱。字尾保留完整原欄位名，避免衝突且不新增核心 metadata 欄位。不透明保留避免在 wrapper 消失時虛構共同欄位 owner。不同 owner 的重複值仍分別保留，外掛消費者必須使用 V4 名稱。只有 wrapper 提供具有解釋語義的呼叫 id 和錯誤標誌；同名的舊外層欄位保持不透明。[轉換規範](../../../../packages/session/session-format-v3-to-v4/README.zh.md#tool-results)擁有精確的保留與拒絕規則。

對話角色 map 是封閉的。模型可見角色必須有持久 Session 事件和介面卡投影，因此介面卡不會把未記錄的擴充功能角色靜默轉換為 user 文字。提供者特有的來源 kind 仍然可合併擴充功能，並由各生產方擁有。

## 曾考慮的替代方案

- **保留包裝形式的 V4 行**——保留已釋出載荷，但規範角色與提供者 wire 格式仍不一致。
- **同時接受包裝和原生 V4 行**——兩種目前表示會讓編碼、解碼、恢復和回放依賴於產出 artifact 的路徑。
- **展平歷史巢狀結果**——葉子文字無法保留巢狀呼叫 ID 或錯誤狀態，而且提供者對巢狀內容的解釋並不一致。拒絕不支援的遷移會保留原始資料，等待能夠保留全部資訊的轉換。
- **保持角色擴充功能開放**——擴充功能角色可能在沒有 Session 事件的情況下到達模型請求，也無法在回放時重建。

## 後果

相鄰遷移會改變邏輯訊息角色，但不改變訊息身份、工具呼叫身份或結果內容。原生 V4 語義失敗屬於硬准入失敗；可恢復解碼仍適用於已釋出 V3 的規範尾部。介面卡把一等角色對映為各提供者自己的工具結果表示。訊息 `toolCallId` 與來源 `callId` 的重複仍作為一對顯式且經過相等性驗證的提供者欄位與來源欄位保留。
