# Agent Note：使用顯式識別 Provider 的實驗性語音輸入

Status: implemented

[English](2026-09-16-experimental-voice-input.md) | 中文

## 問題

聽寫必須保留使用者對編碼任務啟動時機的控制。本地識別帶來模型檔案、原生執行時和 CPU 工作；僅安裝或啟用 UI 貢獻不應分配這些資源。之後的雲端 Provider 需要明確的選擇機制，不能悄悄改變錄音的處理位置。

## 決策

`packages/experimental/` 下的五個公開包組合成一個預設停用的可選語音輸入 Bundle。服務定義、SenseVoice Provider 和 Remote 消費者分開，因為 Provider 部署與瀏覽器傳輸獨立演化。瀏覽器 UI 動態掛載其生成的 Remote 貢獻。穩定 API Remotes 不引入實驗性依賴。

Provider id 選擇確切的註冊。解析捕捉實例，登出先拒絕新任務，再取消並等待已接收的任務。不存在 Provider 退回：本地失敗不能授權將語音上傳至雲端服務。新增雲端 Provider 透過同一註冊表提供自己的憑證設定與顯式處理位置。

錄音與轉寫在使用者提交普通文字前都是臨時資料。識別不啟動智慧代理輪次，也不建立音訊 Session 事件。輸入門面按照捕捉的草稿版本接收非同步純文字，保留引用晶片與撤銷歷史。草稿變化時保留識別文字，等待顯式插入，而非替換之後的編輯。切換 Session 和釋放外掛會使遲到結果失效並釋放錄音資源。採集失敗立即通知目前錄音活動，不受資源關閉耗時影響。取消、失敗和外掛撤銷共同等待同一個釋放 Promise，所有權持續到 AudioContext 關閉。

SenseVoice ONNX 與 Silero VAD 在一個託管 CPU 子程序中執行。原生 sherpa-onnx 包包含 ONNX Runtime；顯式準備只下載並驗證模型；後續呼叫複用預熱模型，直到設定的空閒截止時間。每次啟用都會驗證快取資源，完整快取恢復為待喚醒狀態，不啟動工作程序。就緒狀態因此取決於磁碟內容，而非 Provider 實例的存活時間。錄音在喚醒期間進入有界佇列等待。工作程序在執行時檢查就緒狀態，因此較早的快取檢查使資源失效後，排隊任務也不能隱式下載資源。檢查複用準備任務的生命週期，取消與釋放都會等待檢查結束。停用 Provider 等待其任務和程序退出，同時保留可複用的磁碟資源。瀏覽器原生錄音與重取樣避免增加音訊轉換可執行檔案。帶認證的私有環回協定傳輸完整 PCM 錄音，取消時可以終止工作程序，而不與另一請求共享長時間推理。

Host 獨立於發起檢視擁有準備任務。有序步驟列表在檢視重新掛載後保留，僅隨著執行推進記錄完成。識別模型、VAD 與最終驗證分別準備；下載使用固定位元組數，其他工作報告等待時間。準備狀態和進度透過以包名為 key 的 `plugins.bundle.config` 顯示在詳情頁。通用 `plugins.bundle.activation` Slot 傳遞顯式啟用意圖和詳情導航；語音貢獻等待 Host 快取檢查，只為尚未準備的本地模型提供安裝引導。啟用已準備的 Provider 不彈出視窗也不下載。單個輸入框活動 Slot 展開語音控制元件，同時保留草稿編輯器和提交按鈕。空閒時上下文用量按鈕位於輸入框下方；錄音和轉寫期間，用量按鈕與普通工具欄控制元件一起隱藏，關閉活動後恢復。按鈕、摺疊與狀態標記複用共享原語，語音 UI 只負責實測波形繪製。點選開始錄音，停止後轉寫，回饋留在活動欄內。持久化偏好仍在外掛設定中。

## 考慮的替代方案

在外掛啟用時載入模型，會讓一個 UI 開關在尚未聽寫時就產生大量啟動時間和記憶體佔用。Python/FunASR/PyTorch 增加直譯器、依賴安裝與磁碟成本；ONNX 成品和平臺原生包滿足 CPU 聽寫。使用者端不執行模型匯出。瀏覽器原生語音識別不能提供一致的本地處理保證。流式語音互動需要部分結果修訂、輪次仲裁與雙向音訊語義，而完整錄音聽寫無需這些機制。

## 影響與驗證

首次使用需要下載時間和磁碟空間。本地指 Host 所在機器，包括遠端 Host。取消執行中的推理會丟失預熱程序，下次請求重新載入。可選準備路徑支援已有離線環境，不會悄悄改變預設行為。

驗證覆蓋精確 Provider 路由、註冊釋放、有界音訊解析、麥克風釋放、過期草稿和 Session 切換處理、工作程序佇列與截止時間恢復，以及經過驗證的下載釋出。真實本地推理使用與產品相同的託管工作程序。瀏覽器組合驗證可選啟用與草稿插入；普通 Session 回放驗證只有提交的文字進入模型。

Node 24 與 Electron 44 的真實子程序均完成 FP32 和 INT8 識別。Electron 的 VAD 輸出使用複製緩衝區，避免 external buffer 限制。4.2 秒公開中文樣本的三次識別結果一致；該短樣本不代表完整準確率評測。桌面麥克風請求限制為主應用視窗的音訊請求，macOS 權限由系統處理。Windows、Linux 真實機器及簽名後的安裝檔仍需平臺驗收。

INT8 以降低下載和儲存成本為預設值，`precision: fp32` 選擇參考權重。公開英文與拼接的中英雙語樣本顯示兩種精度存在用詞差異，因此不將量化視為準確率等效。約 101 秒的重複語音樣本在兩種執行時均完成識別；請求後的 RSS 觀測不構成峰值記憶體上限。
