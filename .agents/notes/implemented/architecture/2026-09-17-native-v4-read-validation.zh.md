# Agent Note: 原生 V4 關係的強制驗證

Status: implemented

[English](2026-09-17-native-v4-read-validation.md) | 中文

## Problem

tool 角色結果不能透過已釋出的 V3 user 角色表示進行驗證，否則投影會丟棄目前欄位。替代該驗證檢視後，原生讀取方必須保留原有的生命週期、退役語法和 system 訊息檢查。因此，表示變更與必需的接納驗證需要一同完成。

事件即使符合 TypeScript 宣告和訊息規則，也可能與較早的持久化事件矛盾。沒有宣告呼叫的工具結果、指向另一壓縮事務的檢查點，都可以擁有區域性有效欄位。將它們接納為目前 Session 會讓後續讀取器依賴損壞的關係；釋出後再收緊准入則可能讓已寫入的歷史無法讀取。

## Decision

V4 格式恢復器與目前 JSONL 掃描器共用同一強制跨事件關係驗證，在公開恢復產物或儲存控制代碼之前執行。它檢查 turn 與 step 順序、宣告的工具呼叫及其結算、PTC 父子關係與結算身份、重試鏈與請求 provider、標題的人類訊息引用、命令完成引用、壓縮歸屬與目前區間，以及受保護的 system 首節點。已安裝事件集合控制語義解釋，包括壓縮預掃描和標題引用。未知的可忽略記錄保留其載荷與原始位置；已知記錄即使標記為可忽略仍會接受驗證。驗證直接讀取原生事件欄位，不修改產物，也不將其投影為歷史格式。Node 和 Worker 中的 JSON 參數比較都檢查自有屬性，繼承的原型成員不能代替記錄欄位。[工具角色決策](2026-09-15-first-class-tool-role-messages.zh.md)負責結果表示。

未完成的尾部可以保留開啟的 turn、step、工具呼叫或壓縮事務。關閉事件必須結清它關閉的關係。繼承的未完成壓縮事務在其 `session/end-seed` 標記處結束，不約束子 Session 的生命週期。較早遷移改變序號座標後，修復訊息身份仍保留歷史數字字尾。fork 修復保留經過獨立驗證的原生身份。

已安裝的 Session 接納器繼續負責事件封裝、訊息角色與中繼資料、規範請求頭，以及 surface 替換的引用覆蓋。可選執行時不變式提供診斷；持久化准入不要求安裝它們。原生 system 訊息准入還會在物理恢復可能丟棄行之前，驗證座標、身份、內容塊及已知 image/tool-call 欄位。額外 JSON 欄位和非空的未知內容標籤保持不變，退役的 tool-result 包裝會被拒絕。退役的 `request/header.header.system` 和必需的 `tool/code-dispatch*` 標籤仍在恢復前強制拒絕；標記為可忽略的過時 PTC 記錄保持不透明。僅透過物理分幀不能證明語義有效。

退役的 tool-result 包裝若不屬於對應的 `tool/result` 行，就需要改變事件、角色或來源才能在 V4 中表示。相鄰遷移只提升規範的自有包裝；目標恢復器拒絕解釋內容中剩餘的包裝。原生行准入在可恢復尾部被忽略之前執行同樣的拒絕。檢查沿宣告的訊息、內容和 Assistant stream 欄位進行，不遞迴掃描 JSON，因此工具參數、replay state、schema 參數、巢狀擴充功能和未知可忽略載荷保留其記錄值。

`EpochHeader.system` 透過帶有 `@persistenceReserved` 的 `system?: never` 顯式保留退役鍵。目錄保留其空值集合，使允許某個值被識別為對禁止欄位的修改，而非普通可選欄位新增。原生讀取方和 Session 接納繼續拒絕該鍵；系統提示詞仍由 `system/message` 事件承載。

## Alternatives considered

**將 V4 投影回凍結的 V3 驗證檢視。** 這會將目前准入與退役表示繫結，並容易讓新增欄位在投影中消失。凍結代際仍可獨立讀取，目前恢復器解釋自己的欄位。

**依賴可選執行時不變式。** 分離讀取器和恢復路徑可能不安裝診斷元件。必需關係必須在釋出或消費恢復後的 Session 之前完成驗證。

## Consequences

原生恢復器為每次讀取維護獨立狀態機，在釋出後繼檔案之前拒絕矛盾。凍結的 V0–V3 驗證器及已提交的 Session 代際保持不變。公開目錄迴歸覆蓋無效關係、部分尾部、繼承切分點、未知歸屬的不可變儲存，以及完整工具互動；這些檢查落實已宣告的 V4 表示，不改變其 schema。破壞性變更要求後繼版本；相容新增使用新的確認記錄，實作修復須保留宣告的含義。
