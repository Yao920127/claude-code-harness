# Agent Note: 限制輪次導航工作量並聚合歷史跳轉

Status: implemented

[English](2026-09-18-chat-navigation-performance.md) | 中文

## Problem

長工作階段會放大三類獨立成本：輪次軌道為每個已知輪次掛載一個 DOM 刻度，正文導航重新查詢已知落點，以及歷史跳轉逐頁釋出資料。每次中間前插都會重建不斷增大的對話索引，並在目標輪次可用前再次更新正文。把這些職責放進一個控制器，會使需要 DOM 幾何的操作與只負責閱讀、分頁策略的操作難以區分。

## Decision

### 固定間距虛擬軌道

[TurnNavigator](../../../../packages/client/ui-chat/src/client/chat/TurnNavigator.tsx) 使用 TanStack React Virtual，間距固定為 10px。只保留可見範圍、預載入項，以及鍵盤焦點刻度及其相鄰項。庫負責尺寸容器和絕對定位刻度的變換。全部輪次中繼資料仍駐留記憶體；這裡虛擬化的是軌道，不是正文。

軌道採用 ResizeObserver 提供的視口尺寸和固定條目高度。偏移計算根據快取幾何限制範圍，再呼叫庫支援的 `scrollBy`，避開 `scrollToIndex` 使用的基於 DOM 的最大偏移計算。正文恢復閱讀狀態後，軌道在首次獲得可用尺寸時直接定位到最新已提交的活躍輪次。ref 分別提供啟用輪次和僅滾動軌道的操作。原生指標目標替代座標命中測試，刻度長度透過變換改變。佈局包含作用於懸浮軌道外框，但不承諾瀏覽器幾何讀取只重新整理該子樹。

### 兩層正文導航

[ChatViewport](../../../../packages/client/ui-chat/src/client/chat/use-chat-viewport.ts) 負責 DOM 讀取、限制範圍後的寫入、原生事件和輪次錨點。它返回實際落點及可用的輪次、語義位置資訊。閱讀策略直接消費這些資訊，無需再次命中測試；視口會忽略自身位置未變的滾動回聲，以及內嵌軌道發出的事件。

[ChatReading](../../../../packages/client/ui-chat/src/client/chat/use-chat-reading.ts) 負責跟隨底部、語義恢復和讀者移動取樣。[ChatNavigation](../../../../packages/client/ui-chat/src/client/chat/use-chat-navigation.ts) 負責已載入或未載入輪次跳轉、分頁錨點、任務替換和退回。[useChatScroll](../../../../packages/client/ui-chat/src/client/chat/use-chat-scroll.ts) 提供已提交輸入並協調各物件。定時器與動畫幀完成時直接呼叫負責物件，不再遞增 React tick 狀態。[貼底事件規則](../../../../packages/client/ui-chat/README.zh.md#scroll-ownership) 仍有獨立必要性：期間發生的佈局增長不能抵消讀者的小幅操作。

共用的巢狀跟隨機制與控制元件定位見 [Chat 滾動與頁尾決策](../bug-fix/2026-09-22-chat-scroll-follow-and-footer-geometry.zh.md)；外層取樣閱讀與歷史導航仍由上述物件負責。

### 每次歷史跳轉統一發布

[Session.loadThrough](../../../../packages/api/session-controller/src/client/sessions/session.ts) 在共享目標被覆蓋或載入結束前，保留已接受的頁面和私有分頁遊標。它只反轉一次頁面列表並展開一次，然後釋出一次有序前插。即時事件繼續走正常釋出路徑。後續頁面失敗時，已成功取得的部分統一發布一次；流或視窗被替換時丟棄失效的暫存頁面。單頁 `loadOlder` 仍立即釋出，重複跳轉請求保留既有的最低目標策略。

### 理論工作量模型

設 `T` 為已知輪次數，`V` 為已掛載虛擬刻度數，`P` 為取得頁數，`B` 為每頁條目數，`W0` 為原先已載入條目數。以下估算工作量，不代表耗時測量。

| 操作 | 原有工作量 | 目前工作量 |
|---|---|---|
| 軌道 DOM 與 React 刻度遍歷 | `O(T)` | `O(V)`；輪次中繼資料與初始索引、快取建置仍為 `O(T)` |
| 條目未變時查詢活躍輪次索引 | 線性搜尋，`O(T)` | Map 查詢，期望 `O(1)` |
| 軌道目標偏移計算 | 同步讀取 DOM 總高度、視口尺寸 | 固定算術與快取尺寸；此路徑不讀取 DOM 滾動總高度 |
| 已知正文輪次跳轉 | 定位後重新查詢位置 | 複用落點；不做命中測試，但既有錨點選擇器與輪次查詢成本仍在 |
| 歷史驅動的線性索引遍歷 | `O(P * W0 + B * P²)` | 最終一次遍歷為 `O(W0 + B * P)`，另有 `O(B * P)` 暫存展開 |
| 歷史驅動的排序 | 對每個不斷增大的視窗重複排序 | 對最終視窗排序一次，`O((W0 + B * P) log(W0 + B * P))` |
| 歷史前插釋出次數 | `P` | 一次；即時事件與載入狀態更新仍獨立發生 |

例如，10,000 個輪次只掛載約 50 個刻度，意味著軌道刻度約減少 99.5%，不代表端到端加速 200 倍。若取得 20 個等大頁面且初始視窗可忽略，每頁到達後做一次全量線性遍歷，累計存取 `210B` 個條目；最終只遍歷一次存取 `20B`，該遍歷工作量約減少到原來的 1/10.5。分頁請求仍為 20 次，最終正文仍需裝配、渲染和佈局。

## Alternatives considered

**只加佈局包含或 React 批處理。** 佈局包含不會刪除重複的 JavaScript 工作。僅抑制每頁釋出後的 React 渲染，也會保留上游對話裝配與索引重建。

**修改虛擬化庫。** 現有回呼和相對滾動操作已能完成固定高度定位，無需維護依賴分支。原生滾動容器仍需總高度；刪除總高度會使原生滾動失效，而不是實作虛擬化。

**單一大滾動控制器。** 它能集中狀態，卻把 DOM 操作與跟隨、分頁策略耦合。拆分負責物件後，業務變更無需複製幾何操作。

**虛擬化整個正文。** 這會引入本次範圍之外的 renderer 生命週期與語義錨點約束。聚合目標歷史跳轉即可刪除中間釋出，無需改變正文駐留方式。

## Consequences

跳轉遠處輪次時，目前正文會保持到整批資料落實，不再逐頁展示中間結果。暫存頁面增加與新取得條目數成正比的引用。正文幾何讀取、語義錨點查詢、普通原生滾動指標、最終佈局，以及側欄動畫改變中間區域寬度時的重排仍然存在；本次不聲稱消除了這些成本。變換與顏色變化仍可能重繪，賦值 `scrollTop` 仍可能產生原生滾動事件。

[軌道測試](../../../../packages/client/ui-chat/tests/turn-navigator.client.spec.tsx) 覆蓋有界掛載、首次定位、固定尺寸控制與焦點保留。[Chat 測試](../../../../packages/client/ui-chat/tests/chat-view.client.spec.tsx) 覆蓋語義恢復、跟隨歸因、自身滾動回聲與不做命中測試的導航。[Session 測試](../../../../packages/api/session-controller/tests/session.client.spec.ts) 覆蓋即時事件並行下的原子前插釋出、失敗與替換。[瀏覽器導航](../../../../apps/web/tests/chat-scroll-contract.e2e.ts) 覆蓋真實滾動與未載入輪次落點。功能證據與上述理論估算相互獨立。
