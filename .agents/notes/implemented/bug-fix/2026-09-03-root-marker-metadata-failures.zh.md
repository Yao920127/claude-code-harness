# Agent Note: 根標記中繼資料故障

Status: implemented

[English](2026-09-03-root-marker-metadata-failures.md) | 中文

## 問題

專案根發現從工作階段工作目錄向上遍歷時，會探測每個已設定的標記。把所有 resolve 或 stat 故障都當作標記缺失，會使權限、I/O 或提供者故障越過該目錄繼續搜尋祖先專案，並載入無關的工作區指令。發現結果必須區分確認缺失與中繼資料不可用。

## 決策

只有當主機 stat 報告 `ENOENT` 或 `ENOTDIR`，或檔案系統提供者未返回 stat 資訊，或從解析或 stat 報告 `FS_NOT_FOUND` 時，根標記發現才會繼續向上。檢查取消後，其他標記錯誤會原樣重新丟擲。指令檔案候選項保留獨立的可用性策略：解析、stat 和讀取故障只會跳過該候選項，因為檔案可能與發現過程發生競爭，而不會改變專案身份。

## 考慮過的替代方案

**把所有標記故障都當作缺失並繼續向上。** 不予採用，因為無法存取的子目錄可能繼承無關祖先專案中的指令，而發現過程仍報告成功。

**在第一個不可用標記處停止，並把工作階段工作目錄用作根目錄。** 不予採用，因為這會把未知的專案根轉換為另一個專案身份，並可能靜默省略有效的更寬泛指令。

## 後果

專案根發現優先保證專案身份正確，而非可用性：祖先遍歷中任何不是缺失的中繼資料故障都會使基線載入以原始錯誤拒絕。指令檔案候選項故障保留現有的跳過行為。失敗的基線不會建立工作區上下文 Session event，因此無金鑰錄製工作階段 harness 沒有可用於該路徑的持久輸出。

## 驗證

聚焦單元測試覆蓋確認的提供者缺失，以及不可用的主機與提供者標記中繼資料。不可用情況還證明祖先指令不會進入派生模型歷史。
