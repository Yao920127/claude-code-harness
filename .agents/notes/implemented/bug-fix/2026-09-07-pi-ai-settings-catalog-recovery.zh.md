# Agent Note: pi-ai 目錄變化後可修復的設定

Status: implemented

[English](2026-09-07-pi-ai-settings-catalog-recovery.md) | 中文

## Problem

已安裝的 pi-ai 目錄可能改變未修改使用者設定的有效性。OpenRouter 的目錄外模型可以在所有內建模型協定一致時繼承協定；加入第二種協定會使這種推斷失效。刪除目錄模型也會使按其舊 ID 宣告的覆蓋失效。註冊時拒絕整個 settings 名稱空間，會讓無關提供者消失，也移除了修復設定所需的控制元件。

## Decision

pi-ai 消費者使用現有 settings `validate` 回呼。名稱空間註冊期間容忍目錄診斷；註冊完成後，將變化的提供者與目前已解析分節比較並嚴格驗證。Settings 在更新、整體替換和路徑修改的持久化之前呼叫此回呼。外部過載使用相同的嚴格驗證，失敗時保留最後一次接受的分節。Settings 服務及其公共 API 保持不變。

首次解析 profile 時保留目錄診斷，而 schema 與 profile 自身的約束仍會拒絕載入。寫入會將有效提供者值與已提交快照比較，嚴格解析每個新增或修改的提供者。未修改的錯誤提供者不會阻止其他提供者編輯，刪除仍然可用。修改提供者級設定會驗證其影響的所有模型。

Profile 解析在有效模型旁保留逐模型錯誤。失去引用目標的覆蓋會保留診斷，而不會停用其餘目錄。路由級目錄失敗會保留提供者與可編輯設定，但不提供可呼叫模型。路由級驗證中止目錄解析時，不完整的目錄及其已收集的逐模型診斷會被丟棄，該路由上的模型請求統一報告路由級錯誤。介面卡在解析憑證和網路 I/O 前檢查所選模型已記錄的錯誤，並報告 `INVALID_CONFIG`。載入過程不會猜測協定或改寫使用者設定。不可變快照仍保證進行中的請求使用其捕捉的設定。

`LlmConfigurableProvider.error` 優先為提供者行攜帶首個模型診斷，無模型診斷時返回路由錯誤。提供者建構失敗不會覆蓋已收集的模型診斷，從而保留缺少協定時的具體修復提示。可設定提供者目錄釋出診斷變化，修復設定會重新整理瀏覽器，無需重新註冊介面卡。錯誤模型 ID 保留在設定中，模型選擇器只接收可服務條目。模型設定頁顯示診斷並保留編輯、刪除控制元件。兩個新增操作都要求其所屬 settings 名稱空間存在；普通新增選單會過濾不可用的名稱空間。

本決策擴充功能了[按提供者路由的介面卡決策](../architecture/2026-07-14-provider-routed-llm-adapters.zh.md)：提供者所有權與請求快照不變，目錄有效性不決定設定是否可管理。舊記錄仍保留為路由、所有權與回放設計的依據。

## Alternatives considered

**在註冊時拒絕目錄錯誤。** 這會阻止使用者修復結構可解析的設定，並讓未使用的過期模型停用無關提供者。

**同時放寬儲存驗證。** 對無法推斷協定的新模型，可以立即拒絕並點名提供者與模型。接受它只會製造可避免的請求時錯誤。

**每次儲存都嚴格重驗證整個名稱空間。** 無關提供者的舊錯誤會阻止新增正常提供者，或逐個修復提供者。

**為 OpenRouter 指定固定路由協定。** 路由覆蓋會替換所有模型的協定，可能改變有意使用其他 API 的正常目錄條目。

## Consequences

依賴升級產生的錯誤仍可見、可修復，而新增提供者編輯的驗證不會放寬。設定錯誤與遠端模型是否存在仍然不同：顯式指定協定的目錄外 ID 可以被接受，由端點決定該 ID 是否存在。標量或文件錯誤仍儘早失敗。模型設定頁不展示名稱空間註冊失敗的原因，此類錯誤需要檢查設定與啟動診斷。不增加 Settings API、儲存格式或 session 事件；可設定提供者條目新增一個可選診斷欄位。

## Testing

介面卡測試覆蓋有效與錯誤模型混合、覆蓋目標被刪除、獨立提供者編輯、路由刪除、聯網前失敗及修復。檔案監聽迴歸驗證非法外部編輯保留最後一次接受的 profile，而修復後的檔案能夠生效。完整 Web 期望測試從過期 OpenRouter 設定啟動，保留 zai 與兩個新增控制元件，在不改變檔案的前提下拒絕無效儲存，並透過刪除過期模型修復路由。已有快照測試繼續負責請求凍結與回放行為。
