# Agent Note: Typert 引用追蹤包內轉發模組

Status: implemented

[English](2026-09-07-typert-package-local-forwarding-imports.md) | 中文

## Problem

`WorkspaceAnalyzer` 先把每個型別引用解析到原始宣告再分類，然後只讀引用所在檔案自己的 `import` 語句來判斷該引用是否經由公開匯出跨包。一個包若在自己的某個模組裡重新匯出另一個包的型別，並在別處用相對路徑匯入該模組，就會報 `crosses a package without an explicit package import`，儘管包匯入只隔一跳。這個失敗在任何批次大小和包順序下都會穩定出現；它出現在哪次分析裡，取決於哪次分析把引用方的包選為根，因此 issue 3525 觀察到的現象像是與批次相關。

## Decision

[`targetForReference`](../../../../packages/typert/generator/src/analyzer.ts) 透過該 face 共享的編譯器主機及其模組解析快取來解析相對說明符，且只在解析到的檔案仍位於引用方包內時繼續追蹤。在每個轉發模組裡，它收集承載所請求名字的 `export` 邊：帶說明符的具名重新匯出、由該模組自身 `import` 支撐的 `export { local }`，以及匯出同一符號的星號重新匯出。顯式邊先於星號邊嘗試，與 TypeScript 中顯式匯出遮蔽星號匯出的規則一致；解析後的模組與請求匯出名組成的每個組合只進入一次，因此迴圈的星號重新匯出能夠終止，經同一模組轉發的不同改名路徑仍可繼續嘗試。追蹤在遇到第一個包說明符時停止，並把該包身份和匯出名交給現有的 `packageExportName` 檢查，因此被轉發的型別仍必須在轉發模組所寫的包子路徑上公開，沒有登記的包名也在此被拒絕。引用模型不變：同 face 的所有者仍是 `declaration`，另一 face 仍是 `cross-face`。

當相對說明符解析到引用方包之外、承載該名字的唯一邊是名稱空間重新匯出或被重新匯出的名稱空間匯入，或所有邊都回到已進入的模組與請求名組合時，追蹤得不到包匯入，引用照舊失敗。

## Alternatives considered

**把別名鏈終點在另一個包的相對匯入視為隱式公開。** 已拒絕：這會接受 `../../other/src/file.ts`，也會接受自身用相對路徑抵達另一個包的轉發模組，從而取消公開匯出檢查，而生成的 Remote 宣告依賴該檢查來命名可匯入的子路徑。

**把轉發模組記為引用目標。** 已拒絕：發射器和跨 face 連結需要原始宣告的包和公開子路徑，包內模組沒有自己的公開身份。

**按原始碼順序選邊且不驗證符號。** 已拒絕：回到更早模組的星號重新匯出可能排在真正承載該型別的顯式重新匯出之前，而 TypeScript 本身允許顯式匯出遮蔽星號匯出；顯式邊優先並跳過已進入的模組與請求名組合，既能接受這類模組，又不會無限追蹤。

**讓分批分析與全工作區分析選擇相同的根。** 作為修復方案已拒絕：根的選擇不改變對一個引用的判定，只決定該引用是否被存取，對齊呼叫方只會掩蓋錯誤分類，不能消除它。

## Consequences

包可以為外部型別保留一個轉發模組並用相對路徑匯入它，與自身模組的組織方式一致。每個跨包相對引用每跳付出一次經該 face 共享解析快取的模組解析；`reachableFiles` 現在也透過同一快取解析。[`type-model.spec.ts`](../../../../packages/typert/generator/tests/type-model.spec.ts) 固定了具名、改名多跳、先匯入再匯出、星號和名稱空間匯入這幾種轉發，與迴環星號邊並存的顯式重新匯出，經同一模組轉發的不同改名路徑，被轉發的私有匯出，用相對路徑跨包的轉發模組，唯一出口用相對路徑跨包的迴圈，名稱空間重新匯出，被重新匯出的名稱空間匯入，跨 face 轉發，以及轉發 fixture 在不同批次大小和包順序下全量分析與分批分析相等。
