# Agent Note: DeepSeek 圖片 token 估算器改用 v41 計算器

Status: implemented

[English](2026-09-10-deepseek-image-token-calculator-v41.md) | 中文

## 問題

`llm-deepseek` 中的 `deepSeekImageTokens()` 移植的是提供者公開圖片 token 計算器的 `v4` 設定：384×384 放大下限、384 token 上限、8:1 寬度鉗制、奇數行數額外加一行並做奇偶校正的網格佈局，以及按最壞情況計價的 pad-to-4 對齊。提供者的影象理解指南現在為目前 Flash 模型記錄了另一套投影規則：總畫素小於約 544×544 的圖片放大，更大的圖片縮小到約 1300×1300 總畫素，單張圖片最多 1024 token。公開計算器以 `v41` 設定承載這套規則，文件頁實例化的也是它。舊移植對一張 800×800 的請求圖片低估 73 token，可能使包含這類圖片的工作階段延遲觸發自動壓縮。誤差取決於尺寸：一張 640×480 的圖片會被高估 3 token。

## 決策

`image-tokens.ts` 重寫為 `v41` 設定的逐句移植。常數為 14px patch、每軸 3:1 降取樣、544×544 總畫素下限、1024 token 上限。網格公式為 `rows × (cols + 1) + 2`，沒有奇數行額外行、沒有奇偶校正、求解器也不再把行數截成偶數。沒有對齊 pad，所以估算值是精確值而非最壞情況上界；沒有寬高比鉗制，所以極端長寬比會經求解器的單行和單列分支到達上限。超預算路徑是一次閉式求解加上公開的斷言；逐步遞減的重試迴圈只服務於奇數行佈局。提供者對投影尺寸的定點迭代保持不變。

測試向量按公開計算器重新固定。request-pricing 測試、包 README 和本 note 使用新數字。本次改動保留了 harness 在定價前應用的 640,000 總畫素投影和 catalog 模型 id；[後續決策](2026-09-10-deepseek-v41-request-image-projection.zh.md)把該投影換成了同一套網格，現在省略 `imagePixelBudget` 走 token 網格，正整數或 `low` 仍走總畫素預算。

## 備選方案

**保留兩套設定並按模型 id 選擇。** 提供者說明發往已下線的 `deepseek-v4-flash-vision-exp` 的請求由目前 Flash 模型承接，所以沒有可達路由會按舊設定計價。兩套設定會保留死分支及其測試。

**保留帶 `isNLayout`、pad 和寬高比鉗制開關的通用類。** 單設定移植需要從覆蓋率中排除的不可達分支更少，並直接陳述已上線的規則；提供者未來再修訂時，兩種寫法都只改這一個模組和它固定的向量。

**在同一改動中提高 harness 畫素預算。** 提供者現在每張圖接受約 1300×1300 總畫素，harness 的 640,000 畫素投影會丟棄模型本可利用的細節。那是請求內容的改動，有自己的快照影響，與為實際傳送內容計價是兩件事。

## 後果

800×800 請求圖片的計價從 349 變為 422 token，640×480 圖片從 209 變為 206，低預算下的 512×512 圖片從 201 變為 184。壓縮壓力隨保留圖片的尺寸變化。請求投影后來改為同一套網格（[後續決策](2026-09-10-deepseek-v41-request-image-projection.zh.md)），讓正方形請求圖片計 422 token 的 640,000 畫素預算已不再適用。估算值不再帶 3 token 的保守餘量；請求完成後，提供者 usage 仍是權威錨點。經 `llm-replay` 回放的工作階段使用各自 fixture 的 `imageRequestTokens`，不受影響。
