# Agent Note: 增量終端保留策略

Status: implemented

[English](2026-09-11-incremental-terminal-retention.md) | 中文

## 問題

持久終端輸出在每次 PTY 回呼中都受 scrollback 和未讀傳送輸出的位元組上限約束。如果每次執行這些限制都重建完整的保留字串，回呼成本就會隨保留輸出量增長。即使每個輸入分片很小，4 MiB scrollback 視窗也會使這項重複工作產生顯著開銷。

## 決策

[terminal-bash](../../../../packages/terminal/terminal-bash/src/session.ts) 的私有緩衝區保留字串連結串列、頭部偏移，以及 UTF-8 位元組數與換行符數的彙總值。追加操作檢查輸入文字，並僅淘汰最舊的碼點，直到兩個限制都滿足。每個被淘汰碼點的成本可歸於之前的追加操作，因此保留策略的總工作量與輸入量呈線性關係。讀取時拼接保留字串，成本仍與保留輸出量成正比。

保留字尾與先按行數裁剪、再按 UTF-8 位元組數裁剪的結果一致。末尾換行符貢獻一個空邏輯行。截斷標誌保持為真，直到消費操作清空緩衝區。跨分片相鄰的代理項兩半按一個四位元組碼點計數，並共同淘汰；未配對代理項保留 JavaScript 字串原值，按三個 UTF-8 位元組計數。讀取時的 `utf8Tail()` 保持獨立且不變。

每個非空輸入都在保留前透過 UTF-16 複製，在保留未配對代理項的同時，使清理器返回的切片脫離已丟棄的控制文字。待處理的小片段與大分片都遵循這一規則。私有 `truncated` 和 `isEmpty` getter 讓傳送結算和啟動輪詢無需拼接 scrollback 即可檢查狀態。

頭部字串至少一半被丟棄後，其字尾會被複制，以釋放原始底層儲存。複製成本不超過已丟棄字首，因此維持攤還線性工作量，並使保留字串儲存受保留視窗約束。連結串列節點避免陣列頭部移除或定期掃描所有保留分片。小輸入在非頭部的尾節點合併，最多積累 4096 個 UTF-16 單元；分配後繼節點時，將這些片段複製為一個獨立字串。大尾塊已經擁有獨立儲存，此處不會再次複製。追加期間頭節點不會增長，快取的末尾碼元也避免了為檢查跨分片代理對而將待處理片段展平。這樣即使每次回呼只有一個位元組，片段中繼資料也有界，且無需重新掃描保留文字。

[持久 PTY 決策](../feature/2026-07-16-persistent-pty-sessions.zh.md)繼續負責工作階段生命週期、模型可見輸出與保留語義。本決策細化儲存與效能，不取代任何活躍決策記錄。

## 測量設計

終端 I/O 基準透過合成子程序控制代碼驅動 `LocalPtySession`。固定的 16 KiB ASCII 分片不含換行符，以長邏輯行觸發位元組上限。穩態情境先填滿 128 KiB 或 4 MiB 視窗，再追加同樣的 1 MiB。獨立的空視窗情境傳送 5 MiB。行數上限為 10,000；未讀輸出上限為 256 KiB 與 scrollback 容量中的較小值。

同步接收計時覆蓋傳送啟動與提供者回呼。完成計時還等待終端模擬器處理與就緒，再讀取有界終端結果。保留堆在顯式 GC 後取樣，此時工作階段與返回輸出仍可達。建置後的 JavaScript 在普通 Node 下執行。這些測量不含 shell 啟動、作業系統 PTY 傳輸、模型延遲或瀏覽器渲染。

### 本地參考測量

在 Apple M5 Pro、macOS arm64、Node v26.5.0 上，每個情境用五個全新 worker 比較全量保留計算基線 與增量保留策略。兩個版本使用相同 worker 和輸入，僅私有工作階段實作不同。下表時間單位為毫秒，按取樣順序排列。

| 情境 / 指標 | 全量保留計算樣本 | 增量保留計算樣本 |
|---|---|---|
| 128 KiB 穩態 / 接收 | 232.164, 234.564, 219.511, 219.615, 221.434 | 10.493, 10.474, 9.917, 10.524, 10.327 |
| 128 KiB 穩態 / 完成 | 245.365, 247.826, 233.322, 232.854, 234.926 | 19.600, 19.991, 19.290, 20.049, 19.773 |
| 4 MiB 穩態 / 接收 | 4159.780, 4271.184, 4179.700, 4223.583, 4128.541 | 8.752, 8.584, 8.808, 8.582, 10.073 |
| 4 MiB 穩態 / 完成 | 4183.374, 4296.630, 4205.122, 4247.787, 4151.634 | 29.760, 30.679, 31.510, 31.781, 37.748 |
| 5 MiB 傳送 / 接收 | 5186.998, 5122.875, 5127.790, 5177.788, 5157.274 | 26.440, 27.453, 26.710, 26.328, 27.334 |
| 5 MiB 傳送 / 完成 | 5297.536, 5181.298, 5182.416, 5234.920, 5211.802 | 89.475, 83.310, 88.491, 89.440, 89.339 |

大/小視窗穩態接收時間的中位數比值在全量保留計算下為 18.88，在增量保留計算下為 0.84。5 MiB 完成時間的中位數從 5211.802 ms 降至 89.339 ms（58.3×）。大視窗穩態情境的最大保留堆從 4,512,656 位元組升至 6,219,296 位元組；該指標同時測量活躍工作階段與結果分配，並非僅緩衝區字串。

獨立的記憶體情境以 16 位元組回呼傳送 5 MiB，在完成後對保留堆取樣一次。尾部合併時保留 5,802,840 位元組。相同斷言在未合併連結串列節點下失敗：22,969,720 位元組超過 16 MiB 上限。此情境不判定效能耗時。

過濾輸出的記憶體情境傳送 513 個 64 KiB 回呼，每個含完整的 56 KiB OSC 序列及其後的 8 KiB 可見文字。資料經過生產清理器，填滿 4 MiB 可見視窗後進行有界讀取。直接保留輸入切片時，斷言以 36,706,592 位元組失敗。將輸入複製到獨立儲存後，保留堆降至 7,635,440 位元組，低於不變的 16 MiB 上限。這些測量使用 Node v26.5.0 和全新 worker。

真實 PTY 診斷透過建置後的本地子程序提供者執行 `node -e 'process.stdout.write("x".repeat(5*1024*1024))'`。一次基線樣本耗時 106962.523 ms；一次最終候選樣本耗時 249.007 ms。計時從 PTY/程序 spawn 前開始，到 `session_exit` 和有界讀取完成後結束。兩個樣本均以程式碼 0 退出，無訊號，viewport/read 載荷均為已截斷的 256 KiB。這包括原生 PTY 傳輸與 Node 啟動，不包括互動式 shell 及提示符就緒往返。

[必需基準](../../../../benchmarks/terminal-io/terminal-io.bench.ts)對參考預期值應用共享 CI 係數與餘量：穩態接收 20 ms、穩態完成 50 ms、完整傳送完成 120 ms，對應限制為 50/125/300 ms。容量擴充功能的中位數比值必須低於 4×；最大保留堆為 16 MiB。比值與記憶體限制不縮放。替換為原始編譯後工作階段 worker 時，兩個計時情境都失敗：容量比值 18.977 超過 4，完整傳送完成時間 5066.719 ms 超過 300 ms。最終 worker 的四個情境均透過。本地命令為 `pnpm exec vitest run --config vitest.bench.config.ts benchmarks/terminal-io/terminal-io.bench.ts`，在基準建置完成後執行。

## 考慮過的替代方案

**僅快取位元組數。** 這仍會使每次追加的按行拆分和完整字串字首刪除依賴保留輸出量。兩個限制都需要增量計數。

**在讀取前保留全部輸出。** 這使生產成本較小，但允許讀取之間的保留量無限增長。設定的限制必須在產生輸出時生效。

**每次回呼保留一個節點。** 微小回呼會使節點中繼資料遠大於有界文字。受限的尾部合併使節點數與儲存的文字塊相關。

**保留編碼後的 UTF-8 分片。** 編碼會替換未配對 UTF-16 代理項。字串分片無需引入第二種文字表示，即可保留現有緩衝區語義。

## 影響

追加工作不再依賴重複掃描保留視窗。Snapshot 和 consume 仍分配拼接後的字串。保留策略額外維護連結串列節點與有界的待處理小片段集合。功能測試覆蓋位元組數與行數的互動、消費操作、跨分片代理對，以及 4 MiB 保留視窗。效能證據補充這些輸出斷言；合成提供者不能證明真實 shell 命令延遲。
