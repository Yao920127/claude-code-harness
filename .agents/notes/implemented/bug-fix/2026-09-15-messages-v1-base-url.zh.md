# Agent Note: Messages 基址嚴格識別 v1

Status: implemented

[English](2026-09-15-messages-v1-base-url.md) | 中文

## 問題

Messages 傳輸會在設定的基址後追加 Anthropic 標準 `/v1` 名稱空間。此前，已經以 `/v1` 結尾的基址會生成 `/v1/v1/messages`；而把所有 `v` 加數字的字尾都識別為提供者版本，會提供未經說明的相容性，並可能繞過標準名稱空間。

## 決策

共享 Messages API 所有者移除末尾斜線，僅把嚴格等於 `v1` 的最後路徑段視為已有 API 版本。它保留該根地址並追加 `/messages` 或 `/files`；其他基址均追加 `/v1/messages` 或 `/v1/files`。快取檔案上傳也使用同一個解析後的根地址劃分作用域。因此，官方 `https://api.deepseek.com/anthropic` 基址解析為 `/anthropic/v1`，顯式 `/anthropic/v1` 基址保持不變。

Messages 規則不推斷 `v1beta`、`v2`、`v4` 或其他類似版本字尾的支援；包含這些路徑段的部署會在其下接收標準 `/v1` 名稱空間。

## 考慮過的替代方案

**識別所有以 `v` 加數字開頭的末尾路徑段。** 這可以避免更多自定義端點重複版本，但會把範圍有限的 `v1` 重複修復變成未經說明的相容策略，並可能把請求路由到 Anthropic 標準名稱空間之外。

**始終追加 `/v1`。** 這對無版本根地址遵循標準路徑，但仍會為已以 `/v1` 結尾的設定產生原有重複路徑。

## 結果

Messages、Files 與檔案快取標識使用同一條確定性規則。嚴格匹配 `/v1` 的設定保持相容，推薦的無版本基址無需改變。其他版本式字尾不被視為 API 版本，因此會在其下追加 `/v1`；這會有意放棄對代理的推測性相容。
