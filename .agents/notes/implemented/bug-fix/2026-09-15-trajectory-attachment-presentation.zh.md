# Agent Note: 統一 Trajectory 附件展示

Status: implemented

[English](2026-09-15-trajectory-attachment-presentation.md) | 中文

## 問題

使用者訊息可以包含文字、圖片和普通檔案。Trajectory 曾在文字旁省略圖片數量，在預覽中遺漏普通檔案，並在原始內容中混排檔案 JSON 與渲染後的圖片。讀者無法在列表和詳情面板中一致地確認完整附件集合（Issue #4356）。

## 決定

Trajectory 展示每次附件出現的記錄，並分別提供視覺預覽與已記錄欄位檢查。

| 位置 | 行為 |
|---|---|
| 列表 | 文字摘要旁分別顯示非零的圖片數量與普通檔案數量，無正文的訊息也顯示計數。每條記錄保持為緊湊單行。 |
| 概述與預覽 | 訊息正文之後展示一個有序附件列表。兩個標籤頁使用相同的渲染器；概述保留緊湊間距和滾動容器。 |
| 附件列表 | 等寬的緊湊行使用一致的間距和圓角。檔案型別圖示或完整縮放的圖片縮圖旁展示已記錄的名稱與可用中繼資料。重複引用保留各次出現的順序。 |
| 圖片互動 | 圖片完整縮放到 48px 方形縮圖內，不裁剪。啟用時開啟現有圖片檢視器，保留鍵盤存取。載入與重試圖示適應縮圖尺寸，並提供在地化的工具提示和可存取名稱。 |
| 原始內容 | 圖片塊和檔案塊使用預設收起的中繼資料摺疊區，包含完整記錄欄位。原始內容塊順序與未渲染文字保持完整；生成的顯示標籤不進入原始欄位。 |

已記錄檔名優先於在地化的編號圖片標籤。中繼資料來自記錄欄位或副檔名，零位元組大小仍然可見。視覺上截斷的名稱保留完整的無障礙文字和工具提示。無正文的訊息仍在詳情面板滾動區域內展示全部附件。

### 職責

[ui-trajectory](../../../../packages/client/ui-trajectory/README.zh.md)負責計數、有序附件投影和詳情面板組合。其檢視資料將帶型別的圖片與檔案引用和原始內容使用的序列化文字分別儲存，展示程式碼因此無需解析 JSON 來恢復檔案中繼資料。

[ui-attachment](../../../../packages/client/ui-attachment/README.zh.md)透過現有圖片 slot 負責圖片載入與檢視器。[ui-conversation](../../../../packages/client/ui-conversation/README.zh.md)擁有工作階段級圖片快取：Chat 與 Trajectory 對每個附件共享一次授權讀取和一個瀏覽器 URL。縮圖尺寸和可選顯示標籤隻影響展示，載入仍接收原始引用。Chat 和工具結果相簿保留現有的尺寸行為。

本決定使用現有持久附件引用，不改變上傳、儲存、模型請求或工作階段格式。普通檔案展示中繼資料，不提供內容檢視器或下載操作。產品標籤使用帶型別的在地化字典，樣式使用現有語義 token。

[通用檔案上傳決定](../feature/2026-08-26-generic-file-upload.zh.md)負責上傳、儲存、准入和有序訊息附件；本記錄負責 Trajectory 展示。[不可讀附件隔離提案](../../proposed/bug-fix/2026-08-20-attachment-read-quarantine.zh.md)處理模型請求恢復，與縮圖載入回饋相互獨立。

## 考慮過的替代方案

**預設在詳情面板中內聯展示大圖。** 這樣可以立即閱讀單張圖片，但高圖片會在窄面板中擠走附件名稱和訊息正文。緊湊行加顯式圖片啟用入口能一致地概覽混合附件。

**使用雙列附件卡片。** 網格能在寬面板上突出縮圖，但會壓縮長檔名空間，並要求窄面板採用不同排布。單列等寬列表適用於兩種面板寬度。

**在原始內容中混排檔案 JSON 和圖片預覽。** 這讓同一個標籤頁對兩種附件具有不同含義。中繼資料摺疊區用於檢查已記錄欄位，預覽負責圖片的視覺展示。

## 影響

共享附件渲染器使概述與預覽中的名稱、順序、中繼資料和圖片操作保持一致。將附件集中在訊息正文之後便於瀏覽完整集合；需要原始塊順序時，原始內容保留交錯關係。即使圖片載入共享快取項，重複引用仍各佔一行。

緊湊縮圖需要開啟檢視器才能閱讀詳細圖表。缺失的中繼資料保持缺失，圖片讀取失敗保留重試控制元件，並且不隱藏普通檔案。共享圖片 slot 的修改也會影響 Chat 和工具結果，因此其相簿行為和快取複用仍需迴歸驗證。

## 驗證

[投影測試](../../../../packages/client/ui-trajectory/tests/layout.client.spec.tsx)覆蓋混合附件、純附件、空文字和重複引用。[詳情面板測試](../../../../packages/client/ui-trajectory/tests/table.client.spec.tsx)覆蓋兩種語言、無名稱圖片、長檔名、零位元組檔案、有序列表和完整的原始欄位。[圖片測試](../../../../packages/client/ui-attachment/tests/message-image.client.spec.tsx)覆蓋縮圖標籤、載入、重試和現有檢視器。

已錄製的[混合上傳瀏覽器情境](../../../../apps/web/tests/file-upload-round.e2e.ts)比較概述與預覽，驗證鍵盤啟用和焦點恢復，檢查原始內容收起與展開狀態，並在重新整理後重複檢查。其 [Trajectory 預期輸出](../../../../snapshots/web/file-upload-round/trajectory.expected.md)配合未改動的工作階段 fixture（測試前置資料）使用。[組裝應用圖片快取測試](../../../../apps/web/tests/trajectory-image-display.expected.e2e.ts)也檢查 Chat 與 Trajectory 之間的複用。

佈局驗收覆蓋窄版與寬版面板、兩種主題和語言、縮圖完整縮放及末尾附件可達性。[GIF 工作流](../../../skills/record-browser-gif/SKILL.md)要求評審證據基於乾淨的已提交程式碼樹，在同一個真實服務、真實模型工作階段中展示混合提交、列表計數、概述、預覽中的圖片啟用和展開的原始中繼資料。Issue #4356 及其關聯 PR（Pull Request）記錄已執行的檢查和演示證據。
