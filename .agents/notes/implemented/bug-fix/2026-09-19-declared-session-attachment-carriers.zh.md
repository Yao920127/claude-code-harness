# Agent Note: Session 宣告的附件載體

Status: implemented

[English](2026-09-19-declared-session-attachment-carriers.md) | 中文

## 問題

Session 附件授權與 ZIP 匯出按常見載荷欄位名推斷附件歸屬。因此，未知可忽略事件也能授權圖片讀取或匯出檔案位元組。壓縮事件的 `summary` 與 `rawOutput` 內容不在這套欄位名掃描範圍內。

## 決策

兩個消費者均按內建事件型別選擇內容欄位。它們檢查已完成的 assistant 塊與直接內容塊，包括扁平的 V4 tool 角色訊息。其他內容塊欄位與未知事件載荷保持不透明，即使其中含有類似圖片或檔案引用的物件。

控制器在讀取圖片位元組前應用此規則。匯出器在讀取圖片或檔案位元組前應用此規則，並保留完整邏輯日誌。歷史日誌由持久化層轉換成目前邏輯事件後交給這些讀取器。標題請求不在附件載體之列，因為 V4 要求它只含一個文字塊。壓縮事件使用其宣告的內容欄位：基礎生產者目前輸出文字，其他合法壓縮生產者可以在這些位置提供附件。

## 考慮過的替代方案

**掃描所有事件的常見鍵。** 這使欄位名在沒有明確內容語義時授予附件存取權，也會遺漏其他已宣告欄位中的有效內容。

**在附件讀取器中解釋歷史包裝塊。** 歷史轉換由相鄰格式包負責。目前附件讀取器使用扁平的 V4 內容，不維護第二套舊塊解釋。

## 影響

僅在自定義事件中儲存附件的外掛不能透過這些內建讀取器讀取相關引用。外掛需要使用受支援的內容位置，或提供自己的讀取器。新增內建內容載體時，需要同步更新兩個讀取器及其接納和拒絕測試。歷史編解碼器的清單仍歸各版本所有；調整此策略不能改變已釋出解碼器識別的內容。

此變更影響附件查詢與歸檔成員，不影響 Session 編碼或模型可見訊息歷史。

## 驗證

控制器和歸檔測試覆蓋宣告的載體、扁平工具結果、不透明外掛載荷及誤導性額外欄位。拒絕測試斷言不會讀取附件儲存；歸檔測試還比較匯出的日誌文字。
