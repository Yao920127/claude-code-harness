# Agent Note：補齊父目錄而不遷移子目錄

Status: implemented

[English](2026-09-19-session-local-subagent-migration.md) | 中文

## 問題

開啟歷史父工作階段需要直屬子工作階段的發現事實。子日誌正文損壞、descriptor 無效，或根目錄其他位置的 header 不可讀，都可能拒絕父工作階段的 V4 準備，使原本可讀的歷史無法開啟。

## 決策

開啟 A 時透過 header 發現候選 B Session，讀取其自身 descriptor，並補齊 A 的 catalog。歷史子日誌使用 V0–V3 catalog 讀取，目前子日誌使用原生驗證。這些讀取不準備 B 自己的 catalog，也不釋出 B 的後繼。單獨開啟 B 時才執行 B 的遷移與目錄準備。前端發現繼續讀取父 catalog。模式未知的條目仍可瀏覽；`list_agents` 繼續只選擇已知可繼續的子工作階段。

JSONL 在發現時跳過不可讀或不支援的 header。子正文或 descriptor 欄位失敗會產生帶子路徑的警告，並保留該子的 header 身份。父目錄沒有完整條目時，遷移追加 `subagent/catalog`，與健康兄弟項一同投影為目錄條目，其模式為 `mode: 'unknown'`。已有完整條目仍具有權威性。取消與來源一致性失敗仍中止操作。複用和釋出前會重新檢查已檢查子日誌的修訂，包括解碼失敗的日誌，使修復不能靜默複用舊證據。已釋出前驅保持逐位元組不變。

本決策部分取代[已釋出遷移](../architecture/2026-08-31-released-session-format-migrations.zh.md)和[不完整子證據](2026-09-19-v3-incomplete-child-catalog-evidence.zh.md)中的子錯誤傳播規則。其格式轉換、descriptor 數量、衝突總和檢查碼不可變釋出規則仍有效。

## 考慮過的替代方案

**跳過目錄補齊，讓每個消費者發現子項。** 父工作階段明明有可讀的子 descriptor，卻會因此產生不完整工具結果和額外 UI 狀態。父 catalog 已經服務這些消費者。

**從目錄刪除不可讀子工作階段。** 已釋出父工作階段會丟失相應導航入口。Header 身份足以保留成員關係，無須編造模式或標籤。

**遞迴準備子目錄。** A 只需要 B 自身的 descriptor。準備 B 的後代會增加無關工作與失敗依賴。

**一個子工作階段不可讀就拒絕 A。** 子工作階段的發現中繼資料不足以成為阻斷健康父歷史的理由。警告保留子位置，不虛構 mode 或 label 欄位。

## 後果

首次父準備仍掃描 header 並逐個讀取直屬子正文，不宣稱消除此 I/O。已釋出 V4 父工作階段使用其 catalog，不重新掃描子日誌。釋出後不自動重寫未知條目。開啟子工作階段會重試其日誌，根據實際 descriptor 確定瀏覽能力，或報告該子工作階段的錯誤。Catalog 載荷 v0 保留兩種已知模式，v1 另支援 `unknown`。讀取器支援兩版；正常建立及完整歷史事實繼續使用 v0，未知遷移事實使用 v1。V4 Session header 不變，舊讀取器拒絕新載荷版本。

原始和壓縮測試覆蓋目錄補齊、子工作階段錯誤隔離、來源變化與修復、子代際不變和延後的子目錄準備。隨產品 Web 遷移快照在損壞兄弟存在時檢查父目錄，再獨立開啟子工作階段。額外的歷史子角色使語料預算由十個增加到十一個；守衛拒絕第十二個角色。
