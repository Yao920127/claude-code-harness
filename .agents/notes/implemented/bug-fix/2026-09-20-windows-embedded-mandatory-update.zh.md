# Agent Note: Windows 內嵌強更彈出視窗

Status: implemented

[English](2026-09-20-windows-embedded-mandatory-update.md) | 中文

## 問題

Windows 的第二個原生視窗無法與父視窗原子地縮放，最大化時會出現脫離的蒙層（#4566）。原生模態還會停用使用者退出應用所需的父視窗控制元件。

## 決策

Windows 使用一個原生視窗和頂欄下方的殼源站 frame。此決策部分取代[強更用戶端](../feature/2026-09-11-desktop-mandatory-update-client.zh.md)的展示決策；該說明繼續負責策略與安裝歸屬。macOS 保留原生蒙層。

隔離的應用預載入將私有 MessageChannel 端點直接傳給殼 frame。只有配對私有埠上的訊息才能授權更新 IPC；合成的 window 事件不能呼叫操作。主程序驗證目前應用主 frame，並在主視窗變化時重新繫結狀態投遞。已銷燬視窗不再接收狀態或焦點操作。

## 考慮過的替代方案

**同步第二個原生視窗。** 父視窗移動、最大化與還原會暴露獨立排程的幾何更新；去掉第二個視窗即可消除這一同步問題。

**把 window 事件的 source 和 origin 當作身份認證。** 產品腳本可以建構這些事件欄位。私有埠將操作權限保留在共享產品文件之外。

## 後果

頂欄選單和 Web 控制元件仍可觸達。DOM 蒙層阻止普通背景輸入，但不能阻止產品腳本隱藏或仿造展示；它不是防篡改的安全介面。主程序策略和安裝授權與展示相互獨立。迴歸覆蓋要求包括拒絕偽造事件、真實通道投遞、頂欄鍵盤操作，以及視窗銷燬和替換的生命週期案例。
