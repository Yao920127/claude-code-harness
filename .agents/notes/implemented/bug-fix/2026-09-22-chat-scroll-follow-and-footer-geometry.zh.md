# Agent Note: 分離 Chat 裁剪與獨立滾動跟隨意圖

Status: implemented

[English](2026-09-22-chat-scroll-follow-and-footer-geometry.md) | 中文

## 問題

正文溢位必須保持裁剪，同時不能限制懸浮控制元件或改變 sticky 內容的滾動祖先。即使讀者實際滾動的是外層元素，`overflow-y: hidden` 祖先也會成為最近的滾動容器。這會阻止 Markdown 程式碼塊頭欄和展開的壓縮摘要頭欄吸附在可見工作階段滾動區域；位於該祖先內的懸浮控制元件也會參照正文幾何，而非視口幾何。

限高過程組也有獨立閱讀位置。若組內偏移不變，外層跟隨底部無法展示組內新增內容。把每個未到底的滾動事件都當成讀者輸入，也無法支援原生平滑跟隨：瀏覽器在動畫接近目標期間同樣會發出這些事件。

## 決策

正文、懸浮控制元件及滾動意圖分別由獨立物件負責。[滾動狀態表](../../../../packages/client/ui-chat/README.zh.md#scroll-ownership)與[分組展示規則](../../../../packages/client/ui-chat/src/client/conversation-nodes/README.zh.md#display-modes)定義目前產品行為。

| 範圍 | 實作 | 原因 |
|---|---|---|
| 正文裁剪 | `ChatView` 在無裁剪的外框內，對 `.root` 使用 `overflow-x: visible; overflow-y: clip`。 | 限制縱向溢位，不在 sticky 內容與其實際滾動區域之間引入滾動容器。 |
| 懸浮控制元件 | TurnNavigator 與回到底部按鈕位於正文裁剪層的同級。 | 共享 Conversation 相對外層滾動容器做 sticky 定位；獨立 Chat 相對自身外框做 absolute 定位。 |
| 跟隨意圖 | `useScrollFollow` 為每個滾動區保留獨立控制器。 | 共用閾值、位置取樣及原生滾動，不共用一個跟隨開關。 |
| 小組生命週期 | `useProcessScroll` 負責既有的正文與內容觀察器、方向漸隱和一次性展開位置。 | 正文達到限高後，內容增長仍可被觀察；展開時不立即讀取幾何。 |

被裁剪的根節點不持有滾動偏移。共享 Conversation、獨立 Chat、限高過程組和終端區域保留各自原有的滾動容器。橫軸保持 `visible`：縱向 `clip` 如果與橫向 `auto` 或 `hidden` 組合，縱向溢位的計算值會變回 `hidden`，重新引入不需要的滾動容器。

未關閉的小組展開到自己的底部，已關閉的小組展開到頂部。初始位置由組自身的 `closed` 決定，不取整個 Turn 的狀態，也不遍歷全部節點。組隨後關閉不會重置已展開的閱讀位置。瀏覽器查詢保留自身的展開定位，模式切換保留已掛載成員。

原生平滑跟隨將未完成的目標與目前位置分開記錄。動畫進度保留跟隨意圖。輸入在瀏覽器處理讀者移動前中斷原生動畫，再由實際位移決定是否暫停或恢復跟隨。後續增長保留已發出的目標，直到 `scrollend`。到達該目標（包括內容縮短後的鉗制位置）才允許再次請求最新底部；停在目標之外則釋放跟隨，讓焦點和查詢保留落點。減少動態效果與明確的展開定位使用即時滾動。外層跟隨保留既有的即時行為和取樣策略。

回到底部按鈕只取決於外層跟隨意圖，也只恢復該意圖。只有滾動傳遞確實移動外層滾動區域時，內層滾動才影響外層控制器。小組長高可以改變外層正文尺寸，但兩個控制器不會互相呼叫跟隨操作。分頁和語義恢復仍由既有的外層閱讀與導航物件負責。

## 考慮過的替代方案

**刪除正文裁剪。** 這會放棄溢位約束。縱向 `clip` 保留裁剪而不建立滾動容器；無裁剪的同級外框讓懸浮控制元件位於裁剪區域之外，不需要 Portal 或文件級座標同步。

**保留 `overflow-y: hidden`，僅移動懸浮控制元件。** 這可以保護控制元件，但 sticky 內容仍位於不需要的滾動容器內。將根節點改為 `clip` 也能保留程式碼和壓縮摘要頭欄的滾動祖先，無需把這些頭欄移出其正文。

**共用一個跟隨開關，或複製完整控制器。** 共用開關會僅因外層跟隨就把小組拉離讀者位置。複製兩套完整實作則會重複動畫歸因和閾值規則。共用小控制器可以保留獨立狀態，同時不把分頁、輪次導航及語義記憶搬入其中。

**只把 `scrollTop` 賦值換成平滑 `scrollTo`。** 動畫中間偏移會被誤判為讀者移動，導致跟隨關閉。原生動畫需要明確的目標與輸入中斷處理，無需自寫動畫幀插值器。

## 影響

共享控制器只儲存意圖，不自行排程 React 渲染；呼叫方仍釋出可見狀態變化，小組邊緣漸隱僅在布林值變化時更新。跟隨操作讀取受影響的滾動容器，而非節點集合。原生滾動仍有瀏覽器佈局和繪製成本。這些改動確立行為與職責，不代表已測得延遲或記憶體收益。

[導航決策](../architecture/2026-09-18-chat-navigation-performance.zh.md)繼續負責取樣閱讀、已知落點與聚合歷史跳轉。[分組決策](../architecture/2026-09-21-conversation-build-groups.zh.md)繼續負責 Definition 成員關係與穩定渲染身份。提取滾動跟隨機制不取代這兩項決策。
