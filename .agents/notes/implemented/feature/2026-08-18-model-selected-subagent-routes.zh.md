# Agent Note: 模型選擇的 subagent 路由

Status: implemented

[English](2026-08-18-model-selected-subagent-routes.md) | 中文

## 問題

`dsh-tool-subagent` 可以設定子級 `AgentOptions`，兩個程序內提供者也已把這些值合併到父 Agent 的 LLM 選擇之上。但面向模型的工具不能為某個適合的子任務請求不同的提供者、模型或推理強度。為每條 LLM 路由載入一個名稱不同的委派工具會重複 schema，並把每次呼叫的排程選擇變成部署設定。

模型還需要一種有界方式來發現即時提供者和模型自有的推理強度 ID。把 adapter 目錄渲染到每一份委派描述中，會讓僅供參考且會變化的目錄進入 prompt 字首。

## 決策

只有 Agent 作用域的 `modelSelectionSettings` 實例解析出 Session 策略，且繫結的 subagent 提供者宣告 `SubagentCapabilities.agentOptions` 時，`dsh-tool-subagent` 才公開可選的 `provider`、`model` 與 `reasoning_effort` 欄位。該策略使用[使用者授權的 subagent 模型路由](2026-08-24-user-authorized-subagent-model-routes.zh.md)所擁有的精確使用者授權；不存在無限制靜態模式。停用的實例會省略並拒絕面向模型的選擇，而設定的 `Config.agentOptions` 仍是部署方所有的預設值。如果 settings 已啟用的實例缺少該提供者能力，外掛掛載會失敗。

提供者與模型共同組成一條路由，必須一起提供。如果設定值、父級值或提供者持有的路由預設值能夠提供生效路由，則可以只提供推理強度。靜態的 `provider.agentRouteDefaults` 在存在時構成 provider／model 基線；`Config.agentOptions` 與模型參數會在路由相關強度清除之前覆蓋它。沒有靜態預設值的提供者會使用父 Agent 最新記錄請求中的相容欄位，首個請求之前由建立選項提供退回，並保留其中設定的輸出 token 上限。推理強度 ID 仍由 adapter 所有。只有所選基線的路由不變時才會繼承省略的強度；更換提供者或模型但沒有指定強度時，會清除下層路由自有的值，使所選模型解析自己的預設值。`AgentOptions` 把結果強度傳入子級迴圈，其請求 header 會記錄生效值。可繼續描述符會把它與解析後的提供者和模型一同記錄，使尚未寫入首個請求的子級能以相同選擇冷恢復。

顯式或設定的提供者、模型或強度會在提供者基線與請求優先順序完成後，透過 `ctx.llm.resolveCallConfig()` 解析。具有靜態路由預設值的提供者會在請求省略強度時禁止繼承父級強度，從而保留所選模型的預設值。LLM 查詢負責提供者註冊、精確模型中繼資料、推理強度總和檢查碼 adapter 預設值。非同步查詢完成後、建立子級或後臺 job 之前，工具會再次檢查取消狀態，並確認同一個提供者實例仍處於註冊狀態，因此 HMR 不會把一個提供者的預設值與另一個提供者的程序組合。既沒有面向模型的選擇、也沒有設定路由欄位的呼叫會保留原有提供者路徑，不要求可選 LLM 服務存在。

啟用的定義會註冊 `list_subagent_models`。無參數呼叫列出已授權且已註冊的提供者；提供 `provider` 時先授權，再呼叫該介面卡的建議性模型目錄；同時提供 `provider` 與 `model` 時會先授權精確路由，再解析其推理強度和預設值。因為發現工具使用全域名稱，一個工具作用域最多由一個實例啟用選擇。隨附產品組合在 Agent 作用域的主 `subagent` 實例上設定 `modelSelectionSettings: true`，並註冊 Host 自有的 `subagent-model-selection` 設定，其中包含預設關閉的顯式 `enabled` 開關與 `allowedModels` 列表。Plugins 設定頁會原子儲存兩個欄位。設定啟用時，新的頂層 Session 會在任何模型請求之前，把路由策略快照記錄為 `subagent/model-selection-policy`。子 Session 繼承線上父級的策略；恢復的 Session 使用已記錄事件，而不是目前設定。因此，設定修改隻影響之後組合的頂層 Session。即使缺少可選 LLM 服務，固定發現定義仍保持可用；發現呼叫和所選路由呼叫會在該服務出現前失敗。發現會列出即時目錄與已記錄策略的交集，執行器會拒絕策略之外的顯式路由。

隨附的 `subagent_fork` 實例不會讀取模型選擇設定，即使程序內 fork 提供者支援 `agentOptions` 也是如此。fork 會繼承父級生效的提供者與模型，使複製的對話字首仍可供提供者側 KV Cache 複用。更改任一路由元件都會要求新路由重新預填充繼承的歷史，而這項重算成本可能超過委派任務本身。該限制與發現工具的全域名稱無關：分離發現工具的持有權可以讓設定生效，卻無法保留複用。只有在路由變化仍能保留字首複用，或呼叫方可以顯式限制並接受重算成本時，才重新考慮 fork 路由選擇。

委派定義不會隨 adapter 註冊和目錄變化而改變，因此即時拓撲既不會擴大每個父級請求，也不會使快取字首失效。只有呼叫發現工具時，目錄結果才進入 transcript。自定義的上下文繼承實例如果啟用選擇，其描述會警告，更改提供者或模型可能阻止提供者複用繼承的對話字首。

`SubagentCapabilities.agentOptions` 仍是傳輸事實。如果請求攜帶這些選項，而提供者宣告為 `false`，服務會在呼叫提供者前拒絕。兩個程序內提供者與 DSH SDK 傳輸宣告為 `true`；DSH SDK 會把 provider／model 預設值作為分離且不可變的資料公開給 Consumer 預檢，而 `start()` 會為直接呼叫方與子執行時初始化獨立應用同一份 Config 預設值及 maxTokens。ACP、Codex 與 Claude Code 宣告為 `false`。工具設定提供 `agentOptions`、靜態啟用模型選擇或讓它受 settings 控制時，如果繫結的提供者缺少該能力，也會失敗。

## 考慮過的替代方案

**要求靜態啟用設定部署路由允許列表。** 不採用，因為它會重複即時 LLM 註冊表，並要求自定義組合先設定才能使用已經註冊的路由。隨附的使用者自有偏好屬於另一項授權決定，由[使用者授權的 subagent 模型路由](2026-08-24-user-authorized-subagent-model-routes.zh.md)記錄。

**在每一份委派描述中渲染即時 adapter 目錄。** 不採用，因為一個提供者可能公佈數百個模型，從而擴大每次請求，而且目錄變化會改寫快取字首中的早期定義。按需目錄讓可變資料留在固定 schema 之外。

**把公佈的目錄當作允許列表。** 不採用，因為 adapter 目錄只提供建議，有些提供者接受任意精確模型 ID。精確解析仍是權威。

**在 subagent 服務中增加發現方法。** 不採用，因為提供者／模型／強度中繼資料已經屬於 `ctx.llm`；新工具只是該現有能力面向模型的 Consumer。

**把發現工具作為獨立載入的外掛入口匯出。** 不採用，因為隨附組合總是把發現工具與主委派工具配套載入。在該實例上顯式指定持有權，可以避免重複的全域工具名，無需增加 Cordis 設定項或獨立生命週期。

**分別設定發現與面向模型的選擇。** 不採用，因為發現功能用於向能夠選擇這些值的同一個模型提供有效的路由與強度 ID。一個開關可以避免工具 schema 公開選擇卻沒有對應發現路徑，或公開發現卻沒有適用的委派路由。

**在隨附 fork 工具上啟用面向模型的路由選擇。** 不隨產品提供，因為更改提供者或模型會失去繼承字首的 KV Cache 複用，重新預填充字首的成本可能高於委派工作本身。只有在路由變化仍能保留複用，或介面能把這項成本顯式化並限制住時，才重新考慮該選項。

**使用全域推理強度列舉。** 不採用，因為推理強度 ID 和預設值屬於精確的提供者／模型路由。LLM adapter 會直接驗證，無需中心化翻譯或截斷。

**允許遠端提供者忽略這些欄位。** 不採用，因為請求會聲稱發生了實際上沒有發生的路由選擇。能力標記會讓不支援的路徑在建立子級前失敗。

## 結果

- settings 已啟用的 Session 只能選擇其記錄的精確子級 LLM 路由；停用的 Session 會省略並拒絕面向模型的路由欄位。
- 主委派工具實例預設關閉選擇，為新 Session 提供 Plugins 頁面精確路由 opt-in，並且只在持久策略存在的 Session 中註冊 `list_subagent_models`；發現與顯式選擇都受該策略限制。
- 隨附 fork 工具會繼承父級的提供者與模型，並省略面向模型的路由欄位，使繼承的對話字首仍可供 KV Cache 複用。
- 省略選擇時保留設定預設值，並使用靜態提供者路由預設值或來自父級最新記錄請求的相容繼承；改變路由但不顯式指定強度時，使用所選模型的預設值。
- adapter 目錄和拓撲變化不會改變委派定義及其 prompt 快取字首。
- DSH SDK 子級接受設定和模型選擇的 Agent 路由；ACP、Codex 與 Claude Code 在實作並宣告該能力前仍會拒絕。
- 單元測試覆蓋預設關閉的 Host 偏好、新 Session 讀取、子級繼承、恢復決定、選擇啟用時的 schema 與執行強制、合併優先順序、路由相關強度繼承、預檢取消、即時發現、診斷、定義穩定性、能力拒絕與可選服務行為。隨附的 headless 快照固定從父級已記錄選擇繼承的行為；隨附範例覆蓋組裝後無金鑰、模型可見的 schema，SDK Loader 與快照證據固定完整路由經過獨立子執行時的鏈結。
