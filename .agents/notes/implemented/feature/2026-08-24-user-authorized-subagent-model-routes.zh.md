# Agent Note: 使用者授權的 subagent 模型路由

Status: implemented

[English](2026-08-24-user-authorized-subagent-model-routes.md) | 中文

## Problem

註冊 LLM 介面卡會使其路由可達，但不代表授權 Agent 為子級選擇每一個可達模型。針對即時介面卡註冊表的單一啟用偏好，會在另一個提供者或模型出現時靜默擴大範圍。產品需要一項顯式且穩定的授權決定，同時避免把可能很大的模型目錄渲染進父 Agent 的每次請求。

## Decision

Host 自有的 `subagent-model-selection` 設定 section 儲存顯式 `enabled` 開關與 `allowedModels`，後者是由精確 `{ provider, model }` 路由組成的陣列。啟用時必須至少有一條路由；關閉時可以保留已選路由，供以後重新啟用。Plugins 設定卡透過 `session/modelCatalog` 讀取即時介面卡目錄，讓使用者暫存開關與路由，再在一次帶 revision 限制的設定 mutation 中儲存兩個欄位。它不儲存介面卡自有的顯示名稱、描述或推理強度中繼資料。目前目錄中缺失的已存或暫存路由仍顯示為不可用並允許移除；某個提供者的目錄失敗不會阻塞其他提供者，也不會清除已存授權或未儲存選擇。連線重置會丟棄草稿，因為 namespace revision 只能在同一個 Host 程序內比較。

設定啟用時，新組合的頂層 Session 會在模型可選定義進入請求之前，把路由列表快照記錄為 `subagent/model-selection-policy`。事件存在就表示模型選擇已啟用；事件不儲存全域開關。子 Session 從線上父級繼承同一份精確列表，恢復的 Session 使用已記錄事件而不是目前設定。因此，設定修改隻影響之後組合的頂層 Session，而沒有該事件的舊 Session 仍保持停用，包括顯式為空的恢復 Session。

固定的 `list_subagent_models` schema 不會列舉該策略。呼叫時，提供者和模型列表是 Session 路由列表與介面卡即時公佈目錄的交集。精確 provider/model 查詢先要求授權，再解析介面卡自有的模型中繼資料和全部已公佈推理強度。委派執行器還會獨立拒絕任何生效 provider/model 路由不在 Session 列表內的顯式提供者、模型或強度選擇，然後才由 `resolveCallConfig()` 驗證介面卡可用性與強度支援。完全沒有選擇欄位的呼叫保留設定或繼承路由，因為模型沒有作出路由選擇。

模型選擇不再有無限制的靜態模式。預設關閉的 Host 設定是唯一授權來源，啟用的 Session 始終攜帶精確允許列表。主 spawn 工具讀取該設定；隨附 fork 工具仍不公開路由選擇，使繼承的對話字首繼續符合提供者側 KV Cache 複用條件。

## Alternatives considered

**在委派描述中渲染允許路由。** 不採用，因為很大或變化的列表會擴大每次請求，並使較早的提示詞字首失效。按需發現會保持固定 schema 的字首穩定，且只在請求目錄時記錄其內容。

**只過濾設定 UI 或發現結果。** 不採用，因為模型可以猜測路由，或從較早的 transcript 中保留路由。授權由啟動子級的執行器強制執行。

**從非空 `allowedModels` 陣列推斷是否啟用。** 不採用，因為關閉功能時要麼必須丟棄仍有用的選擇，要麼要保留一個含義取決於寫入歷史的非空陣列。顯式開關是權威依據，設定 scope 會在一次由 Host 驗證的 mutation 中提交兩個欄位，因此不會持久化中間狀態。

**儲存每條路由的推理強度允許列表。** 不採用，因為使用者決定針對子級模型，而強度 id 與相容性屬於精確介面卡路由。路由獲准後，仍可使用介面卡支援的每種強度。

**每次發現或委派呼叫都讀取目前設定。** 不採用，因為設定編輯會靜默改變執行中 Session 的模型可見能力和執行權限。持久 Session 快照會讓恢復與子級繼承保持確定。

## Consequences

- 新介面卡註冊和新公佈模型不會擴大使用者授權。
- 介面卡移除或目錄失敗可以減少發現目前列出的內容，但不會刪除已存路由決定；即使建議性目錄省略某條精確已授權路由，只要介面卡接受它，該路由仍然可用。
- 允許列表本身不消耗父級請求 token。只有 `list_subagent_models` 結果進入 transcript。
- 策略事件僅存在於日誌，並在 Agent 組合期間、兩套 SDK 開始訂閱執行前追加。隨附 SDK profile 不啟用這項 Web 自有偏好，因此該事件不會改變任一 SDK 的預期通知或持久 Session 輸出；其持久投影由包級恢復測試負責，不會為了發出該事件而虛構 SDK 組合。
- 單元覆蓋固定設定驗證、異常持久值、Session 取樣與繼承、發現交集、執行器拒絕、UI 即時目錄失效、暫存路由保留、連線換代失效、暫存後的整陣列寫入、陳舊 revision 拒絕，以及作用域安裝失敗後的重試。組裝 Web 情境固定真實設定文件與 Plugins 設定卡流程。
