# Agent Note: 模型可見的路由切換提示

Status: implemented

[English](2026-09-07-model-switch-notice.md) | 中文

## 問題

工作階段歷史會標明訊息角色，但不會告訴新選中的模型，先前的 assistant 訊息由哪個路由生成。在引出本改動的工作階段中，使用者從 `deepseek-v4-flash` 切換到 `deepseek-v4-flash-vision-exp`。新模型看到圖片佔位文字稱純文字模型省略了圖片，於是誤以為該限制描述的是自己的圖片能力。

## 決策

`installModelSelection` 會比較提示片語裝時捕捉的提供者和模型選擇與最新的持久請求 header。兩者不同時，它會把 `[model changed: assistant turns above this point were generated by <previous>; the session continues with <next>]` 作為帶標識的 user 角色訊息，追加到下游原本會發出模型請求的 `agent/pre-step` 決策中。

同一提供者的路由只使用模型 ID；跨提供者的路由使用 `provider/model`。首次選擇、未變化的路由、僅推理強度變化、被拒絕的步驟和被取消的步驟都不會增加提示。首次空決策與移除待處理訊息後得到的空決策都不會產生請求。工具呼叫後的空續步仍會基於保留歷史請求模型，因此會收到提示。pre-step 處理期間發生的選擇變更會等待下一次提示片語裝。

被接納的訊息會在請求 header 前透過現有 `user/message` 事件寫入磁碟，因此會出現在模型輸入、Chat 和 Trajectory 中。請求 header 仍是新路由已被使用的持久記錄。如果步驟在該 header 寫入磁碟前失敗，持久記錄中的先前路由保持不變，所以下一個請求步驟會再次發出提示。

## 考慮過的替代方案

**把提示放進系統提示詞。** 臨時提示詞變更無法從工作階段日誌重建，也不能標出 assistant 訊息由哪個模型生成的分界點。

**新建單獨的包或能力。** 該行為只協調 `installModelSelection` 已經負責的提示詞快照與請求路由，沒有獨立的服務、提供者或消費方角色。

**只在用戶端展示切換。** 僅由用戶端展示時，新選中的模型仍然缺少解釋先前 assistant 訊息所需的資訊。

## 影響

每條實際發出的路由切換提示都會成為保留的 user 角色歷史，並在後續請求中佔用上下文 token。請求 header 寫入磁碟前發生的失敗可能保留多條相同提示。該行為使用現有工作階段事件，因此工作階段格式不變。
