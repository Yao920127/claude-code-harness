# Agent Note: Composer 選單分節、在地化行與「檔案」行

Status: implemented

[English](2026-09-08-composer-menu-sections-and-localized-rows.md) | 中文

## 問題

composer 的 `+` 按鈕與鍵入的 `/` 按主機註冊順序把每個命令列成 `name description`，全部小寫，沒有圖示也不分組，旁邊還有一個單獨的回形針按鈕用於新增檔案。中文介面下各行仍是英文，因為主機描述符只攜帶英文文案；只知道命令中文名的使用者既搜不到它，也看不出該輸入什麼。Issue #3567 及其設計稿要求：按使用頻次分成兩個小節，每行帶圖示、標題左對齊、說明右對齊，英文標題首字母大寫，中文標題與說明在兩種語言下都能搜尋並同時顯示英文命令名，計劃與目標的宣告用中文填入，以及把「檔案」入口放進選單。

## 決策

`ui-commands` 在 `src/client/presentation.ts` 裡擁有選單的展示：「新增」小節（`file`、`goal`、`plan`、`feedback`）與「指令」小節（`compact`、`permission`、`model`、`export`），各按使用頻次排列，不在兩個清單裡的行按目錄順序排在「指令」末尾。小節清單按名字索引；空查詢返回分節的行，輸入查詢後返回所有可見行的平鋪排序，最佳匹配始終在第一位。

六個內建主機命令從用戶端取得在地化標題、說明、圖示和認領 token。穩定標識選擇與輸入解析遵循[命令標識決策](../architecture/2026-09-10-command-identities-and-composer-file-action.zh.md)。貢獻項攜帶 `label()`、`description()` 和 `icon`，每次生成候選項時讀取，因此 `/model` 行無需重新註冊即可在地化。

選單選中填入目前語言的認領 token：中文下選中「計劃」填入 `/計劃 `，提交時執行 `/plan `。手輸 token 保留原寫法作為認領，因為輸入框從它持有的 token 之後讀取參數。工作階段有效目錄在所有介面語言下透過同一輸入路徑解析中英文別名。

「檔案」行是一個 `action` 貢獻項：裸呼叫消費觸發 token 後執行用戶端回呼，不提交訊息。Conversation 負責該註冊、即時可用性和隱藏檔案輸入框。選單取代單獨的回形針按鈕，`+` 按鈕的無障礙名稱與提示為「新增檔案或呼叫指令」。

`ui-input-trigger` 渲染新的行結構：`InputTriggerCandidate.label` 是標題，也是共享 `rankByName` 的第二個搜尋鍵；label 與名字不同時名字渲染為尾隨別名；`icon` 在引用圖示 token 之外接受圖示元件；說明右對齊。別名與說明使用比主標籤小 1px 的字號。`ui-primitives` 新增設計稿給出的計劃圖示、壓縮用的靜態環形，以及權限盾形輪廓。

選單採用 400 px 的 border-box 高度上限，在視口限制縮小高度前可容納兩個小節標題與八個內建入口。內容確實溢位時，WebKit 系瀏覽器用 6 px 的可拖曳區域承載 2 px 的可見滑塊，軌道避開圓角兩端，視口抵達最後一行前顯示底部漸隱；Firefox 保留標準細捲軸。

## 考慮過的替代方案

**刪除分隔空格時釋放命令認領。** 完整命令名仍能標識已選命令。保留認領直到命令名改變，可以在替換參數時保持高亮，也無需依賴輸入法生成的空格觸發普通按鍵裁決。共享輸入狀態機對所有命令 token 使用這個規則，提交失敗後的恢復也相同；命令名和介面語言都不選擇另一套實作。

**在原生組合輸入結束事件中直接恢復佔位文字。** 瀏覽器可能先傳送該事件，Lexical 隨後才完成最終文字更新。共享編輯器繫結在原生輸入法或編輯器仍處於組合輸入時隱藏命令提示和普通佔位文字，並在編輯器提交更新後重新判斷顯隱，包括沒有文字變化的取消操作。鍵盤提交保護保留獨立的組合輸入結束後保護時段。

**在主機側在地化說明。** 主機沒有語言設定，目錄由所有用戶端共享，在地化產品文案屬於用戶端。

**輸入查詢後保留小節。** 在小節內排序會把「指令」裡的字首命中排在「新增」裡較弱的匹配之下（輸入 `e` 時回饋與檔案排在匯出之上）；平鋪排序讓最佳匹配始終靠前，小節標題只在列表完整時才有資訊量。

**在選單旁保留回形針。** 設計稿與 issue 的驗收條件都要求把入口整合進選單且舊圖示不再重複顯示；隱藏的檔案輸入框與拖放門檻保持原位。

**由貢獻項擁有內建主機行的文案。** 主機包沒有用戶端一半可供註冊，文案只能放在用戶端；在已經擁有 `/` source 的包裡用一張按名字索引的表，能把設計決策集中在一處。

**只在目前語言下解析 `token` 別名。** 遍歷所有詞典解析沒有成本，還能讓在一種語言下持久化的草稿在另一種語言下提交。

## 後果

選單與在地化展示由用戶端負責，主機負責有效命令定義。新增在地化內建命令需要對應的標識對映、詞典條目、圖示和選單位置。工作階段驅動的瀏覽器情境與歸屬模組的 ARIA 預期覆蓋選單。無關的同名定義保留自己的文案，不獲得內建圖示。命令標識決策負責這一劃分和檔案動作的生命週期。
