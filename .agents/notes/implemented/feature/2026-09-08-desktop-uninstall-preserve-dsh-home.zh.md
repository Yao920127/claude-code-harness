# Agent Note: Windows 解除安裝保留 Harness 主目錄

Status: implemented

[English](2026-09-08-desktop-uninstall-preserve-dsh-home.md) | 中文

## 問題

Desktop 和 CLI 在 Harness 主目錄中共享工作階段、憑證、設定和外掛。Electron 把瀏覽器儲存和快取放在 `%APPDATA%` 下，更新器把下載的安裝檔放在 `%LOCALAPPDATA%` 下；上游 NSIS 範本在沒有命令列參數時會把兩者都留下。解除安裝的使用者期望應用不留殘餘，重灌的使用者期望工作階段仍在。

## 決策

Windows 解除安裝隨應用一起刪除 Electron 使用者資料目錄、`%APPDATA%` 下的產品目錄和更新器快取，從不觸碰 Harness 主目錄。這是 2026-09-08 提案的修正形式：僅限 Windows，不含已安裝產物清單方案，也不讓使用者選擇。解除安裝程式沒有自定義頁面；靜默解除安裝刪除相同的資料。以 `--updated` 或 `/KEEP_APP_DATA` 啟動的解除安裝程式保留資料，這覆蓋了 electron-builder 的原地更新和從其他目錄替換舊安裝兩種情況，因此更新保留介面偏好。以 Windows 環境變數釋出的 `DSH_HOME` 會保護所有與其重疊的目標；原生輔助程式看不到只在 shell 設定檔中設定的主目錄。

Electron 根據帶作用域的包名派生使用者資料目錄，因此刪除目標是 `%APPDATA%\@deepseek-ai\dsh-desktop`，隨後移除 `%APPDATA%` 之下普通且已空的父目錄，從不移除連結或非空的作用域目錄。刪除透過 `window-frame.dll` 中的原生輔助程式執行：它拒絕受保護的 Windows 目錄以及與安裝目錄或受保護主目錄重疊的路徑，遍歷期間以列舉權限持有目錄控制代碼，使目錄無法在其下被改名或替換，遇到重解析點只解除連結而不進入目標，清除只讀屬性，並在遇到被佔用檔案後繼續刪除其餘兄弟項。它要求固定的本地驅動器，連結的根目錄或祖先目錄會原樣保留。失敗只留下殘餘，不中止也不提示解除安裝；解除安裝程式沒有任何自定義文案。

安裝時還會在 Windows 解除安裝註冊項上記錄 `InstallLocation` 作為標準的清單中繼資料。Windows 11 上 Win32 安裝檔無法讓開始選單右鍵選單中的“解除安裝”直接啟動解除安裝程式，只有 MSIX 包能做到，因此該需求不在本決策範圍內。

## 備選方案

**在自定義解除安裝頁上按需刪除，包括桌面設定檔和整個主目錄。** 桌面設定檔、工作階段和憑證屬於與 CLI 共享的主目錄，為重灌而保留；剩餘的 Electron 資料只包含介面偏好和快取，不值得讓使用者理解並做出選擇，也不值得為解除安裝程式記錄主目錄路徑並維護雙語原生對話方塊。

**當桌面是唯一設定檔時刪除整個主目錄。** 設定檔的存在不能證明共享資料是否被 CLI 或將來的重灌需要。

**沿用上游預設，保留 Electron 資料。** Chromium 快取會增長到數百 MB，正是使用者解除安裝後回饋的殘餘。

**使用 electron-builder 的 `deleteAppDataOnUninstall`。** 上游的 `RMDir /r` 不遵守歸屬規則、不支援長路徑並會進入連結目錄；改由原生輔助程式負責刪除。

**透過在一次性帳戶上觀察安裝、更新和解除安裝來建立清理清單。** 三個根目錄由 Electron 的 `userData` 派生規則和 electron-builder 的更新器快取名決定，兩者都由設定固定；觀察只會確認設定已經說明的事實。

## 推遲事項

macOS 清理（由簽名輔助程式支撐的“**解除安裝並保留 Harness 資料**”操作，因為拖到廢紙簍無法執行應用程式碼）仍在 #3540 下開放，本決策不涉及。

## 結果

重灌恢復工作階段、設定和外掛，但不恢復介面佈局偏好。主目錄下的桌面設定檔及其包和鎖檔案保留。其他歷史主目錄和使用者專案不會被發現或刪除。位於網路或可移動驅動器上的漫遊設定檔原樣保留。

驗收使用每次執行唯一的帶作用域包名的隔離產品身份。原始碼迴歸覆蓋範本適應；原生刪除器迴歸覆蓋被拒絕的根目錄、受保護的主目錄、持有期間阻止改名、只讀與被佔用檔案，以及空父目錄移除；解除安裝夾具覆蓋互動、靜默、`--updated`、`/KEEP_APP_DATA`，以及位於 Electron 目錄內的 `DSH_HOME`，被刪除的資料內含指向外部專案的 junction。標準解除安裝頁面在開發機 200% 縮放下渲染正確。
