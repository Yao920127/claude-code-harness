# Agent Note: 授權驗證檔案展示覆用檔案系統位元組讀取

Status: implemented

[English](2026-09-08-file-display-through-filesystem.md) | 中文

## Problem

工作階段正文可能引用臨時目錄中的截圖或遠端檔案系統提供者中的檔案。Host 本地工作區白名單無法提供這些路徑。沒有位元組上限的圖片回應還可能讓瀏覽器先下載一張 1 GiB 圖片，再嘗試解碼。

## Decision

授權驗證 `/api/file` 路由透過 `ctx.fs` 讀取普通檔案。授權驗證和所組合提供者的讀取策略決定存取權限；目錄與 MIME 白名單不參與准入。這取代了[本地媒體展示記錄](2026-09-07-session-prose-local-media-display.zh.md)中的檔案服務策略；該記錄保留渲染器歸屬及其理由。

GET 呼叫現有 `readBytes(target, signal, maxBytes)`：提供者在內容 I/O 前拒絕已知超限檔案，並在讀取過程中執行上限。HEAD 使用中繼資料，不讀取內容。`FS_TOO_LARGE` 轉換為 413。MIME 查詢提供回應中繼資料，不嗅探檔案內容；未知副檔名使用 `application/octet-stream`。sandbox CSP 阻止直接開啟的 HTML/SVG 以授權驗證 API 源身份執行腳本。

所有檔案均使用已解析的 `ctx.attachments.imageLimits.maxImageBytes` 上限，通常為 20 MiB。附件服務擁有此部署設定。所有回應均包含完整檔案；忽略 Range，也不宣告支援 Range。

## Alternatives considered

**工作區和媒體白名單。** 它們限制授權驗證後能讀取哪些位元組，卻排除了常見截圖位置和遠端檔案。所選策略允許讀取所組合提供者可讀的任意普通檔案。

**新增檔案系統位元組流 API。** 高效的大檔案傳輸和音影片跳轉需要每個提供者實作，包括遠端 Range 處理。有界完整讀取滿足目前展示範圍，無需擴充功能該介面。相關案例足以支援這項提供者工作時，可以加入流式傳輸與 Range。

**在路由重複實作大小檢查。** GET 無需額外的 stat/read 迴圈：`readBytes` 已經負責讀取前上限、增長檢測和取消。HEAD 單獨檢查大小，因為它不能讀取正文。

## Consequences

臨時與遠端檔案使用與 `read_image` 相同的檔案系統提供者，不增加模型可見事件。本地沙箱提供者約束變更操作並允許讀取，因此授權驗證用戶端的存取範圍大於已註冊工作區根目錄。檔案仍受提供者權限和路由位元組上限約束。

每個 GET 都會在 Host 記憶體中快取完整檔案。音影片使用完整回應，不支援增量傳輸，也不保證跳轉播放。編碼位元組上限不限制解碼後的畫素尺寸。圖片載入失敗後展示作者提供的 alt 文字；alt 為空時展示原始目標路徑。

## Testing

路由測試覆蓋內容 I/O 前拒絕稀疏 1 GiB 檔案、stat 後增長、共用附件位元組上限、普通 MIME 型別、臨時路徑與符號連結、不透明遠端目標、提供者失敗、僅中繼資料 HEAD、忽略 Range 和釋放。瀏覽器期望覆蓋圖片渲染、413/404 及損壞圖片退回，以及工作區之外的圖片。遠端位元組傳輸仍由現有檔案系統提供者測試負責。
