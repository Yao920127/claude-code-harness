# Agent Note：Present 遵循 Session 檔案系統存取規則

Status: implemented

[English](2026-09-09-present-filesystem-access.md) | 中文

## 問題

生成檔案經常位於工作區外，尤其是 `/tmp`。工作區包含檢查會拒絕 Session 檔案系統和側欄已經允許存取的檔案。提供者的程序路徑也可能指向遠端檔案，而非服務 Host 上的檔案。

## 決策

`present` 接受所組合的 `ctx.fs` 可存取的已有普通檔案，相對路徑按 Session 工作目錄解析。不檢查工作區包含關係，也不另設臨時目錄白名單。檔案缺失、為目錄、最終路徑為符號連結或提供者出錯時，宣告失敗。檔案系統提供者不可見的沙箱私有臨時檔案仍不可用。

原生操作使用與宣告一起返回的目前 Session header，為 `workspaceFiles.stat` 提供工作目錄：優先使用其中的 cwd，未記錄時使用部署的工作目錄。側欄預覽和原生驗證使用同一組合檔案系統，無需啟動 Agent，子工作階段也適用。得到的規範化程序路徑必須能透過該檔案系統從 Host 路徑對映回同一程序路徑。對映缺失或不同會返回 422，並顯示使用側欄預覽的在地化提示。這隻支援規範化後與程序路徑寫法相同的 Host 路徑；僅支援不同寫法的 Host 對映的提供者仍可提供預覽。沒有對映時，本機同名檔案不能替代提供者檔案。

本決策替代[原始檔交付決策](2026-09-08-present-workspace-source-files.zh.md)中只允許工作區檔案的存取規則。原說明繼續負責不儲存內容的宣告、Session 事件和編輯目前原始檔。請求仍只按已儲存的 Session、事件和檔案索引選擇檔案，不接受瀏覽器提供的任意路徑。

## 考慮過的替代方案

`/tmp` 白名單會排除其他可讀的輸出位置，並重覆檔案系統策略。把所有提供者程序路徑都視作 Host 路徑可能開啟不相關的本機檔案。增加通用反向路徑對映 API 或複製遠端檔案，會讓提供者與檔案保留承擔原始檔交付之外的職責。

## 影響

工作區檔案、可存取的臨時檔案、Downloads 和其他專案中的檔案使用相同的宣告規則。原生開啟同時要求服務主機有可用桌面和經過驗證的 Host 路徑。中繼資料檢查不能使桌面應用隨後按路徑開啟檔案的操作具有原子性。

定向測試覆蓋工作區外的絕對和相對路徑、最終符號連結、檔案缺失、Session 查詢失敗、Host 對映缺失或不一致，以及在地化的原生操作不可用狀態。已有的 Web 錄製情境繼續覆蓋宣告、預覽、原生操作和不含檔案內容的匯出。
