# Agent Note: 在 Trajectory 中檢查已記錄的 PTC 原始碼

Status: implemented

[English](2026-09-09-ptc-trajectory-code-inspection.md) | 中文

## 問題

PTC 程式以 JSON 字串參數傳入。轉義使長程式在通用參數樹中難以閱讀，而歷史呼叫使用的執行時語言可能不同於目前部署。記錄的結果文字可以同時包含列印輸出與回傳值，卻未保留二者的分界。

## 決策

[Trajectory](../../../../packages/client/ui-trajectory/README.zh.md) 按已記錄的工具名識別呼叫，並從已驗證的 `run_code` 參數派生程式碼檢查器。驗證後的程式攜帶原始 JSON 文字；複製時保留原始碼與參數位元組，並透過獨立切換按鈕展示原始 JSON。語法高亮要求該呼叫記錄的參數說明包含明確且無衝突的 TypeScript 或 Python 提示；未知或衝突的提示使用純文字。不支援的參數保留通用檢查器。

結果檢視保留記錄的文字，只對完整 JSON 物件或陣列使用樹形展示。錯誤保留已捕捉的輸出。程式碼檢視在開啟時讀取共享換行偏好，並在掛載期間保留自身的選擇。

[PTC 執行時決策](2026-06-15-ptc.zh.md) 仍負責執行與結算；[用戶端展示決策](../architecture/2026-08-23-client-derived-tool-presentation.zh.md) 仍負責從已記錄事實派生 UI。此檢查器不增加 Session 事件或主機展示欄位。

Trajectory 思考預設展開，並支援手動展開摺疊。[Chat 展開預設值](../bug-fix/2026-09-14-chat-presentation-defaults.zh.md)是獨立的展示決策。

## 考慮過的替代方案

**把原始碼保留在參數樹中。** JSON 轉義遮蔽程式結構，也使複製可執行原始碼變得繁瑣。

**使用目前執行時語言，或從原始碼推斷語言。** 兩種方式都可能錯誤標註歷史程式。已記錄 Schema 的提示約束高亮，無需修改記錄。

**拆分列印輸出與回傳值。** 歷史渲染文字無法確定二者的分界；解析器可能憑空新增生產方從未記錄的分隔。

## 後果

讀者可以檢查和複製已記錄的程式，無需修改回放資料。Schema 沒有可識別的語言提示時不提供語法高亮。元件測試覆蓋記錄工具名識別、Schema 退回、原始碼與參數原樣複製、輸出狀態及獨立換行。JSON 樹測試覆蓋裁剪幾何、缺少 `ResizeObserver`、懸停切換或解除安裝後剪貼簿寫入落定，以及懸停期間讀取值的次數。思考測試覆蓋手動展開摺疊及 Trajectory 記錄切換；[PTC 瀏覽器情境](../../../../apps/web/tests/ptc-round.e2e.ts) 固定組裝後的檢查器展示，並驗證溢位和原始 JSON 的往返切換。
