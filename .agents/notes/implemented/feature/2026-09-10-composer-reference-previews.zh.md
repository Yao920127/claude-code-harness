# Agent Note: 輸入框引用預覽

Status: implemented

[English](2026-09-10-composer-reference-previews.md) | 中文

## Problem

使用者需要在編寫訊息時和傳送後檢視引用檔案和 skill 指令。檔案標籤與可編輯的斜槓文字具有不同的編輯語義，但都需要明確的預覽手勢，且不能改變下一條提示傳送的內容。

## Decision

[輸入觸發來源](../../../../packages/client/ui-input-trigger/README.zh.md)負責可選的引用啟用。編輯器按來源身份路由原子引用，按來源目前詞表路由可編輯文字。檔案和 skill 來源在編寫訊息的 Session 中開啟現有右側欄檔案資源。Skill 發現保留勝出提供者可選的指令檔案路徑，避免載入正文或根據 skill 名稱、目錄慣例猜測路徑。

[輸入框](../../../../packages/client/ui-conversation/README.zh.md)共用引用懸停樣式，同時保留原子檔案標籤和可編輯的 `/name` 文字。點選不序列化或提交草稿。無效標籤、選擇手勢及不可用的來源目標仍由編輯器處理；虛擬 skill 仍可呼叫，但沒有檔案預覽。

已傳送訊息的氣泡保留日誌中的 skill 呼叫證據作為裝飾依據。[Chat 目標](../../../../packages/client/ui-chat/README.zh.md)在目前檢視的 Session 中開啟檔案路徑，並透過該 Session 的來源路由已載入的 skill 名稱。共享使用者文字元件將這些引用渲染為按鈕，複用現有正文件案連結的懸停和聚焦樣式；工作階段、目錄和命令引用不提供導航。

## Alternatives considered

**將 skill 文字轉換為檔案標籤**會為了展示需求而改變編輯、剪貼簿和提示語義。現有可編輯文字已經能夠透過來源詞表標識 skill。

**在輸入框內解析檔案和 skill 格式**會讓編輯器依賴提供者目錄策略及預覽服務。由來源負責啟用，使這些依賴留在已經負責引用發現的外掛中。

**發現時載入每個 skill 的正文**會在使用者請求預覽之前增加工作和提供者副作用。可選路徑中繼資料足以支援檔案系統 skill，並保留虛擬提供者。

## Consequences

預覽路徑是臨時發現資料，不會加入 Session 訊息。Skill 外掛使用現有的按 Session 快取機制使路徑失效。快取未就緒時，點選等待共享目錄請求並保留所屬 Session 地址；快取失效和外掛釋放會取消待處理的預覽。檔案系統提供者公佈解析後的指令路徑，同時保留髮現時的重新載入定位資訊和資源根。側欄資源讀取器繼續負責目前內容、檔案缺失錯誤和存取策略。[工作區原始檔決策](2026-09-08-present-workspace-source-files.zh.md)仍負責交付檔案行為；輸入框預覽不取代該決策。

針對性測試覆蓋來源路由、釋放、快取失效、帶引號路徑、文字選擇和草稿不變。真實 Web 組合驗證兩種預覽、一致的懸停背景及開啟後的刪除操作；其所屬的預期輸出記錄 skill 文件及已傳送訊息。回放的 skill 呼叫輪次驗證重新整理歷史後兩種已傳送引用仍可預覽。
