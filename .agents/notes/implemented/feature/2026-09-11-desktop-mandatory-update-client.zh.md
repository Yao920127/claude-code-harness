# Agent Note: Desktop 強更用戶端與阻塞視窗

Status: implemented

[English](2026-09-11-desktop-mandatory-update-client.md) | 中文

## 問題

本地業務 server 不會傳遞遠端最低版本策略。Desktop 殼必須獨立獲知強更要求，在不中斷現有任務的情況下阻止後續互動，並在策略查詢或 updater 準備失敗時保留恢復路徑。

## 決策

原生更新浮層在關閉前持有父視窗可見性監聽。在 macOS 上，隱藏父視窗會隱藏但不會關閉其子視窗；重新顯示父視窗不會恢復這些子視窗。浮層等待文件就緒且父視窗可見，並在後續父視窗顯示事件中恢復自身。由公共浮層處理這一行為，既保持普通更新和強更的展示，也不將更新策略與 onboarding 耦合或清除有效阻塞。

殼獨立於業務流量輪詢[介面提案](../../proposed/feature/2026-09-08-desktop-mandatory-update-api.zh.md)中的遊客協定。設定和應用身份在打包時嵌入；打包應用忽略環境覆蓋。[Desktop README](../../../../apps/desktop/README.zh.md)負責設定欄位與預設值。打包在準備產物或簽名前要求提供由 updater 部署環境選定的策略源站。測試環境使用隔離的飛書授權驗證；正式環境保持匿名。測試登入視窗按 F12 會開啟獨立的 DevTools，同時保留沙箱、導航允許列表和僅駐記憶體的 Session。只有未打包開發模式可以省略策略設定。這避免因遺漏策略設定而靜默產出沒有強更檢查的釋出包，或讓測試包查詢正式環境策略。

協調器持有單一在途請求、截止時間、間隔抖動和有上限的失敗退避。請求用與帳號請求相同的五個 Platform 用戶端請求頭標識已安裝用戶端——平臺、用戶端版本、語言、以秒為單位的 UTC 偏移，以及有意保持為空的 bundle id——並額外攜帶架構、更新通道和內建執行時版本。平臺、架構、更新通道和內建執行時版本在打包時固定；語言與 UTC 偏移在每次請求時從殼取樣，版本取自共享的用戶端建置版本而非 Electron 打包版本。手動檢查繞過排程，但複用在途請求。dispose（資源釋放）中止請求、等待結算，並阻止遲到釋出。扁平化 `40005` 建立阻塞不依賴可選的標題、詳情和下載頁面欄位；在地化後備文案與重試操作仍可使用，缺失或未獲批准的頁面地址不會展示。傳輸、JSON、業務碼或 HTTP 錯誤都不能清除已知阻塞。只有新的有效無需強更回應才能清除它。同版本離線持久化未實作，因為其產品行為尚未確定。

使用者發起常規檢查時會觸發獨立的策略重新整理，但不會等待或展示策略失敗。只有已確認的強更決定會取消常規彈出視窗，並把展示移交給強更彈出視窗。測試環境授權驗證會等待目前常規彈出視窗結束；取消和失敗會保留 updater 結果。並行呼叫方複用目前常規操作或授權驗證操作，不建立相互競爭的視窗。

macOS 的殼模態視窗使用獨立沙箱預載入，主程序驗證其精確文件 URL 和 WebContents 身份。Windows 將殼源站彈出視窗嵌入主文件頂欄下方，讓最大化與縮放只有一個原生視窗負責；第二個原生視窗曾造成可見的縮放不同步（#4566）。隔離的應用預載入擁有通向 frame 的私有 MessageChannel，將操作轉發至驗證目前應用源站和主 frame 身份的主程序 IPC。產品腳本共享 DOM，可以隱藏或仿造展示，但不能獲得特權埠、清除主程序策略，或透過 window 訊息事件批准任務收尾。頂欄及其中的 Web 控制元件按設計保持可觸達。伺服器端標題／詳情按文字展示，絕不作為 HTML。Esc 和常規更新彈出視窗不能解除阻塞；阻塞期間主程序拒絕外掛視窗入口和外掛修改。Host 保持現有工作執行，任務影響安裝確認獨立於策略。仍可退出應用。 Windows 展示及其信任限制由[內嵌強更決策](../bug-fix/2026-09-20-windows-embedded-mandatory-update.zh.md)負責。

模態視窗透過常規協調器提供使用者發起的下載和獨立安裝。準備和任務檢查成功後，同一彈出視窗轉為安裝確認，不建立另一個視窗。稍後更新保留阻塞與安裝檔；重試會檢查任務並要求重新確認。檔案驗證與準備共用一個可見階段。只有觀測到受影響任務後，重新啟動提示才描述正在停止任務。兩類彈出視窗均要求所屬 IPC 傳送者；關閉、中止或失去常規渲染程序會取消其批准。

恢復介面在阻塞視窗內保留在地化錯誤和摺疊技術詳情。頁面操作僅在失敗或沒有可用產物時出現，不與正常操作並列。瀏覽器或剪貼簿使用前驗證精確 HTTPS 源站。請求開啟瀏覽器後立即提供複製恢復入口；請求完成不能證明外部網頁載入。僅在複製失敗時展示完整、經過驗證的地址供手動複製。導航和複製結果獨立於 updater 錯誤，策略目標地址改變後忽略遲到結果。開啟瀏覽器、下載就緒和安裝器交接均不清除策略或改變 updater 目標。

後臺就緒時，Windows 請求父視窗工作列提醒，macOS 請求資訊級 Dock 彈跳，並嘗試一次無聲通知。返回目前確認介面會清理原生提醒，不授予安裝權限。重複狀態、稍後更新和焦點變化不會重複提醒同一次就緒。策略解除、安裝和資源釋放也會清理提醒。通知不受支援或被拒絕時仍可使用彈出視窗；原生展示需透過安裝檔平臺驗收。

此決策實作[互動提案](../../proposed/feature/2026-09-08-desktop-update-policy-and-installation.zh.md)的用戶端部分。該提案與介面提案仍負責後端聯調、各平臺釋出驗收和未決產品事項。[釋出策略](../architecture/2026-08-25-electron-desktop-packaging-and-updates.zh.md)保留產物簽名和釋出要求；這些記錄均未被完整取代。

Host 退出與任務成功收尾是兩個獨立結果。程序所有者透過專用錯誤型別報告已確認但非正常的退出。該結果允許後端完成清理，但安裝仍失敗；殼恢復目前版本 Host，並要求重新確認安裝，不清除強更策略。替代 Host 會獲得新的 Web 源站和授權驗證 Cookie，因此 Host 就緒後會重新載入原有應用地址，即使埠未變也會重新取得啟動資料。其他停止失敗會保留後端清理錯誤並阻止替代程序啟動，因為舊程序可能仍持有 profile 狀態。

對於已確認的非正常收尾，兩類彈出視窗都將在地化恢復提示與可展開的技術詳情分開展示。詳情初始摺疊，不授予更新權限。診斷展示程序生命週期事實，而非可能包含憑證的任意外掛 stderr。強更彈出視窗在狀態未變時保留已展開的詳情，診斷改變或清除時則摺疊。

任務警告描述執行中的 agent、排隊輸入和執行中或停止中的後臺任務，而非請求流量。使用者批准安裝後，Host 拒絕新 API 請求，等待已接收請求結束，再檢查任務。這既保護已接收的寫操作，也不因頁面讀取彈出警告。超時或被替代的等待不能授權安裝；失敗後殼解除准入鎖。

產品預載入只發布語義化 updater 階段、版本、進度和失敗類別，不攜帶在地化字串或原始診斷。準備階段失敗攜帶型別化原因，原生與 Web 介面分別選用自身 locale 的提示，無需比較翻譯後的文案。帳戶行和側欄收起狀態透過目前 Web locale 解析這些資料，原生彈出視窗仍使用 Desktop 殼 locale。主動退出應用時，產品視窗會在 Host 收尾前隱藏，並在程序退出前忽略聚焦請求，避免把預期連線中斷展示成恢復操作。

## 考慮過的替代方案

**沒有閘道交接機制時使用系統瀏覽器。** 其 Cookie 不會與 Electron 請求共享。顯式啟用的測試部署改用沙箱 BrowserWindow 和獨立記憶體 Session，不啟用 Node 整合或預載入。文件導航只允許設定的 HTTPS 策略源站及已稽核的飛書源站；拒絕權限、下載、新視窗和 HTTP 授權驗證。閘道不需要新增 token 交換介面。這以跨重新啟動登入及不受限的身份提供者導航換取隔離。預設匿名協定及 updater 傳輸不變。

**在測試登入視窗停用 DevTools。** 這會阻止本地檢查第三方頁面，卻使授權驗證失敗難以排查。F12 是該視窗上的顯式本地操作；正常登入不會自動開啟 DevTools。

**將登入重定向完成視為更新決定。** Windows 閘道探針由未授權驗證的 401 變為應用層 422，關閉登入視窗後仍復用 Session。這驗證了同程序 Cookie 傳輸，並不證明與 Harness 策略 API 相容。用戶端在登入後重新檢查策略，授權驗證過期或回應畸形時保留已知阻塞，且從不使用閘道提供的登入 URL。每次登入視窗都先經過使用者確認。打包應用的首次啟動檢查可在本地後端就緒前說明授權驗證要求；之後的自動檢查保持靜默。說明、登入和重新檢查由同一個操作負責，使並行入口無法建立相互競爭的登入視窗。

**把策略可用作為常規更新回饋的前置條件。** 策略傳輸或協定失敗會壓制有效的 updater 結果，並使常規產物分發依賴強更服務。因此兩個檢查共用使用者觸發入口，但分別處理結果；只有已建立的強更狀態可以搶佔常規展示。

**等待業務 API 返回版本錯誤。** Desktop 業務流量在本地，因此遠端策略必須有獨立遊客請求。

**使用可取消的常規訊息框。** 它不負責持久下載進度、重試、頁面後備和策略重新整理。專用模態視窗保留這些操作，同時不允許取消強更要求。

**策略到達時終止任務。** 策略要求停止後續互動，而非正在執行的工作。安裝批准仍是停止受影響任務的獨立授權。

**讓策略選擇或作廢 updater 安裝檔。** 這會增加第二個產物權威，並違背已確認的高版本覆蓋策略。只有 updater 選擇和驗證其版本繫結的安裝檔。

**技術詳情僅保留在日誌中。** 彈出視窗內的摺疊詳情讓使用者無需查詢本地日誌即可排查停止失敗，同時保持預設恢復提示可讀。

**對每個在途 API 請求都彈出警告。** 啟動讀取會在沒有受影響任務時觸發中斷警告。將請求收尾與任務檢查分開，可避免這種誤報，也無需按 URL 分類 RPC 或丟棄未完成的寫操作。

**透過預載入傳遞在地化更新文案。** Desktop 殼 locale 可能不同於 Web 應用內選擇的語言，已傳遞的字串也無法回應之後的語言切換。語義化展示資料讓元件繼續擁有使用者所選 Web 語言下的文案。

**常規退出時保持產品視窗可見。** 先關閉自有 Host 會把預期斷開展示到連線恢復介面。收尾前隱藏視窗既保留程序正常清理，也不會為主動關閉展示重試操作。

## 後果

常規檢查和下載失敗將語言字典提供的摘要與可展開的 updater 診斷分離。懸停提示不含原始錯誤文字；下載懸停提示說明操作和目標版本。Web 更新狀態獨立於原生彈出視窗語言，跟隨應用內目前 locale。殼報告正在安裝時，更新狀態優先於連線回饋，因為停止自有後端是預期行為。安裝失敗會清除該優先順序，使真實重連保持可見。常規退出會在發生同一預期後端斷開前移除產品視窗。普通長診斷獨立於確認操作滾動；展開詳情不授予安裝權限。

[本地驗證](../testing/2026-09-10-desktop-local-updater-qualification.zh.md)執行真實 Electron 模態視窗、受限預載入、頁面按鈕處理、網路策略和 updater 下載。主入口迴歸驗證 Host 工作保留和業務控制拒絕。所屬測試目錄內的中文 DOM 預期輸出約束可見文案和操作。這些測試不證明生產 API 相容性、原生瀏覽器／剪貼簿整合、完整工作區視覺效果、簽名安裝或重新啟動後健康狀態；[驗證記錄](../../../../apps/desktop/tests/README.zh.md)列出尚缺證據。
