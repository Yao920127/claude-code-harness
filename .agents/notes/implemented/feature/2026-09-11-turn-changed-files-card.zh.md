# Agent Note: 本輪改動檔案卡片

Status: implemented

[English](2026-09-11-turn-changed-files-card.md) | 中文

## Problem

一輪結束後，使用者想看到模型改了哪些檔案、改了多少。Web 的輪尾只列出成功的 `write`、`edit` 與 `str_replace_editor` 呼叫的路徑，沒有行數，也漏掉所有 shell 命令改動的檔案；訊息流中逐呼叫的 diff 卡片只能一次回答一個呼叫。

## Decision

Host 側的 [workspace-changes](../../../../packages/deliverables/workspace-changes/README.zh.md) 外掛彙總每個頂層輪次改動的檔案，用只帶輪號的 `workspace/changes` Session 事件宣告，並透過 `workspaceChanges` 服務提供摘要直到 Session 釋放；[產出物外掛](../../../../packages/client/ui-deliverables/README.zh.md)讀取提供的摘要並渲染為改動檔案卡片，取代修改呼叫行。該事件僅寫日誌，模型永遠看不到。

記錄器在輪次開始和結束時用 git 對工作樹做快照：以儲存庫 index 為種子在私有 index 上執行 `add --all`，再執行 `write-tree`。兩者都寫入 Session 自己擁有的臨時物件目錄，儲存庫自己的物件庫以只讀 alternate 掛接，因此使用者儲存庫不會多出任何物件；把捕捉的每個位元組都放在工作區外學自工作區變更日誌 POC（#2973），而且因為 stat 快取在 index 裡，它對耗時沒有可測量的影響。兩個 tree id 用 `diff-tree -r -M --numstat` 比較，因此摘要恰好只包含本輪的改動——使用者此前未提交的工作，無論是否暫存，都屬於基線——模型在輪中做的提交也藏不住改動。儲存庫自己的 index、物件、工作樹和 ref 從不被修改。在一萬個檔案的儲存庫上，一次快照約 60 ms，比較約 10 ms；基線與首次模型請求並行，工具執行會等待它。

git 使用 `PATH` 上的預設可執行檔案，不詢問任何環境外掛。不在任何儲存庫內或沒有 git 時，不做快照，摘要只列檔案工具的編輯，並以工作目錄作為工作區，因此卡片仍會出現，但缺少 shell 的改動。巢狀儲存庫和 submodule 是 gitlink，不會深入。

快照覆蓋之外的改動來自整檔案捕捉：在 `write`、`edit` 或有修改作用的 `str_replace_editor` 呼叫執行之前，記錄器把所指檔案複製到 Session 的臨時目錄，每輪每個路徑一次，輪次結束時再複製一次；被忽略的檔案、工作樹之外的檔案，以及沒有快照時的每一次檔案工具編輯，都由兩份副本的逐行對比列出（[對比決定](2026-09-15-changed-file-diff-preview.zh.md)）。臨時目錄下的檔案被省略，除非它們位於工作目錄內；留在 `/tmp` 裡的檔案需要 `present` 才能到達使用者。覆蓋之外的 shell 編輯是已知限制。

列表按展示路徑的碼元順序排序：相對工作目錄的路徑，儲存庫內位於其上的檔案為 `../`，家目錄下為 `~`，其餘為絕對路徑；上級路徑與絕對路徑因此自然排在最前，不需要單獨分組。卡片標題顯示總數與增刪行數合計，摺疊前顯示三行，展開後底部有收起控制元件。每一行在右側 Sidebar 開啟本輪的 review tab 並選中該檔案，標題則在第一個檔案上開啟它（[review 決定](2026-09-15-changed-file-diff-preview.zh.md)）；Host 有桌面時，review tab 提供用預設應用開啟。

記錄器在 `agent/turn-stopping` 時於輪內追加事件，並且僅當最後一次記錄之後仍有工具結果結束時在 `turn/end` 後再次追加，因此中止、失敗和被轉向的輪次都被覆蓋。Client 保留每輪最新的宣告，並透過經過認證的摘要路由讀取一次摘要。

日誌有意只攜帶輪號。摘要、快照樹與捕捉的副本只在 Host 程序內隨 Session 存活：摘要在記錄器裡，物件和副本在釋放時刪除的臨時目錄裡。Host 重新啟動後重新開啟的對話，先前輪次沒有卡片。產品上的決定是，Host 已經打不開內容的卡片根本不該出現，所以卡片的壽命等於內容的壽命，而不是日誌的壽命。內容不跨重新啟動保留（[對比決定](2026-09-15-changed-file-diff-preview.zh.md)）。

## Alternatives considered

**給修改呼叫行補上 hunk 計數**會在逐呼叫 diff 卡片旁保留第二個更弱的實作，且仍然漏掉 shell 編輯；git 不管工具是什麼都能看到每次寫入。

**輪末直接與 `HEAD` 比較**只需一條命令，但會把使用者未提交的工作算到本輪。

**每輪打一個 git tag 或 `stash create`**會在使用者儲存庫裡留下 ref，或者遺漏未跟蹤檔案；透過私有 index 寫出的樹兩者都不會發生。

**為沒有 git 的主機引入純 JavaScript 的 git 或捆綁二進位制**會為大多數不使用卡片的使用者增加數 MB 體積和一套平臺矩陣；在 git 出現之前卡片只列檔案工具的編輯。

**累加檔案工具持久化的 hunk** 是未覆蓋檔案的第一版實作；它會把反覆編輯的行計算多次，也給不出整檔案對比，因此記錄器改為在首次觸碰時複製整個檔案（[對比決定](2026-09-15-changed-file-diff-preview.zh.md)）。

**把檔案列表和行數記進事件**是第一版實作：卡片從此可以永遠從日誌渲染，而它開啟的內容卻活不了那麼久。它被只做宣告的事件取代，讓卡片和內容共用一個壽命。

**Harness home 下帶位元組上限的快照物件庫**是第一版實作的放置方式：每個儲存庫一個、所有 Session 共用、超過上限就丟棄。它能活過 Host 重新啟動，而摘要已經不再需要這一點；它還需要兩個設定欄位，並且一個 Session 丟棄物件庫會讓另一個 Session 的快照失敗。每個 Session 一個臨時目錄把這三點一起去掉。

**用於定位 git 的環境提供者接縫**由團隊提出但尚未定案；外掛使用 `PATH` 並把查詢收斂在一處。

**為不在任何儲存庫內的工作目錄建影子儲存庫**，即把 git 目錄放在 Harness home 下、工作樹指向工作目錄，可以讓這些使用者在不多出 `.git` 的情況下也看到 shell 改動，但影子儲存庫沒有 `.gitignore`，一份設定的排除列表無法在所有專案佈局裡可靠地擋住建置產物、快取和依賴目錄。它暫緩到排除策略定下來為止；記錄器已經把儲存庫當作輸入，加這一檔只改變快照寫到哪裡。

## Consequences

每個有工具結果的輪次在 Host 上花費兩次快照和一次比較，並把改動檔案的 blob 與 tree 物件寫入 Session 的臨時目錄，釋放時一併刪除。使用者在輪次進行中的編輯會被算到該輪。每次檔案工具編輯還會把整個檔案複製進該目錄，每輪一次。

只有 Web bundle 掛載記錄器，因此 headless、SDK 與 ACP 日誌不變；錄製的 Web 情境只要某一輪改動了檔案就會新增該事件與卡片；一個專門的情境種入 git 儲存庫，讓卡片也帶上 shell 的改動，其餘情境只列它們的檔案工具寫入。卡片取代了中英文的“本輪檔案改動”行；正文件案提及仍按修改呼叫路徑與交付解析。

聚焦測試用真實 git 覆蓋儲存庫、不在任何儲存庫內的目錄、對已捕捉路徑的覆蓋範圍分類、被下一輪壓上的中斷輪次、排序、上限、釋放、macOS 樁程式、改動檔案路由、卡片的摺疊與手勢狀態，以及一次 Loader 組合。無金鑰的 Web 情境端到端回放記錄器，其中包括一個被儲存庫忽略的新建檔案。
