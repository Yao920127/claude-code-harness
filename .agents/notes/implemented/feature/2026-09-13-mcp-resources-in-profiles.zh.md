# Agent Note: MCP 資源可用性取決於已設定伺服器

Status: implemented

[English](2026-09-13-mcp-resources-in-profiles.md) | 中文

## 問題

未設定 MCP 伺服器的工作階段不需要資源 schema 或 MCP 指引。要求單獨的資源服務條目，也讓使用者在設定每個連線之外還要設定共享資源存取。由首臺伺服器擁有的共享工具集可能隨該伺服器解除安裝而消失，即使其他伺服器仍需要它。

## 決策

每個隨附 profile 統一掛載 `mcp-resources` 一次：包括 Desktop 在內的基於 base 的 profile 從 `dsh-base` 繼承該行；獨立的 `sdk-minimal` 擁有自己的行。使用者只需設定 `mcp-client` 條目。預設不啟用任何 MCP 伺服器。

資源服務使用呼叫方作用域中的已設定提供者註冊，包括由其他提供者掛載的 MCP 用戶端。可見註冊表為空時，不貢獻資源提示詞、native 工具 schema、PTC 宣告或 PTC 繫結。作用域中的首個提供者啟用共享工具；移除最後一個提供者時移除這些本地註冊，同時保留繼承的提供者與工具。資源服務獨立於任何伺服器外掛擁有共享工具 effect。

連線健康狀態不決定這些內容的可見性。啟用的用戶端在請求失敗或重連嘗試期間仍屬於已設定狀態；共享資源工具與伺服器名稱指引保持可用，呼叫會報告連線失敗。伺服器指令保留由連線擁有的釋出規則。

本決策部分取代[資源與指令決策](2026-09-12-mcp-resources-and-instructions.zh.md)中單獨啟用資源服務的掛載方式。該筆記保留操作、作用域選擇、規範結果、二進位制渲染及已記錄指令的設計依據。

## 考慮過的替代方案

**保留單獨的資源掛載。** 這會讓共享能力成為第二項使用者設定任務，並允許隨附 profile 使用不同預設值。

**沒有伺服器時仍顯示資源工具。** 這會向普通工作階段增加不可用操作與提示詞 token，包括預設僅有一個 shell 的極簡 SDK。

**按協商出的資源能力過濾提供者。** 這能省略未宣告資源的伺服器對應的資源指引，但會讓可見性取決於成功的能力交換。已設定用戶端策略對直接設定和由提供者掛載的用戶端使用同一標準，包括首次成功連線前與恢復期間。

**由首臺伺服器外掛擁有共享工具。** 釋放該伺服器可能移除其他已設定伺服器仍需要的工具，因此由服務擁有這些工具的生命週期。

## 驗證

[資源測試](../../../../packages/mcp/mcp-resources/tests/resources.spec.ts)覆蓋空 native 與 PTC 檢視、作用域繼承、首個與最後一個提供者的變化、釋放，以及已設定提供者呼叫失敗。[真實 SDK 測試](../../../../packages/mcp/mcp-client/tests/protocol.spec.ts)固定了只提供工具的伺服器返回空發現結果，以及不受支援的讀取報錯。[Profile 組合測試](../../../../apps/cli/tests/profile-mcp.spec.ts)解析每個隨附 CLI 範本；[Desktop 組合測試](../../../../apps/desktop/tests/profile-mcp.spec.ts)包含其 profile 與 Host overlay。空 native 與 PTC 錄製工作階段使用隨附 headless 組合，不新增資源條目。

## 後果

空 MCP 設定不增加 MCP 提示詞或工具 token。不具備資源能力的已設定伺服器仍貢獻名稱與共享資源 schema。SDK 返回空的發現列表；不受支援的讀取會失敗。新增首個可見伺服器或移除最後一個伺服器，會改變後續提示詞與工具組裝。極簡 SDK 在使用者新增 MCP 伺服器前只公佈一個 shell。資源讀取仍按需進行，無需更改連線或持久 Session 格式。
