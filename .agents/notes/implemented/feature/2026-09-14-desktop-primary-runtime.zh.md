# Agent Note: Desktop 第一方 Runtime

Status: implemented

[English](2026-09-14-desktop-primary-runtime.md) | 中文

## Problem

Desktop 代理需要在沒有開發環境的機器上獲得確定的 Python 資料處理庫和獨立 Node 直譯器。系統直譯器的選擇必須繼續由使用者控制。

## Decision

Desktop 將 Python、Node.js、pnpm、資料處理庫和 Office 創作庫作為繫結應用版本的產物交付。路徑查詢工具從應用資源將產物安裝到 Harness home 下的固定目錄，並返回絕對路徑與內建 Python 分發包版本。版本報告不包含使用者自行新增的包。它不修改 PATH、環境變數或包管理器設定。pnpm 使用原生全域安裝規則。

應用版本、頂層直譯器和包管理器版本、Python 分發包版本表和鎖定輸入摘要記錄在 `runtime.json` 中，不放在目錄名裡。摘要涵蓋所選目標的直譯器與 wheel 壓縮包、共享 wheel 輸入、Python 分發包版本、pnpm 版本和組裝格式；其他目標不會使其失效。所選目標、wheel 記錄及分發包對映內部的鍵順序，以及 wheel 條目順序參與該身份計算；鎖檔案頂層鍵的順序不參與。解壓或組裝邏輯在鎖定輸入不變時改變產物位元組，必須顯式提升格式版本。安裝釋出完整的暫存副本，並在替換成功前保留之前的目錄。相同產物複用已安裝檔案；替換也會移除受管目錄內使用者新增的 Python 依賴。不含摘要的舊清單仍可讀取，並與目前產物區分。分發包名稱按 PEP 503 歸一化，歸一化後重復的名稱會被拒絕。讀取器歸一化舊 `components` 檔案並保留其 numpy/pandas 一致性驗證；目前清單僅在分發包版本表中記錄 Python 庫。Desktop 單實例所有者和工具共享的安裝 Promise 序列處理正常安裝請求。

共享 Node 建置入口下載並驗證完整鎖定 wheel 集的雜湊，將庫檔案解壓到 site-packages。這避免選擇建置主機的 Python 和 pip 版本，也無需實作依賴解析或通用 wheel 安裝。XlsxWriter 的 VBA 提取腳本等輔助腳本保留在 wheel 的 `.data/scripts` 目錄中；命令列入口包裝器不屬於該庫產物。其他 `.data` 安裝方案會被拒絕。本機 smoke 在臨時檔案刪除後執行最終產物，檢查精確鎖定的分發包集合與內建 pip、Python 與固定 wheel 版本、依賴完整性及可編輯 Office 文件的寫入和讀取，因此直譯器連結必須在遷移後仍有效。Smoke 檢查停用位元組碼寫入，避免把驗證產物納入分發內容。

macOS 僅向獨立 Node 可執行檔案授予 `com.apple.security.cs.allow-jit`。缺少此權限的強化執行時簽名會阻止 V8 分配程式碼區域。直譯器和庫的 smoke 檢查在簽名後以及暫存清理後執行；簽名有效本身不能證明程式可執行。

Windows 簽名打包透過受監督的簽名階段覆蓋第一方執行時和應用生產依賴，將檔案準備與執行分開。PE 檢查獨立於副檔名識別檔案內容，排除其他平臺的非 PE Node 原生外掛，並拒絕目錄連結。公鑰驗籤每個程序處理最多 32 個檔案，同時最多執行四個程序，返回失敗前等待目前批次全部結束；硬體操作仍序列執行。有效的上游簽名保持不變；僅未簽名檔案使用設定的 EV 憑證籤名。已有簽名無效時，在存取硬體前失敗；每個新簽名透過有效性、時間戳和憑證身份檢查後，才處理下一個檔案。electron-builder 複製階段的簽名掛鉤僅在逐位元組比對和驗籤透過後保留執行時可執行檔案；保留驗證失敗時，同一序列佇列拒絕後續任務。硬體呼叫複用現有的使用者級互鎖、序列簽名器和脫敏日誌；硬體失敗不允許重試或繼續後續階段。公開時間戳嘗試遵循[簽名完成規則](../process/2026-09-17-windows-signature-completion.zh.md)。執行時執行不接收簽名憑證，並在完整驗籤後進行。開發和未簽名準備保留本機 smoke，不自動存取硬體。執行時清單記錄簽名後的位元組。electron-builder 將檢測到的依賴 PE 檔案放在歸檔外，並保留已簽名的副本。釋出完成前，最終簽名檢查以及 ASAR 載荷和 Host 冒煙檢查使用私有原生快取。

Desktop ZIP 解壓透過定向依賴覆蓋為 `extract-zip` 固定 `yauzl` 3.4.0。2.x 讀取器在 Node 26 上可能無法完成較大 deflate 條目的讀取（[上游問題](https://github.com/thejoshwolfe/yauzl/issues/176)）；保留現有解壓器可保留其路徑總和檢查碼 wheel 條目檢查。開發啟動器使用頂層 await，避免準備未完成卻成功退出。大壓縮 wheel 迴歸測試檢查完整的解壓位元組。

[共享執行時決策](../architecture/2026-09-17-shared-office-runtime.zh.md)持有 Desktop 與 SDK 載體的建置器、鎖檔案和查詢包歸屬，覆蓋 GNU/Linux x64 與 Python-only payload。Desktop 保留本文的安裝與簽名行為，並要求完整的 Python、Node.js 和 pnpm payload。

## Alternatives considered

**只使用系統直譯器。** 無法保證可用性或預裝 numpy 和 pandas。

**注入 PATH 並指定 pnpm 全域目錄。** 這些方式會改變命令選擇，或要求 pnpm 全域命令目錄已在 PATH 中。絕對直譯器路徑和 pnpm 原生行為無需這些改動即可滿足請求範圍。

**獨立更新和版本目錄。** Runtime 釋出與 Desktop 繫結，且請求的安裝位置固定。

**多檔案 SignTool 請求。** 軟體憑證探針在第一個檔案不存在時，仍會先給第二個檔案簽名，再返回錯誤。單個程序無法保證首個失敗後停止硬體操作；權杖簽名仍按每個受監督請求處理一個檔案。

**僅簽名直譯器或跳過本機 smoke。** Windows 程式碼完整性也檢查 DLL 和 Python 擴充功能。啟動程式有簽名不能讓未簽名擴充功能被載入，跳過執行會隱藏安裝後不可用的依賴。保留有效上游簽名既減少硬體操作，也保留上游歸屬資訊。

依賴清單在記錄完整性清單前使用 electron-builder 自身的清理邏輯。否則其歸檔寫入器會在簽名後修改包中繼資料；提前應用該轉換可讓最終歸檔透過驗證，無需在打包後替換已封裝的完整性清單。

## Consequences

應用攜帶額外的原生檔案，並在升級時替換完整受管產物。Windows 上執行中的直譯器可能阻止替換。本機建置 smoke、安裝與複用及恢復測試、無金鑰工具錯誤工作階段分別覆蓋安裝和模型輸出路徑；macOS 簽名複用現有原生 Runtime 簽名器。直譯器壓縮包和 Python wheel 固定雜湊，許可證隨各分發包保留。
