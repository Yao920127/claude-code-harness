# Agent Note: Two-hour reclamation of unattended browser terminals

Status: implemented

[English](2026-09-14-unattended-browser-terminal-reclamation.md) | 中文

## 問題

瀏覽器可能在沒有關閉終端標籤頁的情況下消失。如果始終保留無人使用的終端，shell、後代程序和螢幕緩衝區會無限期佔用資源。輸出訂閱不能代表是否遺棄：隱藏標籤和非目前 Session 合理地停止跟隨螢幕。

## 決策

只有沒有任何視窗持有終端，並且 Host 持續確認空閒滿兩小時，才回收瀏覽器終端。執行中的工作和未知活動都會取消空閒截止時間。工作完成後重新給予完整寬限期；命令執行時長和無輸出時間都不是截止條件。明確關閉標籤，以及 Session 或 Host 解除安裝，仍有權終止工作。

| 情況 | 行為 |
|---|---|
| 已連線視窗持有標籤，包括側欄摺疊或非目前 Session | 保留終端。 |
| 多個持有視窗中的一個消失 | 只要還有其他視窗持有，就繼續保留。 |
| 最後一個視窗消失時，命令仍在執行、停止、等待輸入或後臺執行 | 保留工作，不限制執行時長。 |
| 無視窗持有，且明確確認終端空閒 | 開始完整寬限期，清理前再次檢查。 |
| 視窗在清理前返回 | 重連原程序，取消回收。 |
| 儲存的程序已經不存在 | 保留標籤，顯示在地化的不可用提示和“新建終端”。只有明確點選後，才在原位置用全新身份替換。 |

例如，視窗在 14:00 斷開，而命令持續到 20:00，則最早也不能在 22:00 前回收。期限從之後第一次確認空閒的觀察開始計算。

[側欄](../../../../packages/client/ui-sidebar-right/README.zh.md#state) 按 Session 持久化佈局，並透過 `openTabs` 釋出已儲存和已採用 Session 的標籤中繼資料。啟動發現不會掛載非目前內容、pin 檔案或啟用 Agent。視窗內以已採用的 store 為準；其他視窗對 storage 的寫入不能撤銷目前視窗的活動持有關係。永久刪除 scope 時移除相應中繼資料。

終端 provider 將該清單與自己儲存的終端關聯及未完成的關閉請求取交集。每個視窗為每個不同終端使用一條 `retain(sessionId, id, signal)` Remote 流。確認幀授予持有關係，不傳送螢幕輸出、不啟用 Agent、不接管輸入，也不建立程序。恢復輸出前等待目前持有關係確認。傳輸代次獨立取消，傳輸存活由現有 Gateway 重連和心跳機制負責。

subprocess 能力介面提供帶狀態和 revision 的 `inspectActivity()`。普通非登入的 Bash 4.4+ 和 Zsh 支援顯式啟用生命週期記錄，並結合完整程序表觀察和原始程序身份。Zsh 區分空的頂層編輯提示符與 `vared`、選擇及續行輸入。輸入使提示符證據失效；後臺和停止的後代阻止空閒判斷。原生 Linux 還檢查 systemd task 數，保護脫離程序樹但仍在自有 scope 中的後代。自定義 trap、Zsh 非同步檔案描述符 handler、不支援的啟動方式和不完整觀察保持 unknown。生命週期檔案為私有檔案，在清理成功後刪除。

Host [終端控制器](../../../../packages/api/terminal-controller/README.zh.md#use-this-package) 管理可設定的 `unattendedTimeoutMs`（7200000）、`activityPollIntervalMs`（30000）和 `cleanupRetryMs`（60000）。零隻停用自動回收。控制器使用單調時鐘；觀察間隔超過輪詢週期兩倍時，舊證據失效並重置寬限期。輸入和持有關係變化會使正在進行的觀察失效。最終檢查透過後，在非同步終止前將身份標記為關閉，阻止遲到的建立和連線。已關閉身份不能複用，每個清理任務始終屬於原來的 Session owner。

清理等待 provider 範圍完全停穩和最終螢幕輸出排空。失敗時保留所有權、拒絕新持有關係，並安排一次重試，不重新給予空閒寬限期。分配失敗後的清理採用相同重試策略。owner 解除安裝會停止計時器和流，在清理與觀察都結束後才報告失敗，包括清理早於觀察結束而拒絕的情況。Agent 終端工具、模型輸入和 Session 事件均不改變。

Codex 執行緒解除安裝、OpenCode Location scope 和 [VS Code PTY 寬限期](https://github.com/microsoft/vscode/blob/main/src/vs/platform/terminal/node/ptyService.ts) 的調研支援了獨立引用和延遲清理的設計。兩小時是 DSH 的產品策略，不是行業預設值。[瀏覽器終端決策](2026-09-09-web-sidebar-terminal.zh.md) 與[佈局／provider 恢復決策](../architecture/2026-09-14-sidebar-layout-provider-recovery.zh.md) 繼續有效，因為其資源所有權和持久化職責劃分仍然適用。

## 考慮過的替代方案

**統計輸出訂閱者。** 切換標籤或 Session 會停止輸出訂閱，但並未放棄對應終端。視窗持有關係改為追蹤佈局中開啟的標籤。

**斷開滿兩小時就殺掉所有終端。** 固定截止時間會殺掉合理的長命令。因此執行中和未知狀態的工作沒有自動最長執行時間。

**根據靜默、低 CPU 或前臺身份推斷空閒。** 靜默建置、休眠任務、shell 內建命令及等待輸入的命令都可能滿足這些條件卻尚未完成。必須同時具有正面的生命週期證據和自有任務觀察。

**只恢復可見 Session，或保留每個儲存的關聯。** 前者在重新整理後丟失非目前 Session 的持有關係；後者讓過時關聯保活無人使用的程序。佈局與 provider 的交集才代表該視窗實際開啟的標籤。

## 結果與代價

無人使用的空閒終端具有保留期限，而已連線視窗和長任務能跨重新整理及呈現變化繼續存在。執行中、掛起或長期提供服務的命令可能無限期保留；不支援的 shell 和不確定的程序觀察也是如此。仍可明確關閉。PowerShell、fish、Windows、自定義 shell 參數以及經過 sandbox 包裝的啟動目前返回 unknown。

根 shell 退出不授予終止後代的權限。Linux 程序列舉失敗表示觀察不可用，而不是程序範圍為空；活動保持 unknown，清理保留所有權。明確為空的原生 Linux 範圍和完整且為空的 Linux 工作階段允許清理已退出記錄。macOS 無法在根程序退出後確認未觀察到的範圍，可能保留記錄直到明確關閉或 owner 解除安裝。provider 對已逃逸且未觀察到的後代的限制仍然存在；生命週期記錄不是用於防禦同一使用者惡意程序的安全螢幕障。

瀏覽器 storage 失敗時，目前記憶體狀態仍可使用，但不能保證重新整理後恢復非目前 Session。Host 重新啟動不能恢復 PTY。螢幕歷史和每個 Session 的終端配額保持原有上限，不新增無限增長的到期原因快取。

虛擬時鐘測試覆蓋截止時間、重連競爭、觀察失效和清理重試。真實 PTY 測試覆蓋靜默命令、內建命令、後臺和停止任務、Zsh 編輯模式、啟動檔案及 trap。瀏覽器測試覆蓋持久化佈局、多視窗、摺疊後重新整理、傳輸中斷、保留的程序身份、明確操作後替換失效標籤，以及傳輸中斷後重連原程序。無需金鑰的已記錄 Session 情境驗證檔案預覽佈局恢復。
