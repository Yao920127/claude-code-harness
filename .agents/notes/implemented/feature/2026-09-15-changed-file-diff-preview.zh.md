# Agent Note: 輪次 review tab

Status: implemented

[English](2026-09-15-changed-file-diff-preview.md) | 中文

## Problem

[改動檔案卡片](2026-09-11-turn-changed-files-card.zh.md)告訴使用者一輪改了哪些檔案、改了多少行，但沒說改了什麼。點一行開啟的是檔案目前內容，在 Sidebar 裡或在桌面應用裡，既看不到本輪的編輯，也看不到編輯前的狀態。git 覆蓋不到的檔案——被忽略的檔案、儲存庫之外的檔案，以及沒有儲存庫的工作目錄裡的每一次檔案工具編輯——只有檔案工具隨結果持久化的 hunk：上下文不完整，行數按重複編輯累加，完全沒有整檔案對比。

## Decision

卡片的每一行在右側 Sidebar 開啟本輪的 `changes-review` tab 並選中該檔案，卡片頭部則在第一個檔案上開啟它：每輪一個 tab，由目前檢視的 Session 和宣告事件的序號定址，頭部有一個列出所有記錄檔案的檔案選擇器，一次顯示一個檔案在輪次開始與結束時的對比。Host 側的 [workspace-changes](../../../../packages/deliverables/workspace-changes/README.zh.md) 記錄器透過 `workspaceChanges.diff(sessionId, seq, index, signal)` 提供每個對比；[產出物外掛](../../../../packages/client/ui-deliverables/README.zh.md)註冊該 tab 型別，把行的檔案下標作為導航參數傳入，並透過經過認證的路由讀取摘要和對比。頭部的工具在單欄和左右檢視之間切換、切換自動換行、在 Sidebar 中開啟目前整個檔案，有 Host 桌面時用預設應用開啟它；檢視與換行的選擇按 tab 保留。有沒有桌面，行和頭部都開啟 review，先前行級別的原生開啟和頭部的開啟資料夾都移進 tab，卡片只保留一種行為。

git 覆蓋不到的檔案按 Codex 的 turn diff tracker 對比其 `apply_patch` 編輯的方式對比：用整檔案副本，不用 hunk。在 `write`、`edit` 或有修改作用的 `str_replace_editor` 呼叫執行之前，記錄器本來就要等待基線快照的 `tools/pre-execute` 步驟把所指檔案複製到 Session 臨時目錄裡快照物件旁邊，每輪每個路徑一次；輪次結束時再複製一次該路徑。副本按其位元組的 SHA-1 命名，相同內容只存一份，且不需要 git。快照覆蓋到的路徑保留 git 的行數；其餘每個被捕捉的路徑由兩份副本的逐行對比列出，反覆編輯的行只計一次，檔案工具編輯之後的 shell 改動也包含在內。記錄器不再讀取持久化的 hunk 和由參數推出的 hunk。

兩個上限讓副本和對比保持小。`maxFileBytes` 限制副本和為對比而讀出的快照 blob；更大的檔案列出時帶 `oversized`，沒有行數，其對比被拒絕，整檔案副本因此負擔得起。`diffTimeoutMs` 限制逐行對比，與 Codex 一樣是 100 毫秒；超時後退化為一個替換全部行的 hunk，標記 `coarse`，因此病態的檔案從不會拖住本輪記錄或 tab。兩者都是 Config 欄位。

對比在被請求時在 Host 上計算，來源是儲存在所提供摘要旁邊的兩側內容來源：快照樹中的路徑，用 `ls-tree -l` 和 `cat-file blob` 在位元組上限之內讀出；或者從磁碟讀取的副本。git 報告為二進位制的快照一側和含 NUL 位元組的副本不提供行。tab 渲染帶舊新行號的 hunk，沒有語法高亮；左右檢視把每一段刪除與緊隨其後的新增逐行配對。Host 已不再提供的對比、讀取失敗、二進位制檔案和過大的檔案各顯示一行。

內容仍然只在本 Host 程序內隨 Session 存活，這是卡片決定已經定下的；對比與卡片同壽命，因此 Host 重新啟動後重新開啟的對話兩者都沒有。

## Alternatives considered

**把整檔案的前後文字放進檔案工具的結果中繼資料**，像 Codex 的 `apply_patch` 返回的那樣，會把每個被編輯的檔案兩次寫進 Session 日誌。記錄器改為自己捕捉檔案，日誌繼續只攜帶輪號。

**把副本存在記憶體裡**，像 Codex 的每輪 tracker 那樣，會隨每一輪增長，因為記錄要活到 Session 結束；副本放到 Session 臨時目錄裡快照物件旁邊，只在請求對比時讀取。

**把副本存為私有物件庫裡的 git blob** 能和快照共用一條讀取路徑，但會讓檔案工具這條路徑依賴 git，而沒有儲存庫或沒有 git 的工作目錄給不了它；同一目錄下的普通檔案讓這條路徑與 git 無關。

**給儲存庫之外的工作目錄建影子儲存庫**仍然推遲；副本已經覆蓋那裡的檔案工具編輯，這是使用者能採取行動的部分。

**每個檔案一個 tab**、以檔名作標題，是第一版實作；審閱一輪意味著每行一個 tab。每輪一個 tab 加檔案選擇器把一輪的改動放在一起，行仍然能落到自己的檔案上。

**tab 裡的語法高亮**推遲到純文字檢視被證明不夠用時再做。

**保留行開啟目前檔案**會讓對比多一次點選才能到達；目前檔案仍可從正文連結和檔案 tab 開啟。

## Consequences

每次檔案工具編輯在 Host 上每輪讀寫一次整個檔案，受 `maxFileBytes` 限制，即使快照也覆蓋該路徑；Session 的臨時目錄儲存副本直到釋放。未覆蓋檔案的對比行數是首尾對比，不是累加；兩側都超過上限的檔案列為 `oversized` 而不是丟掉，因為沒讀過的內容永遠不能認定為沒有改動。一次對比最多花費兩次 `ls-tree`、兩次 `cat-file` 和一次有界的逐行對比；超時的對比攜帶兩側的全部行，最多兩倍 `maxFileBytes`，tab 最多繪製其中 5000 行。對比路由會把所列檔案在 Host 上記錄時的完整文字送到瀏覽器，包括被忽略的檔案、工作目錄之上的儲存庫檔案和工作區外的檔案，而摘要路由只送路徑和行數，Sidebar 的檔案預覽也限定在工作區根目錄之內；這些編輯是使用者授權的，因此接受這一點，並記入兩個 README。

`WorkspaceChangedFile` 型別新增 `oversized`，`WorkspaceChanges` 新增 `diff`，兩個提供給用戶端的型別 `WorkspaceDiffHunk` 和 `WorkspaceFileDiff` 加入子系統頁面。Session 日誌不變。改動檔案卡片的行在兩種語言裡都標為開啟該檔案的改動，因此錄製的 Web 情境的黃金檔案變了；同一情境現在會從快照開啟一個 shell 追加過的檔案的對比，從副本開啟一個被忽略檔案的對比。

聚焦測試覆蓋整檔案捕捉的分類、超時退化、從快照樹提供的對比、改名、刪除的檔案、過大的 blob 和副本、對比路由、tab 的地址、store 與各狀態，以及卡片行的接線。
