# Agent Note: 共享的可續接 Activation 容量

Status: implemented

[English](2026-09-15-continuable-activation-capacity.md) | 中文

## Problem

深度限制約束巢狀層數，但仍允許大量並行委派。後臺 Job 限制不覆蓋可續接子代理，而生命週期累計建立配額會在早期子代理完成後阻止有用的後續工作。

## Decision

Subagent 服務透過 `maxActiveSubagents` 設定容量，預設值為 8。每個存活的非可續接父代理擁有一個程序內池，透過連續的可續接父子關係按引用共享。池的所有者自身不計入。一次性執行和外部提供者工作不進入此池。一次性中間父代理為其可續接子代理建立獨立的池；跨一次性代理的容量池繼承暫不實作。委派深度仍獨立設定。

Activation registry 在新建或冷恢復重建首次讓出執行前預佔唯一名額。在 Activation 接管名額前，由 materialization 負責復原；未釋出復原和失敗的 materialization 可以安全地釋放同一個 token。handle 釋放先於名額歸還，名額歸還先於父代理完成通知。向已有 Activation 傳送訊息複用其名額。

池查詢、接納和釋放的攤還時間複雜度均為常數。根代理的弱引用對映不會保留已結束的根 Agent；每個池只持有已佔用的 token。不增加 Session 目錄掃描、樹遍歷、持久計數器或公開的容量查詢 API。

Host 在組合設定之上註冊 `subagent` 設定分節。每次預佔讀取目前容量，因此調低上限不會驅逐駐留子代理，也不會重建註冊表。委派工具在每次嘗試時從同一分節解析省略的深度；顯式數值和 provider-managed 工具策略保留優先順序。GUI 暫存兩個數值，並透過現有的 revision 驗證設定路徑分別恢復組合預設值。池持有計數、設定持有策略，避免增加第二份線上計數或因設定變更而觸發拆除。

## Alternatives considered

累計子代理計數是另一種成本策略，不會在有用工作完成後釋放容量。只統計模型請求會遺漏等待後代的父代理、收件箱排隊內容、重建和清理，這些階段都佔用資源。掃描駐留和待建立對映會增加與無關存活任務樹數量成正比的工作。獨立計數器需要與名額所有權同步。

當所有名額都屬於等待後代的父代理時，等待容量可能造成死鎖。池滿時返回可操作診斷，不保留排隊的啟用請求。

## Consequences

有待處理收件箱內容或所擁有後代的空閒 Activation 仍佔名額。容量耗盡時，即使歷史子代理存在，冷恢復也可能失敗；瀏覽器訊息將其報告為 `subagent/delivery-unavailable`。名額不構成 token 或累計費用預算，也不協調多個 Harness 程序。

[可續接生命週期決策](2026-07-28-continuable-subagent-conversations.zh.md) 仍負責完成判定和先子後父的清理。本容量策略擴充功能該生命週期，不修改持久 Session 資料。

## Verification

聚焦的續接測試覆蓋預設值、非法設定、多層共享容量、根代理隔離、待完成建立、失敗歸還、冷恢復、駐留訊息和釋放。免密 SDK profile 快照記錄後臺建立成功，以及首個子代理仍存活時再次建立所產生的超限工具診斷。
