# Agent Note: Markdown 檔案預覽連結

Status: implemented

[English](2026-09-15-markdown-file-preview-links.md) | 中文

## Problem

Assistant 講解會連結到本輪未修改或交付的現有原始碼檔案。若僅允許產出檔案提及成為可點選引用，讀者就無法在回答旁開啟這些原始碼。

## Decision

落定後的 Assistant Markdown 透過 `MarkdownDelegateProvider` 將顯式本地連結目標傳給 Chat 檔案開啟器。Provider 同時擁有檔案及 HTTP(S) 導航回呼；內部連結元件讀取其目前回呼，中間渲染器無需增加導航 props。渲染器識別絕對路徑和工作區相對路徑，對百分號轉義解碼一次，並將 `#L24` 或 `#L24-L30` 分離為起始行導航請求。檔案控制元件保留原始標籤並顯示檔案類別圖示，絕不讓瀏覽器導航到原始路徑。

現有[側欄導航](../architecture/2026-09-05-sidebar-tab-types-and-navigation.zh.md)負責 Session 定址、標籤複用及預覽選擇。Host 檔案服務保留存取檢查和檔案缺失錯誤。行內程式碼的產出檔案匹配保持獨立。外部 URL 保留協定允許列表；查詢串、僅有片段的目標、不支援的片段、錯誤轉義及無效行號範圍均不可點選。

Web 檔案引用提示詞要求連結命令、設定表示式和程式碼塊以外的每次現有檔案提及，包括重複提及和表格。名稱預設使用 basename 或清楚的別名，僅新增消除歧義所需的父目錄。精確標籤使用 `filename:24` 或 `filename:24–30`，目標仍使用解析器支援的 `#L24` 或 `#L24-L30` 語法。渲染器保留模型原文，不透過重寫標籤強制滿足提示詞。

## Alternatives considered

**相對瀏覽器連結。** 這會跳轉應用 URL，而非請求 Session 檔案內容。

**要求產出檔案條目。** 這會排除普通只讀講解。

**增加預覽服務。** Chat 已提供所需開啟器和行號參數。

**透過渲染器 props 逐層傳遞導航回呼。** 每種新增導航能力都會擴大無關的中間介面。連結元件讀取作用域內的 delegate，也讓快取的 Markdown 能回應回呼變化。

**檔名優先或僅規範顯示的提示詞。** 三版開發對照中 A 的逐次引用連結覆蓋率較高，使用者也更偏好其輸出。B 完全沒有漏鏈的回答更多，因此這些觀察不能證明某版普遍更優。使用者選擇熟悉的冒號格式，放棄顯示 `#L` 字尾；目標保留錨點語法以維持現有導航。

## Consequences

原始碼引用無需新增 Session 事件。靜態 Web 指導透過現有系統訊息機制記錄。連結在訊息落定後可用。範圍定位到起始行；預覽不會高亮多行選區。單元測試覆蓋目標解析、共享的檔案與 HTTP(S) 路由、巢狀作用域及回呼替換或移除；無金鑰的 `markdown-file-links` Web 快照透過正式組合覆蓋檔案內容、冒號標籤、行號導航和標籤複用。包測試驗證每份 Web 提示詞 sidecar 中的指導。
