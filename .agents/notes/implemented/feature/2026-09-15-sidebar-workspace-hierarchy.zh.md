# Agent Note: 側欄工作區層級

Status: implemented

[English](2026-09-15-sidebar-workspace-hierarchy.md) | 中文

## 問題

許多目錄共享同一父目錄時，平鋪的 Workspace 列表不便瀏覽相關專案。若讓父目錄擁有所有後代 Session，則會違背 Workspace 成員 Session 的規範工作目錄必須等於註冊路徑這一要求。

## 決策

側欄預設將 Workspace 顯示為同級分組。在**檢視選項 → 分組方式**中選擇**按工作區樹**後，側欄從已註冊的 Workspace 路徑派生遞迴層級。所選模式儲存在現有的瀏覽器本地檢視儲存中。每個 Workspace 位於最近的嚴格祖先下；相同路徑不會成為自己的父級。比較遵循目錄分隔符和 Host 的大小寫拼寫，不解析符號連結別名。同級專案保留 Host 順序。

新增目錄會直接註冊普通 Workspace 並開啟其 Session。父 Workspace 保留自己的 Session 和標準行操作，子 Workspace 位於父級自己的 Session 之前。現有的瀏覽器本地展開狀態同時控制子 Workspace 和父級自己的 Session 行；沒有顯式偏好時，祖先預設展開。顯式摺疊也會隱藏目前 Session，但祖先資料夾圖示會標識它所在的子樹。所有行的高亮與點選區域等寬，內容按層級縮排。Workspace 拖拽限制在同級之間；後代落點交給最近的相容祖先，同級位置未變時不寫入 Host 順序，搜尋導航會展開全部祖先。

## 考慮過的替代方案

**預設採用樹形分組：**這會把專案隱藏在祖先之下，即使使用者希望直接瀏覽全部 Workspace。顯式檢視模式保留預設佈局，也不為目錄新增流程增加確認。

**遞迴 Workspace 成員關係：**這會改變工作目錄不變數，並讓一個 Session 同時符合多個記帳。展示巢狀不需要這兩項改變。

**獨立父目錄記錄與新增時選擇：**這會重複表示已有 Workspace 目錄，併為普通新增增加確認。根據註冊表派生層級可保留單一新增流程，並讓每個目錄都能擁有 Session。

**自動發現目錄：**這能展示尚未註冊的專案，但需要檔案系統列舉、重新整理和採用行為。側欄僅使用目前 Workspace 列表。

## 結果

使用者可以摺疊相關專案，而不改變 Session 歸屬。刪除祖先會保留子工作區註冊；獨立的 [Workspace 刪除語義](2026-07-27-workspace-registration-deletion.zh.md)仍決定被刪除 Workspace 自身 Session 的處理，該決策繼續有效。瀏覽器本地摺疊偏好不跨瀏覽器同步，巢狀取決於分隔符歸一化後的註冊路徑拼寫。

純路徑測試覆蓋嚴格祖先關係、路徑段邊界、POSIX 反斜槓和 Windows 分隔符。元件與瀏覽器情境覆蓋預設同級分組、樹形模式選擇與恢復、直接新增、後續註冊、父級獨立 Session、摺疊恢復、搜尋展開、透過後代落點進行同級排序、父級子樹移動、摺疊目前工作階段提示及整行等寬。
