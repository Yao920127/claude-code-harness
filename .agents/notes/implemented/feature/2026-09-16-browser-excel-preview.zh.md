# Agent Note: 顯示已儲存公式結果的瀏覽器 Excel 預覽

Status: implemented

[English](2026-09-16-browser-excel-preview.md) | 中文

## 問題

PDF 轉換會丟失工作表導航以及公式與已儲存值之間的關係。瀏覽器能夠讀取工作簿時，表格預覽也沒有必要依賴 Host Office 引擎。

不支援的繪圖內容也可能阻斷單元格預覽。ExcelJS 4.4.0 要求 DrawingML 元素名帶字首，遇到 Openpyxl 生成的合法預設名稱空間繪圖時會失敗。檢視器無法展示的圖表不應使原本可讀的工作表無法開啟。

## 決策

[文件預覽](../../../../packages/client/ui-sidebar-documentpreview/README.zh.md#excel-preview)使用 FortuneSheet 與包內 ExcelJS、SheetJS CE 和 PapaParse 適應層開啟 XLSX、XLS、CSV 和 TSV。適應層接收位元組、格式和限制並返回工作表資料，不包含 React 狀態設定器、計時器或元件引用。依賴庫負責檔案解析，適應層複用顯示格式化和初始選區，不引入另一種工作簿模型。CSV/TSV 保留字面字串和純文字選項；隱式型別推斷可能丟失前導零或把源文字解釋為公式。共享文件讀取器呼叫 `remote.workspaceFiles.readBytes(sessionId, path, {}, signal)`，並透過二進位制 Remote 直接接收原生位元組，保留 Session 授權、檔案版本、重新載入和臨時位元組，無需 base64 解碼。Workspace Files 負責有界檔案讀取，格式解析留在 Client。註冊僅將 XLSX/XLS 標為 `binaryExtensions`，共享文件容器因此為 CSV/TSV 提供純文字選項。每個渲染器以自己的 id 註冊正文。

預覽為只讀，同時保留公式文字與已儲存結果。它不重新計算，因此不受支援的函式不會用錯誤覆蓋有效的已儲存結果。沒有已儲存結果的公式保持為空。包含公式的工作簿會在公式圖示旁顯示緊湊提示，不再用整行提示佔用工作表高度。該表格既不是編寫工具，也不是完整的 Excel 渲染引擎。

包內 `XlsxPreviewArchive` 在解析 Worker 中檢查 XLSX 內容，從臨時 ZIP 中移除 DrawingML 部件及其關係部件。ExcelJS 同時忽略工作表繪圖引用；僅忽略這些引用仍會讓其歸檔級繪圖解析器觸發該故障。源位元組和保留的工作表 XML 均不改變。獨立提示列出實際檢測到但預覽未展示的圖表、圖片、形狀和條件格式，並建議使用系統應用。公式提示保持獨立，未檢測到不支援內容的檔案不顯示此提示。其他格式不返回不支援內容分類。

獨立可釋放的瀏覽器 Worker 承擔解析 CPU 工作。解析前檢查原始檔位元組限制，FortuneSheet 分配矩陣前檢查矩形區域合計限制，並透過超時終止停滯的解析。這些限制不代表嚴格的記憶體沙箱。樣式限定在渲染器區域內，外部超連結僅顯示為文字。

固定版本的 FortuneSheet React 依賴帶有一個[補丁](../../../../patches/@fortune-sheet__react@1.0.4.patch)：只讀輸入框僅在啟用公式引用高亮時才提交佈局狀態更新。無條件更新會在儲存庫交付的 React 18.3.1 執行時下切換工作表時觸發最大更新深度錯誤。啟用工作表時還會保留適應層提供的完整初始選區，避免清空後留下空白或無效地址。瀏覽器情境透過打包後的 ESM 入口覆蓋這些故障。

只讀公式欄直接讀取原始 `cell.f`，透過 `textContent` 寫入公式和單元格文字。FortuneSheet 的公式格式化器會生成含有文件文字的 HTML span，其 HTML 輔助函式會原樣放行公式和以 `<span` 開頭的字串。只讀模式和解析 Worker 都不能隔離這部分 DOM。[core 補丁](../../../../patches/@fortune-sheet__core@1.0.4.patch)會對複製的單元格內容進行 HTML 轉義，包括字面字串和已儲存的公式結果，同時保留剪貼簿表格及其格式。

core 補丁還在 `allowEdit === false` 時跳過凍結分隔線的繪製，保留凍結窗格計算和編輯模式下的分隔線。這些分隔線由 Canvas 繪製，因此區域性 CSS 無法修改。預覽區域內的 CSS 隱藏行列凍結拖拽條。ESM 和 CommonJS 入口應用相同補丁。升級 FortuneSheet 時需要重新檢查工作表切換、完整初始選區、公式欄字面文字、經過轉義的表格複製，以及凍結窗格的繪製和滾動。

## 考慮過的替代方案

**採用 FortuneExcel 面向 React 的轉換輔助函式。** 其元件狀態設定器和渲染後尺寸調整把檔案轉換耦合到一種 UI 生命週期。本地適應層無需掛載工作簿即可測試，也不需要第二種中間工作簿模型。

**自行編寫 OOXML 解析器或建立新的公共包。** ExcelJS 已經負責容器和檔案語義。單個預覽使用方不足以支援另一套公共 API、Cordis 服務或通用工作簿抽象；出現第二個獨立使用方時再考慮提取。

**修補 ExcelJS 的繪圖名稱空間處理。** 正確解析仍不能使檢視器展示繪圖。過濾不支援的部件可防止其阻斷已支援的單元格預覽，無需維護檢視器無法使用的繪圖行為。

**替換 ExcelJS 或要求使用者重寫檔案。** 更換解析器會使現有字型、邊框、合併及凍結窗格的保留面臨風險。重寫原始檔則把檢視器缺陷交給使用者處理。臨時預覽副本同時保留現有介面卡和使用者檔案。

**保留 PDF 作為 Excel 後備，或在匯入時計算所有公式。** PDF 無法保留表格互動與公式檢視，而重新計算可能改變已儲存結果。[Office 引擎決策](../architecture/2026-09-11-node-office-kit.zh.md)仍適用於 Word/PowerPoint 預覽與獨立轉換使用方；轉換能力仍支援表格。

## 影響

渲染器用部分 Excel 保真度換取瀏覽器內導航和可複用的轉換程式碼。包 README 負責說明支援的格式、資源預設值和不支援的功能。真實 XLSX/XLS fixture 和分隔文字案例覆蓋轉換，Worker 測試覆蓋取消和清理，釋出 profile 的瀏覽器情境在停用 Office 轉換後開啟工作簿，並在只讀設定下複製已儲存的 XLOOKUP 結果。該情境還驗證 XLS 工作表切換，以及 CSV/TSV 字面值複製、純文字切換和重新載入。由於公共 npm 儲存庫版本過舊，SheetJS CE 固定使用官方釋出的 tarball；其 Apache-2.0 許可證沿用現有寬鬆許可證及打包宣告規則。

繪圖過濾增加 ZIP 檢查，並在移除部件時分配臨時未壓縮 ZIP。現有 Worker 生命週期和原始檔／矩陣限制仍然適用，但不約束解壓後的記憶體。繪圖 fixture 覆蓋預設及替代字首、保留 XML 和輸入位元組的逐位元組一致性、圖片、形狀及批註 VML。瀏覽器情境檢查提示、已儲存值的複製，以及檔案替換後的提示移除。增加繪圖渲染時，必須同時重新審視過濾和提示分類；僅修復名稱空間不能恢復該能力。
