# Agent Note: 裝置本地 Desktop 引導

Status: implemented

[English](2026-09-16-desktop-onboarding.md) | 中文

## 問題

帳號使用者在完成原生認證後，需要了解額度並選擇展示方式。原生憑證入口已經承擔獨立的啟動職責；重複執行瀏覽器引導，或將缺失的帳號資料當成新使用者，會把展示流程與認證故障耦合。

## 決策

[帳號 UI](../../../../packages/client/ui-settings-account/README.zh.md#desktop-onboarding)僅在存在 Desktop preload 標記、已儲存帳號憑證且本地引導未完成時，掛載一個 shell 覆蓋層。Host 設定持有目前安裝的版本化進度與完成狀態，不使用 Platform 完成標記或逐帳號歷史。重新啟動恢復已儲存的步驟；退出登入會隱藏引導，但不清除進度。未登入且已設定模型憑證的安裝會記錄 API Key 完成狀態，並應用標準過程、詳細用量和開啟開發者工具的設定。帳號登入時丟棄失敗的 API Key 完成寫入，避免重試繞過必需的歡迎頁。

歡迎頁必須顯式開始。額度頁始終出現，包括餘額為正的情況。僅在餘額已就緒且沒有正餘額錢包時，才額外確認是否繼續而不充值；查詢失敗或等待中絕不表示餘額為零。從原生充值頁面返回後保留額度頁，由帳號屬主在後臺重新整理資料。充值期間關閉應用會保留額度步驟。

用途和過程選擇會作為草稿持久化。僅選辦公用途時採用簡潔展示並完成。選擇開發或兩種用途時必須選擇過程詳情。任意可跳過步驟均採用標準過程、簡潔用量和關閉開發者工具。完成時先應用 Chat 和共享開發者工具偏好，再儲存完成標記，避免偏好寫入被拒絕後靜默完成引導。compact、standard 和 detailed 各自持久化為對應的 `ui-chat.transcriptView` 值。

既有[原生歡迎決策](../architecture/2026-09-08-desktop-welcome-window-material.zh.md)負責憑證入口、IPC 限制和視窗材質。Desktop 抑制自動 Web 憑證引導，保留顯式 API Key 編輯。引導不建立工作區、範例任務或 Session 事件。靜態 Figma 插圖使用透明、調色盤壓縮的 3× PNG 資源；歡迎頁圖層合併並烘焙側欄區域性模糊；充值頁前景視窗不透明度為 70%，僅烘焙其覆蓋插圖區域的模糊。帳號包負責整窗覆蓋層及其控制元件樣式，共享基礎元件保留通用行為。品牌標題透過 Web 入口載入附帶許可的 Montserrat WOFF2 字型。儲存選擇時保留焦點，減少動態效果偏好會停用動畫，應用在退出覆蓋層解除安裝前保持不可互動。確認彈出視窗模糊源頁面，避免在半透明視窗內再次取樣背景。

## 考慮過的替代方案

**雲端或逐帳號完成狀態。** 目前版本要求裝置本地進度，且沒有帳號完成 API。將登入狀態用作完成標記，會混淆認證成功與設定完成。

**正餘額時跳過額度頁，或等待充值確認。** 引導獨立於錢包狀態說明計費。等待餘額查詢會使返回導航依賴網路，卻無法確定是否完成支付。

**重複實作偏好控制。** 引導透過現有屬主寫入工作過程、用量與開發者工具設定。

## 後果

尚無引導完成標記的已有 API Key 安裝，在升級後首次啟動時也會應用這些預設值，覆蓋之前的 Chat 展示、用量和開發者工具偏好；已經標記完成的安裝保留原偏好。

同一安裝的完成狀態適用於切換後的帳號，另一安裝則執行自己的引導。偏好與完成狀態按順序寫入，但不屬於同一事務；完成標記寫入失敗後，重試可能再次應用同一偏好。已完成引導的安裝不會在後續啟動時重新應用偏好。[控制器測試](../../../../packages/client/ui-settings-account/tests/onboarding-state.client.spec.ts)與 [UI 測試](../../../../packages/client/ui-settings-account/tests/desktop-onboarding.client.spec.tsx)負責狀態和互動覆蓋；生產授權與支付行為仍需獨立的整合驗證。
