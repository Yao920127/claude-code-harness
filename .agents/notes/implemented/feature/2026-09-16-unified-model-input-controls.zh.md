# Agent Note：統一模型輸入控制元件

Status: implemented

[English](2026-09-16-unified-model-input-controls.md) | 中文

## 問題

DeepSeek 和 pi-ai 分別渲染模型行，導致標籤、圖示和間距不一致。自動列數會在寬度稍有變化時，將圖片輸入移到容量欄位同一行或下一行。圖片支援選擇器也無法表達僅圖片輸入，而兩個介面卡都接受這種宣告。

## 決策

兩個模型目錄渲染同一個模型行元件。兩個容量欄位佔據兩列，輸入型別獨佔下一整行。文字和圖片使用 `ui-primitives` 的受控原生 Checkbox（核取方塊），由呼叫方提供在地化標籤，並保留原生鍵盤行為。至少保留一種輸入型別；最後一個勾選項保持停用，直到選中另一項。

未宣告或為空的輸入欄位優先顯示已安裝模型的輸入型別，其次是路由預設值，最後退回為文字，開啟時不會生成覆蓋值。Pi-ai 目錄發現將可選的 `inputModalities` 經 LLM 服務和 Remote（遠端呼叫）回應傳遞給介面；採納候選時將其複製到 `input`。已知提供者的編輯器讀取已安裝目錄，不向端點傳送請求，因此已有的僅容量模型行也能顯示繼承的視覺能力。上一個提供者的目錄回應會被丟棄，輸入控制元件會等待目前讀取完成。首次修改核取方塊會將確切的非空選擇寫入 DeepSeek 的 `inputModalities` 或 pi-ai 的 `input`。已有顯式選擇保持可見，包括僅圖片輸入。編輯保留無關中繼資料；停用 DeepSeek 圖片時會移除圖片請求限制，因為介面卡在沒有圖片輸入時拒絕這些限制。儲存使用現有的模型目錄陣列變更和介面卡驗證。

## 考慮過的替代方案

**獨立的模型行渲染器。** 介面卡專屬預設值和模型發現仍由各自編輯器負責，但重複的展示實作會造成可避免的視覺差異。共享模型行將這些行為與欄位佈局分離。

**保留圖片支援選擇器。** 僅透過設定檔案編輯能力，會讓自定義視覺模型實際保持僅文字。帶有顯式「預設」選項的選擇器會清楚展示 pi-ai 模型目錄繼承；兩態圖片開關則會將繼承的視覺能力誤表示為停用。核取方塊介面直接展示兩種輸入型別，並在允許編輯前解析繼承的能力。僅開啟模型行仍保留繼承；修改核取方塊後，要恢復繼承需在設定中移除輸入欄位，或重置整個模型目錄覆蓋。

**允許全部取消。** DeepSeek 拒絕空列表，pi-ai 則將其視為繼承。保留非空選擇，避免同一個操作在兩個介面卡中具有不同含義。

**停用 DeepSeek 圖片時保留圖片限制。** 這會留下介面卡拒絕儲存的設定。清除圖片專屬限制，可以讓選中的僅文字狀態有效，同時保留模型的無關欄位。

## 影響

使用者透過相同佈局編輯僅文字、僅圖片和組合宣告。設定宣告上游能力，不會為僅文字模型增加圖片處理能力。移除 pi-ai 輸入宣告後，有效能力可能隨模型目錄或提供者預設值變化。停用圖片後，DeepSeek 圖片限制需要重新設定。提供者路由和[模型目錄恢復規則](../bug-fix/2026-09-07-pi-ai-settings-catalog-recovery.zh.md)保留現有責任方。元件檢查覆蓋預設值、確切選擇、中繼資料保留和停用控制元件；瀏覽器情境覆蓋儲存後的介面卡能力、重新開啟後的選擇，獨佔一行的輸入型別，以及發現、採納和重新開啟過程中傳遞的內建視覺中繼資料。
