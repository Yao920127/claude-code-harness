# Agent Note: Windows 桌面頂欄與應用選單

Status: implemented

[English](2026-09-16-windows-desktop-titlebar.md) | 中文

## Problem

Windows 需要緊湊的頂欄，在側欄隱藏或檔案鋪滿內容區時仍保留側欄導航。獨立的應用/編輯選單多佔一行，且可能與應用語言不同。共享用戶端必須保留普通 Web 和 macOS 的呈現。

## Decision

Windows 主視窗組合 Electron 隱藏標題欄與原生視窗按鈕覆蓋層。只有本地應用 preload 釋出 `data-windows-titlebar`；共享佈局、側欄和全螢幕面板規則均要求該標記。原生頂欄顏色與右鍵選單語言跟隨應用文件。渲染器訊息僅接受主視窗的主框架來源。

Windows 移除獨立的原生選單行。應用 preload 在隔離的 shadow root 中掛載在地化“應用”和“編輯”頂欄入口，主程序為透過驗證的請求開啟原生彈出選單。“應用”與其他平臺共用命令範本；“編輯”保留 Windows 原生命令集合，並顯式提供由語言字典管理的標籤。頂欄導航複用現有側欄回呼，不另建導航儲存，收起態的新建工作階段控制元件位於側欄開關和選單之間。[macOS 頂欄決策](2026-09-13-macos-hidden-titlebar-vibrancy.zh.md)仍獨立適用於 macOS。

## Alternatives considered

按 Alt 顯示的原生選單行額外佔用縱向空間，且依賴鍵盤慣例才能發現。完全移除命令會丟失手動更新和編輯命令。外掛管理使用主應用的“外掛”頁面。頂欄入口保留這些操作而不增加選單行。原生彈出選單保留命令執行與鍵盤導航，無需在 Web 元件中重複編輯器操作。

自定義 HTML 視窗按鈕會讓應用承擔原生頂欄互動。原生覆蓋層保留這些按鈕，同時允許應用內容顯示在旁邊。全域 CSS 修改會影響 Web 和 macOS；由 preload 持有的標記將呈現限制在 Windows 主視窗。

## Consequences

頂欄在全螢幕檔案面板上方保持可用，收起的導航不再佔用縱向軌道。頂欄選單保留應用與編輯命令，普通 Web 文件不獲得桌面控制元件。編輯操作向目前編輯器傳送對應按鍵，以使用編輯器自身的撤銷歷史。頂欄入口位於內容彈出視窗遮罩之上。鍵盤啟用在派發前恢復上一編輯器及選區；指標啟用保留編輯器焦點；選單關閉後清除入口啟用態。主程序驗證拒絕其他框架、未知選單名稱和無效錨點座標。原生彈出選單外觀跟隨作業系統。

## Testing

桌面啟動與 preload 測試覆蓋平臺隔離、語言變更、調色盤訊息、來源驗證、原生命令對映、選單生命週期和桌面外掛快捷鍵的缺失。選單與側欄本地快照覆蓋在地化入口及展開、收起控制元件；佈局測試覆蓋零寬度收起。視窗驗證覆蓋原生彈出選單、頂欄導航和全螢幕避讓。普通瀏覽器驗證檢查桌面控制元件缺失及側欄軌道保留。
