# Agent Note: 常駐計劃卡片與側邊欄閱讀

Status: implemented

[English](2026-09-17-persistent-plan-cards.md) | 中文

## Problem

計劃審批只在使用者回答或關閉之前佔據編輯器。已完成的回合也會把工具呼叫摺疊到執行過程裡。這兩種生命週期都無法在實施繼續時，為已提交的計劃提供容易找到的閱讀入口。

## Decision

`ui-plan` 彙總每個回合的 `exit_plan_mode` 提交，覆蓋原生呼叫和 PTC dispatch。每次呼叫在已完成回合末尾的產物區域貢獻一張卡片。`conversation.chat.turnTail` 列表同時容納檔案產物和計劃卡片。關閉、拒絕或批准審批都不會刪除已記錄的計劃。

審批意圖可以攜帶工具呼叫標識。提問外掛宣告操作插槽，計劃外掛在該插槽和歷史卡片中提供開啟入口。存在呼叫標識時，兩者都開啟由完整工作階段地址和呼叫標識確定的資源。子工作階段地址保留直接父級、子工作階段及執行模式，用於快照讀取、分頁和重新整理恢復。資源地址確定文件所屬的工作階段，目前掛載的側邊欄決定預覽開啟的位置；嵌入式子對話不需要子工作階段自己的側邊欄 store。側邊欄佈局保留該地址；資源 provider 讀取已有工作階段歷史，當呼叫早於初始視窗時向前分頁。臨時 follow 在取得初始快照後關閉。

沒有呼叫標識的審批開啟臨時地址，由瀏覽器生命週期、工作階段和待處理請求共同標識。側邊欄已有的導航參數儲存 Markdown，無需額外的文件 store，也不把正文持久化到佈局中。關閉後從待處理卡片重新開啟會再次提供正文；恢復的標籤頁若缺少導航參數，則顯示預覽已失效。

文件只讀。待處理審批顯示狀態、“檢視全文”連結、標題、兩行純文字摘要，以及“要求修改”和“同意執行”按鈕；完整正文自動在側邊欄開啟。臨時的工作階段級 store 記錄每個已自動開啟的呼叫或無呼叫標識的請求，讓審批元件重新掛載時仍保留使用者的關閉選擇。歷史卡片不會觸發自動導航。卡片採用檔案產物樣式，包含 Markdown 圖示、計劃標題和“開啟”操作。“要求修改”取消待處理等待並恢復編輯器，供使用者輸入回饋。審批仍由待處理提問的屬主負責；重新開啟歷史文件不會恢復已結束的審批，也不會授權實施。即使標題相同，不同提交仍彼此獨立。

## Alternatives considered

**只保留待處理審批或可展開的工具行。** 兩者都會讓文件受其他互動或執行過程狀態控制。使用者需要常駐的產物入口。

**寫入 Markdown 檔案或在側邊欄佈局中儲存正文。** 工具參數已經擁有準確的提交文字。另一份持久副本需要同步，且可能與審閱的計劃不一致。[計劃狀態決策](../simplification/2026-07-22-plan-specific-collaboration-state.zh.md)仍是這項所有權的權威記錄。

**只選擇一個回合末尾區域的屬主。** 計劃和檔案產物可能出現在同一回合。可追加列表讓兩個外掛都能貢獻內容，無需彼此瞭解資料或渲染。

## Consequences

已記錄計劃在審批關閉和瀏覽器重新整理後仍可閱讀，無需新增工作階段事件或檔案。即使工具拒絕呼叫，包括在計劃模式之外呼叫，完整的計劃參數也會保留卡片；卡片不代表批准或執行成功。讀取舊計劃可能需要多個歷史分頁。provider 驗證儲存的地址和呼叫參數，並明確報告歷史不可用。已有 Web 計劃審批錄製情境覆蓋兩個入口、重複開啟、執行過程摺疊、批准和重新整理；定向測試覆蓋多次提交、PTC 去重、裁剪歷史及資源讀取失敗。
