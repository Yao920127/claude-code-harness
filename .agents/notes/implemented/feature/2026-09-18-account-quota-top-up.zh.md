# Agent Note: 帳號欠費充值操作

Status: implemented

[English](2026-09-18-account-quota-top-up.md) | 中文

## Problem

提供者的額度錯誤可能表示第一方帳號餘額耗盡、API Key 帳號問題，或自定義閘道回應。所有情況都需要清晰提示，但只有第一種情況適合開啟已登入使用者的內嵌 DeepSeek 充值頁。若根據提供者文案或目前 UI 設定推斷，會導致歷史錯誤隨目前狀態變化，並可能展示無關的充值操作。

## Decision

`llm-deepseek-account` 外掛為本路由分類額度錯誤：它交給共享 Messages 傳輸的憑證回呼只在設定的推理 origin 上釋放帳號 token，並把提供者中立的 `QUOTA` 錯誤改寫為 `ACCOUNT_QUOTA`，同時覆蓋 HTTP 402 回應與流內 SSE 錯誤。API Key 外掛獨立註冊 `deepseek-official` 並保留 `QUOTA`；兩條路由不會借用對方的憑證，單獨設定的 API Key 也不影響帳號路由的欠費操作。

額度錯誤分別到達訊息記錄和全應用提示這兩條路徑。持久化的終止錯誤記錄保留請求時的錯誤碼，並始終渲染同一段提供者中立的欠費文案，因此 Chat 訊息記錄、歷史分頁和 Session 日誌都不依賴目前憑證。本 Client 已繫結並已物化的 Session 中新追加的 `QUOTA` 或 `ACCOUNT_QUOTA` 錯誤還會發布一條全應用提示；最新提示替換上一條，歷史替換、分頁以及從未開啟的 Session 都不釋出提示。

Chat 擁有提示主機，並將其註冊到全應用的 `shell.overlay` slot，因此提示的生命週期長於報告它的 Chat 面板。主機把這條即時提示連同 `code`、`message`、`dismiss`、`keepOpen` 交給 `shell.quota-notice` chain 子 slot，沒有 entry 認領該錯誤碼時渲染通用警告 Toast。帳號包只認領 `ACCOUNT_QUOTA`，顯示帶取消和去充值按鈕的 Modal；缺少共享主機條目，或快照報告未儲存憑證、帳號流失敗且無快照時，由該條目自行渲染中立文案 Toast，而存在該主機條目時它會等待首個帳號快照，而不是渲染一個可能被自身計時器丟棄的 Toast。外掛為 Desktop 主機唯一的原生檢視保留一個共享 `PlatformPages` 請求通道和一個 `shell.overlay` 主機條目：Account 設定頁、欠費提示與 Desktop 引導充值頁都透過它申請頁面，而不再各自掛載容器；最新請求會在新頁面顯示前退掉上一個持有者，而在更新請求或關閉之後到達的釋放不會清除任何內容。共享主機只關閉它接到的頁面，每個持有者自行決定其返回時重讀什麼：Account 設定頁或欠費提示的充值返回會重讀資料、餘額與未通知贈金，而引導充值返回只重讀資料與餘額。替換頁面、釋放請求、外掛解除安裝與從用量頁返回均不讀取。返回時先恢復焦點，再由任何被延後的 Modal 接管。只要透過該共享請求通道請求的頁面正在顯示，該原生檢視就會蓋住本頁，因此該條目既不渲染 Modal 也不渲染 Toast。在 Account 設定頁已開啟頁面的情況下新到達的欠費不會被保持：它仍受最新提示替換規則約束，返回後若該提示仍是最新一條就顯示 Modal。該 Modal 報告的是原始請求的失敗而非帳號目前餘額：返回時的重讀是一次獨立讀取，返回本身既不證明支付成功，也不會自動撤下該提示。提示自身的去充值屬於被保持的情形：它用 `keepOpen` 保持住提示，並申請 `top-up` 頁面；`keepOpen` 返回身份安全的釋放函式，且該條目在解除安裝時同時釋放保持與頁面請求，因此宣告不會比取得它的條目活得更久。開啟充值頁因此會讓該提示與其頁面在後續欠費期間保持掛載，這些欠費被丟棄而不排隊，其持久化失敗行仍然渲染。關閉或退出登入會釋放保持與頁面請求，使下一條即時欠費重新發布。Chat 對某個 Session binding 即時事件的訂閱在 binding 或外掛先結束的一側終止。

憑證和計費 URL 不會進入 Chat props 或 Session 日誌。關閉提示不會重試請求；退出登入會關閉已開啟的帳號 Modal 或內嵌頁面。

## Alternatives considered

**完全在 renderer 中推導資格。** 目前端點、金鑰和登入狀態可能已經不同於歷史失敗請求的事實；這也會讓 Chat 依賴憑證和提供者設定，而不是在展示邊界只接收穩定錯誤碼。

**在 UI 中解析提供者錯誤文案。** 提供者文案不是穩定契約，無法區分 API Key 和帳號 token 的計費，同時會重複 adapter 的錯誤分類。

**為所有額度錯誤提供充值。** 這會把 API Key 和自定義閘道使用者帶到無關的第一方計費頁面。普通提示已經足夠，不應虛構修復路徑。

**根據全域憑證推斷計費。** 已設定的 API Key 可能屬於其他帳號，也可能未被失敗請求使用。明確的 provider 路由負責憑證選擇和欠費分類。

## Consequences

Session 日誌區分帳號餘額失敗與普通額度耗盡，訊息記錄對兩者渲染同一段中立文案。一條提示服務整個應用，因此在報告它的 Chat 面板關閉後仍然可見，且新提示取代舊提示而不是疊加。由於帳號包透過 chain 子 slot 認領提示，Web 與未登入使用者只看到中立 Toast，沒有計費入口，帳號包也無須匯入 Chat。被去充值保持住的提示會讓該條目的頁面在後續欠費期間繼續掛載，代價是丟棄這些提示；持久化失敗行仍是它們唯一的記錄。一個共享請求通道同時服務 Account 設定頁與提示，因此更新的請求會替換可見頁面，而身份驗證過的釋放使被取代的持有者無法關閉它。

提供者測試覆蓋雙憑證並存時的路由、HTTP 402 分類和流內 SSE 錯誤；展示測試覆蓋僅追加發布、替換、關閉、Toast 退回和內嵌充值頁跳轉。
