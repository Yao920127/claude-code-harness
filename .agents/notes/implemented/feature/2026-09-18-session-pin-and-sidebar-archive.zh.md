# Agent Note: Session pinning and the sidebar archived filter

Status: implemented

[English](2026-09-18-session-pin-and-sidebar-archive.md) | 中文

## Problem

側邊欄工作階段列表無法把重要工作階段固定在頂部，已歸檔工作階段只能透過遠離列表的設定頁（`ui-settings-unarchive-sessions`）存取。使用者歸檔一個工作階段之後就再也看不到它了。

顯隱篩選可以隱藏工作階段，但不改變它的 Workspace 歸屬。把篩選後的行儲存成所屬列表的完整順序，會丟失隱藏項的位置。單獨維護可編輯的置頂順序，也會讓拖拽依賴另一份序列，而不是使用者正在編輯的工作階段順序。

## Decision

`dsh-workspace` registry 將全域置頂與歸檔集合存為工作階段 id 陣列（`pinnedSessionIds` 和 `archivedSessionIds`），並提供持久化的 `pinSession`/`unpinSession` 操作。置頂陣列把最近置頂的 id 放在前面。置頂與歸檔互斥：歸檔會在同一次持久化寫入中移除該工作階段的置頂，置頂已歸檔工作階段則以 `WorkspaceArchivedSessionPinError` 失敗。

### 完整工作階段順序

每份瀏覽器本地排序記錄包含一條完整工作階段序列，包括置頂和歸檔成員。每份序列受 Workspace 成員關係約束，全域置頂與歸檔集合不會把工作階段補進無關的 Workspace。分組、Ungrouped 和平鋪檢視使用同一套規則。

- 已有成員保留位置。缺失的置頂成員按置頂陣列中的順序補到頭部。新增的普通 fork 緊鄰來源之前插入，包括連續 fork，不繼承來源的置頂。已儲存成員保持相對順序，可見置頂行仍排在普通 fork 之前。其他缺失成員按工作階段 `updatedAt` 降序追加，缺失的歸檔成員放在最後。補齊不重複加入同一個 id。
- 補齊是記憶體派生，不自動遷移儲存。一次工作階段順序寫入儲存補齊後的完整序列，包括隱藏的歸檔行。單純切換篩選不重寫工作階段位置。
- 置頂成功後，工作階段被標記為置頂，同時移到所屬完整序列的首位。完成時使用目前儲存的位置與最新 Workspace 成員關係，保留請求等待期間完成的重排序。取消置頂只移除標記，不恢復更早的位置。置頂行與普通行的拖拽都修改同一條完整序列，顯示下標不會覆蓋其中的隱藏成員。
- 目前空白新工作階段排在兩個分割槽之前，其餘工作階段再按置頂區、非置頂區排列。手動模式下，兩區分別保持完整序列中的相對順序。最近更新模式下，兩區都嚴格按 `updatedAt` 降序排序，以工作階段 id 打破平局。置頂記錄只包含工作階段身份，不包含時間戳。
- 工作階段同時命中兩個集合時，歸檔優先。歸檔會清除 Host 的置頂標記，但保留工作階段在所屬序列中的位置。歸檔篩選只改變可見性和停用行的展示，不改變成員關係或排序。

既有的[模式切換與臨時新工作階段規則](../simplification/2026-09-10-derived-workspace-recency.zh.md)保持不變：拖拽選擇手動模式，最近更新丟棄先前的手動佈局，進入手動模式記錄目前時間順序，目前選中的空白工作階段保留臨時首位。顯式置頂更新儲存的位置，但不切換所選模式；時間檢視仍忽略這些位置。

### 取消歸檔

`WorkspaceRegistry.unarchiveSession` 與歸檔及其他註冊表寫入共用序列操作鏈，從全域歸檔集合移除一個 id。id 不在集合中時是冪等空操作，不產生持久寫入或通知。恢復保留 Workspace 成員關係與 Session 日誌，不恢復置頂，也不改變儲存的順序。

取消歸檔不探測 Session 是否存在：移除 id 不會引入未知引用，因此即使 Session 已不存在，也能在不列舉持久化記錄的情況下移除歸檔項。Remote 返回完整歸檔集合，既有 `archived` 增量把同一狀態傳給其他 Client。Client 只在一元回應仍屬於最新歸檔集合請求時安裝它；更新的請求、follow 增量或替換基線會覆蓋舊回應的資格。寫入失敗不改變集合，側邊欄記錄拒絕原因並保留原行；唯一例外是“仍有工作在跑”的拒絕，它會開啟停止並歸檔的確認（[歸檔仍有工作在跑的 Session](2026-09-21-archive-stops-running-session-work.zh.md)）。

### 歸檔顯隱與行動畫

側邊欄在 `ui-workspace` 中派生可見行：

- 已歸檔行保留其記帳位置，置灰渲染且不可開啟。檢視選項選單持有 `ArchivedFilter`（`default` 隱藏 / `show` / `only`），同時作用於列表與搜尋；設定頁的歸檔列表連同其包一併刪除。
- 歸檔動作彈出攜帶撤銷與篩選已歸檔操作的 toast。父元件重渲染不會延長其生命週期，完全淡出後不會保留可點選操作。
- 行動畫由私有 React 元件使用瀏覽器原生位移與透明度動畫實作。元件在結構性提交前後記錄行位置，不使用觀察器或輪詢；被移除的行在滾動列表外留下不可互動的淡出副本。初始載入、拖拽提交、展開/收起其餘工作階段，以及分組/排序/篩選切換直接完成。

### 持久化

Workspace KV、Remote 值與 Client 快照都用工作階段 id 陣列儲存歸檔和置頂成員，不包含物件包裝或置頂時間戳。缺失集合預設為空，不接受物件形式的置頂條目。置頂與恢復不改變 Workspace 領域版本或 Session 日誌格式，也不編輯 Session 日誌。

## Alternatives considered

**保留設定頁的歸檔列表。** 同一狀態出現兩個入口；側邊欄篩選讓已歸檔行顯示在它們原本所在的瀏覽上下文中，因此該包被整體移除。

**只提供恢復操作，不提供已歸檔篩選。** 隱藏行無法提供操作。篩選讓這些行可以被存取，因此恢復可以與 Session 列表放在一起，而不需要獨立設定頁。

**獨立恢復增量，或在取消歸檔時檢查存在性。** 新增幀型別會重複完整集合回應，並增加合併路徑。存在性探測會把移除孤立歸檔 id 變成錯誤，儘管移除不可能引入未解析 id。因此恢復複用歸檔集合協定，不執行該探測。

**顯示缺少 Session 摘要的歸檔 id。** 這些條目可以解釋孤立狀態，但不能提供普通對話行。側邊欄顯示已載入摘要，API 仍支援直接恢復；孤立項管理不屬於目前瀏覽器。

**單獨維護可編輯的置頂序列。** 這會產生兩個排序來源，也需要另一條拖拽寫入路徑。全域置頂陣列只為缺失置頂成員提供初始位置，已有位置由完整工作階段序列管理。

**恢復置頂或歸檔之前的位置。** 讓置頂獨立於手動位置可以恢復置頂前的位置，但置頂本身就是一次有意的重排序。另存恢復記錄增加了這套互動不需要的產品保證；隱藏歸檔行本身已經保留其已有位置。

**用置頂時間給置頂行排名。** 這會讓最近更新不再嚴格表達工作階段活動。在該模式下，新置頂的舊工作階段不必排在置頂區首位；手動模式才顯示置頂操作調整後的首位。

**儲存每次派生或篩選後的列表。** 渲染和顯隱變化不是排序命令。不完整或經過篩選的投影不能覆蓋完整的已儲存序列。

**為每次列表變化播放動畫。** 顯示隱藏行、提交拖拽或切換篩選會整體移動行，觀感誇張；這些變化即時應用，而置頂跳動、歸檔淡出和相鄰行補位仍保留動畫。

## Consequences

側邊欄端到端擁有已歸檔可見性，設定頁少了一個包。置頂集合是 registry 全域的，因此置頂在分組與排序切換後仍然保留。行動畫不持有持久狀態，也不引入依賴。

篩選與重排序共用一條完整成員序列，隱藏的歸檔項不會因拖拽或切換篩選丟失。舊排序遺漏的成員在記憶體中補齊，並在下一次工作階段順序寫入時隨完整序列儲存。Host 的置頂與歸檔成員語義保持不變。瀏覽器不再用置頂時間提升最近更新模式下的位置，也不自動恢復置頂前的位置。

歸檔 id 沒有已載入 Session 摘要時，不會產生可見行或側邊欄恢復操作，儘管 API 仍能移除它。這個 UI 限制不改變註冊表的冪等恢復行為。

單元測試覆蓋補齊、完整序列拖拽、期間發生其他變更後的 Pin 完成、新工作階段優先順序、歸檔導航保護、篩選、toast 生命週期與行動畫生命週期。Workspace 和 Controller 測試覆蓋置頂與歸檔互斥、只含身份的持久化及快照、冪等空操作恢復、缺失 Session 時不探測持久化的恢復、重新啟動恢復，以及被新請求或推送狀態取代的舊一元回應。無金鑰的側邊欄恢復情境驗證行操作與過載後的永續性。
