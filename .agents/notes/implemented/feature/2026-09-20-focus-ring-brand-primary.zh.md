# Agent Note：所有控制元件共用一個鍵盤焦點顏色

Status: implemented

[English](2026-09-20-focus-ring-brand-primary.md) | 中文

## 問題

不同的顯式焦點顏色與瀏覽器預設輪廓無法提供一致的鍵盤焦點提示。瀏覽器預設值還可能取決於作業系統強調色。

焦點回饋另有互動與幾何約束。瀏覽器的 `:focus-visible` 啟發式可能在不移動焦點的按鍵之後顯出指標聚焦按鈕的環，而可編輯文字控制元件在點選時需要焦點回饋。裁切內容的容器可能隱藏外擴環。

## 決策

[主題焦點樣式表](../../../../packages/client/ui-theme/src/styles/focus.css) 擁有共享焦點環顏色與標準寬度。[輸入模態](../../../../packages/client/ui-primitives/README.zh.md#input-modality) 區分 tooltip 輸入與鍵盤焦點導航。

**一個顏色。** 全域與元件的 `:focus-visible` 輪廓和焦點環陰影讀取 `--dsw-focus-ring-color`，退回到 `--dsw-alias-state-business-primary`。全域後備宣告顏色與標準寬度、但不宣告樣式，因此元件停用輪廓時它不會建立輪廓。宣告寬度可讓沒有自有焦點環的控制元件保持標準幾何，而不是落到 Chromium 的 `auto 1px`。

**情境決定幾何。** `--dsw-focus-ring-width` 提供標準的 2px 寬度。密集表格與工具欄可以保留 1px，避免焦點環壓過緊湊內容。元件擁有自己的 offset，並在外擴環會被裁切時使用內嵌環。

**指標焦點不等於鍵盤導航。** 指標模態下，`:focus-visible:not(:read-write)` 控制元件使用透明的焦點環顏色。後代與偽元素上的環繼承該值。只抑制焦點環繪製：選中態邊框與 elevation 陰影保留，可編輯文字控制元件在點選時保留自身焦點回饋。DOM 焦點仍留在控制元件上。

Tooltip 跟隨最近一次輸入，將任意按鍵視為鍵盤輸入。焦點環則在非組合輸入的導航鍵到達時，或非組合輸入按鍵之後焦點到達不同控制元件時，恢復鍵盤樣式。重新聚焦同一控制元件不算導航；指標輸入、組合輸入按鍵和 window blur 會清除待處理按鍵。

## 考慮過的其他做法

**只重寫元件宣告。** 顯式焦點環會一致，但使用瀏覽器預設輪廓的控制元件仍會保留其顏色。要求每個控制元件自行宣告焦點環，也會讓新控制元件在作者補上規則之前保持不一致。

**全域統一寬度與 offset。** 正 offset 可能被滾動祖先裁切，統一的粗環則可能壓過密集內容。顏色一致性和輸入模態都不要求相同的幾何。

**用移動焦點取代樣式抑制。** 對指標聚焦的按鈕呼叫 `blur()` 可以隱藏焦點環，但也會移除後續 Enter 或 Space 啟用的目標。

**指標聚焦時清除所有陰影。** 一個 `box-shadow` 除了焦點環，還可能包含 elevation 或選中態繪製。抑制其焦點環顏色可保留這些獨立提示；豁免 `:read-write` 可保留文字輸入回饋。

**把所有 `outline: none` 改為共享焦點環。** 一些控制元件改用內嵌陰影或容器級焦點處理；一些容器則刻意不顯示焦點環。替換這些宣告會改變焦點處理方式，而不只是顏色。

**讓 tooltip 與焦點環共用同一條模態規則。** 按鍵可以讓後續程式化聚焦顯示 tooltip，卻不一定需要在同一個指標聚焦按鈕上顯示焦點環。分別記錄兩個答案可保留兩種行為。

## 影響

焦點環共享主題顏色，元件保留自己的幾何與非焦點狀態提示。焦點環可見性的變化不改變鍵盤的活動目標。這些規則不保證瀏覽器渲染完全相同，也不會消除元件特有的裁切。

[樣式表順序檢查](../../../../packages/client/ui-theme/tests/client-styles.client.spec.ts)、[焦點樣式檢查](../../../../packages/client/ui-theme/tests/focus-ring-styles.client.spec.ts)與[輸入模態測試](../../../../packages/client/ui-primitives/tests/input-modality.client.spec.ts)覆蓋樣式宣告和模態轉換。靜態宣告與合成事件不能確認焦點環的實際渲染可見性或跨平臺行為。
