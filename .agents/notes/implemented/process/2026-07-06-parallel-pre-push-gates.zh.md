# Agent Note: 並行 pre-push 門禁

Status: implemented

[English](2026-07-06-parallel-pre-push-gates.md) | 中文

本記錄中的本地掛鉤部分已由[快速本地 Git 掛鉤](../../archived/process/2026-07-22-fast-local-git-hooks.md) 取代。有界門禁排程器和包級 `publint` 並行機制仍用於 CI、`doc-sync` 和顯式本地命令。排程器的快速失敗選項記錄在[門禁執行器快速失敗](../../archived/process/2026-08-27-gate-runner-fail-fast.md)。

## 問題

文件同步等聚合任務隱藏了很長的序列鏈，其中各項檢查只讀且相互獨立。在工作流 YAML 中重複這些葉子清單，會使未來腳本變更有多個位置可以發生漂移；而序列執行包釋出檢查，會使一道門禁的耗時與包數量成正比。

## 決策

[scripts/run-gates.ts](../../../../scripts/run-gates.ts) 擁有 CI、`doc-sync` 和按需啟用的 `check:all` 命令所使用的有界排程器。它將具名模式展開為葉子門禁，在啟動子程序前拒絕空的或有歧義的依賴圖，遵守產物依賴，預設緩衝可歸因的輸出，分別報告程序退出與訊號終止結果，並在呼叫方需要不同 worker 上限時接受 `DSH_GATE_CONCURRENCY`。`needs` 邊要求前置門禁透過，否則跳過依賴方；`after` 邊只等待前置門禁以任意結果結算，隨後仍允許後繼門禁執行。標記為 `allowFailure` 的門禁仍會報告結果，但不會使聚合流程失敗。

自身子程序能夠保留有效歸因的長時間協調門禁可以選擇 `streamOutput`。其 stdout 與 stderr 會立即到達父程序，不會被緩衝，也不會在結束時重複列印。分割槽覆蓋率與並行 Web 快照使用該模式，使執行中途的失敗無需等待兄弟工作結束就能顯示。

Node 24 消費方任務採用單個包含 10 道門禁的模式，而非由 shell 管理的程序池。其預設 worker 數等於門禁數，拉取請求 CI 則把活動門禁限制為 8 道，並由依賴關係控制就緒狀態。建置與原始碼相容性立即啟動；建置完成後，`publint` 與已建置包不變式驗證並行執行。lint、兩套快照、文件型別檢查、NodeNext 型別檢查和 built-bin 冒煙測試等待不變式驗證器清除臨時包檢視。

[scripts/publint-all.ts](../../../../scripts/publint-all.ts) 從 `packages/<group>/<pkg>` 發現包，並以根據 `availableParallelism()` 確定大小的 worker 池執行 `publint`。`DSH_PUBLINT_CONCURRENCY` 可以針對資源設定不同的本地機器和 CI runner 限制或提高 worker 數量。結果按包緩衝，並按確定性的包順序列印，因此並行執行不會打亂各包的日誌塊。

各門禁的包腳本仍是臨時本地執行所用的命令入口。`hygiene` 呼叫包含相同十三道檢查且限制為本地四個 worker 的排程器模式，而 `doc-sync` 的成員列表由排程器管理（[透過門禁排程器執行 doc-sync](../../archived/process/2026-07-21-doc-sync-through-gate-scheduler.md)）。

## 驗證

[scripts/run-gates.spec.ts](../../../../scripts/run-gates.spec.ts) 在執行器執行前拒絕無效圖，鎖定必須透過與只等結算兩種順序，鎖定 hygiene、消費方與原生 Windows 清單及其失敗語義，透過真實子程序驗證訊號終止，並證明流式輸出會立即顯示且不被緩衝。[scripts/publint-all.spec.ts](../../../../scripts/publint-all.spec.ts) 在下游產物消費方執行前拒絕缺失的公開匯出。

## 曾考慮的替代方案

- **保持聚合 job 序列**：執行更簡單，但牆鍾時間等於各獨立檢查之和，並重復啟動命令包裝器。
- **每個葉子門禁宣告一個 CI job**：暴露最大工作流並行度，但會重複 checkout、設定和安裝開銷，並在 YAML 中複製排程器清單。
- **在 shell 腳本內後臺執行子命令**：可以並行處理，但會失去各門禁計時、確定性的失敗分組和直接的訊號處理。
- **讓所有門禁繼承 stdio**：可以立即顯示進度，但會交錯普通獨立門禁的輸出，並丟失排程器可歸因的輸出記錄。流式輸出仍是顯式的門禁屬性。
- **每個包宣告一個 `publint` job**：暴露最大包級並行度，但會建立手工維護的包清單，包發生變化時就會漂移。
- **以無界並行執行 `publint`**：雖能最大限度縮短小型儲存庫的耗時，卻會拿程序數量、記憶體壓力、包 tarball 建立開銷和日誌可讀性冒險。

## 後果

由排程器支援的命令耗時取決於最慢的依賴鏈，而非各獨立門禁耗時之和，並會報告決定總耗時的門禁。無效圖會直接失敗，不會先執行其中一部分。代價是維護一個具有顯式模式清單的定製排程器。

這條驗證鏈會讓使用已驗證產物的下游消費方和 lint 延後啟動，直至共享產物檢視經確認有效且臨時暫存已清除；這些下游門禁仍可彼此重疊執行。`publint` 需要建置，卻不依賴暫存的驗證檢視，因此它會與驗證器重疊，而不會延長這條依賴鏈。

大多數門禁仍保留確定性的輸出塊。少數長時間協調器用跨門禁輸出順序和緩衝日誌換取即時診斷，而其最終狀態仍可供聚合摘要使用。

`publint-all.ts` 採用非同步執行並緩衝命令輸出，而不是即時繼承 stdio。換來的是具有穩定輸出順序的包級並行，以及用於資源調節的單一環境變數。
