# Agent Note: 具體表述說明執行者和記錄的事實

Status: implemented

[English](2026-08-09-concrete-prose-names-actors-and-recorded-facts.md) | 中文

## 問題

儲存庫行文使用了抽象的類別名稱，但讀者需要知道的具體事實各不相同。同一個名稱可能指替換操作引用的早期事件 seq、生成訊息的提供者和模型、提供上下文的呼叫方、提供某行設定的檔案，或建置某個二進位制檔案的 CI 任務。讀者必須檢視程式碼，才能知道句子承諾的是哪項事實。

用另一個寬泛名稱替換原名稱，仍會保留這種歧義。在行文整理中重新命名型別、欄位和協定成員，反而會改變與行文問題無關的約定。

## 決策

儲存庫維護的行文直接寫明目前語境下的約定需要的執行者、動作、來源、事件、欄位、檔案或程序。句子說明記錄了什麼，以及由誰或什麼記錄。寫作者還要檢查自己是否會在向同事解釋同一個問題時使用這些詞；如果不會，就替換它們。

該規則適用於 Markdown、README、活躍 Agent Note、JSDoc 與註解、提示詞、診斷資訊和使用者可見字串。審查會分別判斷每個句子，不會在整個儲存庫中用一個偏好的近義詞統一替換某個術語。編輯後的句子保留執行者、動作、條件、順序、情態、例外、歸屬、失敗行為和後果。

註解只保留附近程式碼無法表達的事實。文件停留在內容歸屬的層級；除非私有控制流或罕見實作情形會改變受支援行為、安全使用、相容性、資料完整性、安全保障或另一項持續維護的約定，否則文件不描述它們。[簡化工作流](../../../skills/dsh-find-simplifications/SKILL.md)在同時巡查程式碼與行文時應用此規則。

除非另一項獨立需求明確要求協調重新命名約定，否則確切的程式碼識別符號、公開 API、持久欄位、協定成員、型別名、帶有外部引用的標題和檔名均保持不變。它們周圍的行文直接說明其欄位或行為。生成的文件和目錄在維護它們的原始檔修改後更新。

使用 `contract`、`boundary` 或 `shape` 之前，寫作者要確認句子是否實際指更具體的規則、操作、資料結構、欄位集合、驗證點、時間點、API、型別或失敗條件。呼叫方、被呼叫方、實作方、提供者、生產方或消費方依賴的前置條件、後置條件、不變數、相容性承諾及其他義務仍可準確稱為 `contract`。真實的安全、信任、wire、程序、序列化、事務或生命週期分界仍可準確稱為 `boundary`。當結構形式本身就是主題，且欄位、schema、型別、聯合變體、檔案佈局或匯出形式等更窄的詞無法說明事即時，仍可使用 `shape`。除非另一項獨立需求要求協調重新命名，否則包含這些詞的程式碼和 API 名稱保持不變。

該決策補充了[文件層級與字數預算](2026-07-04-doc-tiers-and-budgets.zh.md)決策；後者繼續規定內容位置、文件形式和字數預算。

[禁止有歧義來源名稱](2026-08-26-ban-ambiguous-origin-label.zh.md)決策對其中一個術語部分取代了逐句判斷規則，因為該術語已經擴散到互不相關的約定中。

## 曾考慮的替代方案

**禁止一份固定詞表中的所有詞。** 不予採納：某個詞可能是確切的識別符號，也可能是另一項約定中最清楚的用詞。例如，呼叫方與被呼叫方依賴的不變數屬於真實的約定，程序邊界或協定邊界也表示真實分界。逐句審查可以找出歧義，且不會拒絕有效名稱。

**將每個抽象名稱都替換為“來源”、“起源”或“中繼資料”。** 不予採納：另一個寬泛名稱仍會讓讀者自行推測句子指的是檔案、呼叫方、事件 seq、提供者／模型組合、commit 還是建置任務。

**在修改行文時重新命名所有匹配的識別符號。** 不予採納：讓行文更清楚，不能作為進行無關 API、協定、持久格式、型別或檔案遷移的理由。這些改動需要各自的消費方審查和決策。

## 後果

文件和診斷資訊可能會多用幾個詞，但每條說明都會告訴讀者哪個值或哪個執行過程有關，無需檢視原始碼。全儲存庫行文審查必須根據句子的具體含義分類，不能盲目替換。雙語對側檔案保留相同的具體事實；生成的副本只會在其歸屬原始檔更改後重新整理。
