# Agent Note: 禁止有歧義的來源名稱

Status: implemented

[English](2026-08-26-ban-ambiguous-origin-label.md) | 中文

## 問題

由 `prove` 與 `nance` 拼成的十個 ASCII 字母術語不區分大小寫時，在儲存庫中已經承載了互不相關的含義。它曾表示來源事件引用、提供者與模型中繼資料、上下文生產方、已安裝產物身份、設定來源、瀏覽器錄製證據和釋出證明。讀者無法僅憑該名稱判斷實際記錄的事實。

現有的[具體表述決策](2026-08-09-concrete-prose-names-actors-and-recorded-facts.zh.md)要求逐句分類，且通常保留識別符號。該規則改善了各個句子，卻仍允許同一個有歧義名稱留在 API、持久化相容 fixture、檔名、生成目錄和新行文中。

## 決策

儲存庫維護的已跟蹤路徑和文字不得包含該術語的任何大小寫變體。每處使用都改為目前語境中的確切概念，例如來源事件引用、提供者中繼資料、模型身份、上下文生產方、設定來源、產物身份或已記錄證據。

該規則適用於原始碼、測試、文件、活躍 Agent Note、提示詞、快照、工作流檔案、腳本、識別符號、欄位、匯出型別和檔名。由於儲存庫尚未正式釋出，公開符號與目前持久欄位應協調重新命名，而不是保留別名。相容讀取器可以在執行時建構已退役的持久鍵，無需在維護文字中嵌入該術語。

`verify-concrete-terms` 會在 NFKC 規範化後，不區分大小寫地掃描已跟蹤檔名、符號連結目標和文字。它作為 `doc-sync` 的快速葉子門禁執行；對應測試證明行文、識別符號和路徑中的違規都會被拒絕。vendored 原始碼與凍結的 archived Agent Note 仍被排除，因為各自的儲存庫規則禁止直接編輯這些內容。

歷史持久化證據保留選定原始碼樹中的識別符號。檢查排除 `docs/persistence-changes/releases/` 下的發行版 schema JSON 和 `docs/persistence-changes/historical-formats/vN.schema.json`。在 `vN.md` 與 `vN.zh.md` 中，只有一組有效 `persistence-format-schema` 標記內的 schema 內容獲得豁免；`verify-persistence-formats` 要求該內容匹配生成的歷史 schema。人工說明、目前目錄和目前 schema 仍接受檢查。重新命名已記錄的識別符號會歪曲歷史宣告；[持久化歷史決策](2026-09-11-persistence-type-history.zh.md)負責這類證據。

本決策針對這一個術語，部分取代了舊決策中不採用固定禁詞和識別符號重新命名的選擇。舊決策仍適用於其他抽象語言，也仍負責要求根據每處使用的具體含義選擇替代名稱。

## 曾考慮的替代方案

**繼續只做語義審查，不設定機械禁令。** 不予採納：該名稱已經擴散到互不相關的約定中，逐句審查無法防止它在識別符號、fixture 或檔名中再次出現。

**用 `origin` 或 `source` 等單一總括術語替換所有位置。** 不予採納：新的寬泛名稱仍會混淆事件引用、模型中繼資料、建置身份和已記錄證據。

**豁免全部識別符號、持久欄位和生成檔案。** 不予採納：呼叫方和目前生成的參考資料會繼續傳播已退役名稱。預釋出政策允許協調重新命名，而舊格式解析器可以在不保留字面術語的情況下繼續提供讀取相容性。範圍受限的歷史證據豁免保留已記錄宣告，但不豁免目前名稱或人工指引。

**掃描 vendored 與 archived 內容。** 不予採納：vendored 內容透過同步流程更新，而 archived Agent Note 是凍結記錄。明確排除兩者，可以使本政策與對應的歸屬規則保持一致。

## 後果

呼叫方使用更具體的公開名稱；目前錄製使用提供者中繼資料，而不再使用已退役的 assistant 欄位。歸屬符號變化後，生成目錄和錄製快照必須重新整理。相容程式碼仍負責讀取已退役的持久欄位。

以後在明確排除範圍之外新增的匹配項會使 `doc-sync` 失敗，並報告對應路徑或行號。審查仍需先判斷預期含義再選擇替代名稱；透過門禁只能證明受檢查內容中不存在該術語，不能證明替代名稱足夠精確。
