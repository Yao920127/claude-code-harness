# Agent Note: 以證據驅動的效能最佳化工作流

Status: implemented

[English](2026-09-06-evidence-driven-performance-skill.md) | 中文

## 問題

效能工作可能改善某個獨立階段，卻把成本轉移到另一階段、保留更多資料，或跳過必要行為。歷史 PR（Pull Request）描述也可能保留已放棄的實作和估計值，因此照搬其表面方案可能恢復已否決的設計，而不是解決目前瓶頸。

## 決定

[dsh-speed-up-perf skill](../../../skills/dsh-speed-up-perf/SKILL.md)（技能）引導廣泛調查收斂到範圍明確、可測量的使用者路徑。它結合聚焦的成本歸因與獨立計時的後端和瀏覽器端點、合成負載分佈、可比較的冷態／熱態與保留記憶體條件，以及收緊預算的負向對照。下方歷史證據區分已合併實作、已被替代的提案、作者報告的測量值和估計值。

該工作流要求獨立於計時的行為證據：模型可見日誌、持久化代際和釋出規則、流順序、取消及 dispose（資源釋放）仍是必須滿足的要求。獲授權的私有語料檢查僅提供聚合負載啟發；提交的輸入和釋出的產物包含合成材料。最佳化 PR 攜帶收緊後的預算，而前置基準測試層可以保護已測基線並保持獨立可合併。

[工作階段開啟效能門禁決策](../testing/2026-09-04-session-open-performance-gate.zh.md)繼續負責測試通道機制與校準。[簡化 skill](../../../skills/dsh-find-simplifications/SKILL.md)繼續負責以刪除為目標的調查。兩者均未被替代：本工作流增加面向效能的候選選擇、測量可比性和停止條件，而不替換它們的決策。

## 考慮過的替代方案

**先最佳化可疑程式碼，再測量。** 否決，因為區域性複雜度不能確定主要使用者成本，也無法證明改善或防止迴歸。

**把歷史加速方案當作可複用處方。** 否決，因為表示方式、所有權和生命週期要求會變化。歷史證據用於產生假設；目前生產路徑與新的測量決定改動是否適用。

**只使用微基準測試，或只使用端到端計時。** 否決，因為獨立階段可能遺漏被轉移的工作，而總計時無法定位原因。兩者都需要在與所選問題相符的範圍內使用。

## 後果

該 skill 不增加執行時行為、基準測試實作或新的 CI 策略。其驗證涵蓋文件／連結一致性和 skill 中繼資料；後續每項最佳化在其所屬位置提供可執行測量與功能證據。有限的情境／修復範圍防止廣泛效能請求演變成無關的架構重寫。
