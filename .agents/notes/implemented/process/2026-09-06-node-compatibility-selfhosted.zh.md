# Agent Note: 自託管 Linux 上隔離的 Node 相容性作業

Status: implemented

[English](2026-09-06-node-compatibility-selfhosted.md) | 中文

## 問題

即使儲存庫已經選擇現有的自託管 Linux 池，Node 22.19、24.9 和 26 相容性作業仍消耗託管 Linux 分鐘數。將版本安裝器移到持久化共享機器上可能造成工具目錄衝突，並讓生成的快取檔案積累在執行器清理範圍之外。

## 決策

[CI](../../../../.github/workflows/ci.yml) 將 Linux 故障切換變數應用於這三個作業，要求作者不是 Dependabot，且非 fork 的頭部儲存庫與目前儲存庫相同。標準託管退回仍然可用。這些條件約束本作業，而非所有可進入該池的工作流。儲存庫身份和 fork 狀態均顯式保留，以便在儲存庫設定改變時保持本作業的信任限制；現有兄弟選擇器不屬於本次遷移範圍。`blacksmith` 故障切換取值下的分支放棄這些條件：它面向臨時的 Blacksmith 執行器，因此儲存庫身份與 fork 狀態不參與門控（見 [blacksmith 故障切換支路筆記](2026-09-09-blacksmith-failover-leg.zh.md)）。

臨時工具快取以重複下載 Node 為代價，換取並行執行器與 Node 版本之間的隔離。僅用於 setup-node 的 [ESM 預載入模組](../../../../scripts/ci-compatible-toolcache.mjs) 在 action 程序內指定快取：Actions 執行器在讀取步驟設定後會覆蓋保留的環境變數。實際執行的路徑檢查拒絕執行器臨時目錄之外的安裝；相容性程序不繼承預載入設定。pnpm 保留現有的私有安裝目錄和持久化內容定址 store。編譯快取與 node-gyp 標頭檔案在首次呼叫 pnpm 前就使用執行器臨時目錄。不引入全域 Node 符號連結或系統軟體包變更。託管作業保留其工具與軟體包快取；自託管作業不恢復或上傳託管軟體包快取。執行器負責作業之間的臨時目錄清理，共享映像提供原生 npm 軟體包所需的編譯器和 Python 前置依賴。

[故障切換手冊](2026-07-26-ci-failover-runbook.zh.md) 仍擁有儲存庫信任與池切換規則。[序列參考決策](2026-07-21-serial-cross-platform-ci-reference.zh.md) 仍擁有 master 排程規則。除相容性作業的執行器選擇外，這兩個決策都未被取代；兩者均保持活躍。

## 曾考慮的替代方案

**讓所有相容性作業保持託管。** 這避免額外的共享主機負載，但繼續為不需要不同作業系統或架構的 Linux 執行時檢查付費。

**使用共享 Node 安裝或全域版本管理器連結。** 這些作業必須並行執行不同的 Node 版本。可變的共享連結會使選中的版本取決於另一作業的時序。

**在同一改動中遷移 Python SDK 作業。** 其 setup-python 安裝和透過全域 pip 安裝 uv 需要單獨的隔離證據。這個短暫的託管作業不是 Node 最佳化的必需部分。

## 後果

每個可信 PR（Pull Request）會為池增加三個作業；每個作業保留門禁並行度一，包括需要建置的 Node 22 條目。9 月 6 日的清單報告了 31 個 Linux 註冊實例，而不是 31 臺獨立機器。共享虛擬機器的資源爭用和下載延遲仍是上線風險；變數保留託管恢復路徑。測試清單、檢查名稱和 master 排程保持不變。

## 驗證

聚焦的[工作流回歸測試](../../../../scripts/ci-compatible-selfhosted.spec.ts) 執行真實的路由表示式和環境設定。移除 fork 條件的負對照使託管退回斷言失敗。它檢查維護者重跑 Dependabot PR、儲存庫不匹配、fork 標誌、停用變數以及執行器範圍內的快取路徑。

實施基線上的成功熱備執行 33984559660 提供 Linux Node 24.19.0 和 Windows Node 24.20.0 基線證據。Linux 作業 101359402557 使用資料捲上執行器專屬的臨時目錄和工具目錄。只讀能力探測 34012679056 (job 101431064925) 報告 Linux x64、192 個線上邏輯 CPU、GCC/G++ 13.3、Make 4.3 和 Python 3.12.3。Python 3.10 缺失，進一步說明 SDK 需要單獨設定。PR 執行 34013779750 驗證了自託管 Linux 上的 Node 22.19.0、24.9.0 和 26.8.1，包括設定、可執行檔案路徑檢查、相容性測試和 post actions。可執行檔案位於各執行器的 `_temp/node-compat-toolcache/node/<version>/x64/bin` 下；完成的作業分別耗時 228s、94s 和 101s。這些觀測證明版本與路徑相容性，而非獨佔主機的容量保證。
