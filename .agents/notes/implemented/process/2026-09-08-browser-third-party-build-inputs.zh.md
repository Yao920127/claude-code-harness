# Agent Note: 瀏覽器第三方庫作為建置輸入

Status: implemented

[English](2026-09-08-browser-third-party-build-inputs.md) | 中文

## 問題

預建置瀏覽器外掛的第三方實作已經隨 JavaScript 分發，但生產 NPM 依賴仍讓安裝器另外下載這些庫並解析其對等依賴（peer dependency）。React 只在建置期宣告時，安裝器可以為這些額外依賴選擇與瀏覽器產物不同的 React 版本。`use-sync-external-store@1.2.0` 與 `@tanstack/react-virtual@3.14.9` 都支援目前 React 18；問題不要求升級 React。

## 決策

瀏覽器專用第三方依賴屬於 `devDependencies`，包括動態外掛內聯的實作、靜態瀏覽器庫的輸入，以及由 Web 殼提供共享實例的 React。該規則部分取代[已釋出依賴分類](2026-08-26-published-dependency-faces.zh.md)對普通第三方宣告的保留策略；該文件繼續規定包的選擇範圍、Host 值依賴與 Cordis 實例身份。

依賴分類器從原始碼匯入和 JSX 收集建置輸入。Host 執行時可達的第三方庫優先歸入 `dependencies`；額外 Node 建置入口也必須納入檢查。原始碼中的純型別引用不產生 Host 執行時依賴。設定中繼資料與共享 Host 匯出的既有分類保持不變。

NPM 欄位不決定瀏覽器打包方式。動態外掛繼續內聯私有庫，並從平臺模組表讀取 React 等共享模組；靜態瀏覽器庫繼續保留裸匯入及樣式，由最終 Vite 建置處理。靜態包是 Web 殼的建置輸入，不承諾獨立安裝後具備二次打包所需的全部依賴。原始碼建置需要開發依賴；安裝已釋出的 Web 產物不需要它們。

許可證分類以交付內容為準。真實瀏覽器建置設定的依賴解析同時覆蓋動態外掛與 Web 殼；解析到的第三方實作仍計入[執行時披露](2026-07-30-generated-third-party-notices.zh.md)，即使清單將其列為開發依賴。測試工具、純型別匯入和建置工具不會僅因處於 `devDependencies` 而算作分發程式碼。

## 考慮過的替代方案

**為生產安裝額外宣告 React，或強制覆蓋對等依賴。** 這保留了瀏覽器不使用的額外安裝圖，且並未使安裝副本成為瀏覽器共享實例。

**把靜態庫的所有依賴提前內聯。** 這會改變 Vite 對第三方分塊、快取和 CSS 的處理；依賴分類不需要改變這些建置行為。

**把帶 Client 的包的全部第三方依賴移走。** 雙面包仍可能在 Host 載入庫，例如 ZIP 輸出所用的 `fflate` 和 RPC 驗證所用的 `zod`；這些安裝關係必須保留。

**按清單欄位直接劃分許可證披露。** 瀏覽器程式碼的交付與安裝器是否下載同名包不是同一事實，不能因此取消對分發程式碼的許可證檢查。

## 結果

生產依賴不再為純瀏覽器實作重複安裝第三方庫。React 與 React DOM 保持同一建置版本，外掛繼續消費 Web 殼的共享實例。分類測試同時約束瀏覽器 dev-only、Host 優先和修復冪等；釋出檢查拒絕 React 安裝洩漏，瀏覽器產物驗證獨立覆蓋實際模組載入。

分類檢查保留原始碼執行方式。許可證解析也不能依賴已有 `lib/` 或寫入建置輸出；其測試覆蓋真實解析、純型別擦除、資源引用與缺失依賴。獨立消費靜態包或公開型別的開發者需要自己提供相應建置依賴；本決策不增加獨立瀏覽器庫的支援承諾。
