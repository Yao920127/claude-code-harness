# Agent Note: Playwright 影片錄製連續瀏覽器演示

Status: implemented

[English](2026-09-08-playwright-video-gif.md) | 中文

## 問題

截圖分鏡省略了動畫的中間幀，也可能遺漏短暫的進度指示。提高 GIF 編碼幀率無法補回源圖片未記錄的運動。連續錄製提供這些畫面，同時由可用的瀏覽器控制工作流負責互動。

## 決策

[錄製 skill](../../../skills/record-browser-gif/SKILL.md) 繼續優先使用可用的瀏覽器控制工作流。該工作流提供 `recordVideo` 時，在同一受控上下文中用影片捕捉中間幀；否則由該工作流截圖。只有瀏覽器控制不可用時，才使用儲存庫已宣告的獨立 Playwright 作為備用方案。錄製影片時，顯式設定相同的 viewport 與錄製尺寸，避免 Playwright 預設縮放到 800×800 以內。錄製程式保留頁面影片物件，等待上下文關閉，再儲存完整 WebM 並編碼。

同一編碼器接受影片檔案或截圖目錄。影片輸入選擇一個連續區間，應用明確標註的播放倍率，並延長末幀。JSON 摘要記錄源影片時長、所選區間、倍率、末幀停留時間，以及編碼後的尺寸、時長、幀數和大小。與輸入模式不符的選項及無效區間會失敗。保留原影片供檢查；裁剪與變速不能證明模型回應延遲。

[證據鏈決策](2026-08-08-browser-gif-evidence-chain.zh.md)規定瀏覽器控制方式選擇、應用狀態隔離、真實模型執行、準確提交歸屬及釋出驗證。影片在這些規則內增加更高取樣幀率的錄製選項。失敗錄製的畫面不得用於成功執行。

## 曾考慮的替代方案

**只提高編碼幀率。**重複少量截圖不能捕捉更多運動。截圖仍適合明確的狀態停留、使用者要求的分鏡，以及不支援影片的瀏覽器工作流。

**安裝獨立錄製器或錄製桌面。**儲存庫已經宣告 Playwright。另一套驅動增加安裝與版本管理成本；桌面錄製可能包含無關視窗和個人狀態。

## 後果

連續錄製保留中間狀態，因此檢查者必須檢視所選區間是否包含敏感內容，以及畫面是否易讀。原始影片佔用額外臨時空間，編碼時可能需要裁剪或縮放以滿足位元組上限。關閉上下文是成功錄製的一部分，不是可選清理。

編碼器的本地 Python unittest 測試呼叫真實 ffmpeg 和 ffprobe，檢查時序、調色盤順序、截圖停留、選項拒絕、覆蓋保護和大小限制。測試依賴 skill 要求的媒體工具，需顯式執行；儲存庫 CI 不預裝這些媒體程式。產品演示還會執行 PR 建置後的伺服器與真實模型流程。
