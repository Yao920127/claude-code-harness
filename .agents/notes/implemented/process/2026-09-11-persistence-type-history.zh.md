# Agent Note: 目錄內的持久化型別歷史

Status: implemented

[English](2026-09-11-persistence-type-history.md) | 中文

## 問題

持久化事件可以保留相同的載荷型別表示式，但其引用的型別已經改變。只審閱宣告文字無法暴露所有巢狀結構變更。摘要能檢測差異，卻不能說明它是新增可選資料還是更改已有屬性。重新生成目錄也不能證明作者已審閱持久化方面的影響。

## 決策

一個規範化型別模型提供可讀持久化目錄、完整 schema 清單和包含傳遞引用的逐根摘要。根標識邏輯工作階段頭、物理 JSONL 頭行、事件封裝以及每個儲存庫內宣告的事件。原始碼位置、別名名稱、普通註解和屬性順序屬於摘要之外的展示細節。歷史記錄保留原始碼檔案路徑而不包含行號，因為其選定的原始碼樹與目前工作樹不同。被引用型別和遞迴型別參與結構比較；不透明值保留明確的覆蓋限制。顯式相容性標記依照[訊息源歸屬策略](2026-09-17-persistence-schema-review.zh.md)攜帶納入指紋的策略資料。

專用的[持久化變更記錄](../../../../docs/persistence-changes/README.zh.md)將確認繫結到每個受影響根的變更後摘要。生成的伴隨檔案儲存完整的變更後 schema。初始記錄覆蓋所有根；後續記錄為每個根指定前驅。前驅的變更後 schema 提供下一次的變更前 schema。驗證拒絕有歧義的歷史，並要求目前原始碼匹配最終記錄狀態，無需查詢 Git 歷史或遠端服務。

自動分類允許可選事件體新增、事件體屬性從必選改為可選，以及普通事件新增保持同一版本。當雙方儲存的 schema 均宣告支援時，受限的[訊息源歸屬策略](2026-09-17-persistence-schema-review.zh.md)也允許新增符合條件的生產者 kind。[事件載荷版本規則](../../../../docs/persistence-changes/README.zh.md#compatibility-rules) 允許在原樣保留所有舊分支時增加更高的數字載荷版本，並記錄舊讀取器限制。其他結構變更需要升版本決策，並在該記錄中包含遞增的頭部版本。[格式版本流程](../../../../docs/cookbook/adding-a-session-format-version.zh.md)繼續負責相鄰遷移工作。每個結構差異都需要顯式記錄，包括允許保持同一版本的新增。

新文件型別保留歷史型別轉換的相容性說明和證據。Agent Note 保留機制層面的決策，不積累單次確認清單。雙語對中的機器宣告保持相同，且只解析一次。

回溯性的[發行版本比較](../../../../docs/persistence-changes/releases/README.zh.md)使用獨立的 `persistence-release` 型別和固定 tag 清單。它們保留變化後的 schema，並重建相鄰版本，包括未變的 tag。早期版本先於這些確認規則，因此其分類只提供資訊，觀察到的版本號不會為滿足目前最低版本要求而被改寫。歷史解析保留可選的 surface 操作；目前解析器和確認鏈仍保持嚴格。這一區分允許近似回填，同時不會將其變成目前變更的授權。

[格式參考](../../../../docs/persistence-changes/historical-formats/README.zh.md)為低於寫入器常數的每個歷史整數版本保留完整目錄。目前寫入器繼續使用現有生成目錄。覆蓋範圍由常數推導，而非手工維護的版本清單，因此推進寫入器必須歸檔其前驅。歸檔命令複製已驗證的目前目錄，保留從根型別可達的定義，移除原始碼行號，並拒絕覆蓋已有快照。同一格式內可能新增事件或改變可選載荷，因此來源檢查點保持明確；這些快照不授權目前變更，也不聲稱遷移安全。機器 schema 與精確生成的 schema 區間保留歷史識別符號和原始碼包路徑；目前術語與包路徑檢查仍覆蓋周圍的人工說明和目前目錄。

記錄命令從儲存庫內範本生成雙語目錄和一致性記錄。作者可以將兩種語言的概述、相容性說明和實際驗證證據作為結構化輸入。生成過程提供識別符號、摘要和快照，不編造相容性說明或測試結果。結構化檢查輸出保留非零失敗結束代碼，並報告獨立於可讀描述的穩定變更種類。

顯式更新可重新整理尚未接受的末端記錄，無需刪除其人工說明。它根據剩餘歷史重新計算轉換，並拒絕基線、已有依賴方的記錄或已定稿記錄。目錄不會推斷定稿檢查點之外的審閱接受狀態，因此作者保留已接受記錄並新增後繼。

### 定稿檢查點

定稿獨立於釋出事實記錄接受狀態。末端記錄不能複用原有頭版本遞增，繼續授權對已寫入資料進行破壞性變更。因此，[狀態記錄](../../../../docs/session-format-status.zh.md#finalization-record)要求完整相容性檢查點：已接受記錄的語義保持鎖定，目前原始碼的相容變更透過新記錄繼續，破壞性變更要求更高的寫入器版本。現有分類器與未知事件協定保持不變。這不會新增執行時欄位，也不能檢測未變宣告後隱藏的行為變化。對目錄內真源與檢查點的協同修改仍須審閱。

## 考慮過的替代方案

**對展示的宣告計算雜湊。** 被引用的定義可能改變，而展示的表示式保持不變。規範化傳遞型別使這些變更可見，同時排除原始檔和別名調整。

**將每次確認繫結到一個整體摘要。** 無關事件的變更會使已審閱的確認失效。逐根歷史將失效範圍限制在受影響的頭部或事件，完整清單仍然保留覆蓋範圍。

**與 PR 的 merge-base 或釋出版本檢出目錄比較。** 這些輸入需要目前目錄之外的歷史。保留的變更後 schema 為本地檢查和 CI 提供相同的比較輸入。沒有 schema 的雜湊無法支援自動結構分類。

**把每次摘要變化都視為升版本。** 可選事件體新增、必選改可選，以及普通事件新增不一定需要新的持久化版本。保守分類區分這些情況，並將相容性說明交給審閱。

**從型別推斷行為，或允許任意相容性豁免。** 型別圖無法證明回放語義。檢查器僅覆蓋可檢測結構，並拒絕低於機械分類要求的決策；它不聲稱能夠檢測純行為變更。

## 影響

作者為每次已接受轉換中的每個受影響根保留一份快照，並在整合該根的競爭變更時解決歷史分叉。獨立根可以演進而不改寫無關確認。[實操手冊](../../../../docs/cookbook/reviewing-persistence-type-changes.zh.md)提供本地編寫與驗證流程。

檢查證明目前目錄的一致性，不證明已接受歷史從未被改寫，也不證明說明在語義上正確。`unknown` 等不透明值內部的隱藏結構仍然無法檢測。本機制不新增執行時摘要或工作階段格式欄位。現有[版本機制](../architecture/2026-08-10-session-log-version-mechanism.zh.md)和[已釋出代際遷移](../architecture/2026-08-31-released-session-format-migrations.zh.md)決策保留其獨立的執行時保證。
