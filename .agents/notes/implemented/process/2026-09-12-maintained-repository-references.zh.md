# Agent Note: 維護中的儲存庫引用

Status: implemented

[English](2026-09-12-maintained-repository-references.md) | 中文

## 問題

歷史證據需要可辨認的發行版本、PR 和測量執行標識。維護中的檔案也面向公開原始碼主頁，而原生髮布使用工作流提供的儲存庫身份。具體提交引用和與部署繫結的組織 URL 無法表達這一區分。

## 決策

歷史證據使用發行 tag 以及 PR、執行或 job 標識，目前儲存庫檔案使用相對連結。[引用檢查](../../../../scripts/verify-repository-references.ts)掃描已跟蹤檔案和未被忽略的新檔案。Vendor 原始碼與凍結的 Agent Note 保留既有排除規則；活躍筆記和歷史發行記錄仍參與檢查。

檢查器針對本地 Git 物件庫解析十六進位制候選值，僅拒絕能明確標識提交的值。標識 blob 的配對雜湊、schema 摘要、無關十六進位制值，以及解析到不同物件標識的十六進位制分支名仍然有效。組織 URL 檢測與既有儲存庫連結策略共享解碼和規範化邏輯。

原生原始碼清單標識公開原始碼主頁。工作流打包期間，[原生打包器](../../../../native/system/scripts/pack-release.mjs)將工作流儲存庫投影到臨時輸入，讓 npm 可信釋出可以核驗產物身份。它保留原始碼清單，生成的 tarball 也不在釋出時改寫。沒有工作流上下文的本地打包保留公開原始碼中繼資料。

## 考慮過的替代方案

**拒絕每個十六進位制字串。** 持久化 schema 和雙語配對合理使用雜湊。Git 物件型別驗證將提交引用與這些值區分開。

**僅檢查新 diff 行。** 策略適用於每個維護中的檔案，包括既有引用。完整掃描也會在釋出前發現暫存或尚未跟蹤的新增檔案。

**刪除釋出所需的中繼資料。** 原生髮布仍需要工作流儲存庫身份。在打包階段投影該身份，可以移除原始碼中的字面量，同時保持 npm 核驗的身份不變。

## 影響

檢查器禁止網路取得，包括 Git 部分克隆的延遲取得。它檢查本地所有可用的提交物件，包括不可達的歷史 PR 頭；缺失的物件無法匹配。因此，包含額外 PR 物件的工作區可能檢測到 CI 完整歷史克隆中不存在的引用。引用驗證建立維護中檔案的策略，不證明遠端 tag 不可變或歷史相容性。已釋出的原生 tarball 在 npm 的 Repository 中繼資料中顯示工作流儲存庫；原始碼清單保留公開原始碼主頁。

Vendored 宣告連結儲存庫內的原始碼位置，同時保留上游名稱、許可證和未變的 vendor 清單。
