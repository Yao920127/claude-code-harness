# Agent Note: 作者審批積分

Status: implemented

[English](2026-09-16-author-approval-credit.md) | 中文

## Problem

審批策略需要讓作者經驗貢獻足夠的積分，使有經驗的作者與一位普通審閱者能夠共同滿足兩分要求。

## Decision

[審批策略](../../../../.github/review-ownership/README.md)為作者在本儲存庫中每個已合併 PR 計入 0.011 分，達到 100 個 PR 時以 1.1 分封頂。歷史查詢在找到 100 個匹配 PR 後停止。僅靠作者積分仍不足以透過審批，阻塞性審閱仍會阻止透過。

## Alternatives considered

**保留 150 個 PR 時封頂 0.6 分的規則。** 在沒有程式碼所有權加分的情況下，該上限與普通審閱的一分相加仍無法滿足要求。

## Consequences

沒有程式碼所有權加分時，一次普通批准與 91 個已合併 PR 的作者積分相加即可滿足要求；90 個則只有 1.99 分。較低的計數上限減少了高貢獻作者所需的歷史遍歷。已合併 PR 數量衡量貢獻歷史，而非審閱品質。

## Verification

策略測試覆蓋積分低於、達到及超過上限的情況、90/91 個 PR 的審批閾值、僅靠作者積分不能透過、分頁，以及顯示值舍入為兩分但實際低於閾值的情況。
