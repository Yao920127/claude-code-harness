# Agent Note: 從完整 dsh 版本派生 Desktop 測試版本

Status: implemented

[English](2026-09-16-desktop-release-version-derivation.md) | 中文

## 問題

用更新通道名替換 dsh 預釋出標識會丟失基礎釋出身份，並改變 SemVer 排序。只有日期無法區分同一基礎版本的多次測試建置。

## 決策

[Desktop 釋出規則](../../../../apps/desktop/README.zh.md#release-versions)在 production 中保留完整 dsh 基礎版本，並從該基礎版本派生帶日期和序號的測試版本。派生出的版本[作為參數傳給打包](2026-09-21-desktop-build-version-as-input.zh.md)，不寫入清單；它從 dsh 基礎版本派生，因此下一次測試釋出不會追加第二個日期字尾。

固定 Nightly feed 是分發地址，與版本派生獨立。現有用戶端繼續使用該地址，允許預釋出更新並禁止降級。test 分發不釋出無字尾基礎版本。操作者分配序號前檢查已有釋出記錄和物件。

安裝版更新物料決策繼續規定私有身份和資料隔離。其中的 Nightly 命名範例不定義測試版本規則。歷史釋出回執和已凍結歸檔保留為實際建置的證據。

## 考慮過的替代方案

**用 nightly 替換 alpha、beta 或 rc。** 這會丟棄基礎預釋出標識，並可能排在其後續版本之上，阻止更新到預期版本序列。

**按預釋出標識重新命名 feed。** 已安裝用戶端仍查詢原有 feed，將無法取得替換後的釋出。

**為修復錯誤版本號而開啟降級。** 全域允許降級會改變常規更新的安全性。受影響安裝使用手動安裝檔；僅修正 feed 無法遷移它們。

## 結果

測試建置具有明確的基礎版本和建立日期，production 版本身份保持一致。簽名與上傳仍驗證最終各包版本相等。安裝版更新物料分配接受帶日期的預釋出版本；保留的舊 Nightly 物料仍可讀取以供審計。
