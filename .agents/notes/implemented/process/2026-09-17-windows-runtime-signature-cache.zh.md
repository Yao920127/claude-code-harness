# Agent Note: Windows 執行時簽名快取

Status: implemented

[English](2026-09-17-windows-runtime-signature-cache.md) | 中文

## Problem

Windows 打包每次都會重新生成未簽名的原生依賴。為未變化的 Python 和 LibreOffice 檔案簽名會重複執行硬體權杖操作和時間戳請求。每個公鑰驗籤任務單獨啟動 PowerShell，也會重複程序初始化。

## Decision

按原始內容、公開憑證、SignTool 位元組、簽名腳本位元組和快取格式快取完整已簽名執行時檔案。保留有效廠商簽名。快取命中後，透過私有暫存副本核對輸入記錄、已簽名檔案摘要、Windows 信任、時間戳和設定的憑證，再恢復目標檔案；無效快取項直接失敗，不自動修復或退回到硬體簽名。完整快取項原子釋出，並行釋出衝突時保留已有有效項。

快取僅在目前 Windows 帳戶內共享。要求固定本地磁碟、目前帳戶所有權及私有目標目錄 DACL；拒絕帶連結或被重定向的路徑。同帳戶執行的程式仍受信任。顯式遷移複製透過完整性檢查的完整快取項，不修改源目錄，也不替換已有有效項。同一輸入和策略鍵下的時間戳位元組不同，不構成替換理由；每次實際恢復仍驗證 Windows 信任。

預設快取位於使用者目錄下，與帳戶已有簽名狀態放在一起。AppData 不適合作為此預設位置，因為 MSIX 啟動器可能將新檔案重定向到私有包儲存，使不同程式啟動的相同 worktree 使用不同快取。獨立建置儲存仍可指定經過驗證的顯式目錄。

透過 Windows 獨佔檔案控制代碼序列執行每個完整簽名階段及快取維護操作。鎖分別覆蓋預檢、主要執行時簽名、應用執行時簽名及產物生成，編譯和準備仍可並行。等待者在取得鎖後重新檢查快取。階段所有權與持久保留的硬體嘗試互鎖具有不同生命週期：關閉階段控制代碼釋放競爭鎖，而硬體失敗或中斷保留現有嘗試證據，絕不構成自動重試授權。

公鑰驗籤按每批 32 個檔案分組，最多同時執行四個程序。要求每個請求路徑都有一條順序對應的結果，並等待失敗批次中的所有程序退出。每次硬體簽名後仍立即驗籤，透過後才開始下一個簽名請求。

在階段鎖內，使用有界工作池恢復不同的快取命中目標，完成後置驗籤後才序列簽署未命中項。首次恢復、驗籤或審計失敗時停止派發，並在釋放所有權前等待在途任務結束。可設定的預設並行為四：對 134 個主要執行時檔案及 228 個應用檔案的熱快取實驗中，恢復加後置驗籤的合計中位耗時從單任務的 226.18 秒降至四任務的 63.22 秒；八任務為 42.18 秒，但實測 CPU 消耗增加 25.5%，峰值提交記憶體從 387 增至 631 MiB。這些三輪測量使用精確重建的未簽名輸入、真實 Windows 驗籤和拒絕硬體呼叫的回呼；不包含完整打包、冷信任狀態或硬體未命中。

[主要執行時決策](../feature/2026-09-14-desktop-primary-runtime.zh.md) 繼續定義執行時內容、廠商簽名保留和執行檢查。[釋出決策](../architecture/2026-08-25-electron-desktop-packaging-and-updates.zh.md) 繼續定義釋出身份和簽名。兩者均未被取代。快取必須保留受監督預檢、每使用者簽名互鎖、單檔案硬體呼叫、已簽名內容清單和最終打包執行時驗證。

## Alternatives considered

**多檔案硬體簽名。** 主要執行時決策記錄了 SignTool 在首個檔案失敗後仍繼續處理的行為。透過快取減少重複硬體操作，可以保留現有停止語義。

**分離簽名的提取與附加。** 快取完整檔案可以避免給打包流程新增 PE 簽名處理程式碼。其額外磁碟佔用可測量，且限於建置儲存。

**僅複用整個已簽名執行時製品。** 該方案還可以省去解壓和複製，但需要標識組裝流程及依賴圖。逐檔案快取可以在應用程式碼或單個依賴變化時複用其餘未變化的原生依賴。

**僅使用逐項鎖。** 它能避免同一鍵的重複簽名，卻無法協調不同檔案、預檢或安裝器簽名對同一硬體權杖的存取。階段級所有權覆蓋這些呼叫，不在無關編譯期間持鎖。

**按快取年齡過期。** 年齡本身不能說明帶時間戳的簽名無效。重新檢查目前 Windows 信任可以保留驗證要求，同時避免週期性重複未變化的硬體簽名。

## Consequences

原生輸入未變化的重複建置不再為快取覆蓋的檔案呼叫硬體簽名，但仍執行預檢和最終制品簽名。內容或簽名策略變化時快取未命中。損壞、不完整、不可信或時間戳不合格的快取項必須失敗，不替換目標檔案，也不重試硬體。並行釋出和程序中斷不能暴露不完整快取項或損壞其他建置的檔案。

同一主機上的完整 Windows x64 簽名建置測量空共享快取與另一個全新 worktree 的複用：硬體呼叫從 379 次降至 17 次，耗時從 37:03 降至 13:45，362 個執行時快取項全部命中。快取恢復耗時 132 秒，其中目前信任驗證佔 130 秒。兩輪均透過最終執行時 smoke 及簽名產物檢查。下載內容在計時前準備好；每種情境均為一次完整執行。另一次受控原生檔案變更產生未命中、命中、未命中的結果，合計兩次硬體呼叫；它驗證快取失效，不代表依賴版本升級。安裝器執行和更新驗收仍需單獨進行。

## Risks

快取佔用本地磁碟，並依賴建置帳戶控制快取檔案及記錄。它不是用於不可信遠端快取的分發格式。簽名驗證仍依賴 Windows 信任服務；快取命中不構成清除簽名互鎖或重試失敗權杖操作的授權。即使預檢成功，時間戳服務故障仍可能中斷冷建置。

不執行自動容量淘汰。顯式維護等待階段所有權，在刪除檔案前先將完整快取項移出已釋出名稱；中斷的暫存目錄仍可與已釋出項區分。執行時摘要區分實際釋出和衝突保留，並將快取驗證耗時與簽名耗時分別記錄；它不測量整個安裝檔的驗證成本。
