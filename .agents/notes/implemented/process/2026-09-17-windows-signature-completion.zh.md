# Agent Note：分離 Windows 硬體簽名與時間戳處理

Status: implemented

[English](2026-09-17-windows-signature-completion.md) | 中文

## 問題

合併的 SignTool 命令把時間戳失敗報告為簽名失敗。重試會重複存取硬體，而把所有時間戳錯誤都視為私鑰操作結果不確定，又需要管理員恢復。公開時間戳請求可以在不使用權杖的情況下獨立失敗。

## 決策

對私有 PE 副本僅簽名一次，不請求時間戳。只有命令成功且 Windows 驗證設定憑證的主簽名後，才釋放硬體互鎖。硬體或主簽名驗證失敗保留互鎖；任何路徑都不自動恢復互鎖。不支援追加簽名。

從固定的已簽名檔案生成新副本並請求時間戳，不傳遞簽名憑證。只有正常退出但返回失敗或警告時才允許再次嘗試：最多呼叫三次，間隔為一秒和兩秒。啟動失敗、終止狀態不確定、儲存變化和驗籤失敗會立即停止。預檢整體 60 秒期限包含這些操作，不保證每次子程序都能獲得完整期限。

要求 Windows 信任、時間戳和憑證身份均透過驗證。使用設定的 SignTool 刪除私有副本的未簽名屬性，再比較完整的規範化位元組。刪除警告僅在所有位元組未變時接受。僅比較憑證無法排除由同一憑證籤署的不同內容；全檔案相等檢查避免自行實作 PE 或 ASN.1 規範化器。

SignTool 在私有臨時目錄中使用保留原副檔名的短檔名。存取硬體前檢查生成的最長路徑，日誌記錄原檔案與暫存檔案的對應關係。目標可以位於另一個卷：將已驗證位元組複製到目標旁的私有目錄，比較摘要，重新檢查原檔案，再在同一卷內重新命名。隨後驗證提交後的位元組。建置帳戶必須擁有受信任的儲存和目標獨佔存取權。

時間戳嘗試耗盡後，停止打包和排隊任務，不再次呼叫硬體。清理暫存目錄前，將失敗證據複製到受監督執行目錄；證據儲存或審計失敗時保留暫存目錄。最終產物驗籤和釋出完成檢查仍是必需步驟。[第一方執行時決策](../feature/2026-09-14-desktop-primary-runtime.zh.md)負責執行時內容與上游簽名。

## 考慮過的替代方案

**重試合併簽名命令或按診斷文字分類。** 結束代碼和在地化文字無法確定私鑰操作結果。分離操作避免重複存取硬體。

**複用失敗的時間戳輸出。** 失敗程序可能已部分修改檔案。每次嘗試均從相同的已驗證主簽名位元組開始。

**所有操作都在目標旁暫存。** 即使原路徑未超限，巢狀依賴的暫存路徑也可能超出 SignTool 限制。短工具路徑和同捲髮布分別滿足不同要求。

## 影響

故障測試覆蓋互鎖保留、獨立時間戳重試、佇列拒絕、憑證隔離、內容替換、目標變化、長路徑和證據儲存失敗。僅使用公開操作的驗收覆蓋 EXE、DLL、PYD 和 NODE 檔案，包括先失敗後成功及跨捲髮布。真實受監督簽名預檢已透過；完整安裝檔對比仍需單獨驗收。此決策不確定或修復時間戳服務的網路故障。

DigiCert [支援分開簽名與新增時間戳](https://knowledge.digicert.com/solution/troubleshooting-timestamping-problems)。Microsoft 記錄了 [SignTool 命令及結束代碼](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool)。設定的工具和規範化實作均參與簽名快取身份計算。
