# Agent Note: 禁止新增到 unknown 的型別斷言

Status: implemented

[English](2026-09-19-no-unknown-casts.md) | 中文

## 問題

經由 `unknown` 的型別斷言會移除 TypeScript 對原始值與後續斷言型別之間的相容性檢查。生產程式碼可能因此掩蓋錯誤的介面，測試也可能聲稱不完整的 fixture（測試前置資料）滿足某項服務型別。現有用法還包括合理地將無型別的解析結果拓寬為 `unknown`，這種情況可以改用顯式的 `unknown` 宣告。

儲存庫中的斷言分佈在許多相互獨立的包和測試中。一次性全部移除會把執行規則的決策與無關的型別、fixture 重新設計混在一起，使每處替換的行為更難審查。

## 決策

第一方 JavaScript 和 TypeScript 禁止新增直接斷言到 `unknown` 的表示式，範圍包括測試、fixture、基準測試和腳本。規則覆蓋 `as unknown` 和 `<unknown>` 兩種語法，也覆蓋帶括號的目標型別，以及直接包含 `unknown` 成員的聯合目標型別。`unknown` 宣告仍然有效：外部資料可以透過 `const value: unknown = JSON.parse(text)` 進入，再交給其宣告的解析器處理後使用。同程序內已有型別的值仍遵循不得新增不必要執行時驗證的現有規則。

[檢查器](../../../../scripts/verify-no-unknown-casts.ts)透過 `pnpm run verify-no-unknown-casts` 執行，使用 TypeScript 語法樹。它掃描已跟蹤的原始檔和未被忽略的未跟蹤原始檔；vendored 原始碼和已凍結的歸檔 Agent Notes 保留各自維護規則要求的排除項。檢查器忽略註解、字串和 `unknown` 宣告。

現有斷言使用精確基線記錄，鍵由儲存庫相對路徑、斷言語法 token 的 SHA-256 摘要及出現次陣列成。基線修改只能刪除條目或減少次數；審查者必須拒絕新增檔案、新增指紋和增加次數。基線之外新增或變化的斷言以及陳舊的基線條目都會使檢查失敗；整個檔案的放行或數量預算不能授權替換成新的技術債。`--prune` 機械地刪除條目或減少次數，存在新增違規時拒絕寫入。沒有可新增新例外的命令。

檢查器加入 CI 靜態模式和主模式，以及[門禁執行器](../../../../scripts/run-gates.ts)中的本地 `hygiene` 和 `check-all` 設定。現有斷言仍是明確記錄的技術債，由所屬模組透過適當的型別、解析器或 fixture 修改來移除。

## 考慮過的替代方案

**先移除所有現有斷言，再執行規則。** 不採用，因為清理涉及互不相關的服務、協定解析器和測試替身。精確記錄現有例外後即可開始執行規則，無須把批次替換視為型別安全的改善。

**放行整個檔案或設定儲存庫級數量限制。** 不採用，因為兩者都允許用新增斷言替代已刪除的斷言。基線識別每個現有斷言，並拒絕增加出現次數。

**在文字中搜尋 `as unknown`。** 不採用，因為註解和字串可能包含這段文字，而空白、token 之間的註解和尖括號語法可能讓實際斷言躲過文字模式。

## 影響

所屬模組必須先解決型別轉換問題，才能將斷言改為未登記的形式或移至未登記的檔案。運算元 token 的任何變化，包括識別符號重新命名或引號、尾隨逗號、括號修改，即使不改變執行時行為，也會使指紋失效。僅修改格式空白和註解不會改變所記錄的 token。刪除斷言後還須縮減其基線條目，防止無效例外悄然累積。

透過檢查只說明沒有未登記的、直接到 `unknown` 的型別斷言，其中包括被直接 `unknown` 成員吸收的聯合目標型別。它不證明整體型別安全，也不解析型別別名或交叉型別。JavaScript JSDoc `@type` 斷言、`unknown[]`、`Promise<unknown>` 等包含該型別的型別不屬於這條語法規則。將斷言替換成 `any`、另一種未經檢查的斷言，或僅隱藏轉換的輔助函式，都沒有解決底層型別問題。
