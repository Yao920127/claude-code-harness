# Agent Note: ACP 作為僅面向自動化的協定

Status: implemented

[English](2026-07-23-acp-automation-only-protocol.md) | 中文

> 僅面向自動化的邊界仍然有效。[標準 ACP v1 自動化控制](../feature/2026-08-22-standard-acp-automation-controls.zh.md)僅取代本說明中僅支援提示詞的方法、設定、MCP、更新和生命週期清單；它不會把 ACP 恢復為 UI。

## 問題

ACP（Agent Client Protocol）橋接層已經變成第二套互動式產品 UI。它將持久事件轉換為編輯器卡片、終端中繼資料、diff、計劃、標題、推理（reasoning）、命令、模式、模型和權限選擇器、工作階段導航以及面向人類的詢問。這些職責與 TUI 和 Web 用戶端重複，同時將自動化傳輸層與 UI 服務、持久化查詢、展示策略和編輯器特定約定耦合在一起。

ACP 仍有一個有用的職責：另一個 agent（智慧代理）或自動化控制器可以啟動 harness 程序、建立隔離工作階段、傳送文字或範圍狹窄的受支援內聯圖片、接收已提交的文字／圖片回答、取消工作並回答權限請求。跨程序 ACP subagent 後端依賴這個標準協定邊界。

快照套件使移除工作更復雜。大多數 ACP 情境測試的是組裝後的 agent 後端，而不是 ACP 展示層；如果隨編輯器橋接層一起刪除整個套件，就會丟失大量無金鑰行為測試。

## 決策

`@deepseek-ai/dsh-acp` 是位於 [`packages/acp/acp`](../../../../packages/acp/acp/README.zh.md) 下、獨立於 `ui` 包組的自動化傳輸層。其公開協定包含標準自動化控制，而非展示：持久工作階段建立／列出／恢復／關閉、每工作階段一個在途提示詞、模型設定、stdio／HTTP MCP 掛載、已提交語義更新、取消、並行工作階段和一次性權限請求。提示詞按協定順序保留文字與受支援光柵圖片，資源連結則展平為方括號文字引用；橋接層仍拒絕附加目錄、音訊、嵌入資源、格式錯誤或空提示詞、未知工作階段和重疊提示詞。

圖片能力必須真實，而不能只看結構：只有持久附件儲存存在，且設定的確切提供者／模型解析後明確支援圖片輸入時，`initialize` 才會公佈該能力。每個提示詞都會在非同步准入前快照確切路由、嚴格解碼全部圖片塊，並在釋出使用者事件前把完整批次委託給 `AttachmentStore.saveImages()`。即使下一輪設定並行變化，同一快照仍驅動已准入輪次。取消會在任何非同步工作前預留並中止准入槽位，使提示詞在已經啟動的寫入停穩後才結算，而且絕不釋出遲到訊息；提示詞進入 Agent inbox 前既不會取消，也不會等待無關的 Agent 工作。已經完成的內容定址寫入可能保持不可達，因為對去重儲存執行破壞性復原並不正確。可由呼叫方修正的圖片策略失敗會對映為無效參數，路由查詢、儲存損壞和持久化失敗則仍屬於內部故障。

橋接層只發出已提交的語義事實。每個工作階段使用一條 Promise 鏈，在非同步重新讀取並驗證助手圖片引用、將其轉換為 ACP base64 交付時，保持 reasoning、assistant 塊、工具生命週期、設定和用量更新順序；物件缺失或損壞會使提示詞交付失敗，而不是變成預留位置。原始分片、待辦事項、計劃、標題、重試標記、終端中繼資料、diff、位置和展示投影不會進入 ACP wire。標準模型和 reasoning 選項、列出／恢復／關閉以及 stdio／HTTP MCP 屬於自動化控制；工作階段載入／刪除／fork、命令、模式、plan 評審、終端、用戶端檔案系統操作和麵向人類的詢問仍不受支援。

保留一次性 `session/request_permission`。它是為橋接層擁有的 agent 提供的機器策略通道，而不是面向人類的審批 UI：應答者只接受橋接層目前工作階段對映中登記的同一 agent 物件；不屬於橋接層目前 agent 的請求或未關聯具體呼叫的請求會繼續委派；RPC 失敗則對映為故障時預設拒絕的 `unavailable` 結果。用戶端可選擇允許一次、拒絕一次或取消，橋接層絕不會將該回應轉換為持久授權。詢問策略仍歸審批 seam 及其生產者所有；[`dsh-subagent-acp`](../../../../packages/subagent/subagent-acp/README.zh.md) 會以程式化方式使用該通道。

應用組裝包含必需 agent 核心、持久化、檢查點策略、派生工作階段查詢和 ACP 傳輸層。ACP 橋接層直接讀取持久化以生成標準可恢復摘要；它不公開命令、工作階段引用、plan mode、權限選擇器或使用者問題展示介面。

傳輸層呼叫 agent、工作階段和審批的介面服務，而不依賴具體的 agent loop（智慧代理迴圈）。工具執行仍留在 harness 內；ACP 絕不會把 shell 執行委派給編輯器。stdout 只承載分幀 JSON-RPC，因此 app 不掛載 stdout logger，橋接層也不會 monkey-patch 程序輸出。

斷開連線與外掛 dispose（資源釋放）共享同一個經記憶化的完全停穩邊界。傳輸關閉無論成功還是失敗，都會取消提示詞准入和 agent、排空有序輸出、將待處理提示詞以已取消狀態結算、dispose 每個由橋接層擁有的 agent，並等待迴圈和工作階段清理完成。建立流程如果在與關閉的競態中落敗，就會 dispose 其尚未釋出的 handle。

## 快照邊界

ACP 快照套件仍會啟動組裝後的 ACP 範例，並保留用於鎖定後端行為的情境。從該套件移出的只有透過已刪除 UI 方法驅動的情境。標準恢復會還原持久 Agent，但不會重放 transcript UI；當 headless SDK 協定本身是測試物件時，語義檢查點恢復覆蓋仍可使用其範例。

協定與生命週期測試會鎖定停止原因編解碼器、版本協商、真實圖片能力、新工作階段建立、有序文字／圖片准入、資源連結展平、寫入前驗證全部成員、持久事件中不含內聯 base64、拒絕空提示詞或不受支援的提示詞、基於同一 agent 物件的權限歸屬、多工作階段隔離、在有序輸出後結算提示詞、經過驗證的助手圖片交付、准入期間取消且不產生遲到 followup 或取消無關 Agent 工作、排除進入 inbox 前的無關失敗、傳輸關閉失敗、ACP 專屬過載清理，以及拆卸完全停穩。組裝後的無金鑰快照透過可執行 ACP 範例傳送一張真實內聯 PNG，並在工作階段日誌中只固定其持久引用。建置產物冒煙測試與真實 stdio 冒煙測試會拒絕混入 stdout 的額外輸出。`session/new` 中在真實 stdio 關閉競態中落敗的分支仍豁免覆蓋率要求，因為記憶體傳輸層無法復現這一順序；該分支會 dispose 尚未釋出的 handle，而周邊 dispose 測試會鎖定無遺留資源不變式。

## 考慮過的替代方案

**在 Web 達到同等能力前，繼續將 ACP 作為編輯器 UI。** 不予採用，因為這會留下兩套需要演進的互動約定，並使編輯器約定繼續存在於自動化邊界中。

**透過嚴格的服務邊界保留早期編輯器橋接層。** 不予採用，儘管該橋接層正確使用了介面服務、工具自有的 render intent、審批與使用者互動應答者、harness 自有執行，以及保持 stdout 純淨的組裝。其終端卡片是經過能力門控、僅用於展示的 Zed `_meta` 投影，並提供文字退回，而非使用 ACP `terminal/create`，因此 shell 執行從未離開 harness。該投影從穩定的逐呼叫 id 派生每個展示用終端 id，以避免衝突；由於純結果展示器接收的是內容塊，而不是結構化退出資訊，它會從渲染後的狀態標記中恢復結束代碼或訊號。標記往返測試和顯式的無能力 `console` 退回測試鎖定了這兩項約定。這些邊界保持一致，卻無法讓編輯器卡片、工作階段導航、設定選擇器和麵向人類的詢問成為自動化協定應有的職責。

**用私有 subagent RPC 替換 ACP。** 不予採用，因為 ACP 已經提供型別化、可互操作的程序協定，並由跨程序 subagent 後端使用。

**隨其他互動功能一起移除機器權限請求。** 不予採用，因為自動化父 agent 必須回答子 agent 的一次性策略決策；這是 agent 之間的控制流，而不是展示層。

**刪除 ACP 快照套件，或在本次變更中遷移每個情境。** 不予採用，因為大多數情境測試後端且仍有價值，而完整的 harness 遷移是一項獨立的測試變更。只有透過已刪除的 UI 方法驅動的情境才離開該套件。

**只要 ACP SDK 具有圖片塊就公佈圖片支援。** 不予採用，因為協定詞彙不能證明目前部署可以持久化位元組，也不能證明設定的確切路由接受視覺輸入。初始化時能力未知即為 false；提示詞准入會重新檢查即時路由。

**把內聯圖片和助手圖片展平為標記，或把 ACP base64 持久化進工作階段事件。** 不予採用，因為標記會靜默丟失模型／使用者意圖，base64 則會讓持久日誌變成二進位制儲存。ACP 在傳輸邊界把自身協定塊與現有持久 `ImageBlock` 引用相互轉換。

**為 ACP、MCP 和 Web 建立通用 RichContent 服務。** 不予採用，因為核心 `ContentBlock` 與附件 seam 已經擁有共享契約。每個入口只保留協定解析、能力證明與生命週期編排；共享批次限制和圖片驗證留在 `AttachmentStore.saveImages()` 中。

## 結果

ACP 具有適合 agent 與自動化的精簡約定，而 TUI 和 Web 擁有面向人類的互動與展示。該包注入的服務、依賴、協定分支和生命週期狀態更少，也不再將自身定位為通用編輯器入口。

自動化用戶端收到已提交訊息、reasoning、通用工具、設定和用量事實，而不是 token 增量或結構化工具 UI。標準列出／恢復／關閉和工作階段設定覆蓋自動化生命週期，同時不增加導航、transcript 重放、標題或其他人工展示。

因此，後端快照測試仍與 ACP 傳輸層耦合，儘管對於受測行為而言，該傳輸層只是附帶因素。
