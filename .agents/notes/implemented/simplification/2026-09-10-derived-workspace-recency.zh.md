# Agent Note: 獨立於手動順序派生 Workspace 最近更新順序

Status: implemented

[English](2026-09-10-derived-workspace-recency.md) | 中文

## 問題

可編輯且按活動置頂的列表即使沒有拖拽，也可能與顯示的時間不符：較舊的 Session 遲到後，會被提升到已觀察到的較新 Session 之前。重複輸入同一份完整列表仍會保留這個逆序。歷史上的[側邊欄順序決策](../../archived/feature/2026-08-11-workspace-sidebar-order-and-folding.md)讓手動排序和最近更新共用一份可編輯順序，以便切換模式時保留位置。這個取捨無法滿足按時間瀏覽的需要。

## 決策

最近更新是目前 Session 摘要的純投影：普通行按 `updatedAt` 降序排列，時間相同時按 Session id 排序。目前選中的空白新工作階段在首條提示詞落實前排在普通行之前。分組、Ungrouped 和單列表檢視採用相同策略。重新載入和摘要遲到不需要檢視儲存中的已觀察時間歷史或提升事件。

手動排序讀取瀏覽器持久化的 Session 顯示順序。拖拽 Session 會一次性記錄所有有效記帳、在對應的瀏覽器本地記帳中應用移動，並原子地選中手動排序。直接進入手動排序同樣會從目前時間順序凍結所有有效記帳。返回最近更新會丟棄手動佈局；再次進入手動排序時，從目前時間戳確定的順序開始。[工作階段置頂與歸檔規則](../feature/2026-09-18-session-pin-and-sidebar-archive.zh.md)說明缺失成員補齊，並讓歸檔顯隱不影響儲存的成員關係。尚無摘要的新成員會等待摘要，而已經儲存的位置在摘要暫時缺失時仍會保留。Workspace 成員關係和 Workspace 分組順序仍由 Host 擁有；拖拽 Workspace 分組仍會呼叫 Host 重排序操作。

目前選中的空白新工作階段是在兩種基礎順序之後應用的顯示不變式：它保持首位且無法發起拖拽。即使 Workspace 流正在重連，手動排序也會持久化已觀察到的空白行位置，並保留其他所有已儲存成員，直到完整基線允許對帳。若等待基線後才記錄該位置，首條提示詞先到達時就會丟失它。首條提示詞會移除空白狀態；此後，手動排序保留原有首位並允許拖拽，最近更新則按提示詞時間戳派生其位置。側邊欄摺疊或搜尋替代列表主體時，排序訂閱和對帳仍保持掛載。

持久化 key 儲存分組方式、展開狀態和手動排序位置。保留有效記帳 key 時會移除持久化的已觀察時間資料。時間準確性由目前中繼資料負責：缺少提示詞中繼資料的冷摘要可能退回到建立時間，這與檢視排序相互獨立。

## 考慮過的替代方案

**保留活動提升，並在重連時再次排序。** 摘要遲到和中繼資料修正也會發生在一次連線內。僅在重連時修復仍會讓時間順序依賴觀察先後。

**切換模式時恢復獨立的手動佈局。** 用舊位置替換可見列表會讓進入手動排序的結果出乎預期。在模式變化時重置佈局，讓手動排序只表示暫停目前排列。

**持久化第二份時間順序。** 目前時間戳已經決定該順序。第二份帳本保留了同步和恢復工作，卻沒有表達獨立的使用者選擇。

**禁止在最近更新中拖拽。** 在提交拖拽時切到手動排序，可以保留既有操作入口，併為編輯後的順序提供明確模式。取消或未產生有效移動的拖拽保持所選模式不變。

## 後果

手動排序暫停目前列表的自動排列。預設模式為最近更新，重新載入保留所選模式和目前手動位置。按時間瀏覽放棄持久化的拖拽例外。檢視儲存擁有 Session 手動位置，但不擁有活動時間戳；Host Session 記帳順序不參與本瀏覽器的顯示順序。

已歸檔的側邊欄記錄保持為凍結的歷史證據；其摺疊和 Workspace 順序決策不在本次修改範圍內。沒有活動記錄擁有被替代的共享順序策略。

## 測試

元件迴歸覆蓋較舊記錄首次到達、時間修正和退回、摘要遲到、已丟棄佈局的隔離、原子模式切換、空白行插入與禁拖、首條提示詞轉換、側邊欄摺疊時的對帳、重新載入，以及拖拽後自動選中手動排序。錄製工作階段 Web 情境在實際釋出組合中驗證持久化位置、原生拖拽、分組與單列表檢視、固定首位的空白項及重新載入。既有摺疊案例保留臨時空白行配額。
