# Agent Note: 將模型設定保留在子代理目錄之外

Status: implemented

[English](2026-09-16-subagent-catalog-membership-only.md) | 中文

## 問題

父目錄用於發現直接子級。記錄子級建立時的 LLM provider 和 model，可以在不開啟子級歷史的情況下保留不可變設定，但發現與導航的消費者不讀取這些值。建立設定也不能確定實際處理某次請求的模型。

## 決策

目錄事件與投影保留子級身份、建立時間、模式和標籤。`establishCatalogChild(parent, childHeader, descriptor)` 只接收發布成員關係所需的值。子級組合與請求歷史各自保留模型設定；目錄載入不增加子級觀察或模型查詢。

本決策僅替代[父目錄決策](../architecture/2026-09-01-parent-owned-subagent-catalog.zh.md)中的建立模型中繼資料選擇。該記錄繼續說明成功釋出、事件順序、fork 隔離和投影所有權。未釋出的可選中繼資料宣告及其專屬預期輸出不予保留；遷移基線中已有的歷史 Session 世代保持完整。

## 考慮過的替代方案

**保留可選建立中繼資料，供未來展示使用。** 可選欄位仍需要持久化 schema、快取失效、寫入方和回放預期輸出。需要不可變建立路由的消費者可以證明這些成本合理，但目前消費者沒有此需求。

**在發現過程中讀取子級歷史。** 這會增加與子級歷史規模相關的工作，卻不幫助確定成員關係。需要展示請求實際使用模型的功能，可以獨立觀察子級已有的 `modelSelection` 投影。

## 後果

目錄不提供歷史建立路由記錄。重新引入此記錄，需要存在無法透過已有子級組合或請求投影滿足需求的消費者。初始讀取、即時更新、重連和授權繼續由現有模組負責。目錄與建立測試、已記錄 Session 回放以及兩套 SDK 的預期輸出驗證了成員關係仍可在沒有額外中繼資料的情況下發布。
