# Agent Note: 工具密集後端續聊的效能基線

Status: implemented

[English](2026-09-06-backend-continuation-performance.md) | 中文

## 問題

開啟一個 Session 不能衡量長工具對話後重復準備模型請求、執行更多工具密集輪次或發現多個非活動 fork 子工作階段的成本。[Session 開啟門禁](2026-09-04-session-open-performance-gate.zh.md)覆蓋首屏歷史和啟用，但有意停在新的模型工作開始前。它的文字與推理負載也不包含歷史工具呼叫參數和大型工具結果。

## 決定

[agent-continuation 基準](../../../../benchmarks/agent-continuation/agent-continuation.bench.ts)增加三個情境組，包含一個已釋出 profile 變體，不修改產品實作。它們透過生產追加、流累積和持久化 API 建構目前代際的 Zstandard Session。獨立播種程序在測量前生成確定性源資料；每個樣本將其複製到私有根目錄，並啟動新的已編譯純 Node worker。輸入不來自錄製 Session、環境儲存庫、網路、私有 Harness 主目錄或已部署 GUI。

共享歷史包含 800 個已完成的雙步驟輪次，每輪四次工具呼叫，工具結果為 2,048 字元：共 13,600 個事件和 5,600 條對話訊息。每條助手回覆攜帶推理、文字和緊湊流記錄；請求工具的回覆還攜帶分片參數。播種資料使用固定時間戳和 id。即時合成回覆使用真實迴圈的時鐘和 id，不覆蓋程序全域狀態。

| 案例 | 計時操作 | 終點 |
|---|---|---|
| 請求歷史 | 在不計時的冷恢復後，向工具密集歷史順序提交 40 個純文字輪次，然後 flush | 空閒 Agent，已完成全部 40 次模型請求；分別報告輪次和最終 flush 時間 |
| 工具續聊 | 冷恢復，順序執行 20 個輪次，每輪八次可安全並行的合成工具呼叫和一條最終回覆，然後 flush | 空閒 Agent，已完成 40 次模型請求和 160 次工具執行；分別報告恢復、輪次和最終 flush 時間 |
| 已釋出 SDK 工作流 | 使用 sdk-minimal profile 啟動已建置 dsh，順序提交 100 個輪次，每輪八次真實檔案檢視呼叫，然後關閉 SDK | SDK 收到 200 條助手訊息和 800 個成功檔案結果；包含 Loader 啟動、stdio JSON-RPC、持久化和關閉 |
| 子工作階段目錄 | 透過真實 Session 查詢和 subagent 服務，兩次觀察一個冷 parent 目錄 | 兩份完整的 16 子級目錄，parent 觀察已釋放；每個儲存的 fork 子級繼承 80 個工具密集輪次，發現只讀取 parent fact |

工具執行管線、請求準備、這些服務所需的 Session 投影、持久化和目錄觀察均保留生產程式碼。只有模型介面卡和有界工具體是合成的。介面卡只保留請求計數，不保留請求物件，因此 fixture（測試前置資料）不會製造不斷增長的保留成本。順序輸入使每個空閒區間對應此 worker 提交的唯一請求；這不代表並行輸入時可以把空閒狀態推廣為逐訊息完成 API。

SDK fixture 透過 profile patch 顯式插入 `fs-local` 和 `str_replace_editor`。這使經校準的檔案檢視負載不依賴[極簡 profile 只提供 shell 的預設組合](../simplification/2026-09-03-minimal-profiles-persistent-shell-only.zh.md)。檔案讀取、計時終點和預算保持不變。

五個樣本報告原始壁鐘時間、CPU 使用者態／核心態時間、峰值 RSS、終點計數及總壁鐘時間的最小值、中位數和最大值。每份彙總報告還在計時 worker 退出後記錄 CPU 型號、可用並行度、平臺、架構以及 Node/V8 版本。預算約束未經舍入的中位數。續聊還相對已初始化 Host 測量保留堆記憶體：計時操作前後各執行兩次顯式 GC，中間讓出一次事件迴圈，空閒 Agent 始終可達。因此該增量包含常駐歷史 Session 和即時追加，而不只是新輪次。GC 與資源釋放不計時；flush 計時。請求歷史的記憶體基線從恢復後開始，只作診斷。目錄峰值 RSS 僅作診斷；沒有保留堆預算聲稱衡量已經釋放的父工作階段觀察。

父程序為每個子程序設定 60 秒上限，獨立檢查超時、訊號、退出狀態和報告，等待程序關閉，並在失敗後刪除私有根目錄。Context 和 Agent 在 finally 中釋放。播種程序無法預熱被測程序的快取。不強制清除檔案系統快取：冷指新程序，不指冷物理儲存。

## 校準證據

實作參考為 Apple M4 Pro、macOS arm64、Node 24.19.0 上的 PR #3537 合併結果。兩輪獨佔的五樣本執行使用相同播種資料，沒有產品最佳化。下表時間單位為毫秒；原始碼期望值向上取整至實測各輪中位數以上，而不是施加尚未實作的最佳化目標。

| 案例 | 第一輪原始總時間 | 第二輪原始總時間 | 中位數 | 歷史 M4 期望 | 歷史縮放預算 |
|---|---|---|---|---:|---:|
| 請求歷史 | 209.134, 210.333, 208.959, 236.355, 238.685 | 222.833, 213.911, 208.089, 211.494, 209.137 | 210.333 / 211.494 | 220 | 550 |
| 工具續聊 | 358.953, 324.790, 318.861, 320.119, 322.896 | 324.280, 321.952, 340.409, 325.470, 324.312 | 322.896 / 324.312 | 340 | 850 |
| 子工作階段目錄 | 318.730, 309.006, 311.404, 308.565, 310.105 | 308.670, 310.030, 280.086, 303.084, 284.829 | 310.105 / 303.084 | 320 | 800 |

續聊保留約 22.295 MiB；原始碼期望值為 23 MiB，預算為 28.75 MiB。SDK 時間期望值使用現有[校準輔助函式](../../../../benchmarks/support/calibration.ts)：2× 共享 CI 時間比例和 1.25× 波動餘量。請求歷史使用[請求凍結校準](../simplification/2026-09-06-agent-request-freeze-evidence.zh.md)中的直接託管期望值，不乘以 2× 比例。記憶體只使用 1.25× 餘量。比例繼承現有通道的校準，並非這些案例的新 Linux 實測值；runner 特徵變化時仍需 CI 證據。基線預算保護實測實作；更緊預算屬於有測量依據且保持行為的修復。

獨立的純 Node 請求歷史 CPU profile 在一次 211.300 ms 操作中，將 132.876 ms 取樣自身時間歸因於 buildRequest 呼叫的 deepFreeze。這把重複遍歷已凍結歷史定位為聚焦調查目標，不是已證實的最佳化結果。目錄首次／重複時間分別報告第一次和第二次 parent 目錄觀察。

已釋出 SDK 變體完成 100 個輪次、200 次請求和 800 次真實檔案讀取。五樣本 smoke 總時間為 1,521.773、1,463.465、1,689.701、1,365.485 和 1,417.106 ms（中位數 1,463.465 ms）；完整套件重複執行報告 1,596.183、1,784.536、2,120.082、1,405.365 和 1,355.894 ms（中位數 1,596.183 ms）。1,700 ms 參考期望對應 4,250 ms CI 預算。重複執行中未改變的服務案例也變慢，因此這是可變主機負載下的驗證，不是放寬其獨佔校準預算的依據。SDK 程序使用白名單環境和私有主目錄／工作區。40 秒截止時間啟動 SDK 關閉；所有路徑等待同一個記憶化 close Promise，並早於外層 worker 的 60 秒截止時間。Profile 時間包含啟動、全部輪次和關閉，分別報告；不把父程序 CPU 或堆指標當作伺服器端記憶體。介面卡不為外部模型服務商序列化請求。

首次 Linux x64 CI 測量使用 `VM-7-113-ubuntu-ci-10` 和 Node 24.18.1（run 34017868081，attempt 1，job 101444810498）。SDK 中位數為 2,753.441 ms，預算為 4,250 ms；工具續聊保留堆中位數為 22.274 MiB，預算為 28.75 MiB。請求歷史與工具續聊時間預算失敗：分別為 785.498 ms 對 550 ms、1,077.285 ms 對 850 ms。未修改的 Session 重開 open 階段也以 31.6 ms 對 30 ms 失敗。Attempt 2，job 101447076381 (run 34017868081) 在同一提交和未修改預算下透過全部基準，但使用 `VM-7-113-ubuntu-ci-29` 和 Node 24.19.0。門禁執行器隱藏成功子程序的輸出，因此該次執行只提供透過結論，不提供原始中位數。Runner 與 Node 版本同時變化，不能把差異僅歸因於資源爭用，也不能宣稱已獲得穩定的重複 CI 校準；這些證據不改變預算或共享比例。

目錄案例使用顯式的 900 ms CI 期望時間，僅乘現有 1.25× 餘量，得到 1,125 ms，不再應用參考機器比例。標準雙 CPU 託管 `ubuntu-24.04` 的 run 34033336380，job 101487280801 報告未修改目錄實作的五個總時間為 797.374、883.157、858.364、790.569 和 904.579 ms：中位數 858.364 ms 超出歷史 800 ms 預算。上表 320 ms M4 期望保留為歷史證據，不是 CI 測量。此方法與 Session 重開使用的顯式 CI 校準一致（CI 期望為 50 ms）；共享係數、負載、計時終點和產品實作均不改變。確定性對照與實測判定使用同一斷言：未經舍入的錄製中位數透過 1,125 ms 並被 800 ms 拒絕，合成的 1,400 ms 中位數則被 1,125 ms 拒絕。更快主機上的透過結果不能校準標準託管 runner。

工具續聊同樣使用 900 ms CI 期望時間與 1.25× 餘量（1,125 ms）。未修改的實作在標準雙 CPU 託管 run 34034524265，job 101490056074 中報告總時間為 917.007、892.091、887.839、905.659 和 898.252 ms：中位數 898.252 ms 超出歷史 850 ms 預算。340 ms M4 期望保留為歷史證據。與實測判定相同的斷言在 1,125 ms 下接受未經舍入的錄製中位數，在 850 ms 下拒絕它，並拒絕合成的 1,400 ms 退回。負載、計時、產品程式碼和 28.75 MiB 保留堆預算均不改變。

基線請求歷史使用 600 ms CI 期望時間與 1.25× 餘量（750 ms）。未修改的實作在標準雙 CPU 託管 run 34035306987，job 101492163630 中報告總時間為 618.598、618.606、582.035、582.304 和 581.832 ms：中位數 582.304 ms 超出歷史 550 ms 預算。220 ms M4 期望保留為歷史證據。與實測判定相同的斷言在 750 ms 下接受未經舍入的錄製中位數，在 550 ms 下拒絕它，並拒絕合成的 900 ms 退回。此校準僅針對未最佳化基線；負載、計時、產品程式碼和記憶體預算均不改變。

## 考慮過的替代方案

**重複現有遷移和首次開啟變體。** 拒絕：現有十二個案例已經區分只讀準備與可寫釋出。這些案例使用目前代際並開始或繼續實際模型工作，或者列舉語料集合而不是開啟單個 Session。

**只測 deriveMessages。** 拒絕：它的增量快取不包含完整請求凍結、介面卡分發、即時追加或持久化。實際順序請求保護 Agent 每一步支付的成本。

**只使用投影快取行已預熱的無種子子工作階段。** 拒絕：該路徑繞過正文觀察，遺漏 fork 子工作階段的精確繼承切點要求。原始校準有意不掛載可選投影快取，報告帶種子的退回路徑。parent 自有目錄的測量觀察持久 parent fact；子級正文讀取只屬於已記錄的校準實作。

**將最佳化及其目標預算與首次測量一起應用。** 拒絕：純基線層可以獨立合併，並在歸因或實作改變前記錄目前負載。環境變數不能覆蓋原始碼常數。

## 後果

通道增加三個情境組中的四個案例、二十個測量 worker 和兩個播種程序。整合續聊案例覆蓋恢復、完成模型／工具工作及持久化 flush。已釋出 SDK 工作流額外包含 profile 啟動、SDK 傳輸、真實檔案工具和關閉；只有模型介面卡是合成的。它建立新 Session，因為公共 SDK prompt API 建立而非恢復已儲存身份。兩條路徑均不包含網路模型延遲、服務商專屬請求序列化、可選使用者外掛、壓縮、失敗工具結果、影象、取消或瀏覽器渲染。功能測試仍負責事件內容、不可變訊息、工具語義、fork 譜系以及只讀／可寫副作用；終點計數防止把跳過的工作當作測量結果，不重複這些斷言。

本記錄補充而非取代 Session 開啟門禁的隔離和校準依據。不退役任何現有活躍決策。
