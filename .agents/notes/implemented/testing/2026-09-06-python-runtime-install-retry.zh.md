# Agent Note: Python runtime 依賴安裝的有界重試

Status: implemented

[English](2026-09-06-python-runtime-install-retry.md) | 中文

## 問題

Python runtime 通道的 `Install (immutable)` 步驟在每個目標上執行 `pnpm install`，安裝期原生建置下載會從 nodejs.org 取得 Node 標頭檔案。該端點會間歇性停滯：2026-09-06，託管的 `node24-macos-x64` 單元在 `fs-ext` 建置的 node-gyp 下載對 nodejs.org 丟擲 10 秒連線超時後的 `ConnectTimeoutError` 時失敗，使不可變安裝中止。該停滯屬於外部、瞬時問題；此前通道除人工重跑作業外沒有任何恢復手段。

## 決策

安裝步驟對 `pnpm install --frozen-lockfile` 最多重試三次（共三次嘗試，失敗間隔十秒），並在每個平臺上以 `bash` 執行（託管 Windows 映像自帶 Git Bash）。任意一次成功立即結束步驟；每次嘗試都會失敗的檔案鎖檢查或原生建置錯誤仍會在有界預算後使步驟失敗。這借鑑了 Wine 通道已記錄的有界傳輸策略，而不引入映像，因為這些安裝還會解析原生 addon，其二次下載來源同樣重要。

## 已考慮的替代方案

**提高連線或作業超時。** 不採用：觀察到的停滯是 10 秒後的連線超時，而對該失敗模式適用的恢復是攜帶新連線的整體重試；端點故障時更長的超時仍然失敗。

**為 Node 標頭檔案下載使用映像。** 推遲：Wine 通道的映像只續傳自己的歸檔；Python runtime 通道需要按目標設定映像及自己的驗證權威，而瞬態故障的重試並不需要這些。

**人工重跑失敗作業。** 不採用為該通道的常設補救：它消耗一整個通道週期且停留在手動層面；有界重試吸收瞬態故障，持續性故障仍會響亮失敗。

## 後果

一次 nodejs.org 瞬態停滯最多付出兩次額外安裝嘗試（約二十秒），確定性的安裝缺陷仍會在預算後失敗。所有目標共享同一重試路徑，安裝診斷仍為步驟內捕捉的 pnpm 輸出。
