# Agent Note: Publint 測試子程序繼承執行通道期限

Status: implemented

[English](2026-09-07-publint-test-subprocess-lifetime.md) | 中文

## 問題

publint 腳本測試自設五秒同步子程序期限，低於 Windows 覆蓋率通道現有的 90 秒測試與掛鉤預算。已捕捉的 Windows 失敗在有效和無效 JavaScript/CSS 案例中都報告空退出狀態；有效案例耗時 5028 毫秒。這些日誌沒有記錄子程序錯誤和訊號，因此不能證明 ETIMEDOUT。期限不匹配是共享測試缺陷，不是產品改動導致失敗的證據。

## 決策

[publint 測試](../../../../scripts/publint-all.spec.ts) 使用現有 Execa 依賴和 Vitest 測試上下文訊號，不設獨立子程序超時。[工作流](../../../../.github/workflows/ci.yml) 和[覆蓋率參數所有者](../../../../scripts/coverage-partitions.ts) 繼續負責預算。這與[子代理清理測試](2026-09-07-subagent-teardown-test-budgets.zh.md) 採用相同的通道所有權規則，但不改變其清理邏輯。

每個直接 Node 子程序建立後立即登記，取消請求傳送 SIGKILL；清理先等待所有已登記子程序的結果與 close 事件，再刪除私有包根目錄。預期結束代碼斷言之前先診斷程序錯誤、取消、超時標記、訊號及捕捉的輸出流。正常結束代碼一仍是 publint 負例的有效結果。五個案例均透過隔離的釋出夾具呼叫真實腳本。

## 曾考慮的替代方案

- 增大五秒常數：另一個區域性常數仍會覆蓋執行通道預算。
- 預載入或替換 publint：兩者都不能驗證冷啟動腳本匯入與真實發布檢查。
- 傳送終止訊號後立即返回：程序與管道關閉必須先於夾具刪除。

## 後果

以就緒狀態為前提的期限迴歸測試取消兩個存活子程序，並檢查兩個關閉事件、PID 已不存在及有用的診斷資訊。缺失工作目錄驗證啟動錯誤診斷。獨立並行測試程序驗證臨時目錄隔離和子程序排程。Windows 終止與檔案系統證據仍由原生 Windows CI 負責；macOS 結果不能證明這些保證。產品程式碼、工作流預算和快照輸出均不變。
