# Agent Note: 子代理清理測試繼承執行通道的時間預算

Status: implemented

[English](2026-09-07-subagent-teardown-test-budgets.md) | 中文

## 問題

Windows 覆蓋率執行 (run 34085536250, job 101628739668) 為測試和掛鉤提供 90 秒預算，卻報告了兩個清理失敗。ACP 忽略 EOF 測試讓清理與自設的五秒定時器競爭。真實 Codex 測試將掛鉤預算覆蓋為 30 秒。這兩個期限都不用於驗證產品延遲保證。Codex 測試正文在掛鉤失敗前已經觀察到程序樹退出；日誌未指出究竟是上下文釋放、HTTP 關閉還是臨時目錄刪除超出了掛鉤預算。

## 決策

[ACP 測試](../../../../packages/subagent/subagent-acp/tests/subagent-acp.spec.ts) 在執行通道的測試預算內等待清理完成，然後檢查真實子程序的結果。失敗清理先等待釋放和子程序完成，再刪除私有目錄。延遲的退出觀察證明，清理不能僅因已請求終止而完成。生產環境的 EOF 與終止寬限期保持不變。

[Codex 測試](../../../../packages/subagent/subagent-codex/tests/real-product.spec.ts) 繼承執行通道的掛鉤預算。清理在第一次非同步等待前取得其上下文、HTTP 夾具和臨時根目錄，因此超時掛鉤不能取走其他測試註冊的資源。清理保留上下文釋放、伺服器關閉、目錄刪除的順序，等待所有已取得的釋放操作，並在拒絕後繼續嘗試其餘清理階段。收集的錯誤指出各自失敗的階段或路徑並保留原始原因；只有全部已取得資源都嘗試清理後才報告錯誤。

[原生 Windows CI 決策](../process/2026-08-08-native-windows-pull-request-ci.zh.md) 繼續負責通道排程和預算。本次改動僅移除衝突的區域性期限並加強資源生命週期斷言；它並不證明 Windows 程序終止或檔案系統存在缺陷。

## 曾考慮的替代方案

- 增加生產環境寬限期或檔案系統重試次數：這些失敗不能證明產品時序錯誤或刪除重試耗盡。
- 用更大的常數替換區域性期限：這樣仍會覆蓋未來的通道預算。
- 請求終止後立即結束清理：這樣會允許子程序或套接字存活超過夾具的生命週期。
- 將覆蓋率測試序列化：無關測試不應為兩個區域性期限覆蓋而失去並行能力。

## 後果

通道超時仍為掛起提供時間上限。定向測試驗證觀察到的子程序完成和清理所有權，而不是主機終止速度。taskkill、程序退出通知和 NTFS 刪除仍需原生 Windows 執行提供證據；macOS 測試透過不能證明這些機制。模型可見輸出、Session 夾具、生產環境超時與 CI 路由均不變。
