# Agent Note: 使用隔離的本地伺服器驗證 Desktop 更新下載

Status: implemented

[English](2026-09-10-desktop-local-updater-qualification.md) | 中文

## 問題

Desktop 更新互動依賴清單解析、網路失敗、下載完整性和平臺準備。模擬 updater 事件無法證明這些操作能夠協同工作。每輪回饋都要求設定雲端快取並完成硬體簽名，會讓本地產品驗證依賴釋出基礎設施。

## 決策

[Windows 本地驗證命令](../../../../apps/desktop/README.zh.md) 在 Electron 中執行建置後的生產協調器，並使用真實的 `ElectronHttpExecutor` 和 `NsisUpdater`。隔離的應用介面卡提供測試版本和私有更新設定。迴環伺服器提供 Nightly YAML、強更策略和不可執行的二進位制位元組。安裝器、外部瀏覽器和剪貼簿呼叫被替換為觀測記錄。釋出者驗證僅在此私有 fixture（測試前置資料）設定中預設，生產設定不受影響。

每次呼叫都原子分配臨時目錄和由作業系統分配的迴環埠。請求屏障在不使用休眠的情況下建立並行條件。移除臨時檔案之前，測試會等待伺服器關閉和子程序退出。獨立程序可以並行執行，互不共享 updater 快取或使用者資料。此命令依賴建置後的 Desktop 模組，與原始碼側單元測試分開執行。

此測試決策補充[釋出策略](../architecture/2026-08-25-electron-desktop-packaging-and-updates.zh.md)，並不取代簽名、釋出完整性、已安裝產物驗收或待實施的[強制更新提案](../../proposed/feature/2026-09-08-desktop-mandatory-update-api.zh.md)。這些記錄保持有效。

## 考慮過的替代方案

**僅使用模擬 updater 事件。** 它們覆蓋狀態轉換，但無法證明真實的 YAML 解析、Electron 傳輸、下載位元組或總和檢查碼拒絕。本地驗證使用真實依賴實作；原生彈出視窗和渲染器元件測試仍獨立執行。

**每輪本地迭代都要求雲端託管的簽名包。** 這會讓常規互動除錯依賴簽名硬體和 CDN 設定。釋出驗收仍需要這些系統，但本地下載測試不需要。

**放寬生產簽名要求或執行偽安裝器。** 觀測下載就緒和安裝授權不需要這兩種做法。fixture 從不載入生產更新設定，只記錄安裝，不啟動下載的位元組。

## 後果

可執行情境覆蓋無更新、拒絕降級、HTTP 404/408 和無效 YAML、清單與下載停滯截止時間、同地址清單替換、單一在途檢查或下載、顯式下載授權、SHA-512 不匹配、傳輸中斷、顯式重試、已準備版本保留、拒絕重新啟動、關閉失敗，以及檢查未完成時的 dispose（資源釋放）。原生彈出視窗迴歸覆蓋檢查回饋、檢查失敗、拒絕下載和獨立安裝操作；帳戶行測試負責進度和持久重試展示。

常規輪詢迴歸使用真實協調器、模擬時鐘、實例私有隨機樣本和可控的網路完成時機。它驗證從完成時刻起算的抖動、有上限的指數退避、成功重置、手動複用自動檢查時的失敗可見性、下載失敗和已準備安裝檔保留，以及 dispose 後不重新啟動計時器。主入口測試將同一期限連線到視窗聚焦、系統恢復、顯式 IPC 和應用退出。移除失敗退避會使計時斷言失敗。這些確定性測試證明請求時序，不證明使用者端總體容量或啟動峰值分佈。

真實的[強更視窗](../feature/2026-09-11-desktop-mandatory-update-client.zh.md)、沙箱預載入和頁面按鈕處理會對接策略伺服器與 updater。停滯的策略請求達到真實截止時間後不會清除阻塞。所屬測試目錄內的 DOM 預期輸出約束中文文案和操作。截圖失敗單獨記錄；缺少截圖不能證明視覺驗收透過。

[工作區瀏覽器情境](../../../../apps/web/tests/desktop-updates.e2e.ts) 使用生產展示函式檢查兩種語言下建置後的側欄組合。頁面私有的載體提供更新狀態並記錄操作；Host、用戶端外掛、樣式和連線保持真實。slot 位置與點選保護的證據因此與 Electron IPC、任務授權和安裝證據分開。截圖和結果檔案使用每次呼叫獨有的忽略目錄，不替代釋出驗收。

[Host 驗證執行器](../../../../apps/desktop/scripts/test-host-updates.ts) 在私有 profile 中載入建置後的 Host 和 standard agent 預設。真實任務註冊表、排隊訊息、等待答覆的工具提問／審批和 Node job 提供任務探測與准入鎖定證據，不替換 Host 組合。腳本化模型輸出和暫停的人工答覆器控制等待點；取消和程序退出確立完成狀態。這些證據不包含開發啟動器的依賴投影、Electron 安裝確認和任務停止失敗。並行呼叫各自擁有獨立的 home、專案和工作階段目錄。

[Electron 工作區執行器](../../../../apps/desktop/scripts/test-workspace-updates.ts) 將編譯後的主入口和真實預載入連線到獨立的真實 Host。私有 profile 外掛控制真實排隊任務並刻意阻塞停止過程；本地 HTTP 分發替代釋出基礎設施，updater 的安裝器呼叫被攔截。它驗證確認期間任務變化、收尾失敗後拒絕安裝、替代 Host 就緒，以及普通和強更策略下的重新確認。頁面操作等待有限佈局動畫完成，並拒絕被遮擋的目標；視窗監聽清理獨立保留 web contents，不依賴已銷燬視窗。執行器不證明打包主入口部署或重疊視窗的作業系統合成效果。

執行器啟動 Electron 時不隱藏 GUI，並在輸入或截圖之前斷言主視窗可見。隱藏或被遮擋的渲染器即使能夠完成 DOM 查詢，也可能暫停幀回呼。每次 DOM、點選佈局和截圖操作僅臨時關閉自身 WebContents 的後臺節流，隨後恢復並檢查原設定。真實動畫和點選遮擋斷言保持啟用；生產視窗設定不變。每項操作都有主程序截止時間及本次執行獨有的跟蹤記錄；失敗診斷在獨立截止時間內記錄視窗可見性和動畫狀態。診斷捕捉失敗不能替換原始測試失敗。重新啟用 Windows 程序隱藏會使可見性斷言失敗，未保護的並行視窗可復現幀等待停滯。

生產使用的 `DesktopUpdateHttpExecutor` 保留依賴庫傳輸，併為真實 Electron 請求新增無活動截止時間。Electron 44 會在回應頭到達前觸發可寫流的 `close`，因此該事件不能代表 HTTP 完成。回應完成、中止和錯誤釋放計時器；收到位元組會重新整理計時器。回應頭停滯與負載停滯均在本地 fixture 中失敗，並透過顯式重試恢復。

[簽名下載執行器](../../../../apps/desktop/scripts/test-signed-updates.mjs) 使用已有的簽名及未簽名可執行檔案、公開憑證和真實 Windows Authenticode 驗籤，補充不可執行位元組測試。私有清單使用合成版本號，安裝呼叫被攔截。雜湊正確但釋出者錯誤或未簽名的檔案被拒絕，並從快取移除；傳輸損壞的位元組先被總和檢查碼驗證拒絕。自動檢查保留失敗，不傳送新請求；顯式重試簽名檔案後進入就緒，並要求單獨批准重新啟動。輸入檔案保持不變。每個程序獨佔埠和快取；截止時間觸發時先停止完整的 Electron/PowerShell 程序樹，再清理執行時目錄。缺少釋出者設定會使拒絕斷言失敗。

可選的舊安裝器輸入啟用真實差分重建，使用私有快取和原始 blockmap。伺服器支援單段與多段位元組範圍，並顯式提供缺少 blockmap 和拒絕 Range 的故障。雜湊與簽名驗證覆蓋重建及全量退回結果；請求記錄要求實際複用位元組，不允許全量退回冒充差分成功。停用差分下載會使 blockmap 請求斷言失敗。歷史輸入檔案保持只讀，獨立並行執行各自擁有快取和埠。

本地下載 fixture 在向磁碟寫入部分位元組後，為其可執行檔案寫入流注入 `ENOSPC`。真實 updater 必須清理不完整的可執行檔案、拒絕安裝、保留顯式重試，並在恢復原始寫入器後下載透過驗證的位元組。只攔截私有下載路徑，且等待流關閉。這驗證檔案系統寫入失敗的處理，不耗盡共享主機卷。

這些證據不能證明真實安裝器執行、重新啟動後健康狀態、生產 CDN Range 行為、macOS updater 準備或真實卷耗盡。測試伺服器不釋出任何內容，也不讀取雲端憑證；生產分發和簽名已安裝版本升級仍需獨立驗收。
