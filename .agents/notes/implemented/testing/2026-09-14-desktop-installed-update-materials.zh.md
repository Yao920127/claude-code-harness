# Agent Note: 將安裝版更新物料與釋出及使用者資料隔離

Status: implemented

[English](2026-09-14-desktop-installed-update-materials.md) | 中文

## 問題

安裝版更新演練需要兩個遞增版本共用應用身份。複用正常釋出路徑可能向無關用戶端暴露測試中繼資料，而把測試狀態放在安裝目錄中會在替換時丟失證據。複製成功不能證明已有簽名安裝檔。

## 決策

版本派生遵循[釋出版本決策](../process/2026-09-16-desktop-release-version-derivation.zh.md)；本記錄繼續規定物料、應用身份和使用者資料的隔離。

[物料準備器](../../../../apps/desktop/scripts/prepare-installed-update-runtime.ts)接受保留的 test 專用清單，其中包含隨機身份和分發名稱空間。它將已驗證的原始執行時複製為獨立的派生測試版本，僅修改釋出家族版本和匹配的依賴引用，再生成並驗證兩個完整性清單。原始執行時再次驗證，其描述檔案雜湊必須保持不變。已有輸出目錄不被覆蓋；複製失敗保留失敗記錄，不能生成完成回執。

生成的啟動入口在匯入生產主程式前驗證已安裝檔身份。兩個版本將相同的應用資料子目錄用於測試 Electron profile、Harness home 和外部日誌。首次啟動繼承的環境變數不決定這些路徑。清單讀取器拒絕已改變的 test 目標、身份和目錄位置。[人工指南](../../../../apps/desktop/tests/installed-update/README.zh.md)區分原始碼準備、獨立執行時副本和簽名安裝版驗收。

[日誌決策](2026-09-14-desktop-installed-update-journal.zh.md)與[本地 updater 驗收決策](2026-09-10-desktop-local-updater-qualification.zh.md)繼續有效：物料準備既不證明已安裝應用升級透過，也不改變硬體授權。這些準備工具不包含簽名、上傳、安裝或網路改動。

## 考慮過的替代方案

**在兩次建置之間修改儲存庫包清單的版本。** 這會改變工作區釋出版本，可能影響其他任務或釋出命令。獨立執行時副本與包專屬中繼資料保持原始碼工作區版本不變。

**使用生產身份或僅透過終端覆蓋資料目錄。** 生產身份與普通安裝共享註冊和資料；終端覆蓋不一定在安裝器觸發啟動時保留。獨立身份與包內啟動入口維持跨版本隔離。

**覆蓋準備到一半的版本來繼續執行。** 這可能混合不同原始碼代際並丟棄失敗證據。已有輸出或準備記錄拒絕複用；全新嘗試需要新批次。

**從桶設定查詢被拒絕推斷上傳失敗。** 物件存取與桶設定使用不同權限。新增前置檢查可能拒絕物件操作原本可用的憑證。申請擴大權限前，先定位準確 API 並對照已有成功證據；沒有嘗試 PUT，就沒有觀察到上傳失敗。

## 結果

feed 釋出複用已完成的二進位制上傳結果，其保留計劃必須與目前已驗證分發計劃完全匹配，包括批次身份、版本、目標地址、大小和雜湊。釋出記錄回執及計劃雜湊，僅在遠端讀取 feed。首次二進位制上傳保留完整公網位元組驗證。每次寫 feed 都重複傳輸會增加延遲和流量，卻不改變不可變物料；保留回執證明此前分發成功，不保證物件此後未被外部刪除。回執缺失、失敗或不匹配時拒絕釋出，不隱式觸發另一次大檔案下載。

獨立的[釋出入口](../../../../apps/desktop/tests/installed-update/publication/README.zh.md)預設僅驗證本地回執與位元組。二進位制上傳不能公佈版本；後繼版本 feed 釋出要求原版本啟動證據及匹配的舊 feed。test 專用傳輸停用 SDK 寫入重試，在使用不可變物件保護前要求權威查詢確認儲存桶未啟用版本控制，並驗證準確的公網位元組。本地鎖不提供分散式排他：必須由一個操作者跨機器獨佔可變 feed。每次授權操作保留獨立階段記錄；寫入結果不確定時要求檢查，不能自動重試。匹配物件可核對而不替換。記憶體順序測試和替代 HTTP 傳輸測試不證明真實 COS 釋出或已安裝應用啟動透過。

獨立的[人工打包入口](../../../../apps/desktop/scripts/package-installed-update.ts)在載入憑證前檢查持久簽名保護鎖，並在互動確認後再次檢查。每次執行只擁有一個版本和一個不復用的打包目錄。它使用現有監督程式與 15 分鐘階段期限，保留脫敏輸出和選定的原始碼/工具雜湊，並在建置後比較這些輸入。上傳憑證絕不傳給建置器；入口不包含釋出和安裝。無功能子程序測試覆蓋拒絕、脫敏、失敗保留與不復用；實際簽名產物和包驗證仍需獨立證據。整體期限不能限制 CSP 內部 PIN 嘗試，也不能授權無人值守簽名。

應用準備按批次凍結一次已建置的主程式/預載入模組、介面檔案和生成的啟動入口，記錄 SHA-256，並拒絕凍結檔案被修改、缺失或額外增加。[驗收打包設定](../../../../apps/desktop/scripts/installed-update-builder.ts)將選定的獨立執行時傳給常規設定工廠，使資源驗證與簽名使用同一執行時版本。它保留安裝器掛鉤和釋出者檢查，同時選擇共享測試身份、包入口和固定 test feed。依賴樹和建置工具仍是獨立的可變輸入，需要最終建置記錄。設定驗證使用固定版本建置器和替代簽名器，不是硬體或已安裝應用證據。

只讀[分發規劃器](../../../../apps/desktop/scripts/installed-update-distribution.ts)逐版本核對生成的 YAML 與本地安裝檔位元組，並將不可變二進位制物件與一個可變 feed URL 分開。它從已驗證的值重建 feed 欄位，不保留任意輸入欄位。輸出明確標識僅驗證檔案完整性、沒有釋出授權；憑證、簽名、包身份與版本 1 啟動不屬於本檢查。

獨立的[簽名讀取器](../../../../apps/desktop/scripts/installed-update-signature.mjs)要求真實 updater 驗籤、有效 Authenticode 與時間戳屬性，以及未變的可執行檔案位元組。驗籤子程序移除憑證和繼承的 PowerShell 模組路徑；不相容模組覆蓋不能被當作驗籤成功。釋出者來自可信公鑰憑證，而非遠端 YAML。只讀檢查絕不呼叫 SignTool、存取簽名權杖或執行被檢查檔案。簽名透過不能證明包內容或安裝完成。

[安裝檔檢查器](../../../../apps/desktop/scripts/verify-installed-update-package.ts)解開簽名安裝檔本身，而非信任相鄰的解包目錄。歸檔內身份、更新設定、凍結應用檔案和 Harness 執行時必須與保留批次一致，測試強更策略也必須有效。檢查器從 ASAR 讀取執行時檔案，只接受 electron-builder 對依賴 manifest 的轉換，並在 `app.asar.unpacked` 中檢查可執行檔案簽名。未簽名的執行時可執行檔案變化不能僅靠重新生成清單就透過。獨立且不可覆蓋的記錄保留每次檢查的階段與失敗。最終輸入雜湊防止安裝檔/feed 變化繼承舊結果。真實 ASAR 和執行時夾具覆蓋不符情況，僅替換外部驗籤和歸檔程序；實際簽名包仍需各自回執。安裝器註冊和已安裝應用行為不屬於檔案檢查，保留為人工檢查項。

[網路故障步驟](../../../../apps/desktop/tests/installed-update/network/README.zh.md)將指定程式的出站規則繫結到已驗證原版本可執行檔案雜湊及隨機批次身份。它在建立前和確認後拒絕變化的位元組，僅移除匹配的自有規則。可執行檔案消失後仍可恢復。兩次改動均由操作者控制；每次操作前後持久記錄階段，失敗即停、不重試。防火牆命令替身執行真實腳本，但記錄規則存在或不存在絕不證明流量中斷或下載恢復成功。不改網路卡或 VPN，因為這可能斷開操作者的遠控。

生成入口測試只替換 Electron 路徑 API，執行兩個版本並在主程式匯入前核對共享目錄。執行時測試驗證依賴版本替換、第三方版本和原始位元組不變、損壞輸入拒絕以及失敗現場保留。副本額外佔用磁碟。原始碼準備可啟動原始執行時，但副本版本啟動、最終包內容、簽名、釋出和安裝均需獨立證據；完成回執說明這些侷限，不推斷成功。
