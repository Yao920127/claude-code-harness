# Agent Note: 可回溯壓縮：索引檢查點、狀態檢查點與工作階段內歷史回溯

Status: proposed

[English](2026-07-06-recallable-compaction.md) | 中文

## 問題

壓縮（compaction）對模型的目前上下文不可逆。模型看到的摘要沒有指向被其遮蔽內容的引用，因為 `shadowedRange` 只存在於僅寫入日誌、模型不可見的 `compaction/summary` 事件上，也沒有工具能讓模型重新讀取被遮蔽的區段。即使僅追加日誌仍儲存每一個位元組，摘要器丟棄的內容也對模型不可用。重複壓縮會進一步加重這些結果：每一輪都會重寫頭部檢查點，因此請求字首每次都會完全失去提示詞快取命中，而更早的摘要也會在後續每一輪中重新生成摘要。

根本原因是一個產物承擔了兩個互相沖突的角色。**索引**需要凍結、按時間排序且成本低廉；模型的**工作記憶**則需要全域檢視、重新確定優先順序並且可變。單一摘要無法同時勝任兩者。

主流編碼 harness 都沒有讓模型在迴圈內回溯，而且調研過的實作均未讓壓縮感知字首快取。事件溯源工作階段具備持久原文、可按 seq 定址和精確回放的特徵，是支援這兩項功能的天然底座。

## 提案

把檢查點拆為兩類，並讓被遮蔽的歷史重新可達。

### 凍結的索引檢查點

新近變為陳舊的歷史按確定性策略拆分為分片：向 `chunkTokens` 累積；使用 `toolPairingBalancedBefore`／`toolPairingBalancedAfter` 對齊邊緣；優先選擇輪次邊界；在平衡允許的範圍內，把最終邊界放在儘量接近保留邊界的位置，使尾隨切片縮小到大約一個輪次。每個分片透過一次 `compactRegion` 呼叫壓縮為一個**索引存根**（`stubTokens`，約 100–200 個 token）：

- 用兩三行說明發生了什麼；
- 用一行關鍵詞記錄低頻字面錨點，例如確切的錯誤字串、值和設定鍵，並按類別分組；
- 由程式碼組裝頁尾：`[checkpoint c<summarySeq>: shadows conversation span #<start>–#<end>; originals retrievable via history_read]`。程式碼根據 `compaction/summary` seq 和 `shadowedRange` 組裝這些指標，模型絕不會編寫它們。

已經提交的存根永不重寫，也絕不再次進入之後的壓縮區域。存根呼叫採用分層輸入：固定前導內容與逐位元組相同的本輪開始狀態檢查點（該階段所有呼叫共享的字首）；隨後是先前所有已提交存根的關鍵詞行，使新條目索引其分片的獨特內容，而不是重複整個目錄；再加最近一兩個已提交存根以維持時間連續性；最後是切片本身。同一輪中的同級存根不作為輸入，因為並行階段禁止這種依賴，而與輪次對齊的邊界已經維持區域性連續性。狀態檢查點只作為背景，絕不能成為存根需要總結的材料。完全由回溯內容構成的切片只透過程式碼生成存根，即只寫一行指標，不呼叫 LLM（大語言模型）。存根呼叫失敗時採用相同降級方式：其切片獲得一個僅由程式碼生成的指標存根，本輪繼續執行，使狀態重寫成為一輪中唯一的強制 LLM 依賴。

### 狀態檢查點

系統維護一份可變的工作記憶文件（最多一份；第一次壓縮前為零份），位於所有存根之後、保留尾部之前。每一輪根據先前狀態與本輪變為陳舊的內容重寫它，成本為 O(previous + new)；過程遵守摘要提示詞中已有的「合併而不重複陳述」規則，並覆蓋決策、目前狀態、約束和後續步驟。它帶有自己的頁尾，其大小上限與現有摘要處於同一量級。

膨脹保護會約束整輪操作：如果壓縮後大小沒有嚴格小於壓縮前大小，就不提交任何內容，並繼續目前輪次；本次嘗試延後至積累更多陳舊歷史後再進行。保護邏輯在兩側比較同一項度量：優先使用請求路徑上提供者報告的用量；如果不可用，則兩側都退回為字元估算器。

### 一輪的執行過程

- 分片切片由表面位置範圍表示。一輪分兩個階段執行：所有摘要呼叫先並行執行並在表面之外緩衝；隨後嚴格從左到右提交區域，先提交各分片，最後提交尾隨切片，使狀態檢查點透過連續的單節點替換落在所有存根之後。牆鍾時間維持在接近一次摘要呼叫的水平。
- 被取代的狀態檢查點會作為普通曆史折入下一輪的第一個分片，不需要墓碑或新原語。其存根省略該狀態，`history_read` 會把它渲染為 `[prior state checkpoint]`，並讓頁尾隨渲染文字一同傳遞，使每個尾隨切片都可透過兩跳鏈結觸達。
- 範圍選擇會感知凍結邊界：可壓縮區段從最後一個已提交索引檢查點之後開始；只有在不存在索引檢查點時，才從表面頭部開始。舊工作階段現有的頭部檢查點會被視為狀態類檢查點：其文字作為合併基線，其節點則像其他被取代狀態一樣折入歷史。
- 摘要階段發生崩潰時不會提交任何內容；提交中途崩潰會留下一個從左到右的已提交字首，恢復後的一輪從日誌中最新的狀態類 `compaction/summary` 事件讀取合併基線，並無條件提交剩餘區域。恢復 `[stubs…][state][tail]` 的優先順序高於縮減大小。

### 回溯工具

新增包 `@deepseek-ai/dsh-tool-recall`，它只是 `dsh-session` 與 `dsh-compaction` 詞彙之上的消費方，註冊兩個面向模型的工具：

- `history_read(checkpoint, offset?)`：把日誌中任意檢查點（包括已被取代的檢查點）遮蔽的區段渲染為 `User:`／`Assistant:`／`Tool result:` transcript（文字記錄），並按設定預算分頁，提供續傳遊標。
- `history_search(query, checkpoint?, limit?)`：對每個被遮蔽區段進行不區分大小寫的字面量掃描；返回帶檢查點 id 的片段與覆蓋中繼資料（`scanned`／`matched`／`truncated`）。零匹配提示會說明掃描按字面量執行，並建議對可能的檢查點直接使用 `history_read`。

兩個工具都按[同步事件讀取棄用規則](../../implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.zh.md)使用顯式非同步分頁歷史讀取（拒絕非 agent（智慧代理）呼叫方），只渲染表面型別的訊息事件，並返回普通 `tool/result`：回溯位元組會進入上下文尾部並記錄到日誌，因此無需特殊處理即可滿足可重建性。系統不增加新儲存或伴隨索引：工作階段日誌儲存內容，`compaction/summary.shadowedRange` 和 `shadowedSeqs` 指明每個檢查點替換了什麼，這些工具讀取兩者。工具 schema 與該包唯一的系統提示詞章節都是靜態字串；檢查點 id 只會透過頁尾抵達模型。transcript 渲染器從 `compaction-basic` 移入 `dsh-session`，供摘要器與工具共享。

### 快取與成本

一輪後的請求字首為 `[system][stubs…][state][tail]`。凍結存根在各輪之間逐位元組穩定，因此快取缺失從替換先前狀態檢查點的 token 才開始，規模保持 O(new chunks + state + tail)，而基線實作會從位置零開始缺失。回溯輸出落在尾部，不會改變字首。每輪摘要輸入大約是基線輸入的兩倍，另加一個 m·S 背景項；該成本受到 `chunkTokens` 下限（狀態上限的小倍數）以及經過驗證的 `stubTokens`／`chunkTokens` 比例上限約束。共享字首輸入佈局依次為前導內容、逐位元組相同的本輪開始狀態、位於尾部的切片內容，使同級呼叫可以按快取費率重複讀取。

### 打包方式

該設計以新的後端 `dsh-compact-recallable` 交付，掛在現有 `ctx.compaction` seam 上，並在已交付的範例設定中預設啟用。`compaction-basic` 保留為參考實作和該 seam 的設計對照，與成對 LLM 介面卡的模式一致。seam JSDoc 中「最多一個自動生成的檢查點，始終位於頭部」這一條會放寬，改為說明兩個後端各自的行為。

### 與進行中工作的關係

- **工具結果裁剪**（進行中的裁剪服務）：其替換節點攜帶 `sourceEventSeqs`；同一註冊表摺疊會把經過裁剪的結果列為可回溯。它屬於後續範圍，兩項工作互不阻塞。
- **提供者 token 用量核算**（正在把壓縮壓力遷移至提供者報告用量的工作）：為保護邏輯提供核算基礎；本實作堆疊在它之後。
- **「查詢工作階段」backlog（待辦清單）條目**：它是跨工作階段的泛化方案；本 Agent Note 把範圍限定在即時工作階段內，並選擇工具名稱與渲染方式，使該工作能夠擴充功能本設計而不產生衝突。
- **訓練**：何時回溯屬於學習到的行為。確定性頁尾與關鍵詞錨點為訓練提供穩定目標，而回溯使用情況在工作階段日誌中完全可見，可供軌跡匯出；基準測試與 RL 設計由後訓練側推進。

### 後續事項

以下專案延後至觀察結果證明需要時再實作：

- 保護邏輯降級階梯（透過程式碼彙總最早的存根字首，保留頁尾，已彙總 id 仍可作為回溯目標；隨後在凍結邊界後生成一份摘要）：觸發條件是觀察到保護邏輯活鎖或存根區域壓力。
- 存根輸出回聲檢測（句子級 n-gram，豁免短字面量；先重試，再剝離）：觸發條件是觀察到職責分工洩漏。
- 定期使用分片原文重新整理狀態：觸發條件是交接探針觀察到漂移。
- `stateFallbackThreshold`（存根數量低於閾值時使用完整細節的狀態提示詞）：觸發條件是短工作階段迴歸。
- 延遲註冊回溯工具：觸發條件是在從不進行壓縮的工作階段中測得上下文開銷。
- 在 pre-step 分攤存根起草工作：一旦已經陳舊但尚未壓縮的內容積累超過 `chunkTokens`，就在下一個 pre-step 起草該分片的存根（一個僅寫入日誌的草稿事件，在分片周圍的上下文仍然存活時寫入），讓壓縮輪提交草稿，而不是集中執行摘要。這是後臺壓縮的確定性、精確回放等價形式（Claude Code 工作階段記憶採用這種模式；OpenClaw 證明同步語義完全相同）。觸發條件是觀察到壓縮輪次的執行延遲，或近即時起草帶來的存根品質收益得到驗證。
- 拆分摘要模型；由模型選擇分片邊界；跨工作階段回溯；語義搜尋退回：每項都必須由各自證據支援。
- 更豐富的 `history_search` 查詢形式：正規表示式，以及對日誌 JSON 工具結果執行的結構化查詢（sql／jq 風格，或由 agent 針對索引儲存編寫查詢）。觸發條件是觀察到搜尋漏檢；首版先交付字面量匹配，使回溯路徑保持為日誌的純函式。

## 考慮過的替代方案

- **分階段交付**（先在現有後端之上單獨交付回溯工具；觀察到回溯使用後，再決定是否拆分檢查點）：不予採納。未經訓練的模型會低頻使用任何新工具，因此該條件測量的是訓練缺失，而不是設計價值；訓練側需要完整機制來建置環境；預釋出階段修改持久化格式的成本最低；快取經濟性則屬於第一方已經掌握的知識，不是等待遙測驗證的假設。該機制仍先引入回溯工具，再拆分檢查點；這只是建置順序，不是決策門檻。
- **只保留凍結的全尺寸摘要，不設狀態檢查點**：不予採納，因為永久字首會無界增長、自我加速並最終發生顛簸，而且沒有任何內容可以重新確定優先順序。
- **只保留純存根，不設狀態檢查點**：不予採納，因為這假定模型知道自己缺少什麼，在面對未知的未知時會失敗。
- **由 LLM 老化／整合凍結分片**：不作為常規機制，因為摘要的摘要會丟失資訊，並使凍結字首頻繁變化；其保留下來的形式是由程式碼彙總，且延後實作。
- **把完整字首作為分片摘要器輸入**：不予採納，因為成本為 O(N²)；狀態文件以 O(state) 提供相同背景。
- **一次摘要呼叫輸出全部結果**：不予採納，因為摘要路徑沒有結構化輸出約束；解析一份自由文字回應並將其拆開，正是保守失敗設計要避免的脆弱邊界。
- **由模型選擇分片邊界**：延後實作，因為相對於未經證明的收益，解析與驗證成本過高；分片策略由設定控制。
- **由模型編寫指標**：不予採納，因為指標必須精確，應由確定性程式碼組裝。
- **FTS／向量索引伴隨儲存**：以即時日誌常駐記憶體且大小有界為依據的否決，被[事件讀取策略](../../implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.zh.md)取代。實作回溯前，需要針對分頁歷史讀取重新評估索引選擇。
- **回溯路徑中的語義搜尋退回／次級模型提取**：不予採納，因為其中的 LLM 或嵌入呼叫會破壞無金鑰回放的確定性；回溯必須保持為日誌的純函式。
- **使用原始事件而不是渲染後的 transcript**：不予採納，因為這會洩漏僅日誌可見的詞彙與分片噪聲；模型應讀取模型曾經看到的內容。
- **什麼都不做（用恢復／fork 補救）**：不予採納，因為這會把恢復變成人工操作。

## 驗收標準

- 長工作階段自動壓縮後，每一輪完成時都會得到 `[stubs…][state][tail]`；先前存根在各輪之間保持逐位元組相同；已提交存根絕不落入後續區域；被取代的狀態檢查點無需墓碑即可折入歷史，渲染時帶有標籤，並可透過兩跳鏈結觸達和搜尋。
- 每個檢查點的表面文字都以確定性頁尾結束；頁尾透過回放逐位元組往返；狀態檢查點的 `shadowedRange` 記錄其更寬的輸入範圍。
- 在全部摘要就緒且保護邏輯透過同類核算前，不提交任何內容；保護失敗不會提交任何內容，也不會讓輪次失敗；提交中途被終止後，下一次 pre-step 會恢復處理，從日誌讀取合併基線，並無條件提交狀態區域以完成本輪；舊版頭部檢查點會被視為狀態類。
- `history_read` 在預算內渲染任意已記錄檢查點的區段，並提供可用遊標；`history_search` 覆蓋每個被遮蔽區段，返回帶檢查點 id 的片段與覆蓋中繼資料，測試尤其要能找到只存在於被已取代狀態檢查點遮蔽區段中的內容，這是鎖定尾隨切片可達性的迴歸案例；兩個工具都會拒絕非 agent 呼叫方，並對從未存在的 id 或遺留 `compaction/start` 返回型別化錯誤；回溯內容作為普通 `tool/result` 出現；請求重建不變數會在同時包含壓縮與回溯的工作階段上透過；一項無金鑰快照情境端到端覆蓋先壓縮再回溯；工具 schema 與提示詞章節在各輪之間逐位元組相同。
- 在長時間跨度 bench 套件中：任務成功率在預算相同的條件下不低於 `compaction-basic`；交接保真探針（在一輪後重新陳述 K 項已知決策和約束）的得分不降低；每次執行都透過 dsh bench 報告流水線彙報回溯使用頻率和命中有效性，並同時報告存根目錄注意力度量與快取命中遙測。
- seam JSDoc、壓縮能力 seam Agent Note、`architecture.md`，以及生成的工具、設定、持久化與模組圖目錄都在同一改動中更新；全部預算位於設定中；新原始碼目錄具備逐檔案 100% 覆蓋率與 HMR（熱模組替換）dispose（資源釋放）測試。

## 風險

- **回溯屬於學習到的行為**：未經訓練的模型會低頻使用它，bench 報告會持續追蹤這項差距，直至訓練彌合問題。在此之前，狀態檢查點會讓品質下限保持在現有摘要的品質水平。
- **未知的未知仍然存在**：如果某項細節既未出現在摘要中，也未出現在關鍵詞中，就不會觸發回溯。回溯把「即使已經懷疑也無法觸達」變成「懷疑時可以觸達」。
- **存根目錄會佔用注意力**：每次請求中包含數十張穩定的索引卡，可能稀釋模型關注點；驗收標準中的 bench 度量會將其與 `compaction-basic` 對比。
- **成本**：每輪摘要輸入大約是基線輸入的兩倍；短工作階段的成本和品質接近基線水平，而設計收益隨工作階段長度增長。
- **狀態漂移與職責分工洩漏**可以透過交接探針和存根評審觀察；對應措施已列為後續事項。
- **兩個後端**會擴大維護範圍；seam 約定和共享回溯消費方會限制這一範圍，bench 對比則用於逐步決定預設實作。
