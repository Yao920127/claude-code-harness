# Agent Note: Desktop 更新後續擴充功能

Status: proposed

[English](2026-09-08-desktop-update-extensions.md) | 中文

## 問題

高頻釋出後續可能需要 Desktop 獨立修訂、穩定版訂閱、下次啟動安裝或替換較舊待安裝更新。這些選擇引入額外發布與安裝器狀態，初期固定 Nightly、明確確認安裝的流程並不需要它們。

## 提案

將這些候選與[一期更新設計](2026-09-08-desktop-update-policy-and-installation.zh.md)分開。它們不是一期驗收要求，也不授權修改依賴；實作前需要產品批准與平臺驗證。[強制更新介面](2026-09-08-desktop-mandatory-update-api.zh.md)繼續獨立，自動安裝不向其中增加安裝器欄位。

### 獨立修訂

預釋出線上確有 Desktop 獨立修復需求時，評估預留的 `.dsk.N` 格式。保持完整 SemVer 比較，使引入該格式不需要自定義版本解析器。預期排序為：

```text
0.1.3-rc.2
< 0.1.3-rc.2.dsk.1
< 0.1.3-rc.2.dsk.2
< 0.1.3-rc.3
```

這類釋出將 Desktop `0.1.3-rc.2.dsk.1` 與內建 dsh `0.1.3-rc.2` 分別記錄。只有同時補齊建置、執行時描述、profile 校準、釋出工具與後端策略驗證，才引入獨立的 `desktopVersion`、`bundledDshVersion` 和 `releaseChannel` 記錄。一期建置繼續要求版本相等。

不能用 `0.1.3-dsk.1` 修復穩定版 `0.1.3`，因為 SemVer 將其排在穩定版之前。穩定版修復需要更高的共用 dsh/Desktop 補丁版本，例如 `0.1.4`。獨立預釋出修訂是特殊釋出路徑，不是每次建置的常規計數器。

### 穩定版訂閱與通道切換

| 使用者選項 | Feed | 釋出內容 |
|---|---|---|
| 穩定版 | `latest.yml` / `latest-mac.yml` | 僅穩定版本 |
| Nightly | `nightly.yml` / `nightly-mac.yml` | alpha、rc 和穩定版本 |

[一期釋出規則](2026-09-08-desktop-update-policy-and-installation.zh.md)在共用穩定版本出現時增加穩定 feed，不切換固定 Nightly 用戶端。面向使用者的穩定版訂閱與選擇器仍延後。啟用後持久化所選通道，不從已安裝版本反推。設定 updater 通道時保持 `allowDowngrade = false`。從 Nightly 切到穩定版時，較高的已安裝 Nightly 持續執行，直到出現更高穩定版；不得降級 Desktop 或內建 dsh。

切換通道可以立即檢查，下載行為必須遵循獲准設定。忽略舊通道回應，安裝前按新通道重新確認已下載產物。通道改變不能在缺少新條件有效策略回應時解除強制阻斷。選擇器下方常駐 Nightly 說明，候選中文為“提前體驗新功能，版本可能不穩定。”；選擇穩定版後隱藏，必要時另行說明需等待更高穩定版。

僅為實際分發過的 Desktop 安裝檔設計相容。後續遷移若存在讀取 `alpha.yml` 或 `rc.yml` 的真實用戶端，應向舊 feed 與 Nightly 釋出更高橋接版本，直到可淘汰舊入口。一期不需要這類橋接。

### 自動安裝設定

候選設定為自動安裝；僅在產品批准與平臺實測後考慮預設開啟。候選中文輔助文案為“關閉後仍會提示更新，需手動升級。” 若下次啟動安裝體驗不滿足要求，則評估僅自動下載的設定，並保留明確安裝確認。

| 設定 | 發現更高版本 | 後續完整啟動應用 |
|---|---|---|
| 開啟 | 自動下載與準備，包含手動檢查發現的版本 | 安裝條件滿足時應用有效待安裝更新 |
| 關閉 | 繼續檢查與提示，等待明確下載操作 | 不自動安裝，保留手動入口 |

表中的自動下載與安裝是後續產品選擇；一期每次下載都需要使用者操作，安裝另行確認。關閉未來的自動設定後不發起新的自動下載與安裝；在途下載可以完成，不新增取消按鈕。承諾立即生效前需確認能否取消平臺已暫存安裝。不得主動退出使用中的應用或繞過任務影響確認。沿用一期檢查觸發與回饋，不新增網路恢復檢查或未經確認的全域提示。

### 下次啟動安裝

目標是完整程序啟動，不是重開視窗或重新整理渲染層。優先在恢復業務任務或啟動本地 dsh 前安裝；仍存活的受管資源需要明確關閉確認。已快取 ZIP 或安裝器不證明原生準備完成。如實展示解壓、總和檢查碼準備，不偽造進度。

使用已經準備好的目標，不為下載新包延遲啟動。限時檢查若發現更高候選，且平臺仍允許放棄暫存目標，可以推遲本次安裝並開啟目前應用；原生安裝器接管後可能無法取消或改換目標，不得透過刪除原生暫存目錄模擬。分別測量下載到就緒、點選到退出、應用替換，以及新版本 profile 校準與 Host 啟動耗時。

### updater 依賴驗證

一期依賴宣告仍由 [Desktop 包中繼資料](../../../../apps/desktop/package.json)負責。electron-builder 27 / electron-updater 7 配套遷移是評估候選，不是本文授權的依賴升級。以下 API 與平臺專案需針對選定版本和真實安裝檔核驗；本提案不宣稱已在本機執行驗證。

| 候選專案 | 必需驗證 |
|---|---|
| `autoInstallEvent` | 核驗 `manual`、`onQuit` 與 `onNextLaunch`；僅遷移依賴必須保留手動安裝 |
| 物件參數形式的 `quitAndInstall` | 核驗 `isSilent`、`isForceRunAfter` 及 macOS 特定語義 |
| 下次啟動快取 | 安裝前重新讀取中繼資料，驗證產物雜湊與平臺簽名 |
| Windows 每使用者 NSIS | 驗證無需 UAC 的下次啟動行為；不假定每機器安裝可靜默 |
| Windows 工作階段結束 | 驗證關機／重新啟動／登出不啟動不安全的退出安裝；不假定 NSIS 原子性 |
| macOS Squirrel 暫存 | 驗證原生準備、退出／重新啟動替換、簽名、公證與兩種架構 |
| 中繼資料與安全預設值 | 檢查現代 `files[]`、舊 `path`／`sha512` 消費者、`sha2` 淘汰與 NSIS Web Installer 預設值 |
| 建置工具遷移 | 核驗 Node 引擎要求，包括候選 22.12 下限，以及原生 ESM、設定、簽名 hook 與釋出工具相容 |
| 已分發舊用戶端 | 改中繼資料前實測其真實 feed 與載荷，不僅按依賴版本推斷相容 |

### 多個待安裝版本

候選策略跟隨最新適用版本，不向使用者提供安裝檔集合管理。同一時刻僅持有一個有效下載／安裝目標；暫存檔案不承諾可安裝的舊版本後備。

| 情境 | 候選行為 |
|---|---|
| A 下載時發現 C | 不反覆取消 A，後續檢查處理更新候選 |
| A 就緒、自動設定開啟、發現 C | 準備 C，用 C 進度替換 A 安裝入口 |
| A 就緒、自動設定關閉、發現 C | 顯示 C，僅在使用者操作後開始下載 |
| C 下載時出現 D | 不打斷 C，之後再考慮 D |
| 已確認安裝與任務關閉 | 鎖定所選目標，後臺不能替換 |
| 替換 A 後準備 C 失敗 | 繼續執行已安裝應用，顯示錯誤重試，不承諾安裝 A |

放棄已準備目標前重新確認平臺支援。快取身份包含產物中繼資料與雜湊，不僅是版本字串。就緒後的替換是應用協調邏輯，不是假定 updater 庫自動提供的能力；必須結合通道變化、新發布、重試與安裝器交接單獨測試。

### 快取失效與撤回

複用已驗證完整快取，不承諾部分下載續傳或保留舊可安裝檔。問題版本透過釋出更高修復版本並更新 feed 處理。中繼資料不匹配可能使部分快取失效，但不是嚴格撤回：已暫存或安裝中的產物仍可能被應用。失敗後繼續執行已安裝應用不同於安裝舊快取。不實作獨立的安裝檔撤回清單或安裝前撤回攔截。強制 API 判定是否必須升級，不決定安裝或作廢哪個 updater 產物。

## 考慮過的替代方案

**首版啟用全部擴充功能。** 在尚無 Desktop 分發時增加未經驗證的安裝與釋出路徑。固定 Nightly、明確確認安裝提供較小一期範圍。

**將修改設定視作取消。** 原生暫存可能已經持有安裝操作。產品文案與狀態轉換必須反映經過驗證的取消能力。

## 驗收標準

- 獨立批准每項擴充功能；滿足對應驗收前保持一期行為。
- 釋出 `.dsk.N` 前測試獨立修訂排序及所有版本拆分消費者。
- 驗證兩個通道釋出、選擇持久化、拒絕陳舊回應、重新驗證快取和禁止降級。
- 實測 Windows 每使用者安裝與 macOS x64/arm64 的更新準備、終止、下次啟動、原生暫存、profile 校準與 Host 啟動。
- 承諾即時撤銷前證明關閉設定對在途及暫存更新的實際影響。
- 覆蓋 A 替換為 C、C 失敗、期間出現 D、通道切換與安裝目標鎖定。
- 保留任務確認、真實進度、自動檢查失敗靜默和恢復到可用已安裝應用的行為；不因網路失敗阻斷正常啟動。

## 風險

原生安裝器歸屬限制取消與替換。API 存在本身不能保證啟動更快，中繼資料替換也不是通用復原機制。庫 API 候選、安全預設值、建置引擎與舊用戶端相容性需要按釋出版本核驗；寫入本提案不代表已驗證為產品能力。
