# Agent Note: Desktop 更新策略與安裝

Status: proposed

[English](2026-09-08-desktop-update-policy-and-installation.md) | 中文

## 問題

Desktop 通常執行本地 dsh server，無法依靠遠端業務錯誤可靠觸達強制更新策略。使用者需要自動發現、主動下載、可見的準備狀態，以及考慮執行中任務影響的獨立重新啟動確認。

### 釋出與後端驗收

釋出負責人須端到端驗收真實簽名 Windows x64 與 macOS x64/arm64 升級：發現、下載、雜湊與簽名檢查、任務安全的關閉、安裝、重新啟動、新版本 Host 啟動及 profile 校準。先發布不可變安裝檔和 blockmap，再發布可變 Nightly 清單。[打包決策](../../implemented/architecture/2026-08-25-electron-desktop-packaging-and-updates.zh.md)負責版本與產物規則。[介面提案](2026-09-08-desktop-mandatory-update-api.zh.md)負責策略欄位；生產聯調須驗證遊客存取、強制／無需強更回應、錯誤、平臺選擇、獲准源站和速率限制。啟用強更策略前先發布能解除要求的 updater 版本。

### 未決產品選擇

同版本離線重新啟動後持久保留強更阻斷仍需產品確認。若 A 正在下載或等待安裝時出現新版 C，在產品負責人批准替換前保留 A；不能把安裝 A 的授權靜默改為安裝 C。已安裝 Windows 與 macOS 的提醒仍受通知權限、專注模式、最小化視窗及過期點選影響。[後續擴充功能](2026-09-08-desktop-update-extensions.zh.md)負責自動替換和安裝。

### CDN 與容量驗收

以下發布與運維選擇尚待確認，不代表已生效的 CDN 設定或已完成的負載驗收。

- [ ] 運維：分別設定 `/dsh-desk/feeds/*` 與 `/dsh-desk/bin/*`，生產大檔案下載不應長期沿用全路徑繞過快取。清單建議評估用戶端透過 `max-age=0` 重新驗證、CDN 節點快取 30～60 秒、釋出時重新整理。約定最長傳播延遲，並跨區域測量固定 URL 覆蓋後的可見時間；重新整理不保證全球立即可見。
- [ ] 運維與釋出負責人：對帶版本號或雜湊的安裝檔和 blockmap，評估 30 天至一年的節點快取，不覆蓋其 URL。先上傳並驗證安裝檔、完成預熱，再發布清單；確認保留週期覆蓋舊用戶端差分更新所需的輸入。
- [ ] 運維與 Desktop 維護者：將節點 TTL 與用戶端 Cache-Control 分開驗證，檢查重複請求的快取狀態、命中率和 COS 回源指標。確認 updater 附加的查詢參數是否分散快取鍵或繞過快取；只忽略已證明不影響內容的參數。透過實際 updater 驗證 Range/206、Content-Range、完整檔案雜湊和清單及時更新。參閱騰訊雲[節點 TTL](https://cloud.tencent.com/document/product/1552/70777)、[瀏覽器 TTL](https://cloud.tencent.com/document/product/1552/70758) 與[快取設定](https://cloud.tencent.com/document/product/1552/95263)文件。
- [ ] Desktop 維護者與產品負責人：確認啟動及到期恢復的突發請求處理。週期抖動和有上限的失敗退避已實作並測試；啟動和到期喚醒仍立即檢查。為這些觸發增加短暫隨機延遲需要產品確認。強更策略輪詢仍使用獨立 API 與排程策略。
- [ ] 運維與釋出負責人：依據線上使用者端數、啟動／手動／重試峰值、安裝檔大小和預計下載比例制定請求量與頻寬預算。按均勻分佈的十分鐘輪詢，10 萬線上使用者端平均約 167 次檢查／秒，100 萬約 1667 次，尚未計入額外觸發。CDN 快取減少回源壓力，不消除使用者端下載流量費用；功能探測不是負載測試。
- [ ] 運維：設定快取命中率、回源 QPS、錯誤率、頻寬及費用告警，約定閾值與值班負責人。驗證異常請求防護不會破壞 updater 請求或誤傷共享 NAT 用戶端；updater 端點不能要求互動式瀏覽器驗證。上線前記錄故障處置流程。

## 考慮過的替代方案

**自動預下載安裝檔。** 會在使用者請求下載前消耗流量。保留自動發現，但一期每次傳輸與重試都需要使用者操作，與後續安裝授權分開。

**自動重新啟動或普通退出時安裝。** 會繞過明確的任務影響確認。自動安裝需要單獨的產品授權與平臺驗證。

**一個遠端介面控制全部更新。** 強制策略與普通產物發現職責不同。策略頁面與 updater 中繼資料分離，驗證透過後僅複用安裝協調器。

## 驗收標準

- 真實簽名 Windows x64 與 macOS x64/arm64 安裝版升級透過，包括新版本 Host 啟動及資料保留。
- 已部署策略服務透過介面提案的遊客、強制／無需強更、錯誤和平臺矩陣，不以本地 fixture 替代。
- 釋出負責人記錄 CDN 及時更新、Range 與雜湊行為、請求和頻寬預算、告警閾值及故障負責人。
- 產品負責人在承諾離線強更持久化或目標替換前作出決定。

## 風險

本地 updater 與介面檢查不能證明已安裝升級相容性、線上策略可用性或 CDN 效能。若在能解除要求的產物可用前啟用強更策略，使用者可能被阻斷且無法在應用內升級。
