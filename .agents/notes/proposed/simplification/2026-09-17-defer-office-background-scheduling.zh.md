# Agent Note: 待呼叫方需要時再引入 Office 後臺排程

Status: proposed

[English](2026-09-17-defer-office-background-scheduling.md) | 中文

## 問題

[轉換佇列](../../../../packages/document/office-to-pdf/src/queue.ts) 實作了前臺優先順序提升、讀取方取消後的降級、排隊後臺任務的驅逐、預留前臺讀取名額，以及獨立的後臺並行計數。這些機制保護前臺轉換不受推測性預熱影響；普通轉換仍需要佇列的通用資源限制。

[Office 預覽](../../../../packages/client/ui-sidebar-documentpreview/src/client/office/index.ts) 呼叫快取時未傳優先順序，因此[Client 快取](../../../../packages/client/ui-sidebar-documentpreview/src/client/office/cache.ts) 向 Host 轉發預設前臺優先順序。在儲存庫中搜尋 `officeToPdf`、`OfficeToPdfRequest`、`OfficeToPdfPriority` 和 `maxBackgroundConversions`，未發現生產後臺請求。[轉換冒煙測試](../../../../packages/bundle/web-app/tests/document-conversion.e2e.ts) 也提交前臺請求。後臺請求出現在佇列、Remote 和 Client 快取測試中。僅憑暴露 API 和 Client 優先順序傳遞邏輯，無法確定預熱需要哪種排程策略。開放的交付檔案預熱 PR #4064已經提供具體預熱消費者，但其實作仍呼叫不含優先順序的舊 `documentRender` API。刪除排程前必須先與該消費者協調；尚未進入 master 不足以支援直接實施。

[有界轉換決策](../../implemented/architecture/2026-09-15-bounded-office-conversion.zh.md) 有意為前臺消費者預留容量。存在推測性任務時，這條規則仍然正確，但目前呼叫方清單不足以支援維護推測性請求類別及其生命週期互動。

## 提案

移除 `OfficeToPdfPriority`、請求中的 `priority` 和設定 `maxBackgroundConversions`。刪除讀取方及任務的優先順序欄位、升降級、推測性任務驅逐、前臺讀取名額預留，以及佇列的後臺計數器。同時刪除 Client 快取的優先順序傳遞邏輯並更新 Remote 簽名。在轉換容量可用時，接納源預留容量足夠的最早排隊任務；中繼資料佇列滿時拒絕新的獨立任務。仍允許在共享讀取方數量限制內加入已有源任務。

保留提供者、可複用轉換器、延遲授權讀取、其餘所有資源限制、源版本驗證、內容共享、有界結果快取、讀取方獨立取消，以及等待實際工作結束的清理。這項提案改變接納策略，不改變轉換所有權或引擎選擇。

同步更新請求及設定定義、包 README 雙語文件、子系統與生成目錄，以及轉換 fixture（測試前置資料）。刪除僅針對優先順序的斷言；將混合優先順序測試中的資源與取消迴歸改寫為普通請求，並保留覆蓋。現有有界轉換記錄繼續有效，因為其快取、授權和生命週期理由仍然成立；採納本提案只會替換其中的排程策略。

## 考慮過的替代方案

**為未來的預熱呼叫方保留優先順序。** 這可以避免後續 API 變更，但在產品呼叫方能夠定義所需行為之前，就保留了排程狀態與設定。應在有具體預熱呼叫方和實測前臺資源爭用時重新引入優先順序。

**預設停用後臺轉換。** 這可以避免推測性執行，但仍保留公開請求類別、設定及全部排程分支。

**刪除整個共享提供者或快取。** 這超出了證據支援的範圍：獨立轉換和有界共享仍是完整的能力，Loader 冒煙測試也在不依賴展示外掛的情況下驗證它們。

## 驗收標準

- 實施前先明確交付檔案預熱 PR #4064 的排程需求，再重複呼叫方搜尋。若該消費者需要前臺保護，則保留優先順序；不能僅因消費者尚未合入而刪除。
- 從維護中的原始碼、測試、文件和生成目錄移除優先順序型別、欄位、設定及排程分支。決策記錄可以描述被移除的策略。
- 聚焦佇列及提供者的測試保留有界接納、源及摘要共享、取消隔離、輸出所有權和延遲容量釋放覆蓋。真實轉換的 Loader 冒煙測試仍然透過。
- 驗證前臺 Office 預覽路徑；若受影響，同步更新其記錄工作階段快照。執行相關型別檢查、生成引用檢查、文件檢查及 lint。

## 風險

儲存庫外呼叫方可能使用已暴露的穩定前 API，即使儲存庫搜尋未發現後臺消費者。移除優先順序及其設定欄位要求呼叫方更新；本提案不提供相容別名。推測性呼叫方會失去前臺保護，必須停止預熱，直到明確的排程需求得到實作。本提案被接受並實作之前，執行行為不變。
