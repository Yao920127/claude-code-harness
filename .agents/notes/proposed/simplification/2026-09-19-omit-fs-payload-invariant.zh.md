# Agent Note: 省略僅驗證載荷的檔案系統 invariant 配套模組

Status: proposed

[English](2026-09-19-omit-fs-payload-invariant.md) | 中文

## 問題

[檔案系統 invariant](../../../../packages/fs/fs/src/invariant.ts) 檢查目標字串非空、present 版本非空及觀察值的判別標籤。它只讀取一次分發的載荷，不保留歷史，也不與提供者、策略、檔案系統或獨立可變狀態比較。其[測試](../../../../packages/fs/fs/tests/invariant.spec.ts) 直接建構格式錯誤的載荷。釋出該檢查需要配套模組、匯出/建置設定、invariant 依賴、編譯器引用和專用測試。

目前指導需要顯式決策：[獨立觀察規則](../../implemented/simplification/2026-08-28-omit-unneeded-invariant-companions.zh.md) 要求能夠獨立分歧的觀察值，而[執行時約定範例](../../implemented/architecture/2026-07-19-package-invariant-runtime-contracts.zh.md) 明確認可檔案系統目標/版本有效性檢查。後者的語義權威仍被較新的規則保留，因此不能僅憑時間先後解決衝突。

## 提案

將獨立觀察標準應用於這個具體配套模組，並刪除它。事件生產方來自獨立外掛，但逐一檢查單個載荷的格式，並沒有比較它們的觀察值。保留型別化檔案系統事件和實際的[觀察策略消費方](../../../../packages/fs/fs-observation-policy/src/index.ts)，以及現有歸屬處的解析器、wire、讀取、編輯和寫入驗證。

刪除 48 行配套模組、55 行專用測試、`./invariant` 匯出/釋出項、僅供 invariant 使用的依賴和編譯器引用。在 fs 的兩個 README 中補充包特有的省略理由。實作本決策時修改較早的代表性檢查行，保留其他語義範例及共享 invariant 序號產生器制。本提案獲接受前不修改這些目前歸屬文件。

## 考慮過的替代方案

**將載荷驗證保留為顯式策略例外。** 它能提前發現第三方格式錯誤的事件，但這會有意擴大已宣告的獨立觀察標準。提案傾向於在輸入歸屬處驗證，並將配套模組留給關係檢查。

**新增第二個狀態源以證明配套模組有必要。** 在沒有具體缺失 invariant 的情況下否決。僅為保留此診斷而複製策略狀態或暴露新 API，會增加維護負擔。

## 驗收標準

- 在目前歸屬 Agent Notes 中解決已指出的策略衝突；不將其宣稱為已有共識的機械省略。
- 不再保留配套原始碼、測試、匯出、產物條目、僅供 invariant 使用的依賴或編譯器引用；包拓撲檢查接受有說明的省略。
- 真實檔案工具和觀察策略測試保留過期版本、目標缺失、別名、執行方路由及外部狀態斷言。事件及其消費方保留。
- 執行聚焦的 fs 與觀察策略測試、相關檔案工具整合檢查、原始碼/建置產物 invariant 拓撲檢查、build/hygiene、doc-sync（文件同步門禁）和 lint。不用等價的通用載荷驗證機制替換該模組。

## 風險

來自受信任外掛的格式錯誤事件會失去這項可選的早期診斷。刪除該檢查不構成削弱外部資料驗證的理由，也不意味著可以刪除比較生命週期、持久化歷史或獨立組裝值的其他配套模組。如果載荷格式診斷本來就是配套模組策略的一部分，應保留模組並澄清該例外。
