# DSH 統一圓角規範

[English](ui-radius.md) | 中文

## 概述

按元件用途和尺寸選擇統一圓角，並對齊巢狀區域、hover、底色與描邊。適用於 DSH Web 和 Desktop 中的按鈕、cell、卡片、選單、對話方塊與大頭貼。

<a id="scope"></a>
## 範圍與依據

本參考文件規定 DSH Web 和 Desktop 的圓角尺度及元件應用規則。區域性視覺調整限定在指定元件或元件族內，不自動改變全域尺度。

通用樣式職責見 [Web UI 樣式參考](web-styling.zh.md)。共享數值位於 [`base.css`](../packages/client/ui-theme/src/styles/base.css)，曲線行為位於 [`corner-shape.css`](../packages/client/ui-theme/src/styles/corner-shape.css)。修改規則時同步更新主題實作及本規範的中英文版本。

<a id="radius-scale"></a>
## 選擇圓角

H 表示以 CSS 畫素計、包含邊框的設計外部高度。R 表示瀏覽器壓縮相互重疊的圓角之前的 CSS `border-radius`。先確定元件用途，再確定尺寸變體；寬度、文字長度、偶發換行和內容展開都不單獨決定使用更大的圓角。

| 用途 | 典型尺寸或範例 | 圓角 | 共享 token |
|---|---|---|---|
| 小細節 | 低於 H20；鍵帽、行內程式碼、微型控制元件 | R4 | `--dsw-radius-xs` |
| 緊湊控制元件 | H20–28；小按鈕、緊湊圖示按鈕、緊湊選單項 | R8 | `--dsw-radius-sm` |
| 標準控制元件或單行 cell | H32–40；按鈕、輸入框、選擇器、導航行 | R12 | `--dsw-radius-md` |
| 大控制元件或分組內容 | 大按鈕、明確設計為多行的 cell、巢狀表單組 | R16 | `--dsw-radius-lg` |
| 獨立內容卡片 | 設定卡片、訊息氣泡、引匯入口卡片 | R20 | `--dsw-radius-xl` |
| 主容器 | 對話輸入框、對話方塊、主面板或懸浮面板 | R28 | `--dsw-radius-panel` |

擬定控制元件尺寸落在檔位之間時，優先複用已有的公共尺寸變體。高卡片仍是卡片，不因高度超過按鈕就升到 R28。專門設計為多行的 cell 使用 R16；普通按鈕的文字發生換行時，仍保留其按鈕變體。

具體預設值：`Button` 的 `sm` 使用 H28/R8，`md` 使用 H36/R12，包含描邊變體。標準 H32 輸入框和 H36 選擇器使用 R12。“工作區檔案”和“新建終端”引匯入口統一使用 R20，包含僅標題與帶描述的變體。R28 留給包圍它們的面板或對話方塊，不用於這些入口。

程式碼塊、diff 與檔案預覽共用 R16：包括改動檔案入口卡片、交付檔案卡片、通用附件檔案卡片、懸停預覽浮層，以及入口卡片內部的檔案圖示底框。各自的 hover 保持同一輪廓。

<a id="shapes"></a>
## 複用 token，保留有意設計的形狀

新增功能自有的幾何規則前，優先複用 `ui-primitives` 控制元件。固定外部尺寸使用 `box-sizing: border-box`。填充、描邊、ghost、載入中和停用變體保持相同尺寸與圓角；hover、按下、選中和焦點狀態不改變圓角。

普通控制元件和卡片使用具名 token，不新增 10px、14px、18px、24px 等區域性數值。計劃任務控制元件、Desktop 引導、帳號通知和快捷鍵控制元件保留所屬包的幾何規則；[圓角例外記錄](../packages/client/ui-theme/tests/expected/radius-exceptions.expected.json)逐項固定允許的檔案、選擇器及宣告，不豁免整個包。元件族專用屬性可引用共享 token，例如 `--dsl-guide-entry-radius`。由真實內縮距離派生的幾何可使用 `calc()`；它不構成新的尺度檔位。

普通圓角表面在支援時使用主題的 `superellipse(1.5)` 曲線。`corner-shape` 不會繼承：主題將它應用於元素及其 `::before`/`::after`。不支援的引擎保留普通圓弧。不要新增元件專用的平滑規則，導致底色與外框使用不同曲線。

保留有意設計的圓形與膠囊：大頭貼和狀態點使用 `50%`；明確的膠囊與全圓軌道可使用 `999px`。每個此類全圓宣告都在同一規則中配對 `corner-shape: round`。不要因為高度較小就把所有按鈕變成膠囊。圖形標記或微型軌道等細小繪製細節可保留既有區域性幾何，但不能據此給外圍控制元件使用任意圓角。

大頭貼的容器和內部 `img` 都要保持正圓；圖片不能只繼承 `border-radius`，還必須顯式使用 `corner-shape: round`，或從正圓容器繼承曲線。圖片和容器均保持寬高相等。帳號大頭貼的具體尺寸見[帳號設定](../packages/client/ui-settings-account/README.zh.md#use-this-package)。

貼邊停靠表面與相鄰 cell 的共用邊緣可以使用 R0。緊貼卡片的標題欄、底欄或圖片僅對外露的外圍拐角設定圓角；保留內部拼接處的直角，不要給每個子元素的四角都加圓角。

<a id="nested-hover"></a>
## 巢狀幾何與 hover

修改子元素圓角前，先區分以下三種關係：

| 關係 | 規則 | 範例 |
|---|---|---|
| 同心內縮 | 內層 R = max(0, 外層 R − 內縮距離)；使用相同曲線 | 外層 R16，內縮 4，內層 R12 |
| 底色緊貼容器邊緣 | 由外框決定可見圓角；裁切底色或繼承相應圓角 | 兩個獨立 hover 區域組成的分體按鈕卡片 |
| 容器內獨立的卡片或表單組 | 按子元素用途選擇檔位；不機械減去全部父級內邊距 | R20 設定卡片內的 R16 編輯器 |

標準選單使用外層 R16、4px 內邊距、R12 選單項。緊湊選單使用外層 R12、4px 內邊距、R8 選單項。公共 `SegmentedControl` 使用外層 R12、4px 內縮、R8 分段和指示器；`SegmentedTabs` 使用外層 R16、4px 內縮、R12 分段和指示器。修改內邊距時，同步保持指示器偏移、寬度計算、子選單對齊與指標橋接區域一致。

單個可點選表面在自身繪製 hover。貼邊的偽元素或覆蓋層使用與可見外框相同的圓角和曲線。避免單獨給底色設定圓角，導致背景與邊框之間出現月牙狀空隙。

對於分體式引導卡片，在外層卡片設定共享圓角和裁切，貼邊的內部按鈕使用直角。各按鈕可保留獨立的 hover 顏色，由外層卡片把兩塊底色裁切到同一輪廓。透過既有 portal 將下拉選單放在裁切子樹之外。保留可見的鍵盤焦點樣式，不要把外部焦點環一併裁掉。

```css
.entry {
  border-radius: var(--dsl-guide-entry-radius);
  overflow: hidden;
}

.main,
.trigger {
  border-radius: 0;
}
```

外圍引導頁設定 `--dsl-guide-entry-radius: var(--dsw-radius-xl)`。外層卡片為 R20 時，不要再給內部按鈕設定獨立的 R28 端部。

<a id="settings-cards"></a>
## 設定卡片材質

帳號資料、餘額、模型提供商、預設與外掛卡片共用以下預設材質。選中、警告、錯誤和展開狀態可以使用既有語義色，同時保持幾何一致。

```css
.card {
  border-radius: var(--dsw-radius-xl);
  border: 0.5px solid var(--dsw-alias-settings-card-stroke);
  background: var(--dsw-alias-settings-card-fill);
}
```

主題在色板別名所在的 `body` 上，將卡片底色解析為 `--dsw-alias-bg-layer-2`，描邊解析為 `--dsw-alias-border-l4`。功能樣式在明暗主題中均使用這些別名。巢狀編輯器使用 R16 和既有模組底色。帳號的查詢用量、充值連結遵循 H36/R12 的 Button 幾何；授權按鈕使用公共 Button。

平面中性邊框使用共享的 0.5px 髮絲線。具有層級陰影的選單、浮層、對話方塊和麵板使用 `border: 0` 與既有 `--dsw-elevation-*` 材質，其陰影已包含髮絲描邊。不要在該描邊上再疊一層中性邊框，也不要僅為區分設定 tab 就給普通設定卡片加陰影。保留語義狀態色邊框與既有的半透明選單背景效果。

<a id="verification"></a>
## 應用與驗證

1. 一併檢查指定元件、其公共原語、覆蓋層、偽元素和同類變體。先按用途分類再替換數值；不要把同一個舊圓角的所有出現位置機械對映到同一新 token。
2. 適合時修改共享所有方，再對齊依賴它的底色、子元素圓角、裁切和狀態樣式。獨立子卡片保留自己的用途檔位。
3. 在明暗主題中比較實際渲染的外部尺寸、圓角、曲線、底色和描邊。按適用範圍檢查預設、hover、按下或選中、停用及鍵盤焦點狀態；分體按鈕需懸停兩側。元件可能受影響時，檢查窄佈局和較長文案。
4. 使用既有的 radius、corner-shape、elevation 樣式表檢查，以及最小相關瀏覽器情境。圓角檢查會拒絕未納入尺度的字面量和未知 token；它不能判斷合法 token 是否適合某元件，也不能判斷兩個渲染輪廓是否貼合。這些需要視覺確認。
5. 根據實際差異遵循儲存庫驗證和文件要求。確認目標外觀後再更新受影響的預期結果。報告最終規則、已測試介面及未驗證狀態；不要為簡單區域性調整新增僅重複 CSS 數值的測試。
