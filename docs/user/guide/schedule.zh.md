# Schedule 提醒

[English](schedule.md) | 中文

## 概述

在對話中建立提醒，再從自動化任務頁面檢視活動和未執行任務，並修改活動任務的名稱、指令和執行時間。每日提醒遵循儲存的本地時間與時區；固定速率提醒遵循經過的時間間隔。已投遞的一次性任務會保留到顯式刪除為止。

<a id="create-reminders"></a>
## 建立提醒

釋出的 Web profile 會掛載 Schedule 及其時鐘上下文，後者把目前時間和瀏覽器時區交給模型。在請求模型建立提醒前，先設定模型 provider。

向模型提出建立、列出、修改或刪除提醒的請求。模型使用 `schedule_create`、`schedule_list`、`schedule_update` 和 `schedule_delete`（更新原地修改一條提醒，保留其 id 與已儲存的投遞記錄）；「自動化任務」頁面的「新建」操作則為建立開啟一個新工作階段，其 composer 已寫好該請求。支援正整數秒的一次性延遲、絕對日期時間、至少一分鐘的固定間隔、帶 IANA 時區的每日本地時間、帶 IANA 時區和 ISO 星期（週一 1 至週日 7）的每週本地時間，以及帶顯式 IANA 時區的五欄位 cron 表示式（表示式以規範化形式儲存）。

例如，請求：“每天 Asia/Shanghai 時區 23:00 提醒我檢視天氣。”開啟自動化任務頁面並選擇剛建立的提醒，檢查頻率顯示的是每日規則和所需時區，而非僅一次。一次性提醒不會在投遞後變成重複任務。

<a id="manage-tasks"></a>
## 檢視和刪除任務

從側欄開啟自動化任務頁面，可跨 Session 檢視提醒，而不啟用相應對話。按任務已儲存的名稱、指令或任務所屬的內部 Session id 搜尋，並用唯一的“全部/已開啟/未執行”狀態篩選行過濾。Session 行在其 Session 有至少一個活動任務、自身空閒且未歸檔時顯示時鐘標識；歸檔行該格留空，其即時狀態只在懸浮卡片中顯示。懸停任一帶活動任務的 Session 行時，最多列出其中兩個任務及其頻率，以及裝置時區下的下次執行時間與相對時長。已開啟 Session 的頂部在有活動提醒時顯示僅圖示時鐘入口：只有一個任務時直接開啟其詳情，否則列出該 Session 的提醒。

選擇任務開啟“規則”，再選擇“傳送記錄”載入最新的 20 條已儲存記錄。每條已儲存記錄為一行緊湊資訊：時鐘圖示、任務儲存時區下的發生時間（一次性或間隔任務則為瀏覽器時區），以及儲存過的指令。沒有儲存指令的記錄不會用目前指令頂替。“載入更早的記錄”增加下一頁。記錄按儲存順序從新到舊排列，即使時鐘回呼也不改變順序；它們不描述模型執行結果。原工作階段入口位於詳情頁籤條內，因此在“規則”檢視滾動時都保持可見。不帶修飾鍵的左右方向鍵和 Home/End 可切換已聚焦的頁籤；不會攔截與 Alt、Ctrl、Meta 或 Shift 的組合。重新整理任務會保留目前頁籤。

記錄空態表示查詢成功且沒有返回已儲存記錄。載入中、請求失敗、任務不存在和較早記錄遊標無效分別顯示不同提示。請求失敗或返回任務不存在時，使用“重試載入傳送記錄”；遊標無效時，使用“重新整理傳送記錄”重新載入最新一頁。請求失敗時，此前載入的記錄可能仍會顯示，並附有警告。新的最近一次投遞會重新整理最新一頁。離開任務或檢視後才到達的回應不會替換目前檢視。

沒有已儲存歷史的任務只能顯示已有的最近一次回執，直到新投遞增加記錄；後續投遞不會恢復缺失歷史或清除相應提示。未儲存的更早記錄和指令快照無法恢復，不會用目前指令代替缺失的已儲存指令。僅當主機標記更早記錄不可用時，才顯示更早歷史提示；尚未投遞的新任務顯示空態，不顯示該提示。

活動任務參與排程；未執行任務不會再次安排投遞。一次性任務在提醒持久寫入對話收件箱後變為未執行；選擇所有任務或未執行即可找到它。對話頂部目錄和模型 `schedule_list` 僅顯示活動提醒，因此從這些檢視消失並不表示保留的任務已被刪除。

詳情頁籤條內的關聯工作階段入口在中繼資料就緒、Session 可用且未歸檔時開啟原對話；否則入口停用並顯示原因。即使原 Session 無法開啟，任務詳情與刪除操作仍然可用。瀏覽任務不會取消 Session 歸檔。

選擇刪除任務並確認，可停止未來投遞並將該任務從列表中移除，包括未執行任務。刪除會移除該任務及其已儲存的傳送記錄，因此該任務的已儲存歷史隨之消失。確認刪除會關閉發起刪除的面板或頁籤，並在同一個應用級提示裡報告結果——已刪除，或失敗（失敗時任務保留、可重試）；刪除不會刪除原對話，也不會撤回已進入佇列的訊息。該行會保留到成功查詢確認剩餘任務為止。查詢失敗時可透過重試重新載入目錄；錯誤不會被視為查詢成功的空結果。

<a id="edit-timing"></a>
## 修改活動任務

在自動化任務頁面選擇活動任務，開啟“規則”，即可修改其名稱、指令和執行時間。未執行任務保持只讀，修改先儲存在本地草稿中，直到選擇“儲存更改”。編輯保留任務 id、原對話、最近一次投遞迴執以及全部已儲存的傳送記錄。

- Daily 和 Weekly：修改“時間”和“時區”；每週規則還可切換“星期”。時鐘行顯示整秒，未改動的行在提交時保留已儲存的毫秒值，已儲存的 IANA 時區保持不變。規則改變後，按下文的夏令時規則選擇首個未來時點。
- Every：選擇“每 N 小時”“每 N 分鐘”或“每 N 秒”，並按行內標出的單位填寫數量；該單位下的最小間隔為 1 小時、1 分鐘或 60 秒，提交的間隔為整秒。新間隔從主機接受儲存的時間起算，首個目標為一個新間隔之後。時區不影響這個經過時間間隔。
- 一次性 After/At：分別修改“日期”“時間”兩行以及“時區”。初始時區取記錄已儲存的時區；記錄未儲存時區時取本裝置時區，初始鐘錶值在該時區下仍表示同一已儲存瞬時。未儲存時區的一次性規則會顯示一條提示，說明輸入的日期時間按所選時區解釋。更改時區會保留這些鐘錶值並改變時點。目標改變後以相同任務 id 儲存為 At，不將時區保留為重複規則中繼資料。

各行只修改本地草稿。“儲存更改”會以一次更新提交名稱、指令和完整規則；草稿與已儲存任務不同時顯示儲存欄，“取消”恢復已儲存的值。“重複”選單提供每週、週一至週五、每天、每 N 小時、每 N 分鐘、每 N 秒、僅一次和自定義（cron），主機接受其中任何一項，因此一次性 After 可儲存為 At。規範化後等價的規則不寫入或重設目標：相同的 Every 間隔不會重新起算，未變更的一次性目標保留 After 或 At。儲存期間卡片各行停用。離開卡片不會復原主機已開始的寫入。

重新整理目錄會保留你已修改的欄位，其餘欄位取自已重新整理的記錄，因此其他欄位的並行變化不會被未儲存的修改覆蓋。輸入無效時顯示錯誤並阻止儲存。若投遞或其他編輯改變了任務，衝突會阻止覆蓋該變化；請重試以修改最新規則。更新被接受後重新整理目錄。更新被拒絕或無法確認與目錄載入錯誤相互區分：應使用“重試”重新載入目錄，而不是重複已確認的更新。若更新本身無法確認，應在重試前檢查任務。關閉詳情或切換任務後才到達的回應不會替換目前檢視。

<a id="timing-and-delivery"></a>
## 時間與投遞參考

Session 未開啟時，提醒仍然儲存。主機執行期間，在提醒到期時恢復原 Session 並排入 follow-up，不中斷目前工作。重新啟動後檢查儲存的任務，投遞逾期的一次性提醒，或每條重複任務最近錯過的一次。關閉主機後，排程停止，直到主機再次啟動。同一 Session 的到期重複任務可以共用一條訊息。

固定速率提醒在間隔改變前與建立時間對齊；間隔改變後與接受儲存的時間對齊。每日提醒則遵循儲存的本地時間與 IANA 時區。不存在的每日本地時間或日期會被跳過；重疊時間選擇當天較早的一次。絕對時間請求會拒絕不存在的本地時間，並在重疊時選擇較早時刻。瀏覽器提供其時區來解釋自然語言請求；顯式指定時區可以避免歧義。任務詳情在頻率文案裡保留鐘錶規則儲存的時區，並把每個下一目標顯示為裝置時區的鐘點；一次性任務僅儲存 UTC 時點，因此其時間戳使用瀏覽器時區。

已儲存的傳送記錄確認訊息已持久化到對話收件箱，不表示模型完成了所請求的工作。收件箱持久化或任務寫入失敗時，不增加已儲存記錄。收件箱持久化後崩潰或任務寫入失敗，可能留下未記入傳送記錄的已投遞訊息，並重復投遞；不保證恰好投遞一次。這不是執行歷史，也不是外部通知渠道。

已儲存的記錄在追加確認時裁剪：主機保留確認時間落在設定的 `deliveryHistoryDays` 視窗內的記錄（視窗以本次追加回執的 `deliveredAt` 向前計算），且最多保留最新的 `deliveryHistoryRecords` 條。最近一次回執始終保留，發生裁剪時標記更早記錄不可用。主機將保留的歷史儲存在記憶體中，每次確認均重寫完整任務行。分頁限制返回的記錄數，不限制保留的歷史或指令位元組數。

不支援暫停和每次執行新建 Session。名稱、指令和執行時間的修改對模型開放：`schedule_update` 原地修改提醒並保留其 id 與已儲存的投遞記錄；自動化任務頁面也可按所選任務的繫結修改。兩者都不是跨工作階段轉交工作流。僅記錄在舊 Session 日誌中的提醒不會自動排程；請重新建立仍需要的提醒。此前已刪除的任務記錄不會被重建。
