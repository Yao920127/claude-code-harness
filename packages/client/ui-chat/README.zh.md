# @deepseek-ai/dsh-client-ui-chat

[English](README.md) | 中文

## 概述

使用本包可在瀏覽器中渲染已記錄的 Session 對話，包括歷史圖片、在地化操作和滾動位置恢復。工作步驟展示模式控制思考預覽與過程顯隱，不隱藏最終答案；完全展開模式保持已完成輪次的過程行可見。本地 transcript（文字記錄）與 steering（中途引導）提交會立即顯示並保留在原區域，在權威工作階段記錄到達時原子地消失，而排隊中的提交始終不進入 Chat。本包不組裝或修改模型請求。

檔案提及提供者同時接收目前檢視的工作階段 ID 與收尾輪次的屬主資訊，因此繼承歷史中的連結可以指向 fork 自身。

<a id="reference-previews"></a>
## 引用預覽

Chat 在節點列表外透過一個 `MarkdownDelegateProvider` 提供檔案及 HTTP(S) 導航。Assistant Markdown 檔案連結在訊息落定後可於右側欄開啟，包括未修改檔案的引用。相對路徑基於目前檢視的 Session 工作區解析；絕對路徑仍使用同一 Session 的檔案系統存取。`#L24` 和 `#L24-L30` 定位到指定起始行，並複用現有檔案標籤。檔案缺失時顯示預覽錯誤狀態。

獨立的 Markdown 圖片以內嵌預覽顯示，點選開啟共享圖片浮層；本地路徑在訊息落定後基於目前檢視的工作區解析。圖片檔案連結保持點選開啟側欄，滑鼠停留或鍵盤聚焦時顯示縮圖，Esc 關閉縮圖。圖片載入失敗時保留在地化狀態與圖片說明；不執行重複圖片過濾。

設定 → 通用設定 → 網頁連結預設開啟方式控制普通點選 Chat HTTP(S) 連結時的目標：「應用內側邊欄」（預設）開啟新的右側 Sidebar Browser tab，「預設瀏覽器」開啟外部標籤頁。該設定項僅在 Sidebar Browser 可用時顯示。若 Sidebar Browser 未註冊，兩種選擇均使用外部瀏覽器；帶修飾鍵的點選保留原生行為。`ui-chat.linkOpening` 偏好在迴環地址瀏覽器中持久化，設定無法持久化寫入時僅在目前程序內生效。已傳送的檔案引用及訊息日誌確認呼叫的 skill 也可在右側欄開啟預覽。檔案路徑使用目前檢視的 Session；skill 名稱由該 Session 目前的輸入觸發源解析。兩者懸停或聚焦時均使用正文件案連結的虛線下劃線。工作階段、目錄和命令標籤仍只作為引用展示。

<a id="system-prompt-row"></a>
## Chat 隱藏的行

Chat 在所有工作步驟展示模式下都不顯示系統提示詞行、普通上下文注入和 `permission` 命令列。包含工具新增或移除記錄的上下文仍然可見。該過濾不改變已記錄的 Session 事件或 Trajectory 檢視能力。非人工輪次觸發仍作為獨立通知顯示，其他命令列仍保留在 Chat 中。

Assistant 嘗試結束且沒有可見訊息時，Chat 隱藏已釋出的 Node，不移除其 key。同一 Step 的重試再次產生可見內容時，複用該 key。已載入視窗缺少 Step 起點時也遵循此規則。

<a id="command-and-failure-rows"></a>
## 指令與失敗行

通用指令行在所有生命週期狀態中都保留普通指令圖示；失敗仍透過行狀態與摘要表達。每個終止輪次都渲染自己的紅點行；欠費失敗的行使用中立的 `message.failure.quota` 文案，而不是提供者訊息。新追加的 `QUOTA` 或 `ACCOUNT_QUOTA` 產生的瞬時提示來自本包註冊在 `shell.overlay` 的全域條目，它不隨 Chat 面板消失：該條目把唯一一條即時提示交給 `shell.quota-notice` 鏈，並在無人接管時退回到自己的警告 Toast，接管該錯誤碼的條目會替換該退回。只有本 Client 已繫結並已物化的 Session 會發布提示；它從未開啟的 Session 中的欠費不會發布。更新的提示會替換目前提示，除非認領條目用 `keepOpen()` 保持住目前提示：該呼叫返回一個由呼叫方持有、必須在解除安裝時呼叫的釋放函式，只要存在保持，認領條目就繼續掛載，後續提示被丟棄，釋放後恢復後續提示但不重放已丟棄的提示。退回 Toast 自身沒有延後策略：當 Desktop 帳號的不透明原生 Platform 頁蓋住本頁時，它仍會在下方執行，其顯示計時器可能在不可見時走完並自行撤下提示，因此只留下持久化失敗行。釋放只移除自己的保持，因此它在關閉或更新的保持之後執行時不會影響更新的保持。關閉與退出登入會清空所有保持；被丟棄的提示不排隊，其對應的持久化失敗行仍會渲染。歷史替換和分頁不會發布提示。中間重試不會建立終止行；輸出 token 上限使用琥珀色警告點。

<a id="turn-token-usage"></a>
## 輪次 token 用量

只有當已載入視窗包含 `turn/start`，且每次已啟動的模型嘗試都報告安全、精確的用量時，已完成輪次才顯示可展開的用量行。該行會省略不可用的可選用量桶。記帳不完整或相互矛盾時，整個詳情都不顯示，避免把部分總量冒充完整結果。

設定 → 通用設定 → 效能與用量將 `ui-chat.performanceUsage` 儲存為 `detailed`（預設）或 `compact`。簡潔模式僅在輸入框下方顯示可用的輸出速度和快取命中率，不顯示統計互動卡片或每輪用量。詳細模式提供工作階段統計和每輪 token 用量。兩種模式的已完成輪次頁尾均不顯示耗時。該偏好僅影響展示，記帳和 Session 事件保持完整。

在非迴環地址瀏覽器中，設定作用域無法持久化寫入，因此該偏好僅在目前程序內生效。明確選擇會立即更新所有使用方；迴環地址瀏覽器收到 Host 已接受的設定後會同步目前值。

偏好選單在釋出新選擇之前，先將焦點還給觸發按鈕，且不引起滾動。

<a id="completed-turn-footer"></a>
## 已完成輪次的頁尾

產物擴充功能可透過 `ChatNodeStore.turnDataSource` 訂閱一個 Turn 中指定型別的節點資料。來源包含隱藏節點，並按錨點順序提供其業務資料。成員關係增量更新；只有被訂閱的集合才生成有序陣列，其他 Turn 或型別的更新不通知該集合。

已完成輪次的操作頁尾位於記錄的輪次結束之後。操作行與前方正文或擴充功能內容相隔 20px。只有最新輪次且最後可見內容為回覆時，操作常顯；其他結尾及歷史輪次在懸停或鍵盤聚焦時顯示操作。不支援懸停的裝置始終顯示操作。

<a id="turn-process-folding"></a>
## 輪次過程摺疊

正常線上時，本地 transcript 與 steering 回顯在 Inbox 接受與領取期間保持掛載，直到持久訊息到達，不會重複觸發跟隨底部。跨用戶端的待處理 steering 遵循 Inbox 順序，在匹配位置使用本地回顯。已入檔的本地 steering 還會排除匹配的舊 Inbox 行，直到領取投影到達；沒有本地提交身份的 steering 仍按 Inbox 投影顯示。重連後，Host 訊息替代已有接收回執的本地回顯；已領取但尚未入檔時，氣泡可能短暫消失。

Chat 末尾為進行中的 Turn 控制行，且該輪尚無可見輸入時，第一條本地 transcript 回顯顯示在控制行前。其他回顯保留在正文末尾。控制行與回顯共用一個 keyed 列表，因此控制行到達時不會重新掛載回顯。持久輸入在同一次渲染中替換匹配的回顯。

工作步驟展示模式控制過程組顯示與推理預覽。簡潔、標準、詳細模式收起符合條件的已完成輪次，不隱藏最終答案；完全展開模式保留時長或狀態抬頭，但不支援收起，歷史過程行直接顯示。[業務規則明細](src/client/conversation-nodes/README.zh.md#display-modes) 統一說明模式表、組頭行為、整輪摺疊資格、時鐘與開合重置。

<a id="grouped-rendering"></a>
## 分組渲染

Chat 透過 `uiConversation.groups` 註冊過程 Group Definition。React 透過穩定的 Group 與 Node 容器渲染混合 `node`/`group` 根序列，組頭資料與成員陣列分別訂閱。已結束組的標題獨立於即時詳情偏好，只有執行中的標題在該偏好變化時更新。[過程分組業務規則](src/client/conversation-nodes/README.zh.md#process-grouping) 定義切分方式與活動摘要。

`groupPart` 在 Assistant 渲染器中選擇推理或回覆，不複製 Node 載荷。同一個 callId 的準備、派發與結果階段由 Tool 節點自己擁有。每個部分有獨立的 DOM 錨點用於恢復閱讀位置；輪次導航使用原 Node key，落到它的第一個可見部分。展示模式切換以及為完整舊組補入更早成員時，保留組來源、成員父級及 key。原 Node Store 仍是唯一節點資料所有者，替換 Builder 時重新繫結按鍵訂閱，不重掛載容器。模式變化保留尺寸觀察器，並複用整輪狀態選擇器。

即時工具 delta 與推理共用按幀合併的釋出節奏；持久呼叫和結果立即釋出。重複具名 delta 在投影呼叫、錨點、位置及可見性均未變化時保留 Tool 節點及其資料引用。

過程組使用穩定的 `div` 佈局盒子、滾動正文及不限高的內容盒子，後者報告正文內部的內容增長。業務樣式必須適應組內及組邊界間距，處理隱藏或空成員以及回答前的間距特例。CSS 變數不屬於 Group Definition。

滾動邊緣漸隱在 `ResizeObserver` 報告已展開組的佈局後初始化；展開組時不會在 layout effect 中立即讀取滾動尺寸。

每個組擁有本地 `useDisclosure` 狀態，元件保持掛載時，模式切換保留該狀態。

Chat 節點 slot 為推理與工具注入繫結重置來源的 `useDisclosure` 掛鉤。中間 renderer 只直接傳遞、不訂閱，每次呼叫擁有獨立展開狀態。來源回呼保留接收物件及穩定引用。外層輪次實際隱藏過程成員時，所在節點重置這些開合狀態，不替換元件 key，也不改變掛鉤引用。展示模式切換保留展開狀態。

<a id="scroll-ownership"></a>
## 滾動歸屬

Chat 會在歷史前插與 renderer 重新掛載時恢復語義錨點，並且只在跟隨底部時停用自己滾動區域的瀏覽器自動錨定。沒有讀者移動的貼底滾動事件，以及確實到達最底部的讀者輸入，會立即更新跟隨歸屬，避免後續佈局變化使其底部位置失效。其他讀者移動即使位於跟隨閾值內，也保持待處理直到取樣週期或 `scrollend`，防止佈局增長抵消小幅滾動操作。提交正文輸入或 steering 時立即恢復跟隨底部，並清除先前待處理的讀者滾動取樣。讀者跟隨底部時，`ResizeObserver` 追隨新的底部，並且無需讀取行幾何就選中最後一個已載入輪次；讀者離開底部後，高度變化會保持頂部位置，再由閱讀線幾何選擇活躍輪次。輪次導航預覽位於 Markdown 程式碼塊粘性頭欄上方，而導航外框始終處於 composer 上方的 transcript 區域內。

輪次軌道與回到底部按鈕位於正文裁剪層外。它們相對共享工作階段滾動容器做 sticky 定位；Chat 自己持有滾動容器時，則相對 Chat 外框做 absolute 定位。正文扣除水平內邊距後的可用寬度不超過 900px 時，隱藏輪次軌道；判斷依據不是瀏覽器視口寬度。

正文根節點使用 `overflow-x: visible; overflow-y: clip`：裁剪縱向溢位，但不建立滾動容器。因此，在沒有更近的滾動祖先時，Markdown 程式碼塊的 sticky 頭欄和展開的壓縮摘要頭欄仍以實際工作階段滾動容器為參照。限高過程組和終端區域保留各自的滾動容器。

外層文字記錄與每個已展開限高組的跟隨狀態彼此獨立。原生動畫的中間滾動保留跟隨意圖；讀者手勢中斷動畫，是否繼續跟隨由實際位移決定。滾動傳遞可以帶動外層，外層再按自身離底距離判斷。回到底部按鈕只恢復外層跟隨。

| 外層跟隨 | 已展開小組跟隨 | 回到底部按鈕 | 新增內容 |
|---|---|---|---|
| 開啟 | 開啟 | 隱藏 | 各自跟隨自己的底部。 |
| 開啟 | 關閉 | 隱藏 | 外層跟隨，小組保持原位置。 |
| 關閉 | 開啟 | 顯示 | 小組跟隨，外層保持閱讀位置。 |
| 關閉 | 關閉 | 顯示 | 兩者都保持閱讀位置。 |

輪次軌道只掛載可見刻度、預載入範圍及鍵盤焦點刻度的相鄰項。固定間距和觀察到的視口尺寸決定滾動偏移，不讀取 DOM 滾動總高度。初始定位等待正文恢復活躍輪次，以及軌道首次獲得可用視口尺寸。ref 控制介面分別支援啟用輪次和僅滾動軌道；正文自身仍完整掛載。

指標位於軌道外時，自動跟隨在活躍刻度中心處於非漸隱區域內時保持軌道不動，越界後才將其居中。預覽隨指標移動或焦點切換；刻度在靜止指標下滾動不會選中另一個預覽。

<details>
<summary>滾動實作——點選展開</summary>

過程組內的 wheel、touchstart 和任意 pointerdown 都會中斷正在進行的平滑動畫，包括按下工具卡片。上下方向鍵、PageUp/PageDown、Home/End 和空格鍵也會中斷動畫，除非子控制元件已阻止該按鍵的預設行為；輸入控制元件不被排除。這些事件無需產生滾動位移就會停止動畫，之後的位置取樣再決定是否繼續跟隨。

`useScrollFollow` 提供各自獨立的控制器，共用觸底閾值判斷、跟隨意圖與原生滾動實作。`useProcessScroll` 負責小組觀察、初始定位及邊緣漸隱。外層保持即時跟隨；組內增長使用原生平滑滾動，減少動態效果偏好開啟時改為即時滾動。`scrollend` 前的增長保留目前動畫目標；到達該目標或因內容縮短而鉗制的位置後，再追隨最新底部；停在其他位置則釋放跟隨。展開時仍即時定位。沒有進行中動畫時，容差範圍內的貼底請求使用即時定位，避免小數位置上的無位移操作留下未結束的平滑目標。

`useChatViewport` 負責識別輪次的 DOM 讀取、限制範圍後的寫入、原生事件及一個持續保留的分頁錨點。載入更早時，Node 與 Group 容器根據已有開合狀態標記可選錨點。視口按正文順序選擇第一個非空、未隱藏的標記，不做命中測試或按幾何位置搜尋，再測量該元素及其滾動容器。先補償錨點所在的限高組，再把剩餘位移交給整段文字的滾動區域。內層補償寫入透過該組繫結的控制器取消動畫並暫停跟隨，讀者滾回底部後恢復。提交和後續內容尺寸變化複用該錨點；訊息行重掛載時按同一語義 key 重新定位。補償限於實際可滾動範圍，不增加底部空白。

`useChatReading` 負責跟隨策略、讀者輸入取樣和語義位置記憶；`useChatNavigation` 負責輪次跳轉，並向視口請求位置保持。閱讀手勢釋放分頁錨點，composer 內的點選、打字和非滾動按鍵則保留錨點；分頁仍在載入時，`scrollend` 會記錄讀者的新位置。`useChatScroll` 協調已提交的輸入。顯式導航把測得的落點交給閱讀策略，因此無需透過命中測試重新尋找已知目標。

活躍輪次高亮採用近似定位：`readVisibleTurn` 對正文容器的直屬 Node/Group 佈局盒二分，落在間隙時保留前方候選。它不做文件命中測試，也不查詢 Group 成員或全部 Turn 標記。空 Seat 保留零高度的流內佈局盒，使外層位置有序且不增加間距。這種定位不改變語義位置捕捉或分頁補償。

</details>

<a id="model-experience"></a>
## 模型體驗

無，因為本包在瀏覽器中渲染已記錄的對話狀態，不註冊任何面向模型的內容。

#### KV Cache 影響

無；Chat 呈現不會組裝或修改提供者請求。

## 已知限制與暫緩事項

<a id="known-limitations-and-deferred-work"></a>


- **工具變更展示** — `developer-message` Definition 與 `input-message` 共用上下文展示。僅包含工具變更的 developer 訊息在單個工具新增或移除時直接顯示工具名，不提供展開操作。多個變更顯示新增、移除數量，展開後按變更型別分別以逗號分隔顯示一行工具列表。混合內容使用通用上下文展示。

- **開場回顯預測本地順序**——執行狀態更新前連續發出的多條訊息可能都留在 Chat。初始排列遵循本地提交順序，而非 Host 佇列順序；Host 按不同順序接收請求時，入檔可能調整它們的位置。

- **transcript 只反映已載入的 Session 視窗**——只有工作階段控制器載入前一頁事件後，更早的 transcript node 才會出現。輪次導航比視窗更寬：軌道把已載入的輪次與主機 `turnOutline` 投影合併，每個已開始的輪次都有固定間距刻度（相隔 10px；階梯高於外框時在框內滾動並以漸變淡出標示可滾方向），啟用未載入刻度會先把歷史分頁拉到該輪次的 `turn/start` seq 再落到它的行上。沒有該投影時（未掛載 `dsh-session-turn-outline` 的裝配），軌道退回到僅顯示已載入輪次。
- **導航預覽按卡片尺寸截斷**——提示詞一行（50 字元）、回覆至多三行（120 字元），已載入與未載入 Turn 一致；未載入 Turn 的回覆要等該輪落定後才隨大綱到達，進行中的輪次在此之前只預覽提示詞（或僅輪次號）。
