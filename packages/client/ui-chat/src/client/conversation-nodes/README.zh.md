<a id="reading-model"></a>
## 先理解一輪對話怎樣顯示

分組、類別計數、展示模式和整輪摺疊分別回答不同問題：分組決定哪些過程行放在一起；計數概括一個已有組裡做了什麼；展示模式決定組內顯示多少；沒有中途輸入打斷時，整輪摺疊可以一次隱藏跨越多個組和階段回覆的全部過程。

### 一個完整例子

假設助手先思考、讀檔案、執行命令，給出一段進展回覆，然後繼續思考、執行程式碼，最後給出答案。該輪完成後，內容在業務上分成：

- 使用者輸入。
- 整輪控制元件。
- 由整輪控制元件控制的過程範圍：
  - 過程組 G1：思考、`read`、`bash`。
  - 階段回覆：不屬於 G1 或 G2，但仍屬於整輪過程。
  - 過程組 G2：思考、`run_code`。
- 最終答案正文，不隨過程收起。
- 已完成輪次頁尾。

每次回覆都會截斷二級組，但只有最終答案正文不參與整輪摺疊。因此，階段回覆雖然是一行獨立內容，整輪收起時仍會消失。最終答案附帶的思考仍屬於過程內容。

| 問題 | 由什麼決定 | 例子中的結果 |
|---|---|---|
| 哪些行放在一起？ | 分組邊界 | 階段回覆分開 G1 與 G2；從 `read` 換成 `bash` 不會拆組。 |
| 一組做了什麼？ | 類別計數 | G1 為 `read=1, commands=1`，G2 為 `code=1`；思考不增加工具次數。 |
| 組標題寫什麼？ | 組狀態與摘要 | 未結束組顯示最近執行活動；已結束組顯示次數最多的類別。次數不決定摺疊。 |
| 組內顯示多少細節？ | 展示模式與手動開合 | 簡潔、標準、詳細模式保留歷史組頭；詳細模式直接顯示執行中正文，完全展開模式直接顯示執行中與歷史正文。 |
| 過程整體是否可見？ | 整輪開合 | 整輪收起時，G1、階段回覆和 G2 一起隱藏。 |

### 使用者實際看到什麼

以下假設上面的輪次正常結束，使用者尚未手動開啟內部控制元件：

| 檢視狀態 | 可見內容 |
|---|---|
| 整輪收起，簡潔／標準／詳細模式 | 輸入、整輪控制元件、最終答案和頁尾；過程組頭、正文及階段回覆都不顯示。 |
| 整輪展開，簡潔／標準／詳細模式 | G1/G2 組頭、階段回覆及最終答案；組正文初始收起。 |
| 整輪和 G1 展開，標準或詳細模式 | G1 的思考與工具行，思考帶已結算預覽；G2 仍是組頭。單個完整正文仍需手動開啟。 |
| 完全展開模式 | 不可收起的整輪時長或狀態抬頭、全部過程行、階段回覆與最終答案。沒有組頭，單個工具／思考正文仍需手動展開。 |

顯隱從外向內生效：整輪 → 二級組 → 單個思考或工具。內層展開不能越過外層收起。類別變化不會開合任何一層；切換模式保留分組和使用者的手動展開選擇。

若過程開始後又出現 steering、User 或觸發通知，該輪不提供整輪收起，只保留各組自己的開合。`G1 → steering 1 → G2 → steering 2 → G3` 在簡潔／標準模式中始終保留三個組頭及兩條輸入的順序，階段回覆也保持可見；開啟一個組只顯示該組正文。詳細模式僅在該輪仍執行時直接顯示組正文，完成後保留組頭及手動開合；完全展開模式在兩種情況下都直接顯示組正文。整輪控制元件仍顯示時長或狀態，但不提供摺疊操作。

<a id="whole-turn-folding"></a>
## 整輪摺疊

簡潔、標準、詳細模式的整輪摺疊控制已載入的過程範圍，獨立於二級組。完全展開模式保持該範圍可見，保留時長或狀態抬頭，但不支援收起。已經記錄輪次結束時，即使向前分頁尚未載入到輪次起點，也可以對該範圍摺疊。

整輪控制元件位於該輪所有起始輸入之後，包括人工 steering 和非人工觸發通知；等待首個 Assistant 輸出及輸出到達後均保持這一順序。首個過程證據之前的連續輸入都屬於開場，以最後一條為準；過程證據之後的輸入留在原位，即使分頁尚未載入其入隊記錄、訊息暫時歸為普通 User，也不能把前面的過程移到它後面。

| 已進入請求的輸入 | Chat 展示 |
|---|---|
| 從 `next-step` 領取的人工訊息 | Steering 訊息，不參與過程摺疊。 |
| 目前 `next-turn` 領取批次中的非人工訊息 | 獨立、預設收起的輪次觸發通知。 |
| 空閒時從 `next-step` 領取的非人工訊息 | 僅在 Step 1、已載入輪次起點、領取發生於起點之後、本輪沒有 `next-turn` 領取、同一 `next-step` 批次沒有人工訊息時，作為輪次觸發通知。 |
| 其他非人工輸入 | 普通 Context，保留在 Node Store，但不顯示在 Chat 中。未領取、已取消或重新入隊的訊息不構成喚醒領取。 |

觸發通知的標題與圖示使用記錄中的 `source.kind`：`schedule`、`tool-jobs`、`cordis-host-runner` 分別表示排程任務、後臺任務和外掛更新。目標、Agent、團隊、子任務和 webhook 來源有各自的標題；`provider: github` 的 webhook 使用 GitHub 標題。未知來源顯示通用執行請求標題。展開通知顯示記錄的正文，不代表執行成功。

| 輪次條件 | 目前行為 |
|---|---|
| 尚未結束 | 過程內容保持展開，不能收起整輪；二級組仍按模式表展示。 |
| 已停止或失敗 | 過程內容保持展開，不能收起整輪。 |
| 首個過程證據之後還有可見輸入 | 不能收起整輪；保留各段過程、階段回覆及輸入的順序，組級開合仍可用。開場連續輸入不屬於此情況。 |
| 其他已結束輪次，有已載入的過程內容 | 過程預設收起，允許手動開合；不要求已載入到輪次起點，也不要求整個 Session 歷史都已載入。 |
| 已結束但沒有最終答案 | 滿足其他摺疊條件時收起全部過程行。 |
| 已載入結束記錄，但缺少起點 | 對已載入內容應用上述已結束輪次規則；不顯示耗時，不用最早載入的工具或訊息時間冒充起點。 |
| 起點與結束記錄均未載入 | 保留過程行可見，不顯示整輪控制元件。 |
| 存在整輪控制元件，但沒有過程內容 | 保留標題，不提供摺疊操作。 |

最終答案取最後一個 Step 中已結算的 Assistant 回覆，要求有可見回覆內容且沒有工具呼叫塊。最終答案的回覆正文不參與整輪摺疊，推理仍屬於過程。使用者與 steering 輸入、觸發通知、終止錯誤、最大 token 提示及已完成輪次頁尾保持獨立。二級分組把模型重試視為分隔節點，但整輪摺疊仍包含重試行。

載入更早的一頁保留使用者的組級開合選擇。最終答案未變化且仍符合整輪摺疊條件時，新載入的過程內容沿用該輪的開合狀態；若新頁揭示中途輸入，則改用各組開合，不再整輪隱藏。真正的起點到達後才顯示時長，是否已載入完全部歷史不是額外摺疊條件。若新內容只是接在舊組前面，舊組和舊訊息行保留身份及已有展開狀態。新頁出現回覆、steering 等真實邊界時仍按規則分組，不把所有新增內容強並進舊組。

點選載入更早時，按正文順序錨定按鈕下的第一個可見內容項，不根據它在視口中的位置選擇。組收起時選組 header；展開時跳過組 header，選內部第一個可見成員。整輪過程控制元件不作為錨點，因為分頁可能將它移到新載入的過程及 steering 前面。整輪收起時，錨定第一個仍可見的訊息，例如 steering 或最終答案。普通訊息與 steering 選擇自身，跳過隱藏和空行。新增內容全進入收起的組時，組 header 保持原位；前面出現更早的組或節點時，仍保持該組 header 的位置，讓新增內容出現在它上方。

分頁把更早內容加到保留的錨點上方，不主動跳到新內容頂部。限高組先在自己的滾動範圍內吸收位移，剩餘部分由外層文字滾動補償，包括組正文剛達到限高的情況。可滾動範圍不足時，補償停在實際邊界，不增加底部空白。後續內容撐高沿用同一個錨點，直到閱讀手勢或顯式導航釋放它。在 composer 中打字或點選，以及 transcript 內的非滾動按鍵，保留錨點。分頁請求期間若讀者滾動，優先服從滾動，停止後以新的閱讀位置作為分頁錨點。

執行時鐘按整秒更新，最少顯示一秒，滿 60 分鐘使用小時。完成後固定時長，取消與失敗使用對應狀態替代。生命週期變化有禮貌播報，時鐘跳動不播報。該控制元件是 Chat 唯一的輪次級執行指示。

自動收起若會隱藏鍵盤焦點，則保持過程展開。手動收起先將焦點移到過程控制元件，再隱藏成員。收起整輪會重置內部組及推理、工具的開合，不重置渲染器的其他狀態。瀏覽器查詢可以顯示可搜尋的隱藏內容。

<a id="display-modes"></a>
## 展示模式

設定 → 通用設定 → 工作步驟展示提供 `compact`、`standard`（預設）、`detailed` 和 `verbose`，說明為「選擇希望看到多少工具呼叫細節」。舊值 `normal` 讀取為 `standard`，`expanded` 讀取為 `detailed`，不自動回寫；已有 `detailed` 保持不變。未設定、無效值以及 Host 設定到達前均使用 `standard`；其他設定的無效值仍會驗證失敗。

| 行為 | 簡潔 | 標準 | 詳細 | 完全展開 |
|---|---|---|---|---|
| 過程組頭 | 類別摘要 | 摘要與即時任務詳情 | 執行中輪次隱藏；歷史輪次保留 | 隱藏 |
| 過程組正文 | 初始收起 | 初始收起 | 執行中輪次直接顯示、不設組級限高；歷史輪次按手動開合顯示 | 執行中與歷史輪次都直接顯示，不設組級限高 |
| 已結算推理預覽 | 隱藏 | 首行 | 首行 | 首行 |
| 單個推理與工具正文 | 手動展開 | 手動展開 | 手動展開 | 手動展開 |
| 符合條件的已完成輪次 | 初始收起 | 初始收起 | 初始收起 | 始終展開；時長或狀態抬頭不能收起它 |

已結束組的組頭展示排序摘要的前三類，不顯示次數；沒有類別時使用思考標題。執行中的組頭展示即時工具類別，沒有執行工具時使用思考標題；標準模式附加即時詳情。即時標題至少保留 150ms，只保留最新待顯示標題。

### 組標題規則

三個階段共用下方工具名分類。準備中的 Tool 節點使用對應類別的準備文案；`read` 為「準備讀取檔案」，`read_image` 為「準備讀取圖片」，`write` 為「準備寫入檔案」，`edit` 和 `apply_patch` 為「準備編輯檔案」，`todo_write` 及目標工具為「準備更新計劃」。只有通用類別的「準備呼叫工具」在標準模式中追加協定工具名，其他類別不追加。它計為一次呼叫，不解析參數，只渲染不可展開的一行。具名即時 delta 可以建立該節點；歷史呼叫直接從 tool/call 開始，不重現準備過程。

以下文案描述已記錄的活動，不保證操作成功；例如失敗的讀取仍參與「已讀取檔案」類別。

| 類別 | 未結束組的活動文案 | 已結束組的摘要文案 |
|---|---|---|
| 無即時類別 / 無計數類別 | 正在分析請求 | 已完成分析 |
| `read` | 正在讀取檔案 | 已讀取檔案 |
| `readImage` | 正在讀取圖片 | 已讀取圖片 |
| `search` | 正在搜尋程式碼 | 已搜尋程式碼 |
| `write` | 正在寫入檔案 | 已寫入檔案 |
| `edit` | 正在編輯檔案 | 修改了檔案 |
| `commands` | 正在執行命令 | 執行了命令 |
| `code` | 正在執行程式碼 | 執行了程式碼 |
| `webSearch` | 正在搜尋網頁 | 已搜尋網頁 |
| `webFetch` | 正在存取網頁 | 已存取網頁 |
| `subagents` | 正在協調子代理 | 已協調子代理 |
| `plan` | 正在更新計劃 | 更新了計劃 |
| `questions` | 等待你的操作 | 向使用者提出了問題 |
| `tools` | 正在呼叫工具 | 已呼叫工具 |

| 組狀態 | 標題組合規則 |
|---|---|
| 未結束，有執行工具 | 取即時類別，不取計數最多的類別。標準模式用 ` · ` 追加非空詳情，簡潔模式不追加。 |
| 未結束，沒有執行工具 | 即使已完成工具次數非零，也使用分析文案；標準模式可以追加執行中推理詳情。 |
| 已結束，零個類別 | 使用「已完成分析」。 |
| 已結束，一個類別 | 使用該類別的已結束文案，不帶次數。 |
| 已結束，兩個類別 | 按排名用「並」連線；僅當兩項都以 `已` 開頭時省略第二項的 `已`，例如 `已讀取檔案並搜尋程式碼`。 |
| 已結束，三個類別 | 按排名用中文逗號 `，` 連線三項文案。 |
| 已結束，超過三個類別 | 只顯示前三項文案，末尾加「等」。 |

英文組合標題將第一項之後各項的首字母轉為小寫。組結束時立即切換完成摘要；150ms 最短保留時間針對執行中標題變化，不延遲完成狀態。詳細模式隱藏執行中輪次的組頭，包括被回覆或 steering 截斷、但所屬輪次尚未結束的小組；完全展開模式也隱藏曆史組頭。

組頭顯示類別圖示，懸停或鍵盤聚焦時替換為向下箭頭，展開時顯示向上箭頭。手動展開的組正文使用 8px 行間距、`min(400px, 50vh)` 限高及 24px 方向漸隱；到達邊緣時滾輪可以繼續滾動外層文字記錄。詳細模式對執行中輪次取消組級限高，使用 16px 行間距；完全展開模式對歷史輪次也採用該佈局。

已展開的限高組僅在自己的滾動位置處於底部時跟隨內容增長。滾離底部暫停該組跟隨，滾回底部後恢復，與外層文字記錄的跟隨狀態獨立。手動展開未關閉的組時定位到底部並跟隨增長；手動展開已關閉的組時從頂部開始且不啟用跟隨，即使初始內容無需滾動即可容納。資料中的組變為已關閉，或透過模式切換恢復限高時，不重置已展開組的閱讀位置。瀏覽器查詢沿用自身的展開定位。

單個推理初始收起，包括流式輸出期間。四檔都預覽最近一個首行以換行結束的段落；未完成的單行沒有預覽，該段落後續文字不改變預覽。結算後按上表展示。展開的推理使用緊湊 Markdown 排版。

切換模式保留手動展開的組和內部開合狀態，只改變顯隱與尺寸，不重建訊息行。詳細和完全展開都不表示自動開啟每個內部控制元件；只有完全展開模式始終展開整輪。

<a id="process-grouping"></a>
## 過程分組

[process-groups.ts](process-groups.ts) 劃分可見 Chat 內容，[process-activity.ts](process-activity.ts) 彙總每組活動，兩者共同遵循下列業務規則。

一組收集同一輪次內相鄰的過程內容，僅 Step 編號變化不會拆組。四檔模式使用同一分組結果。組的 `closed` 表示這段內容已經結束，不表示 UI 開合控制元件處於收起狀態。

| 輸入 | 歸屬與切分 |
|---|---|
| 非空白 Assistant 推理 | 將該 Assistant 的一個 `reasoning` 引用加入目前組，必要時建立組。 |
| Assistant 回覆 | 結束前面的組，輸出獨立的 `response` 引用。同一 Node 含有推理時，先將推理加入組，再結束該組。 |
| `user`、`steering`、`turn-trigger`、`model-retry`、`turn-error`、`turn-max-tokens`、`turn-tail` | 結束前面的組，Node 作為獨立根引用保留。 |
| `turn-process` | 控制元件作為獨立根引用保留，不結束目前組。 |
| 輪次內其他可見 Node，包括工具 | 將整個 Node 加入目前組，必要時建立組。 |
| 另一輪次或沒有輪次歸屬的 Node | 截斷同輪次序列。無輪次 Node 保持獨立，Assistant 也不拆分。 |
| 隱藏 Node、系統提示詞、普通 Context 注入及 `permission` 命令 | 不進入分組輸入，既不入組，也不截斷組。 |

回覆須包含非空白文字、圖片或其他可見塊；推理和工具呼叫協定塊不算回覆。既無非空白推理、也無回覆內容的 Assistant 不產生引用。只有存在成員才建立組，因此僅含中繼資料的輪次不會產生空組。

### 範例

`A` 表示 Assistant Node，`T` 表示工具 Node，`G[...]` 表示過程組。箭頭表示輸入或根引用順序；未註明時，範例均屬於同一輪次。

| 輸入序列 | 分組後的根引用 |
|---|---|
| 同一 Step 的 `A1(thought, reply) → T1` | `G[A1.reasoning] → A1.response → G[T1]` |
| `T1(step=1) → A2(thought, step=2) → T2` | `G[T1, A2.reasoning, T2]` |
| `T1 → steering → T2` | `G[T1] → steering → G[T2]` |
| `T1(turn=1) → U(no turn) → T2(turn=1)` | `G[T1] → U → G[T2]` |
| `A1(reply)` | `A1.response`，不產生過程組 |
| `read → bash → subagent_codex`，中間沒有回覆或輸入 | 同一組；工具類別變化不會拆組。 |
| `run_code` 內含 `read`、`bash` 子呼叫 | `run_code` 工具 Node 是一個組成員，其巢狀呼叫不產生獨立根引用。 |
| 工具收到失敗結果 | 更新該成員，不因此拆組；另外產生的 `turn-error` Node 才會截斷序列。 |

即使輪次仍在執行，回覆和獨立分隔節點也會立即結束前面的組。尾組在後面出現另一輪次或無輪次 Node 時結束，所屬輪次狀態為 `closed` 時也結束。其他輪次狀態或無法獲知輪次狀態，本身不會結束尾組。分隔節點消失後重新分組，原組可以再次變為未結束。

## 活動摘要

[process-activity.ts](process-activity.ts) 從一組的成員 Node 計算類別次數和即時詳情，不決定成員歸屬或展示文案。

### 類別計數

這裡統計本組的工具呼叫，不是成功運算元、修改檔案數、子 Agent 數量或工作時長。先按下表確定計數，再按類別排序。

| 本組中的呼叫記錄 | 計數規則 |
|---|---|
| 準備中呼叫、執行中呼叫、成功結果、失敗結果，或保留原呼叫資訊的中斷結果 | 按記錄的工具名計入對應類別一次；結算或失敗不會增加或扣除次數。 |
| 重複的 `callId` | 只計首次出現，包括同時作為根呼叫和巢狀呼叫出現的情況；後續重複記錄及其子樹不再處理。 |
| 父子呼叫的 `callId` 不同 | 父子分別按各自類別計數；父呼叫先於子呼叫，同級按記錄順序處理。 |
| 同一工具使用不同 `callId` 多次呼叫 | 每次都計數，即使參數相同，或操作的是同一個終端、Session。 |
| 已結算根結果缺少原呼叫記錄 | 不從結果文字或 metadata 猜測類別；根呼叫不計數，已記錄的子呼叫仍參與統計。 |
| Assistant 推理、Assistant 內的工具呼叫協定塊，或其他 Node 型別 | 不增加工具次數；呼叫由獨立投影出的工具 Node 負責計數。 |

去重範圍是單個組。類別按次數降序排列，同數時保留該類別在成員順序及父先子後遍歷中的首次出現順序。`read → bash → read` 排為 `read=2, commands=1`；`bash → read` 排為 `commands=1, read=1`。次數相同時沒有固定的類別優先順序。

### 工具名分類

分類只使用記錄的工具名：不轉換大小寫、不剝離名稱空間、不查 provider，也不根據參數推斷。名稱按下表從上到下首次命中的規則分類，摘要保留全部非零類別。

| 類別 | 工具名匹配 |
|---|---|
| `read` | `read` |
| `readImage` | `read_image` |
| `search` | `grep`、`glob`，或以 `_inspect` 結尾 |
| `write` | `write` |
| `edit` | `edit`、`apply_patch` |
| `commands` | `bash`、`pwsh`、`exec_command`、`write_stdin`，或以 `terminal_` 開頭 |
| `code` | `run_code` |
| `webSearch` | `web_search` |
| `webFetch` | `web_fetch` |
| `subagents` | `subagent`，或以 `subagent_` 開頭 |
| `plan` | `todo_write`、`create_goal`、`update_goal`、`get_goal` |
| `questions` | `ask_user_question`、`request_user_input` |
| `tools` | 其他所有名稱，包括 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` |

### Subagent、後臺任務與巢狀呼叫

Subagent 工具遵循普通分組邊界，不會僅因委派任務就單獨成組。它的類別描述父 Session 中的工具呼叫，不表示子 Session 的數量或生命週期。

| 情況 | 類別與活動規則 |
|---|---|
| `subagent`、`subagent_codex`、`subagent_claude_code` 或其他 `subagent_*` 名稱 | 每個不同 `callId` 計一次 `subagents`，但先命中更靠前的名稱規則時除外；provider 和 model 選擇不改變類別。 |
| 設定為 `subagent_inspect` 這樣的名稱 | 歸 `search`：`_inspect` 字尾先於 `subagent_` 字首匹配；同理，`terminal_inspect` 歸 `search` 而不是 `commands`。 |
| 子代理控制工具 `send_message`、`list_agents`、`list_subagent_models`，以及任務控制工具 `job_output`、`job_kill` | 歸 `tools`，不歸 `subagents`；業務用途不覆蓋名稱表。 |
| 委派工具被改為表外名稱，例如 `research_agent` | 即使呼叫相同的 subagent provider，也歸 `tools`。 |
| 後臺 subagent 的啟動呼叫已返回工具結果，但子代理仍在執行 | 保留類別次數，但該呼叫不再參與執行中活動選擇；子代理的執行不會維持父組的 subagent 活動狀態。 |
| 工具呼叫只記錄在子 Session 中 | 不納入父組計數或即時詳情；只有實際附在本組成員 `subCalls` 中的呼叫才遞迴參與。 |

`run_code` 根呼叫自身計一次 `code`，已記錄的每個 PTC 子呼叫另按自己的類別計數。不會用葉子呼叫替代包裝呼叫，也不會把子呼叫統一歸為 `code`。各呼叫 id 不同時，`run_code → [read, bash, subagent_codex]` 得到 `code=1, read=1, commands=1, subagents=1`，同次數時按此順序排列。外層 `run_code` 仍在執行時，組的即時類別可以由子呼叫決定。

精確名稱規則也意味著：記錄為 `functions.read`、`mcp.read` 或 `Read` 的名稱歸 `tools`，`browser_inspect` 歸 `search`。`terminal_*` 即使只檢查或關閉終端，也按命令規則分類，除非先命中 `_inspect` 規則。

### 即時活動與詳情

準備中的呼叫使用首個具名 delta 的時間，只有通用工具類別提供工具名詳情。已派發呼叫使用 tool/call 的時間和完整參數。

執行中的呼叫以最大 `time` 決定即時類別和詳情；時間相同時取後遍歷的呼叫。沒有執行呼叫時，類別為空，詳情取成員順序中最近一個含有非空推理段落的執行中 Assistant 的最後一個非空段落。推理詳情移除 `**` 標記，不要求首行以換行結束；單個推理行的預覽另有規則。

即時選擇依據呼叫開始的 `time`，不是最近一次輸出或進度的時間。投影后的工具值尚無結果時就參與執行中候選；等待批准或等待結果不會產生另一個類別。

| 成員目前狀態 | 即時類別與詳情來源 |
|---|---|
| `bash(time=10)` 與 `read(time=20)` 都執行中 | 取 `read` 及其參數，與哪個工具最近輸出無關。 |
| 較新的 `read` 已結算，較早的 `bash` 仍在執行 | 回到 `commands`，使用 `bash` 參數；`read` 失敗後結算也一樣。 |
| 執行中的父子呼叫開始時間相同 | 子呼叫因後遍歷而勝出；同級同時間則後遍歷者勝出。 |
| 工具全部結算，組尚未結束，執行中的 Assistant 有推理 | 即時工具類別為空，詳情取最近的非空推理段落。 |
| 沒有執行工具或可用的執行中推理，組尚未結束 | 即時工具類別為空、詳情為空，即使類別次數非零。 |
| 工具尚無結果，但回覆或其他分組邊界已結束該組 | 釋出的即時類別與詳情清空；組結束優先於呼叫未完成。 |

工具詳情按以下優先順序取第一個非空且受支援的參數欄位：`title`、`description`、`objective`、`task`、`task_name`、`name`、`question`、`questions`、`prompt`、`message`、`command`、`cmd`、`queries`、`query`、`pattern`、`url`、`uri`、`file_path`、`path`、`target`、`action`、`status`。支援字串及全部元素均為字串的陣列，陣列使用 `, ` 連線。`questions` 欄位則取物件陣列中首個非空的 `question`。無效、不完整或自由文字形式的 JSON，以及沒有可用詳情的參數，均退回到工具名。

這份優先順序對所有工具相同，不按類別定製。例如 shell 呼叫的 `description` 可以覆蓋 `command`，`title` 可以覆蓋檔案路徑。按順序選擇受支援且合併空白後仍非空的首個欄位，不支援的值會跳過。

| 工具與參數範例 | 最終詳情 |
|---|---|
| `subagent`，`{"description":"Review parser","prompt":"Long instructions"}` | `Review parser`，不追加 prompt。 |
| `send_message`，`{"subagent_id":"child-1","message":"Check tests"}` | `Check tests`，類別仍是 `tools`。 |
| `exec_command`，`{"cmd":"pnpm test","description":"Run focused tests"}` | `Run focused tests`；沒有可用 description 時才是 `pnpm test`。 |
| `read`，`{"file_path":"src/app.ts","path":"fallback.ts"}` | `src/app.ts`，`file_path` 先於 `path`。 |
| `grep`，`{"pattern":"TODO","path":"src"}` | `TODO`，不追加搜尋路徑。 |
| `web_search`，`{"queries":["React hooks","external store"]}` | `React hooks, external store`。 |
| `web_search`，僅有 `{"queries":[{"query":"React hooks"}]}` | `web_search`，不遞迴提取物件陣列中的查詢。 |
| `web_fetch` 的 `{"url":"https://example.com"}`；`read_mcp_resource` 的 `{"uri":"resource://guide"}` | 直接使用 URL 或 URI。 |
| `request_user_input`，`{"questions":[{"header":"Scope","question":"Which package?"},{"question":"Which mode?"}]}` | `Which package?`；找到首個非空問題後，不取 header 或後續問題。 |
| `run_code`，僅有 `{"code":"print(1)"}` | `run_code`，`code` 不在詳情欄位列表中。 |
| `apply_patch`，參數為原始補丁文字而非 JSON 物件 | `apply_patch`，不從補丁中提取路徑。 |
| 任意工具，`{"description":" ","command":42,"path":"src/app.ts"}` | `src/app.ts`，跳過純空白字串和數值。 |
| 不完整 JSON、JSON 標量、混合型別陣列，或僅有不支援的欄位 | 沒有其他可用欄位時使用工具名，不猜測不完整參數。 |

所有即時詳情都合併空白、去除首尾空白，並限制為 160 個字素簇；截斷時末尾的 `…` 計入上限。已結束組釋出的摘要清空即時類別和詳情，保留類別次數。
