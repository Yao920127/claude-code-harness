# @deepseek-ai/dsh-client-ui-deliverables

[English](README.md) | 中文

## 概述

本包渲染已完成輪次末尾的改動檔案卡片——列出本輪改動的檔案及 Host 記錄的行數，每一行在該檔案上開啟本輪的 review tab——以及顯式交付檔案的卡片，並把收尾正文中匹配的行內程式碼引用轉為連結，讓被點名的檔案在右側 Sidebar 中開啟。列出與連結的路徑來自記錄的改動摘要、成功的檔案修改與顯式交付，而非收尾正文。只有正式提供的 Web patch 載入本包；刪除其 cordis.yml 條目會同時移除指引、卡片與正文連結。

## 使用本包

與 `ui-conversation` 和 Host 側的 [workspace-changes](../../deliverables/workspace-changes/README.zh.md) 外掛一起掛載本外掛；已完成輪次隨即以改動檔案卡片收尾，位於收尾訊息正文與其動作頁尾之間。沒有可提供的摘要時——本輪沒有改動任何檔案、該外掛被組合出去，或該輪之後 Host 重新啟動過——卡片不出現，只保留交付卡片與正文連結；工作區不在 git 儲存庫內時摘要只列檔案工具的編輯。

改動檔案與交付檔案的入口卡片、內部檔案圖示底框和懸停預覽浮層遵循 [R16 預覽卡片規則](../../../docs/ui-radius.zh.md#radius-scale)，hover 保持相同輪廓。

<a id="explicit-deliveries"></a>
### 顯式交付

`present` 工具的準備階段是帶文件圖示的不可展開單行。記錄的呼叫提供參數前，該行不顯示檔名、不建立交付卡片，也不啟用檔案操作。

Web 的 `standard`、`ptc` 與 `cordis` preset 提供 `present`，用於宣告工作階段檔案系統可存取的最終檔案，包括透過 Bash 建立的檔案。建立後以 `files: [{ path, description? }]` 呼叫。[present 工具](../../deliverables/tool-present/README.zh.md)擁有檔案數量限制和工作階段宣告。單個交付佔滿一行，多個交付使用雙列網格，超過四個時預設收起。卡片顯示檔名、說明或檔案型別，以及共享的原生開啟控制元件。交付和改動檔案卡片的圖示底塊在淺色主題下使用 50% 不透明度的白色，深色主題下為 5%。圖示底塊與單檔案改動卡片的外框使用與交付卡片相同的描邊。點選卡片會在右側 Sidebar 預覽檔案。控制元件開啟預設應用，並列出關聯應用，檔案定位始終放在最後。匹配的行內程式碼引用也開啟 Sidebar 預覽。重複宣告使用收尾回覆之前最近一次的說明。

`present` 工具行在執行、成功、失敗和中斷狀態下保留文件圖示及記錄的結果。原生操作共享等待狀態，並在卡片顯示進度或可重試錯誤。開啟或定位成功的回饋顯示五秒後，在 200ms 內淡出並恢復檔案說明；失敗資訊保留到下次嘗試。卡片掛載時讀取桌面資訊，連線更換時清除快取。Host 沒有桌面時，卡片保留 Sidebar 預覽並隱藏原生控制元件；中繼資料讀取失敗時提供重試。交付卡片和變更對比頁透過 `deliverables.file.actions` 和 `deliverables.review.file.actions` 使用 [ui-open-in-app](../ui-open-in-app/README.zh.md) 提供的控制元件。關聯應用 GET 查詢與原生 POST 操作都會先驗證記錄中的檔案座標及工作階段檔案系統對映，再呼叫 Host 桌面。

### 改動檔案卡片

只有開啟程式碼工作工具才展示此卡片並請求其摘要。關閉該偏好會立即隱藏卡片，同時保留顯式交付卡片、行內檔案連結和已記錄的工作區改動。

卡片渲染 Host 為本輪最新一條 `workspace/changes` 宣告提供的摘要，每條宣告透過經過認證的摘要路由讀取一次；讀取尚未完成、Host 答覆摘要已不存在，或摘要沒有列出任何檔案時，沒有卡片。僅改動一個檔案時，標題顯示“已編輯”和檔名，配合對應的檔案型別圖示，不展示檔案列表；標題保留增刪行數或二進位制/過大狀態，並透過無障礙描述提供完整路徑。多個檔案使用程式碼檔案圖示，標題給出改動檔案總數與增刪行數合計；滑鼠懸停或鍵盤聚焦時，統計資訊替換為“在側邊欄預覽”。每一行使用普通介面字型顯示檔案路徑，增刪行數保留等寬字型，二進位制檔案顯示“二進位制”，Host 沒有捕捉的檔案顯示“過大”。行按記錄的展示順序排列，因此儲存庫內位於工作目錄之上的檔案與工作區外的檔案排在最前。摺疊前顯示四行；控制元件展開全部記錄檔案，展開後從底部收起列表。每一行在右側 Sidebar 中開啟本輪的 review 並選中該檔案，標題則在第一個檔案上開啟它。 在檔案行或單檔案標題上懸停 500ms 後，會出現可滾動的單列改動浮層，不受 Sidebar 檢視設定影響。頂部完整路徑使用較淺的等寬字型，超出寬度時可橫向滾動。浮層不顯示程式碼旁的檔案狀態說明和 hunk 頭；沒有 hunk 的對比仍顯示狀態文字。每行透過無障礙描述提供完整路徑。浮層比卡片窄 48px，左右各內縮 24px，高度最多 420px，並受視口可用空間限制。整個浮層的淡入和淡出各持續 100ms。滑鼠移入浮層後保持開啟；移出、按 Escape 或透過滑鼠和鍵盤啟用檔案行會關閉浮層。對比只在浮層開啟時載入，與 review tab 共用快取及重試狀態。

### review tab

行在該行的檔案上開啟本輪的 `changes-review` tab，其地址由目前檢視的 Session 和宣告事件的序號組成，以輪號作標題；同一張卡片的另一行會在其檔案上顯示同一個 tab。頭部的檔案選擇器列出所有記錄的檔案及其行數，用於切換對比。新 tab 預設選擇不換行的左右對比。只有新增或只有刪除的對比（包括周圍的上下文行）使用單欄展示，不改變所選檢視；同時包含增刪的對比按所選檢視展示。其控制元件用於切換單欄或左右對比、切換自動換行、在 Sidebar 中開啟目前完整檔案，並在 Host 有桌面時用預設應用開啟檔案；原生開啟的等待與可重試錯誤狀態與卡片一致，檢視和換行選擇按 tab 保留。tab 透過經過認證的路由各讀取一次摘要和每個對比。文字對比逐個列出 hunk，每一行帶舊側和新側的行號，並按程式碼預覽的檔名 grammar 與 Shiki token 色分別高亮每個已渲染 hunk 的兩側。新增與刪除在各主題下使用獨立的程式碼區與行號區底色，併為行號、增刪符號和對齊的左側色條著色；普通程式碼文字保留主文字色。檔案是本輪新建或刪除、兩側內容相同、Host 的逐行對比超時而按整檔案替換顯示，或 tab 在 5000 行處停止繪製時，tab 還會給出一行說明。二進位制或過大的檔案、Host 已不再提供的對比，以及讀取失敗各顯示一行提示；讀取失敗時提供重試。對比是本輪對該檔案的快照，不是它目前的內容。

目前檔案標題使用 `ui-primitives` 的共享元件 [`PathLabel`](../ui-primitives/README.zh.md#component-catalog)：空間足夠時完整靠左顯示，否則從左側裁剪並漸隱，保留尾部字元和副檔名。目錄使用弱化顏色，檔名使用主色，懸停顯示完整路徑。調整面板寬度或切換檔案時更新漸隱；下拉箭頭、行數和工具欄操作保留各自的空間。

關閉自動換行時，兩列同步縱向滾動，橫向偏移同步到各自可滾動範圍內。各行背景（包括用於對齊的空行）覆蓋所在列的完整可滾動寬度。兩列在雙軸上都停用彈性邊緣回饋和向外層傳遞滾動；各列可滾動範圍內的原生慣性仍由瀏覽器控制。兩側橫向捲軸始終位於可見對比區域底部；如果只有一側需要橫向滾動，上下滾動會保留該側的橫向偏移。

### 行內程式碼連結

收尾正文連結產出或已交付的路徑：行內程式碼 token 按精確路徑解析，或當它恰好等於其中某條路徑的 basename 且該路徑唯一時解析——兩條路徑共享同一 basename 時保持不可點選而不作猜測，因此提及絕不開啟錯誤的檔案。解析成功的提及保留程式碼標籤，並採用 Markdown 樣式表的連結樣式，完整路徑作為其 `title`。

## 理解實作

<details>
<summary>實作細節——點選展開</summary>

Node 半部註冊[模型體驗](#model-experience)所述的靜態 `ui:deliverable-file-references` 系統提示詞段。顯式 Markdown 連結使用共享的 [Markdown 渲染器](../ui-primitives/README.zh.md)；行內程式碼匹配仍僅限產出或交付檔案。瀏覽器半部把組合改動檔案卡片與顯式交付的包裝元件註冊進 chat 檢視的 `conversation.chat.turnTail` 列表，與其他功能產物並列。`deliverablesDefinition` 把每個輪次最新且透過驗證的 `workspace/changes` 宣告的序號摺疊進 `DeliverablesTurnData.changes`，卡片按它向 Host 讀取摘要並快取到連線被替換為止，把 `deliverables/presented` 事件摺疊為交付，並根據 `write`、`edit` 和有修改作用的 `str_replace_editor` 命令中經過驗證的原始參數把成功的第一方修改呼叫摺疊為產出路徑；產出路徑只供正文提及解析器使用。讀取、刪除、不受支援的工具、格式錯誤的呼叫、格式錯誤的事件和失敗結果不貢獻任何條目。每一行透過 `ctx.sidebarRight.openResource` 開啟 `dsh-resource://changes-review/session/<sessionId>/<seq>/<turn>`，並以檔案下標作為 `changes-review` 的導航參數；本包在 `builtin` 檔為該模式註冊 `changes-review` tab 型別，把其 body 連同一個按 tab 儲存選擇的獨佔 store 註冊到按鍵的 `sidebar.right.pane.tab` 座位下，body 透過經過認證的路由把摘要和對比讀進連線更換時清空的 store。本包還提供 chat 檢視按收尾訊息查詢的 `chatFileMentions` 服務；把外掛組合出去會移除全部表面，檢視的空列表以零成本留下。

原生開啟使用經過認證的 POST，透過目前檢視的工作階段、事件序號和原始檔案索引定位宣告；review tab 對改動檔案的原生開啟使用同一組座標。對宣告，Host 讀取事件及目前檢視的工作階段 header，將其中的 cwd 傳給 `workspaceFiles.stat`，未記錄 cwd 時使用部署的工作目錄；對改動檔案，傳的是所提供摘要攜帶的工作目錄。它與側欄預覽使用同一組合檔案系統，無需啟動 Agent，子工作階段也適用。原生操作要求規範化的程序路徑能從 Host 路徑對映回同一程序路徑。提供者沒有這種對映時返回 422，之後 review tab 隱藏原生開啟；Host 上存在同名檔案並不足夠。同一份桌面可用性設定同時約束資訊查詢和實際執行。編輯會影響後續開啟的內容；刪除後返回錯誤。不建立檔案內容副本或附件。外掛釋放時取消並等待進行中的原生開啟請求。

</details>

## 模型體驗

### 可點選檔案引用指引

#### 模型看到的內容

提示詞建議在最終回覆中展示主要結果：內嵌圖片用於講解與對比，圖片連結用於引用和檔案列表，圖片檔案卡片用於獨立交付。檔案目標路徑使用尖括號包裹，包括含空格的路徑。對於需要完整檔案的交付，尤其是 Office 檔案，建議使用獨立的 `present` 卡片，通常選最重要的一兩項，需要時可以更多，但每次呼叫最多四項。提示詞建議避免僅為列出程式碼改動生成卡片，也不為確認 diff 是否顯示額外執行命令。程式碼工作工具關閉時仍採用這條建議，接受較少的檔案展示入口，以減少重複展示和不必要的工具呼叫。檔案引用要求連結命令、設定表示式和程式碼塊以外的每次現有檔案提及，包括重複提及和表格。標籤預設使用檔名或清楚的別名，僅新增足以區分檔案的父目錄。精確引用顯示為 `filename:24` 或 `filename:24–30`；目標保留完整相對路徑或絕對路徑，以及 `#L24` 或 `#L24-L30` 錨點。顯示字尾不含 `#` 或 `L`。

#### Token 影響

載入本包時增加一段包含產出選擇、渲染效果和檔案引用指導的固定提示詞。[present 工具](../../deliverables/tool-present/README.zh.md#model-experience)擁有交付 schema 和結果文字。

#### KV Cache 影響

該段落在本包掛載期間始終以 first-party 順序 9000 保持靜態，因此留在可複用的提示詞字首中，不會隨輪次改變。

## 已知限制與延期工作

<a id="known-limitations-and-deferred-work"></a>


這些限制界定了目前產出物詞表。它們是目前包約束，不是通用檔案連結對比或任務積壓。

- **本地行內圖片要求 HTTP(S) 頁面**：Desktop 的 `dsh-app:` 頁面不支援此檔案路由。支援 POSIX 絕對路徑與 Windows 磁碟機代號路徑；Chat 中的相對圖片路徑需要目前檢視的 Session 工作區根目錄。圖片的獨立檔案連結是可選的。
- **提及匹配只認精確路徑或唯一 basename**——字尾式提及保持惰性；等真實的收尾訊息形態產生需求後再放寬匹配規則。
- **終端建立的檔案需要顯式交付**——git 記錄到改動後卡片會列出它們，但交付卡片和行內程式碼引用需要呼叫 `present`；顯式 Markdown 連結可以直接引用現有檔案。
- **宣告不儲存檔案內容**：重新開啟或轉移 Session 後，原始檔仍需能被目前檢視的 Session 檔案系統存取。檔案缺失、為目錄或最終路徑為符號連結時返回 404。
- **原生開啟需要 Host 桌面**——沒有桌面時 review tab 不提供原生開啟；對比本身只需要記錄了該輪的 Host。
- **對比高亮使用 hunk 內上下文**——省略的原始碼行不可用，因此每個已渲染 hunk 的新舊兩側分別分詞；未知字尾保持純文字，tab 最多繪製 5000 行並給出提示。
- **對比攜帶整個檔案的文字**——對比路由會送出所列檔案在 Host 上記錄時的完整文字，包括被忽略的檔案和 Sidebar 預覽所限定的工作區根目錄之外的檔案。
- **工作區外的檔案只按絕對路徑開啟**——記錄的路徑是記錄時的 Host 路徑；工作區移動或換一個檢視 Session 都無法重新定位它。
