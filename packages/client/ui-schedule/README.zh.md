# @deepseek-ai/dsh-client-ui-schedule

[English](README.md) | 中文

## 概述

在「自動化任務」頁面和右側欄的任務頁籤中管理各個工作階段的活動和未執行排程任務：搜尋、篩選、修改名稱、指令和執行時間、瀏覽任務執行記錄、刪除任務，或開啟原工作階段。每個介面都用任務已儲存的標題命名任務。已開啟工作階段在存在活動提醒時，頁頭顯示僅圖示的提醒時鐘，點選在右側欄開啟該任務詳情；`schedule_create` 呼叫把建立的任務渲染為工作階段卡片；側欄中帶活動任務的未歸檔空閒工作階段行顯示時鐘標記，其懸停卡片列出這些任務。

## 使用本包

釋出的 Web bundle 將 `ui-schedule` 與 Host Schedule 服務、以及為模型提供目前時間的時鐘上下文一起掛載。側欄的自動化任務入口開啟全域頁面，不選擇或啟用工作階段。頁面頁頭的“新建”操作會開啟一個新工作階段，提醒由模型在該工作階段中建立；頁面本身沒有建立表單。列表支援文字搜尋和一行“全部/已開啟/未執行”狀態篩選；搜尋匹配任務已儲存的名稱、指令和內部工作階段 id，不匹配解析出的工作階段標題，空狀態在提示旁保留頁頭的“新建”操作。選擇活動或未執行任務後，進入含“規則”和“任務執行記錄”頁籤的第二層詳情。每條列表行顯示任務已儲存的標題及其狀態、頻率和下次執行，不顯示原工作階段名稱；詳情中的名稱輸入框顯示任務已儲存的標題。“規則”顯示完整提醒、狀態、活動任務的下一目標時間、原始重複規則和任務 id。每天的規則標籤顯示已儲存的本地時間與精確的儲存 IANA 時區，保留非零秒與毫秒，而不替換為瀏覽器時區。詳情頁籤條內的“關聯工作階段”入口按工作階段標題顯示，取不到標題時退回顯示工作階段 id。中繼資料載入後，它可開啟可用且未歸檔的工作階段；工作階段或 Workspace 中繼資料尚未就緒、工作階段已歸檔、工作階段不在列表中或 Workspace 查詢失敗時，入口保持停用並顯示原因。點選時會重新檢查可用性；瀏覽不會取消工作階段歸檔。僅此操作請求啟用工作階段。刪除位於詳情頂部條帶的“更多工操作”選單。

從列表選擇任務時預設開啟“規則”；重新整理同一任務會保留目前頁籤。活動任務的“規則”修改名稱、指令和執行時間；這些修改保留在本地草稿中直到儲存，未執行任務保持只讀。不帶修飾鍵的左右方向鍵迴圈切換頁籤，Home/End 選擇第一個/最後一個頁籤，鍵盤焦點隨選擇移動。頁籤不會攔截這些鍵與 Alt、Ctrl、Meta 或 Shift 的組合。共用的工作階段入口位於詳情頁籤條內，在“規則”頁籤可見；確認刪除操作在兩種頁簽下都可用。

“規則”在“執行時間”卡片中以行編輯本地草稿：“重複”是含每週、週一至週五、每天、每 N 小時、每 N 分鐘、每 N 秒、僅一次和自定義（cron）的選單，每週規則增加“星期”行，固定速率選項只修改它所屬單位的間隔數量，一次性規則用獨立的“日期”和“時間”兩行編輯目標，自定義（cron）用一行“Cron 表示式”編輯按所選時區解釋的 5 欄位表示式。卡片在瀏覽器中解析該表示式，並在該行下方顯示描述它的在地化語句；Host 會拒絕的表示式改為顯示在地化驗證資訊，並在解析透過前阻止儲存。已儲存的每週規則若星期集合恰好為週一至週五，則選中“週一至週五”選項。“日期”行是隻讀觸發器，以 `YYYY/MM/DD` 顯示暫存的日期並展開帶在地化星期表頭、月份切換和今天標記的月曆；草稿與提交文字保持 ISO 形態；“時間”行是隻讀觸發器，顯示統一的 24 小時時鐘，並展開時、分、秒三列可滾動列表，目前值高亮並在開啟時滾動到可見。在月曆或時鐘上點選即按與其他行相同的分階段儲存寫入草稿；方向鍵在開啟的列或網格內移動，Enter 選定目前值，Escape 關閉面板並把焦點還給所在行，被停用的行無法開啟面板。時鐘行顯示到秒，未改動的行在提交時保留已儲存的毫秒值，編輯時間時按整秒精度提交。“時區”使用高度受限的可搜尋選單。頂部無標題區域保留瀏覽器本地最近選過的 5 個準確時區；首次使用按真實系統時區和 UTC 初始化，而不根據介面語言猜測所在地。系統時區帶有標記，其餘清單按目前 UTC 偏移、再按規範 IANA 標識排序。可見文案把 `UTC±HH:MM` 放在在地化時區名稱之前；IANA 標識僅在內部使用，但可用於搜尋。ICU 顯示成相同偏移和在地化名稱的多個時區只佔一行；所有被合併的標識仍可用於搜尋，任務已儲存的標識也會繼續作為選中值，不會被改寫。時區清單來自 `Intl.supportedValuesOf('timeZone')`，名稱來自 `Intl.DateTimeFormat(..., { timeZoneName: 'longGeneric' })`：兩者都是瀏覽器內建的 ICU/CLDR 資料，不是抓取或產品自維護的翻譯表。因此沒有需要重新整理的爬蟲或生成時區資源；第三方語言包只需提供常規的 `time.locale` 值，即可自動獲得對應的 ICU 名稱，僅需翻譯選擇器周邊的 UI 文案。執行時無法列舉時改用簡短的標識候選列表，已儲存但不在其中的時區會保留。每天、每週和 cron 保留各自已儲存的規則與時區，其頻率行僅在時區與主機系統時區不同時標出時區。一次性 After/At 以記錄已儲存的時區初始化日期和時間；記錄未儲存時區時取本裝置時區，初始鐘錶值在該時區下仍表示同一瞬時；更改時區會保留輸入的鐘表值並改變時點。因選擇種類而重新初始化的種類使用已提交發生時點的鐘表值和該選項的時區，該時區取記錄已儲存的時區或本裝置時區：每週的星期取自該發生時點在該時區下的星期，cron 則把該發生時點的鐘表值寫成每天執行的表示式。固定間隔至少為 60 整秒，不受時區影響。一次儲存以分階段的變更提交完整預期記錄，並保留 id、原工作階段、最近一次回執及已儲存歷史；未來目標選擇、重新確定起算時間和未變更規則的無寫入語義見 [Schedule](../../schedule/schedule/README.zh.md#use-this-package)。

行在儲存進行中、目錄載入中、刪除期間以及任務未執行時停用。僅當本地草稿與已儲存任務不同時才出現儲存欄：顯示“有未儲存的修改”及“取消”和“儲存修改”，儲存期間“儲存修改”變為“儲存中…”。“取消”恢復已儲存的值。僅當草稿沒有未儲存修改時，目錄重新整理才會成為顯示值，因此未儲存的草稿會保留到權威重新整理之後。儲存失敗保留草稿並顯示在地化提示；衝突後針對重新整理後的記錄重試。任務從目錄消失時，“刪除”會停用，直到任務重新出現。更新成功後重新整理權威目錄。更新被拒絕或無法確認與目錄讀取失敗相互區分：“重試”重新載入目錄，不將該更新顯示為失敗。若更新本身無法確認，應在重試前檢查任務。切換任務或關閉詳情後才到達的回應不會替換目前檢視，任何失敗都不會復原主機已開始的寫入。

開啟“任務執行記錄”時才請求最新的 20 條已儲存記錄。“載入更早的記錄”按追加順序從新到舊增加一頁，不受實際時間回呼影響。該檢視中頁籤條就是整個頁頭：名稱輸入框和“下次執行”行只屬於“規則”。每條“已儲存的任務執行記錄”以時鐘圖示和任務時區下的本地月份名與時鐘欄位開頭（一次性記錄使用瀏覽器時區），並在存在時顯示實際儲存的提示文字。超過兩行的提示文字只顯示前兩行並提供“展開”，展開後可“收起”；面板寬度變化時，收起狀態的提示文字會重新判斷是否超過兩行。舊回執沒有提示文字時，絕不以目前指令代替。

最後一頁載入完成後，非空且確認裁剪過的歷史在詳情面板左下角顯示無分隔線的清理提示，資訊圖示可展開或收起目前主機的保留規則。空歷史、未確認裁剪的舊格式歷史、尚未載入完的分頁和讀取失敗均不顯示清理提示。

歷史查詢成功的空頁與載入中、查詢失敗、任務不存在或遊標無效相互區分。請求失敗時保留此前載入的記錄，並顯示警告和“重試載入任務執行記錄”；遊標無效時提供“重新整理任務執行記錄”，重新載入最新一頁。最新 `messageId` 變化時重新整理最新一頁，不切換頁籤。被重新整理取代的回應，以及切換任務、離開任務執行記錄或關閉詳情後才收到的回應，不會替換目前檢視。

自動化任務頁面要求確認後才能刪除任務。刪除是硬刪除：Host 連同已儲存的任務執行記錄一起移除儲存的任務行，該任務因此停止後續投遞、離開 `list` 與 `catalog`，其投遞歷史不再可讀。刪除保留原工作階段和已入隊訊息；列表僅在權威查詢確認移除之前保留該行。每條刪除路徑——自動化任務頁的詳情、工作階段的任務頁籤、以及頁頭彈層——都把最終結果寫入同一個儲存，由應用級 `shell.overlay` 提示渲染，因此提示的生命週期長於發起它的面板或頁籤：Host 連同已儲存的執行記錄移除該行後提示顯示「任務已刪除」，失敗時顯示「無法刪除任務」，並保留規則以便重試。確認刪除會關閉確認所在的面板或頁籤，每條提示按自身序號區分，後一條會重新開始橫幅而不是併入前一條。查詢失敗保留最近已知記錄，並顯示獨立的重試操作；不會呈現為查詢成功的空結果。一次性任務在持久收件箱投遞後仍以未執行狀態儲存。顯式刪除前，透過全部或未執行篩選仍可檢視詳情與原工作階段 id。最近一次投遞顯示其發生時間，不顯示訊息 id 和投遞確認時間；未執行狀態和該回執均不表示模型執行完成。

已開啟的工作階段只有在確實有可開啟的內容時，才在頁頭右側功能位中、緊鄰更多操作選單左側渲染一個僅圖示時鐘按鈕：首次讀取前不渲染任何內容，讀取結果為沒有活動提醒時頁頭不顯示該按鈕，重新整理期間保留上一次已知的提醒，讀取失敗則保留按鈕及其重試。該規則避免時鐘在首次結果前後出現又消失。其無障礙名稱在讀取就緒時給出提醒數量，否則顯示通用提醒標籤。當該工作階段只有一個活動提醒時，按鈕直接在右側欄開啟該任務的詳情。其餘數量都會開啟彈層：先列出逾期提醒，再按目標時間列出未來提醒，顯示已儲存的標題、頻率、瀏覽器本地目標時間、相對時間及刪除按鈕；標題本身是一個按鈕，點選後在右側欄開啟該任務的詳情。任務頁簽在標籤上顯示目前任務已儲存的標題，並提供與自動化任務頁面相同的規則、任務執行記錄、名稱、指令和執行時間修改、確認刪除和原工作階段入口；它不會啟用工作階段。每日頻率文字保留儲存的本地時間和時區；每個下一目標時點都顯示為裝置時區的鐘點和括號內的相對時長；規則自身的時區只顯示在該頻率文字中。Escape 關閉彈層並將焦點返回按鈕；點選外部將其關閉。刪除最後一條提醒會移除按鈕；在此之前，已經開啟的彈層保持可展開狀態。

彈層透過 portal 掛到 body，目標寬度為 336px；空間足夠時與觸發按鈕左邊緣對齊，觸發器靠近視口右側時向左避讓並保留 16px 視口邊距，寬度不超過視口寬度減 32px，列表溢位時縱向滾動。它不顯示任務 id、原始 UTC 值或投遞詳情；每行只帶自身的詳情入口和刪除操作。

呼叫 `schedule_create` 時，建立的任務會以卡片形式渲染在 transcript 中，包含時鐘圖示、已儲存的標題、頻率，以及開啟該任務右側欄頁籤的“開啟”按鈕。卡片先按該呼叫持久化的結果 JSON 收窄出任務，並從該結果讀取 `title`；當一次在卡片出現之後成功結束的目錄讀取解析到該任務時，卡片改為跟隨目錄顯示目前名稱與頻率，若該讀取中不含該記錄，則以“已刪除”代替頻率顯示。在已儲存欄位存在之前錄製的結果退回為指令首行。仍在執行的呼叫、建立失敗，或結果中沒有完整任務時，卡片保留該行，並在結果為單個非空文字塊時顯示原始結果文字，不提供“開啟”操作。卡片不增加 Host 欄位，也不改變 Session 日誌格式，因此早於該卡片錄製的 Session 也會渲染它。

側欄的 Session 行會標記有排程任務的工作階段：當某行處於空閒狀態、未歸檔且其工作階段至少有一個活動任務時，該行顯示時鐘標記；歸檔行該格留空，其即時狀態只在懸浮卡片中顯示。對存在活動任務的工作階段長按懸停時，無論該行是否空閒，都會在其已有的懸浮卡片內增加自動化區段，最多列出兩個任務（圖示、已儲存的標題、頻率與下次執行文字），還有更多工被隱藏時顯示遺漏行。處於更高優先順序狀態的行——有待處理互動、活動仍在進行，或有未檢視的完成提醒——保留自身狀態點且不渲染標記，兩者不會同時出現。該標記和懸停區段讀取共享的活動與未執行 Host 任務目錄，並從中篩選本工作階段的活動任務；它們不會啟用、保留或取消歸檔任何工作階段，也不讀取 Session 日誌。

### 時區資料來源

時區清單與在地化完全離線。`Intl` 讀取瀏覽器執行時內嵌的 ICU/CLDR 表，DSH 執行時不會取得或下載時區資料。沒有需要重新整理的爬蟲；第三方語言包提供 `time.locale`，並僅翻譯選擇器自身的 UI 文案。

## 理解實作

<details>
<summary>實作內部細節 — 點選展開</summary>

瀏覽器入口註冊 `schedules` 主面板及對應的側欄入口、Session 頁頭右側功能位中位於 `order: -5` 且緊鄰更多操作選單左側的 `schedule-catalog` 入口、經由 `ctx.uiConversation.events` 與 ui-chat 的 list seat `conversation.chat.turnTail` 在輪次層級註冊的 `schedule_create` transcript 卡片（因此它渲染在該輪收尾的 assistant 文字之後，並在工具呼叫組摺疊時仍然可見）、root 作用域的兩個 Session 行 seat `sidebar.session.row.leading` 與 `sidebar.session.row.hover`，以及 kind 為 `scheduleTask` 的右側欄頁型別 `@deepseek-ai/dsh-client-ui-schedule/task`。該型別分兩階段註冊：先把其定義註冊進 `ctx.sidebarRightTabs`，再按該定義的 id 把正文與 chip 註冊進帶鍵 seat `sidebar.right.pane.tab` 與 `sidebar.right.pane.tab.title`。從 Session 入口開啟任務時呼叫 `ctx.sidebarRight.openTab`，傳入該入口的 Session id 與所選任務 id，詳情因此出現在該入口所屬 Session 的右側欄中；自動化任務頁面保留自己的列表並共用同一個詳情元件。全域頁面、任務頁籤、行標記與行懸停區段都從同一個 `schedule.catalog` 源讀取活動與未執行任務；頁頭入口保留自己的按 Session `schedule.list` 讀取，只返回該 Session 的活動任務。每個面都使用同一套可觀察的查詢生命週期，並在 `schedule/changed` 或連線重置後重新整理。transcript 卡片從該呼叫持久化的結果 JSON 收窄出建立的任務，而不是依賴 Host 追加欄位；該呼叫自身的工具呼叫組單元格由 ui-tool 的通用鍵控檢視渲染，且卡片只對產生完整任務的呼叫出現。該對齊是因果判定而非時鐘比較：目錄快照帶有 `readRequest`（最新被請求的讀取序號）與 `readSettled`（產出目前記錄的讀取序號）；Turn 尾部掛載時錨定 `readRequest` 並請求一次讀取，僅在 `readSettled` 大於該錨點後才用其保留記錄判定，且源把一次提交內的請求合併為單次 `list()`，只把該讀取共享給尚未觀察到它的呼叫者。比較瀏覽器時鐘與 Host 時鐘無法確立這一順序。共用的刪除回呼與注入的 `onUpdateTiming` 保留所選記錄的原 Session 繫結，而不使用目前開啟的對話。詳情保留目前任務的本地草稿、用於比較的權威值以及等待中或失敗的儲存；儲存等待中或失敗期間以及刪除確認後，屬主保留所顯示的任務，使目錄重新整理在丟棄該行時既不能關閉已呈現的失敗，也不能關閉陳述刪除的詳情。儲存發出一次攜帶完整預期 `ScheduleRecord` 和分階段變更的 `schedule.update` 請求；`onUpdateTiming` 重新整理目錄，而不把回讀失敗變成修改失敗。

重新整理恢復出的任務標籤沒有導航參數，因為 Sidebar 只持久化標籤的佈局記錄，不持久化開啟方傳入的內容。因此該頁面型別自行儲存從 Session 加布局記錄 id 到該記錄最後顯示任務的 Session 和 id 的關聯：每個 Session 一個 `dsh.schedule.task-tab.v1.<sessionId>` localStorage 鍵，按 tab id 一條記錄，且從不儲存任務內容。正文和 chip 只對沒有導航參數的記錄讀取該條目，在標籤出現之後成功的一次讀取無法解析時將其刪除，且不代替關聯聲稱任務缺失。這樣的一次讀取無法為該標籤給出任務標識時，正文陳述該狀態，而不呈現永不結束的載入。

僅在框架觀察資料來源期間訂閱。最後一個訂閱取消時釋放事件監聽，並使尚未完成的回應失效。元件接收框架繫結的 `useCatalog` hook 和明確的操作回呼。已掛載的任務執行記錄檢視使用所選任務的原工作階段繫結讀取 `schedule.history`；目錄和列表回應不包含完整歷史。元件擁有可丟棄的搜尋、篩選、選擇、確認和歷史分頁狀態。提醒記錄由 Host 擁有，不來自歷史工作階段投影或瀏覽器本地演示資料。

本包不釋出執行時 invariant companion，因為目錄呈現 Host 擁有的任務狀態，自身只擁有可丟棄的查詢和互動狀態。

</details>

## 已知限制與後續工作

<a id="known-limitations-and-deferred-work"></a>

- 已儲存的記錄描述收件箱投遞，不表示模型執行結果。沒有已儲存歷史的任務僅呈現已有回執，直到新投遞追加記錄；未儲存的更早記錄和提示文字快照無法恢復。此前已物理刪除的任務不會恢復。
- 每頁 20 條僅限制請求的記錄數，不限制提示文字位元組數或任務保留的儲存。投遞歷史由 Host 外掛的設定設界：`deliveryHistoryDays`（預設 30）與 `deliveryHistoryRecords`（預設 200），在追加確認時裁剪，最近一次回執始終保留，被裁剪的更早視窗報告為不可用；見 [Schedule 限制](../../schedule/schedule/README.zh.md#known-limitations-and-deferred-work)。
- 刪除不會取消已經排隊執行的提醒。詳情頁籤條內的關聯工作階段入口使用普通工作階段導航及其恢復策略開啟原對話，不直接跳轉到特定訊息。
- 建立提醒仍透過 Schedule 工具完成。僅在活動任務的“規則”中可修改名稱、指令和執行時間，自動化任務頁面和任務頁籤均可；不提供暫停或立即執行，且“執行時間”卡片的“重複”選單接受任意選擇，包括改變已儲存重複規則種類；此時按新規則重算目標。頁面的“新建”操作會開啟一個工作階段，而不是在頁面內建立任務；工作階段頁頭的彈層本身不提供執行時間編輯器。“時區”選單提供執行時的 IANA 時區清單，執行時無法列舉時改用簡短的候選列表。
