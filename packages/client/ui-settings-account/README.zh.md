# @deepseek-ai/dsh-client-ui-settings-account

[English](README.md) | 中文

帳號憑證被伺服器端判定失效後，清空顯示的帳號詳情，並彈出一次在地化的重新登入提示 toast；帳號快照重放不會重複提示。

## 概述

設定中的帳號頁面顯示 DeepSeek 登入狀態，並提供瀏覽器登入和取消；側邊欄帳號選單提供 Platform 退出登入。Desktop 使用者還會進入可恢復的引導，瞭解帳號額度並選擇展示偏好。

<a id="use-this-package"></a>
## 使用此包

用戶端僅在具有 preload 橋接的 Desktop 內啟用。普通 Web 用戶端保留標準設定入口和 API Key 引導，不顯示帳號登入和帳號設定，也不訂閱帳號狀態。

側邊欄和帳號設定以正圓圖片顯示帳號大頭貼，直徑分別為 24px 和 32px；大頭貼 URL 缺失或圖片載入失敗時使用帳號圖示後備。摺疊側邊欄將大頭貼居中放置在 36 × 36 px 的按鈕內。登入前側邊欄入口改為「更多」行，以三點圖示開頭。

該頁面透過 settings.section 註冊，並使用 account Remote 名稱空間。共享 Remote 管理器負責連線恢復後的流重連。頁面使用功能自有的中英文文案，將 API Key 與帳號狀態分開。

帳號操作會把本介面的用戶端身份傳給 Host：建置版本、目前語言，以及發起操作時取樣的目前 UTC 偏移（秒）。

餘額沿用 Platform Web 的金額格式：兩位小數和千分位分組，正金額截斷至分，小於一分的正金額顯示為 <0.01，負金額按舍入規則處理且顯示絕對值至少為 0.01。Host 返回的原始餘額字串保持不變。

Desktop 的用量、充值與引導充值操作在 48px 返回欄下方開啟同一個隔離的原生 Platform 檢視。Desktop 主機只有一個這樣的檢視，開啟新頁面會銷燬上一個，因此外掛在 `shell.overlay` 註冊一個共享主機條目，Account 設定頁、帳號欠費提示與 Desktop 引導充值頁都透過其 `PlatformPages` 請求通道申請頁面，而不再各自掛載容器。新請求會在新頁面顯示前退掉上一個持有者，其身份安全的釋放只清除本次請求，因此過期的持有者無法關閉它已不再持有的頁面。在 Windows Electron 中，返回欄與原生檢視都從 Desktop 頂欄下方開始，Application 和 Edit 選單文字不會蓋住“返回 DeepSeek Harness”。返回操作銷燬檢視並保留 Account 設定頁，且先恢復焦點，再由任何被延後的 Modal 接管。從充值頁返回時會等待任何已在進行的讀取結束後再讀取，因為充值可能改變帳號持有的內容。Account 設定頁與帳號欠費提示會重讀資料、餘額與未通知贈金；引導充值返回則只重讀資料與餘額，因此不會觸發未通知贈金的讀取。替換頁面、釋放請求、外掛解除安裝與從用量頁返回均不讀取。載入失敗時保留返回操作，居中顯示在地化錯誤提示和“重試”按鈕。重試重新載入同一目標頁面；渲染程序命令不接收帳號 token。

Chat 透過 `shell.overlay` 中的主機把已繫結 Session 的即時欠費交給全域 `shell.quota-notice` 鏈，提示的生命週期因此長於上報它的 Chat 面板。帳號條目認領 `ACCOUNT_QUOTA`：已儲存帳號憑證且存在共享主機條目時，Modal 提供取消和去充值。只要透過該共享請求通道請求的頁面正在顯示，原生檢視就會蓋住本頁，因此該條目既不繪製 Modal 也不繪製 Toast。在 Account 設定頁已開啟頁面的情況下新到達的欠費不會被保持：它仍受最新提示替換規則約束，返回後若該提示仍是最新一條就顯示 Modal。該 Modal 報告的是原始請求的失敗，而不是帳號目前餘額：返回時的重讀是一次獨立讀取，返回本身既不證明支付成功，也不會自動撤下該提示。提示自身的去充值屬於被保持的情形：它呼叫 `keepOpen()` 並透過共享請求通道申請 `top-up` 頁面，使該提示與其頁面在後續欠費期間保持掛載。存在共享主機條目時，該條目會等待首個帳號快照，而不是渲染一個可能被自身計時器丟棄的 Toast；快照報告未儲存憑證，或帳號流失敗且無快照時，才由該條目自行渲染同一段中立警告 Toast，缺少該主機條目時則立即渲染該 Toast，而不依賴 Chat 主機退回。該條目持有保持與頁面請求，並在自身解除安裝時釋放二者，因此後續欠費會重新發布而不重放已丟棄的提示；關閉與退出登入也會清除保持和頁面請求。關閉、取消、退出登入或離開該提示自己的內嵌頁面都會撤下提示，且不會重試請求。

帳號選單的“意見回饋”入口在系統瀏覽器中開啟飛書問卷。連結透過 prefill_* 參數填寫已有的建置版本、介面語言和螢幕物理解析度，併為所有上下文欄位設定 hide_*=1；不傳帳號 UID、token 或聯絡方式。可在 ui-settings-account 外掛設定 contactFormUrl，切換到另一個 HTTPS 問卷。問卷支援 Harness 來源選項前，contactSource 預設為空；OS 和裝置欄位沿用 Web 實作，保持未填寫。

帳號資料與餘額卡片共用[設定卡片材質與圓角](../../../docs/web-styling.zh.md#corner-radii-and-settings-cards)。用量與充值連結與標準 Button 尺寸一致；授權操作使用公共 Button。

側邊欄帳號選單使用公共 Menu 的表面和背景模糊。已登入選單沿用公共選單項排版；未登入選單使用自己的較寬選單項，並將“意見回饋”入口的文案改為“聯絡我們”。設定選單項顯示外殼傳入的有效組合鍵。關閉設定後，焦點回到側欄帳號入口。

帳號卡片的“更多帳號資訊”連結不帶下劃線，透過系統瀏覽器開啟 Host 提供的 Platform 用量 URL 的根路徑，遵循 `platformOrigin` 設定。

退出登入先查詢正在使用帳號 token 的任務，再開啟確認彈出視窗。有此類任務時提示執行將被打斷，否則提示資料保留且可重新登入。取消、關閉和 Escape 均不退登。影響查詢失敗仍開啟確認彈出視窗，並明確提示無法確認任務狀態；退登失敗保留彈出視窗以便重試。

贈金到帳時，側欄帳號入口上方顯示一條由伺服器端提供文案的通知，不搶佔焦點。用戶端僅在帳號進入登入態時、以及每次進入設定頁時讀取一次未通知贈金，不做輪詢。候選順序與文案均由伺服器端決定，用戶端只展示第一條並原樣渲染其訊息。

伺服器端返回後即繪製通知，包括在設定面板的半透明蒙層之下；同時要求文件可見且卡片已完成一幀繪製。這一幀繪製就是全部的展示訊號：卡片不檢測遮擋，因此處於開啟蒙層之下的卡片與其他情形同樣計數，使用者關閉卡片同樣計入展示。卡片展示後即排隊確認，因此同一張掛載的卡只確認一次。確認失敗會在本次登入工作階段內按帶上限的退避重試，且不會在帳號介面報錯。讀取失敗不會影響已展示的卡片及其待確認佇列，因此連線重連後仍會繼續重試。不寫入瀏覽器儲存。同一次登入的第二個登入態幀以及重連後重放的登入態屬於同一工作階段而非新工作階段，因此保留卡片與重試；只有退出登入、憑證被換成另一帳號，或解除安裝外掛才會丟棄。每個登入態幀都會重新讀取，且新的讀取會取代仍在進行中的舊讀取，因此就地更換的憑證會由一次全新的讀取來識別，而不會沿用被替換帳號的讀取結果；讀取結果中的帳號 ID 隨後會丟棄上一個帳號的卡片與佇列，即使沒有中間的退出登入狀態。下一次登入會展示伺服器端仍然下發的內容，包括上一次登入已確認過的訂單；使用者已看到的卡片會保留到關閉為止，即使之後的讀取沒有返回贈金。

<a id="desktop-onboarding"></a>
### Desktop 引導

Desktop preload 標記在帳號憑證已儲存後啟用引導。進度屬於本地 Host 設定文件，不屬於 Platform 帳號：重新啟動後恢復未完成的步驟，完成或跳過後不再於目前安裝中重複執行。瀏覽器用戶端不掛載此流程。API Key 是否存在由原生歡迎後端透過僅返回布林值的 Desktop preload 橋接提供，與登入共用憑證發現邏輯。未登入但已設定模型 API Key 的安裝會繞過這些頁面，應用標準過程、詳細用量和開啟程式碼工作工具的設定。

歡迎頁必須點選“開始設定”。額度頁始終展示。首次進入時若已確認有正餘額，則主操作為“繼續”，次操作為“去充值”。該選擇在引導控制器重建前保持固定且不持久化，後到的餘額結果不會改變按鈕。僅在確認不存在正餘額時，繼續而不充值才需確認；查詢中或失敗時不阻止繼續。用途卡片選中後描述不變。從原生充值檢視返回後保留額度頁，並在等待任何已在進行的讀取結束後於後臺重讀資料與餘額，不受頁面載入或支付結果影響。該讀取不會重新計算該選擇，因此充值成功後按鈕仍保持首次進入時的狀態，而繼續前行仍按重新整理後的餘額判斷。“下一步”僅在確認零餘額時提示；額度頁的“跳過”使用充值提示，答題頁使用設定提示。僅選辦公用途時以簡潔展示完成；選擇開發或兩種用途時還會詢問過程詳情。上一步保留已有選擇，任意可跳過步驟均採用標準工作過程、簡潔效能與用量以及關閉程式碼工作工具的預設值。此流程不建立工作區或範例任務。

<a id="understand-the-implementation"></a>
## 理解實作

僅登入後在設定導航首位顯示帳號頁；帳號狀態載入完成前以及退出登入後隱藏該頁。 外掛持有一條 Host 快照流，透過框架 hook 供 settings.section 和 settings.launcher 共享。入口選單可開啟設定，並僅在已儲存帳號憑證時提供退出登入。Platform 請求失敗時保留選單，以供重試。外掛不維護獨立憑證狀態，因此不釋出 invariant。

桌面控制器透過 Host 設定將進度寫入 `ui-settings-account`。完成時先一併應用 `ui-chat.transcriptView` 與 `ui-chat.performanceUsage`，再透過共享程式碼工作工具偏好儲存 `ui-settings.enabled`，最後儲存完成標記；寫入被拒絕時保留引導以供重試。成功完成後透過 180ms 淡出顯露工作區；選擇和普通翻頁立即預覽，寫入在後臺按順序執行。佇列最後一次寫入失敗時恢復已儲存進度，並允許重試。完成操作會等待選擇佇列及偏好儲存成功，再關閉頁面；減少動態效果偏好會跳過淡出。onboarding 選項 compact、standard、detailed 直接應用到對應的 Chat 工作過程模式。API Key 進入與顯式跳過均採用 standard；onboarding 不選擇 verbose。完整 Figma 示意圖層以透明、調色盤壓縮的 3× PNG 資源打包；歡迎頁圖層合併並烘焙側欄區域性模糊；充值頁前景視窗不透明度為 70%，僅烘焙其覆蓋插圖區域的模糊，標題使用已打包的 Montserrat 品牌字型，英文標題和描述使用 Light（300），標題中的 DeepSeek Harness 使用 Medium（500）；卡片標題選中前後均使用 Regular（400）。英文底部導航使用 Light（300）。確認進入引導後，視窗最小寬度設為 960px，較窄視窗自動放大；完成後解除寬度限制，但不恢復原尺寸。載入中或已完成引導的啟動不改變視窗尺寸。底部導航空白區域透過滑鼠事件，避免遮擋主操作。卡片區域不參與原生視窗拖曳，核取方塊的鍵盤焦點僅在卡片外框展示。帳號包負責引導覆蓋層和控制元件尺寸樣式。每個步驟和確認彈出視窗各有獨立元件，流程元件協調導航、切換動畫和充值。初始帳號與進度載入期間，覆蓋層隱藏工作區。答題標題和卡片獨立於操作按鈕，位置對齊 Figma 的 1440 × 920 和 960 × 600 斷點。macOS 的內容層清除 body 浮層繼承的 no-drag，位於內容之前的拖拽層保留 8px 原生縮放邊緣；互動控制元件和後續彈出視窗排除自身區域；原生平臺頁面開啟時停用底層引導拖拽層。上方工作區彈出視窗插畫在兩種語言和主題下均使用不透明背景，下層側邊欄不繪製選中行高亮。歡迎頁保持示意圖的原始尺寸，在窄視窗內調整插圖位置並裁切，在寬視窗內展示完整插圖。[引導決策](../../../.agents/notes/implemented/feature/2026-09-16-desktop-onboarding.zh.md)記錄持久化與展示方面的取捨。

<a id="further-exploration"></a>
## 深入探索

[憑證子系統](../../../docs/subsystems/credentials.zh.md)定義儲存介面；[架構](../../../docs/architecture.zh.md)說明應用組合。

帳號登入在模型引導的憑證編輯器之前顯示可關閉的彈出視窗。彈出視窗底部採用緊湊的右對齊橫排操作，主操作位於末尾。側邊欄優先顯示暱稱，缺少暱稱時顯示伺服器端返回的脫敏手機號或電子郵件；資料載入期間保持留空。 彈出視窗文字和側邊欄帳號狀態文字不可選中，複製登入連結按鈕始終可用，並在每次複製成功兩秒後恢復原文案。剪貼簿失敗時，連結原位顯示“複製失敗”兩秒，不中斷登入。等待狀態提供可複製的授權連結和載入圖示；超時和失敗均須使用者手動重試。彈出視窗的“複製登入連結”和設定頁的“開啟”連結會從目前主題快照讀取 Desktop 生效配色，追加 `theme=light` 或 `theme=dark`，使兩條路徑都以目前應用主題開啟 Platform 頁面，且不改變 Platform 已儲存的主題偏好。登入失敗在該彈出視窗內呈現；退出登入失敗時選單保持展開以便重試，入口本身不展示失敗提示。關閉等待彈出視窗會取消對應 Host 登入流程。側邊欄透過設定協調器重新開啟同一個 API Key 編輯器。

帳戶狀態流的終止錯誤會顯示在登入對話方塊或帳戶設定中。外掛解除安裝後不再報告延遲到達的錯誤。

餘額卡片分行展示充值餘額與贈金餘額。贈金行在登入態下常駐；沒有正額贈金時顯示暫無可用贈金。餘額或贈金讀取失敗時，沿用既有的不可用文案並改為指向 Platform 的連結，目標與行為同“查詢用量”一致：Desktop 開啟內嵌頁面，其它環境新開標籤頁；載入中與暫無贈金仍為純文字。不同幣種分別顯示；日期只在伺服器端自己的訊息中出現。


登入成功時，若其他提供者均未設定 API key，則將 `deepseek-account` 的第一個可用模型設為預設值，即使此前儲存過預設選擇。其他提供者只要設定了 key，就保留原預設值，即使其沒有可用模型。工作階段內的顯式選擇保持不變。

## 已知限制與後續工作

<a id="known-limitations-and-deferred-work"></a>

- 資料和充值錢包餘額透過 Host getProfile / getBalance 複用已有 Platform Web 介面。頁面在開啟、登入及重連後重新整理，原樣顯示伺服器端脫敏後的聯絡方式，並分別處理查詢失敗，不將失敗顯示為零餘額。用量和充值使用 Host 按 platformOrigin 派生的連結，並沿用瀏覽器自身登入態，不攜帶 DSH token。
- 已完成引導的安裝不會重新應用預設值或覆蓋使用者後續調整的偏好。完成狀態不跨裝置同步，也不建立逐帳號歷史。
- 引導跟隨介面語言和主題，使用中文、英文分別搭配淺色、深色外觀的四套 Figma PNG 插圖。匯出畫布包含完整插圖範圍，Finder 插圖在兩種主題下使用一致的縱向漸變。

- 通知文案按用戶端讀取時的介面語言由伺服器端在地化。切換語言本身不會重新讀取未通知贈金，因此已在螢幕上的通知會沿用伺服器端先前語言下發的文案，直到使用者手動重新整理或登入生命週期重新開始。

- Platform 檢視的彈出視窗會把文件內其它子節點設為 inert，其中包括 Desktop 擁有的頂欄選單 host，因此 Application 和 Edit 選單保持可見，但在檢視關閉前無法操作。放行該 host 需要 Desktop 側提供 inert 契約。

### 開發備註

[桌面登入決策](../../../.agents/notes/implemented/architecture/2026-09-14-deepseek-account-login.zh.md)記錄取消和儲存的職責。

用量和充值在原生頁面載入完成前顯示居中的 24px 載入圖示，不顯示載入文字；返回操作始終可用。載入 SVG 從 Figma 節點 2957:72553 內嵌到本地樣式。

預設模型初始化在登入幀釋出並確認接收後執行，不延遲後續帳號幀。初始化失敗會記錄診斷日誌，不會將已登入帳號標記為失敗。

引導設定只讀或初始帳號流失敗時，工作區保持可存取。首次設定讀取失敗會顯示重試入口，重新發起共享設定讀取。引導與 Platform 覆蓋層重疊時，最後一個持有者解除安裝後才恢復背景互動。
