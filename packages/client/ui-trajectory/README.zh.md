# @deepseek-ai/dsh-client-ui-trajectory

[English](README.md) | 中文

## 概述

Trajectory 標籤頁讓你以按輪次組織的事件記錄表和互動式時間概覽檢查 agent（智慧代理）活動。它對使用者、助手、工具、巢狀子工具和壓縮（compaction）記錄分組，標示輪次與步驟邊界，併為所選記錄開啟檢查器，顯示 token 用量、耗時、輸入、輸出、計時、圖片和附件摘要。較長曆史開啟時定位於目前尾部，按需載入更早頁面，並且只渲染可見行。流式輸出期間，檢視會跟隨尾部，直到你向上滾動。工作流標籤頁把同樣的記錄畫成流程圖，顯示各個步驟以及每一步呼叫的工具。

## 使用本包

在對話檢視環中開啟 Trajectory 標籤頁，把 agent 活動作為事件記錄表與時間線檢視。初始尾部完成定位前，記錄表會用明確的載入行遮住真實記錄；更早的字首仍未載入時，首行控制元件會在點選時載入一頁更早的歷史，並在該頁載入期間顯示共享 ongoing loading。

### 檢查記錄

呼叫按已記錄的工具名識別。對於 `run_code`，記錄行展示程式說明，檢查器顯示帶行號和語法高亮的原始碼。“程式碼”頁提供換行、檢視原始 JSON 參數的 `{}` 切換按鈕，以及保留末尾換行的原始碼原樣複製。複製原始參數時保留記錄中 JSON 的空白。每個新開啟的程式碼檢視採用上次選擇的換行狀態；切換時，其他已開啟檢視保持原狀。輸出保留記錄中的文字，完整 JSON 物件或陣列使用樹形展示。高亮只採用已記錄工具 Schema 中明確且無衝突的 TypeScript 或 Python 提示；提示缺失或衝突時顯示純文字原始碼。回放約束見 [PTC 檢查決策](../../../.agents/notes/implemented/feature/2026-09-09-ptc-trajectory-code-inspection.zh.md)。

選擇、時間線導航、摺疊與搜尋只覆蓋 React 可見視窗。請求編號與累計用量覆蓋完整的駐留快照。選擇記錄會開啟區域性檢查器，檢視 token 用量、耗時、輸入、輸出、計時與持久保留的圖片。圖片 URL 使用 Conversation 擁有的逐工作階段快取，因此 Chat 與 Trajectory 對每個附件共享一次已授權讀取。使用者記錄會在文字旁同時顯示非零的圖片與普通檔案數量，僅含附件的記錄也顯示這些數量。獨立執行的壓縮請求會按時間順序顯示在自己的 `Between turns` 區段中，而帶編號的壓縮仍位於其所屬輪次內。

概述與預覽共用正文之後的有序附件列表，保留重複引用。每行展示完整縮放的圖片縮圖或檔案型別圖示、已記錄的檔名（未命名圖片使用在地化的編號名稱），以及可用的已記錄大小、型別和圖片尺寸。零位元組檔案保留大小顯示，截斷的檔名透過提示顯示完整名稱。圖片開啟現有燈箱。原始內容保留內容塊順序和未渲染文字，圖片與檔案使用預設摺疊的展開項，包含完整的已記錄欄位。

檢查器中的思考內容使用緊湊 Markdown，沿用檢查器固定的 13px 字號和 20px 行高，不受內容字號設定影響。標題只加粗，不放大字號或行高。助手輸出保留常規 Markdown 排版。

### 時間概覽

當記錄的流包含 token 時間戳時，歷史回覆會保留 TTFT、生成耗時與吞吐量。TTFT 從步驟開始計量到首個 token，包括更早重試嘗試中的輸出；步驟起點尚未載入或流中沒有 token 時，對應指標保持不可用。

固定在記錄表上方的 Overview 區域從左到右投影記錄的真實開始時間與耗時；助手時間條區分記錄到的 TTFT 與解碼時間，懸停 500 ms 後可檢視精確時刻與耗時詳情。拖選區間會把記錄表聚焦到該閉區間內任何時刻處於活動的記錄；滾輪手勢用於縮放時間域；右鍵單擊會清除所選區間，在已放大的視口上按住右鍵拖曳則會平移。初始檢視與流式更新都停留在尾部；向上滾動會暫停跟隨，因此新記錄不會打斷對舊記錄的檢查。

### 工作流圖

工作流標籤頁把每條駐留記錄畫成一個節點，按記錄順序由左到右排列，每條記錄都有箭頭指向下一條。每一輪以使用者訊息上方的輪次標籤開始；每一步先顯示模型回覆，再把它發出的工具呼叫疊放在同一列，下一步的回覆再把它們匯合。`run_code` 的子呼叫顯示在父呼叫之後的一列。每種角色有自己的顏色，工具欄的圖例會列出：使用者訊息、模型回覆、工具呼叫、子工具呼叫與上下文。節點會顯示該記錄做了什麼——回覆的開頭文字或呼叫的參數——以及耗時；模型回覆還會顯示輸入與輸出 token 數。失敗的記錄顯示紅色邊框，執行中的記錄顯示虛線邊框，指向它的箭頭帶有動畫。系統提示詞和上下文注入預設隱藏，按下 **顯示上下文** 後才出現。拖曳畫布可平移，滾動或雙指縮放可縮放，**適合畫面** 顯示整張圖，角落的縮圖可用於跳轉。

點選節點，或在節點獲得焦點時按 Enter，會開啟詳情面板，顯示該記錄的狀態、耗時、做了什麼、輸入、思考和輸出。對於模型回覆，面板列出輸入、快取讀取、快取寫入、輸出與推理 token 及其合計；工具記錄會註明執行工具本身不消耗模型 token，因為它的結果會計入下一次模型請求的輸入。JSON 格式的工具參數與結果使用 JSON 樹。工具記錄的 **在軌跡中檢視** 按鈕會切換到 Trajectory 標籤頁並選中該呼叫。更早的歷史尚未載入時，工具欄的 **載入更早的歷史** 按鈕會為兩個檢視再載入一個工作階段頁面。

## 理解實作

<details>
<summary>實作細節——點選展開</summary>

檢視是純投影：Trajectory 自有的定義從共享工作階段視窗組裝業務記錄——包括因取消而定稿並持久保留的字首、僅有分片時採用的中斷退回記錄，以及被中斷的工具記錄——因此 Trajectory 既不讀取也不改變 Chat 工作階段快照。其 steering（中途引導）分類器透過持續保留的拼接狀態只保留下一步的 Inbox ID，並讓後續上下文共享目前已認領的每個批次。

原生與巢狀 PTC 工具結果保留原始結構化錯誤詳情。失敗記錄在記錄表中顯示錯誤程式碼，在檢查器中顯示錯誤名稱和程式碼。

工具記錄從持久 tool/call 事件開始，使用完整參數。Chat 的瞬態 preparing 階段不建立 Trajectory 工具行，也不改變歷史工具計時。

完整的追加提示詞在請求頭未載入時顯示為獨立系統行；僅提供已知文字，不推斷請求選項或工具目錄。補入其請求歷史後，該獨立展示被替代而不重複提示詞。歷史中的系統提示詞變更與最近的請求狀態比較，包括沒有新請求頭的先前提示詞更新。每個請求保留其所在位置生效的提示詞與變更。包括壓縮在內的 surface 替換會恢復最後一個非空的存活系統提示詞，即使沒有新的系統事件；未載入的提示詞在對應分頁到達前仍不可用。

### 虛擬行

長記錄表最初只從掛載時尾部結束的 50 個 target Node 派生 React 資料。後續 Node 會擴充功能這個固定起點的視窗而不會逐出其字首；現有載入控制元件會先顯露更早的駐留 Node，再請求下一個工作階段頁面。虛擬化只掛載可見行視窗加少量緩衝；僅含請求的分隔行併入下一個具備可測高度的虛擬項，語義行鍵與 ARIA 索引在向前補頁後保持不變。虛擬化器負責結構性追加後的底部跟隨；非虛擬記錄表會直接寫入末尾位置。僅含內容更新的流式幀會保持虛擬行的鍵與高度、複用測量結果，並且不會重複寫入末尾滾動位置。已完成的回覆會在 Trajectory target State 中保留組裝後的塊、計時與用量，共享工作階段視窗則保留原始事件。

### 佈局

Trajectory 要求工作階段殼把 composer 作為浮層置於全高記錄表上方；其回應式縱向滾動容器會預留 composer 的即時高度，確保仍可滾動到最後幾行。工作流在 `flow-graph.ts` 中把同一份佈局摺疊成帶座標的節點，並用 `@xyflow/react` 渲染；它以同樣方式讓 composer 浮在上方，並在畫布和詳情面板下方預留其高度。可滾動的 Summary 區域在懸停或聚焦前保持捲軸滑塊透明，同時不改變預留的滾動幾何空間。本包不提供服務，也不宣告上下文合併。

## 已知限制與延期工作

<a id="known-limitations-and-deferred-work"></a>

- **工具變更展示** — 僅包含工具變更的 developer 訊息在單個工具新增或移除時直接顯示工具名，不提供展開操作。多個變更顯示新增、移除數量，展開後按變更型別分別以逗號分隔顯示一行工具列表。混合內容使用通用上下文展示。


這些限制定義工作仍在進行時檢視能顯示什麼；它們是目前包約束。

- **進行中時 Time 保持空白**：`partial` 與 `runningCalls` 行會顯示執行狀態，但不會虛構耗時，因此 Overview 區域只渲染開始標記，而不會杜撰即時跨度。記錄選擇與時間線選擇位於 Trajectory 內部，不提供錨點深連結。
